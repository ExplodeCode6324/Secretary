# 运行批次与验收建议

下表为本测试包建议执行计划，尚未运行。任何涉及服务、模型或故障注入的实际执行均使用隔离测试环境，不操作现有 Secretary 数据。

| 批次 | 时长/规模 | 必需场景与证据 | 结束条件 |
| --- | --- | --- | --- |
| C0 设计核验 | 每次设计变更 | scripts/check.py；catalog/来源/fixture 一致 | DOC_ONLY 全部检查成功 |
| C1 确定性核心 | 每提交，全部 P0/P1 offline 场景 | 状态、权限、未知作用、真实文件和进程恢复 | 已执行项全通过；阻塞单列，不宣称全验收 |
| C2 数据库 | 独立临时 PostgreSQL | WLD 全部仓储/桥接；同键/slot 竞争；断线 COMMIT | 数据/receipt/outbox 对账，无重复/缺失 |
| C3 竞态与崩溃 | 每一 F 窗口×前后×20 次；每对竞态三种排序×20 次 | 控制器日志、真实 SIGKILL、外部作用计数 | 零 P0；保留所有失败 seed |
| C4 加速长期记忆 | 30/90/365 逻辑日，各 5 个 seed | MEMORY 的时间轴、问题和分类评分 | 独立评分门槛；只证明事件回放 |
| C5 真实模型 | 每组主/任务模型×每场景 10 次起 | 原始 Context、输出、工具、用量、产物独立验证 | 无 P0；报告区间与失败样本，不凭十次称可靠 |
| C6 持续运行 | 24h → 72h → 7 个真实日逐阶段推进 | 每日真实输入/任务、随机故障、恢复和冷却期；逐模块资源指标 | 运行时间达到且正确性/资源门槛达标 |
| C7 实际使用 | Master 自主使用，至少 14 个真实日的候选观察窗口 | 未履行事项、人工纠正、真实工作成果，资料受控 | 逐项人工复核；不继承合成 PASS |
| C8 扩展能力 | 能力实现后 | 快照/一致备份/物理掉电/未来事件或通知适配器 | 单独报告能力与范围 |

## 负载模型

使用 12 个独立事项、1 个慢主会话模型、N 个任务执行者。每 100 个事件建议分配：35 个 Master 输入、20 次 task_query、15 次任务提案、10 次工作决定/批准、10 次记忆查询/变更、10 次反馈/通知。每 10 轮插入一个明确失败、一个未知作用、一次恢复；未知只用合成接收器。正常负载先以达到无持续积压的实测吞吐 λ 为基线，执行 0.5λ、0.8λ、1.2λ 的 30 分钟阶段及 10λ 的 60 秒突发，再降至 0.5λ 冷却 30 分钟。

并发取 1、2、max_workers、max_workers+1、2×max_workers；同计划仍不重叠。工作集取 100/1,000/10,000 任务、1万/10万/100万日志事件；最高档依硬件记录 BLOCKED_ENV，不偷换分母。控制器限制磁盘预算；达到磁盘阈值停止生产新数据并测试受控退化，不挤满真实系统盘。

## 指标与候选门槛

正确性硬门槛：已 ACK 输入丢失=0；未经授权作用=0；未知后自动重复作用=0；状态/证据错配=0；静默截断=0；损坏后空会话继续=0。容量与速度再好也不能抵消这些失败。

逐模块记录输入接受、批准 UI、task_query p50/p95/p99，队列深度/年龄、模型 in-flight、摘要积压、outbox 积压、worker 数、goroutine/线程、FD、RSS、CPU、日志/对象增长速率、恢复耗时、失败原因、模型 tokens/费用。长模型调用期间，批准与查询应独立取得进展。

建议本地离线控制面 p95≤500ms、p99≤2s；无外部等待的请求在 5s 内完成或返回明确过载；10万事件冷启动≤30s。必须写明硬件、数据大小与基线，这些是待实测校准的测试建议，不是原设计承诺。业务等待无 deadline 时仍可长期存在，不能套用此 5s 超时结束它。

资源：预热后每小时取相同负载窗口的中位数；FD/worker 在冷却期回到基线+5 以内；RSS 不因重复闭环持续增长（候选：72h 首尾稳定窗口增长≤20%，至少三段等负载窗口趋势一致）。原始历史不做 GC，磁盘随日志增长属于预期，必须报告 bytes/event 和剩余容量，不能为了过测试删除历史。队列在冷却期应恢复至预设稳态；超过预算仍需可靠拒绝或背压，不静默丢数据。

## 执行适配与已有测试

Go 的参考落点：internal/store/store_test.go、internal/engine 下 engine/memory/compaction/scheduler/world_test.go、internal/world/postgres_test.go、internal/transport/server_test.go。Pi 的参考落点：pi_secretary/test/runtime.test.ts、world.test.ts。完整相对链接在 [覆盖索引](COVERAGE.md)。

接线时先读取对应原型的启动/测试说明，使用其公开 API 或内部测试依赖注入；当前 Go 无外部 worker HTTP 入口，不能将 API 设计表当作现成端点。Go/Pi 的差异与不支持能力逐项标记。性能比较仅在相同输入、Context、模型、硬件、输出验证和外部作用限制下进行。

停止步骤：控制器停止投新事件，暂停新分派，记录在途 intent/attempt/PG receipt，等待可证明的静止点；超时者保持 UNKNOWN。关闭本 run 应用与临时 PG，保存证据清单，最后清理临时资源。不存在已实现 runner 的自动停机承诺；这是后续 runner 必须实现的契约。
