# 敏捷迭代

## 领取和实现

1. 读仓库统一的 [AGENTS.md](../AGENTS.md)、[敏捷专题](../docs/fix/fix_20261108start_敏捷迭代专题/000-实例部署与保留约定.md)、当轮 Master 使用记录及相关 issue。核对运行分支、未跟踪材料、实际服务状态与数据域。区分磁盘上的源码提交和当前进程所用版本。
2. 沿用专题内三位编号，以同一编号关联领取稿、双语方案、构建、验证及复核。保留原使用记录、附件和旧轮次。若任务只是只读诊断，从现有代码、实例与对应运行记录作答。
3. 从核准的 agile 基线建纯源码工作分支，PR 目标为 agile，正式实例始终在 agile 分支。按[复核流程](review.md)将计划交独立 reviewer 复核，取得 Master 实施授权，在源码 checkout 或 CI 完成适合离线执行的检查。需要实机或短暂停机时，把候选版本、观察项、恢复动作及窗口写入计划并核对授权。

## 在唯一实例验收

- 常驻 Core、PostgreSQL 与前台终端 TUI 使用同一数据域。保留 journal、CAS、任务工作区、TUI 草稿、Scope、附件、配置、凭据及历轮材料。实例持续运行，没有实例级累计请求、工具调用额度或到期时间。
- 维护前识别原服务、会话、数据域和维护标记，按任务需要取得可恢复备份。只在已授权的维护窗口使用实例的 stop/start。按[实例操作入口](../docs/agile-attention/README.md)恢复原服务，核对维护标记清除、原域与会话连续、历史可读以及本轮功能。失败时保留证据，按已审恢复方案处理。
- 源码检出、备份都不启动第二个敏捷实例。隔离 benchmark 使用其独立入口、凭据和数据。数据库清理 helper 禁止接触敏捷库。终端交互用真实终端 TUI 验收，人工项目记录实际观察者及结果。
- 采用调度模式时，调度 agent 在本轮全部工作包完成并验证后提交以 agile 为目标的 PR。独立 reviewer 复核当前 HEAD，通过后交 Master 终审确认。实际合入 agile、实例部署、agile 合入 main 和 issue 关闭分别记录授权与结果。同步时核对共享规范版本，保护本地启动器、实例使用说明和私有数据。既有 [005 操作与验证](../docs/fix/fix_20261108start_敏捷迭代专题/005-操作与验证.md) 给出了备份和只读诊断的实例。
