# 缺陷修复

沿用 Master 指定的范围。要求“先写计划”时交付双语方案和计划复核；要求修复现有 PR 时在其原分支继续。来自 issue 的修复按[常规开发](development.md)建立任务分支。

1. 阅读 issue、PR 差异、失败的任务或 CI 日志。登记最初的输入、版本、环境、预期和实测行为，以及能区分故障与修好的观察点。不能安全复现时引用既有失败证据并注明缺口。
2. 在双语计划中说明原因或待证假设、修改位置、正常调用入口及验收条件。视实际影响覆盖旧数据、失败后重试、部分写入和并发。按[复核与验收](review.md)处理每轮意见，取得本轮要求的实施授权。
3. 先验证具体修复，再运行影响范围内的回归和项目要求的完整检查。记录首次失败、修正依据和复测结果。原断言变化时说明需求依据；保留可比较的旧结果。
4. 更新原 PR 或从 issue 创建 PR。交付准确 HEAD、构建记录、测试证据、复核意见及处置。新提交重新核对 CI 和审查覆盖。最终决定及合并后核验按[复核与验收](review.md)执行。
