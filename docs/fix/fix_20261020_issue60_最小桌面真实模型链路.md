## 2. 批准后的实施单元

### A. 类型化展示与有界订阅

把 Connected 拆为对话、任务/详情、关注事项/审批、结果/产物组件；提取纯展示模型与合并函数，使用现有生成 DTO。沿用 FE-00 浅色/蓝色最小样式；完整 PhaseUI、项目切换、管理页和高级长文导航后置。

连接期间固定基础订阅 assistant、timeline、attention、tasks。打开/切换任务、执行、审批、产物只用有界 bridge_query，不调用 subscribe；当前 subscribe→clear_cache 会清空缓存/cursor 并把已受理 outbox 改回 VERIFY_ACCEPTED，仅供明确重建/恢复。TS Snapshot 补上原生已提供的持久 cursor，详情在 cursor 变化、主动打开/刷新、相关本地命令后合并刷新，保留旧内容并标 loading/stale。空事务造成过频刷新时补轻量投影版本通知，不另建同步协议。请求绑定 generation/domain/instance/selection，旧响应不能覆盖当前选择。回归连续切换详情，证明时间线/cache/cursor、滚动和已受理 outbox 状态保留，不重新验证回执。订阅小于 16，显式分页。重开恢复草稿及版本化 message ID/相对偏移锚点，通过 timeline/around 定位，兼容旧数值 scrollTop；从 Core 收敛离线完成工作。保留显式“跳到最新”、文本选择和焦点。

展示连接中、追赶、断开、认证/域/能力冲突、重试/错误和陈旧投影状态。错误保留草稿与意图。未知状态显示原值并禁用依赖该状态的动作；能力 unsupported/not-configured/allowed=false 时说明原因并禁用对应操作。

### B. 对话与真实流式预览

可读地显示有界时间线消息/活动的角色、时间、状态；安全文本/Markdown，内容未完整时可继续读取。适配现有 Message 组件，不增加原始 HTML、外部资源或导航能力。中文 IME 确认候选、取消、焦点转换不能发送；明确发送一次，经原有草稿→outbox 事务提交。排队/受理/不确定与模型/任务结果分开显示。

transient 按完整快照替换、校验限量并按调用标识组合 blocks。当前 timeline 同时包含进行中的 message:<call_id>，公开 messageView 又过滤 running/truncated，因此 call_id 或空文本均不能证明消息已持久化。增加小型兼容 API v1 投影字段：可选 Message.persistence=transient|durable，直接由 timeline row.source 推导；瞬态另提供 preview_status=running|saved|incomplete 和 truncated。同步修改 timeline/messageView、schema、生成合同及相关示例。这是展示元数据，不创建业务状态机。旧/未知合同缺少 persistence 时标最终态未知，不能凭文本推测。相同 ID 持久消息取代预览；空的进行中 timeline 行不能覆盖实时文本。中断如实显示；晚到瞬态不复活最终气泡，断线/实例变更清理瞬态。测试调用中持久 invalidate、saved/incomplete、合法空最终消息、内容分片、重启和乱序快照。通过独立 journal main.message/display_call_id 证明恰好一条持久最终消息，并检查单一 UI 气泡；没有最终消息的合法调用不伪造最终态。

**UI 集成前必要桥修正：** 两帧 sync_channel/try_send 小于实际 1 秒消费周期，Core activity.observed_at 又每约 100ms 改变，空闲也会溢出。将瞬态放独立有字节上限的最新快照 mailbox；持久帧保留校验及有界提示队列，持久队列溢出才断开并追赶，不吞未知/非法帧，不从提示推进 cursor。增加限定 bridge_transient 轻量读取，含 domain/instance/epoch 与单调本地 version；UI 每 250ms 读取，仅访问 mailbox，不抢网络/sync 锁、不拉完整 cache。完整持久快照另行合并刷新，不暴露 token 或任意能力。保留限额、取消及真实连接状态。真实桥按实际 tick 运行 fixture Core 至少 10 秒，空闲及 >=10Hz 瞬态/持久交错均验证非空演进预览、无无谓重连、内存有界、持久收敛与最终去重；另测持久溢出、主动 SSE 中断恢复。不必修改 Core activity 时间语义。

### C. 任务、决策与授权

从对话生成的真实工作展示 task ID、goal、提案/验收内容、request/execution ID 与权威状态。执行详情展示 result、conditions、取消状态、未知操作；提供刷新及能力支持时的显式取消。可选 viewed 只影响留存，本阶段后置，不从 refresh 提交。TaskRequest 仅受理/等待时明确显示，不假装已有执行结果。

通用用户决策/AnswerCommand 后置，本阶段只实现 Issue 要求的授权批准/拒绝。授权先读取当前详情，完整显示真实 display 参数、scope/root、revision、expiry、决策后果；不能只凭摘要审批；RESPONSE_TOO_LARGE 时显示原因并禁用批准。Authorization.display 是可选 JSON：必要的同意详情缺失或无法解释时，禁用批准并说明缺项；不从当前 UI 选择推断授权根。APPROVE/REJECT 使用实际展示的 expected_revision/display_hash；明确点击，pending 从匹配 authorization ID 的未解决持久 outbox 读取，重开仍防双击；若现有 50 条展示窗口会隐藏待批记录，补有界未解决审批目标元数据查询，不解析截断 body 恢复 pending，request_id 由现有桥生成持久化。记住权限与规则管理不纳入本阶段。

版本过期、hash 改变、审批到期/已处理等领域拒绝，保留原意图并刷新权威内容；不静默修改参数或自动批准新版。再次批准必须重新查看并主动操作。域/实例/选择切换使已打开决策面板失效。ACCEPTED 仅是受理，不证明授权执行或任务成功。

### D. 结果、回执与产物

展示真实 Result 字段，包括 limitations/needs_action/verified_by，准确区分未知、未完成和失败。使用实际暴露 ID 关联消息请求→回执→任务请求/任务→执行→结果→产物，不猜因果。POST /messages 不暴露后来生成的 TaskPlan 链接，UI 标明“未暴露关联”，验收另以 journal ID 审计。outbox 2048 字符预览或回执摘要不足时，经统一桥查询完整回执。

列出选中结果/执行的产物，展示名称、字节数、类型、content version/hash、状态、relative_path/path_base/scope 绑定或不可用原因。复用原生元数据校验、下载与保存选择器，以清洗后的产物名作为默认保存名。取消、散列/长度不符、缺失、限额失败均可见，不声称成功、不遗留部分目标。实际窗口下载后独立比对文件字节/hash。
