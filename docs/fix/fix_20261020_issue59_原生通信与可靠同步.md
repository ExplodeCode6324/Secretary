## 设计与实施顺序

### 1. 原生受控连接

在 `src-tauri/src/` 拆出 discovery、transport、protocol、storage、sync、outbox 模块及独立可测试库，main 只装配 Tauri commands。

- 原生配置保存本机 Core 数据目录、预期模式和固定启动配置；WebView 只使用 profile ID，不提交任意文件路径、URL、shell 或启动参数。开发/fixture 与用户数据目录分离。
- endpoint 使用 no-follow 打开并对同一文件描述符 fstat，验证普通文件、owner、0600（不接受组/其他人权限）、大小上限 16 KiB，直接父目录须当前用户拥有且 group/other 无写权限（允许 0755），拒绝 endpoint 与直接父目录符号链接；允许 macOS `/var` 等合法祖先路径经解析后使用；校验 API 版本、严格 loopback URL、合法端口、token 格式及身份字段。
- GET core 校验 instance_id、data_domain_id、mode 与协议能力。attach 不启动；显式 start 使用已配置 Node/backend 的固定 argv、脱离客户端生命周期运行，等待 endpoint 就绪。退出窗口不停止 Core；stop 是独立明确管理操作并走现有协议，不从退出钩子调用。
- 启动配置来自 Application Support 的原生 0600 配置：node_abs、core_root、backend_entry、data_dir、expected_mode，路径项均为预先核验的绝对路径，expected_mode 为显式模式值；缺失时报告配置缺失，不猜测 PATH 或执行 JS 提交的路径。通过受控本地配置文件设置，不增加任意文件读取 IPC。固定 argv `[--import, tsx, backend_entry]`，cwd=core_root（包含已安装 tsx 的 node_modules），显式设置 SECRETARY_DATA/SECRETARY_MODE；stdin=/dev/null，stdout/stderr=<data>/core.log（no-follow、打开后 fchmod 0600），新建 data_dir 为 0700。GUI 原生 start 首期支持 fixture；live 由现有 live wrapper 在准备好模型/数据库环境后启动，再通过此桥 attach，不把模型凭据发给 JS。直接启动 backend 而非会快速成功退出的 start CLI；使用独立会话/进程组，脱离 app 管道。
- start 先 attach；身份/模式/认证错误不触发 spawn。确认无运行实例后启动并有界轮询；子进程退出时先尝试附着并发启动的赢家，否则立即报启动失败。测试 Finder 等价非仓库 cwd，以及 app 退出后 Core 继续处理已受理任务和写日志。
- 原生 HTTP 禁用代理与重定向，限制连接/读取时间、响应大小、并发；Host 与 loopback 一致，不转发 WebView Origin。token 只存在原生连接内存，不进入数据库、DTO、JS、日志或原始错误文本。
- Tauri commands 按 operations 表的操作标识与结构化参数映射固定路由，分别提供受限查询、命令、同步订阅、下载；登记表是 operations 的明确子集：FE-01/02 必需查询、消息/确认等命令、receipts、sync、artifact 和独立 stop；默认排除 admin/*，后续具体页面需求才扩展。拒绝未登记操作、未知参数和路径注入。权限只给本地 main 窗口；保留 CSP，禁止 WebView 直接访问 Core。
- 下载仅接受 artifact ID，原生读取元数据后流式下载，校验长度/hash，以原生保存选择器授予的目标写临时文件后提交；取消/超限/校验失败删除临时文件。不开放任意文件读写。

### 2. 合同与错误边界

- 从现有公开 schema/operations 生成或校验桌面 TS 类型和 Rust DTO/操作表；生成物可重复，CI 检测漂移。浏览器不能导入 Node CoreClient。
- revision/sequence/bytes 保持十进制字符串；仅有界 limit/count 为数值。未知扩展字段可忽略，未知状态保留可显示原值并禁用依赖该状态的动作；未知 sync change 不吞掉或推进 cursor，触发明确不支持状态；允许用户发起保留 outbox 的投影重建，从新 S 加载窗口。若重建后仍遇未知语义则保持不支持状态，不能无限重建或宣称持续同步正常。
- 区分版本/能力不支持、认证失效、身份/模式冲突、RESYNC_REQUIRED、CURSOR_EXPIRED、REQUEST_CONFLICT、领域拒绝与网络不确定。错误只输出稳定 code 和本地说明，禁止透传敏感错误。
- capability 判定依据 core.capabilities 的 state（supported/not_supported/not_configured）、allowed/reason 和 operations，未知能力状态禁用相关动作；不额外假设服务端提供能力协商 API。

### 3. 持久存储和配额

采用 Rust SQLite（bundled）事务存储，macOS Application Support 下每个客户端 profile 独立库。目录 0700，数据库及 WAL/SHM 0600；启动核验，schema_version 顺序事务迁移，迁移失败保留原库并阻断写入。

- `data_domain_id` 隔离草稿、阅读锚点、outbox 和缓存；`instance_id` 标记当前连接、分页和请求代际。相同域重启保留草稿/outbox，实例相关分页失效；换域不迁移或自动发送旧命令。
- 每 profile 有独立 client_id 和 applied cursor；两个客户端不共用同步进度。投影以资源键及查询键保存，可清理和重建；草稿、未解决 outbox 不参与 LRU 淘汰。
- 初始上限：投影 64 MiB/10,000 项、transient 2 MiB、下载临时空间 256 MiB、待处理同步 512 KiB、并发读取 4、单命令正文不超过 Core 的 1 MiB；outbox 1,000 项/32 MiB、草稿总计 16 MiB。达到持久意图上限拒绝新提交并保留编辑内容，不静默丢弃。
- 清理只自动淘汰可重建缓存；已完成 outbox 保留 30 天且有数量上限，未解决意图不自动删。清空域数据须显式操作并提示未解决项。下载预算可通过明确本地配置调整，不能由任意 JS 参数扩大。
- 使用 WAL + synchronous FULL；事务故障/磁盘满时不清空草稿、不推进水位。文件损坏不能自动删除并重新建立空库冒充恢复。

### 4. 同步与刷新

- 新建/重建缓存：先取 S，再加载当前订阅的有界资源窗口，逐页追赶 changes(after=S)，最后建立 SSE；不以全库无界读取为初始化。
- 每个持久 change 解析为待刷新键，包括 aggregate invalidate，不能因根 revision 相同跳过。数据刷新与 applied cursor 在同一事务提交；失败保留待刷新状态和旧水位。
- 以连接 epoch、每查询 generation 丢弃旧连接/旧轮次结果；最新刷新失败时旧请求成功也不能覆盖失败状态或推进水位。
- SSE change 入有界队列，transient 只在内存按 call_id 合并，不持久化、不推进 cursor。队列满断开并从已提交 cursor 追赶；指数退避带抖动且有上限，关闭连接可取消任务。
- 同域实例重启重新验证身份/凭据，清除实例分页与 transient，再用持久 sync cursor 续传；RESYNC_REQUIRED 重建投影并保留 outbox 对账。认证失败显示阻断，不能转成空列表或自动启动另一个 Core。
- cache eviction 同时移除完整性标记；后续订阅重新读资源，不能把已推进全局水位解释为被淘汰资源仍完整。

### 5. 命令 outbox

- 提交时原子保存 UUID request_id、原操作/路径、原参数/序列化内容、所属域和草稿版本，再清除该版本草稿；异步编辑产生的新版本不能被清除。数据库提交成功后才尝试网络请求。
- 发送记录与 receipt 持久化；202 只代表已受理，展示业务进度需查询对应资源。短命令 receipt 保持 ACCEPTED，不等待 COMPLETED；完成以关联资源为准。NO_CHANGES 属于内部命令 result（state/status），不是公开 Receipt.state，也不假设公开 receipt 暴露 result。
- 超时、断线、5xx、客户端在发送边界强杀后，先 GET requests/{id}。找到回执就对账；仅明确 NOT_FOUND 且本地无受理/UNKNOWN 证据时按原 ID、原路径、相同参数重投。
- UNKNOWN 或已受理后 receipt 消失（例如备份回滚）进入需用户处理状态，禁止自动新建 ID 或重执行副作用。同域历史分叉重同步不能擦除曾受理证据。
- 400/404/409/410/422 按命令拒绝处理，保留意图供用户修订；REQUEST_CONFLICT 保留原 ID 已有回执并阻断原参数覆盖。401/403、域/模式冲突停发并显示。
- `core/stop` 是绑定当前 instance 的独立管理意图：仍先持久记录 request_id/原参数和待发送标记，单发后只观察，不参与通用自动重投；重开或实例改变均不补发；发送前崩溃标为未发送/需重新确认。原实例 endpoint 消失且连接关闭可报告已断开；网络拒绝本身不能证明进程已退出，观察超时报告未知。明确已受理则保留回执；任何不确定结果供用户重新检查，不能将旧 stop 发给新实例。
- 每 profile 串行调度投递，数据库事务领取防重复本地 worker；重启先对账。Core 原 request_id 去重是最终依据，不声称跨未知副作用 exactly-once。

### 6. 最小用户入口与后续复用

提供连接 profile、attach/start、连接/认证/同步状态、持久输入草稿、发送与 outbox/receipt 状态、显式重新连接和单独停止 Core 入口。FE-02 只经统一桌面 adapter 使用这些接口，不建第二网络栈。FE-00 合成 study 页面留在独立 study/test 入口，真桥验收只使用真实连接界面，证据区分两者。测试钩子只在 native-test 构建启用，release 权限不能带测试通用入口。
