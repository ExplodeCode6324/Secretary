## 4. Rendering, long content and safety

Extract MarkdownIt configuration into a production module with HTML disabled, no executable HTML/svg/iframe, remote images rendered as alt text, no embedded resources. Render GFM-style tables and fenced code through existing MarkdownIt features, preserve code whitespace and horizontal scrolling within the block. Cache by domain/instance/timeline generation, row ID/revision, content length/version and display preference, with the budgets below; no whole-timeline HTML replacement.

Links: explicit user activation only, show destination and provide copy address. Permit absolute http/https only after URL parsing in TypeScript and the narrow native opener; reject javascript/data/file/custom schemes, credentials, control-character obfuscation and malformed URLs. Open via one new `bridge_open_url` IPC: revalidate with the already available reqwest::Url/url parser, then under cfg(target_os="macos") call `Command::new("/usr/bin/open").arg(validated_url)` directly, with a 2048-byte URL cap, no shell and no arbitrary executable/args. Expose only its specific custom permission. Links render as non-navigating controls with destination/copy action; add a WebView navigation guard allowing only the packaged app origin (exact loopback Vite origin in development) and rejecting outside navigation/new windows. Display bounded ASCII/punycode host plus full destination on explicit inspection. Copy uses user-activated `navigator.clipboard.writeText` with success/error feedback, first verified in actual WKWebView app scheme. If unavailable, the pre-planned fallback is a write-only `bridge_copy_text` IPC, capped at 2 MiB, piping UTF-8 text to `/usr/bin/pbcopy` stdin under macOS cfg, explicitly setting LANG and LC_ALL to en_US.UTF-8 with only its own custom permission, no clipboard reads or shell. Verify CJK/ZWJ round-trip using pbpaste in tests only, including a launchd-like environment without inherited locale; production never reads clipboard. For pbcopy, write all stdin and close it before waiting; use a 2s timeout with cleanup and truthful failure. For open, bound the IPC wait to 2s but treat a still-running cold browser launch as requested/unconfirmed, not failed: reap completion asynchronously, do not kill a potentially successful launch or automatically retry. No third-party opener/clipboard package or broad permission is required; CSP is unchanged. Attach the navigation guard via a small local Tauri plugin on_navigation hook to the existing config-created window, rather than recreating it. No automatic fetch on hover/render.

Each fragment request captures domain, instance, timeline generation, row ID/revision, preference epoch and request sequence. Serialize one outstanding fragment per row; accept a cursor once; verify identity/revision; append exactly once; reject late results after navigation reset, preference change or disposal. On CURSOR_EXPIRED, preserve the readable old content as stale, discard its cursor and explicitly reload that row revision. Never concatenate different revisions. Assemble raw text/thinking using opaque server cursors, without calculating server offsets in JS. Server currently avoids surrogate splits, not all grapheme splits: retain the trailing grapheme across fragment boundaries using Intl.Segmenter, concatenate before segmentation, and only finalize it when more content or EOF establishes the boundary. Test ZWJ emoji, combining marks, flags and non-BMP text; do not normalize text or drop/duplicate code units.

Default content is bounded preview with explicit continue. Proposed hard client budgets: page request 50 rows (server maximum 200 / 1 MiB); resident window at most 3 pages / 150 rows; total resident raw content 8 MiB UTF-8, at most 2 MiB per expanded message; rendered fragment cache 8 MiB; at most 2 foreground reads total and 1 thinking refresh. Enforce byte budgets before accepting/concatenating, including text and thinking. If a single row or an active selection would exceed the cap, keep existing content, stop prefetch and show a manual continuation/replacement boundary; never silently truncate or evict selected/focused content. Full-copy action explicitly retrieves the selected code/message within the 2 MiB cap and reports success only on EOF; otherwise offer copying the clearly labelled loaded portion. Requests and caches stop on disposal/domain switch.

## 6. Thinking, synchronization and sending

Thinking is on by default, with its body collapsed behind an explicit expandable summary, and immediately hidden/purged from presentation and in-memory thinking caches when disabled. Keep the durable baseline timeline subscription `thinking=false`; opt-in thinking responses are one-shot queries and are never written into the durable projection cache. Do not call `subscribe()` for every toggle: it currently resets sync/cache and is unnecessary. Preference epoch rejects pending opt-in results after OFF. This is display/data-minimization behavior, not a claim of secure disk erasure or ability to expose hidden provider reasoning. A per-data-domain `localStorage` key, using the established client theme/motion mechanism and falling back to ON when no preference can be read, persists the display preference. It is entirely separate from anchors and requires no preference-table migration. The preference enables only non-redacted thinking already exposed by Core; this is not a request to expose internal hidden reasoning. Use the query flags specified below; keep cursor scope consistent within each path. SSE remains its current text-only bounded mailbox. Refresh only visible running message IDs through `messages/{id}/content?thinking=true&streaming=true` with no cursor (first fragment), never the whole 1 MiB window. Global maximum one request/second, one outstanding, at most 64 KiB response admitted per refresh, round-robin over visible running rows; obey the existing client budgets and stop when settled/hidden/offline. SSE is the sole text source for transient rows in BOTH ON and OFF modes, using Core’s existing newline-between-blocks assembly. The per-row query contributes THINKING ONLY: ignore its text entirely. Page/around/durable-content queries use thinking=true&streaming=false when ON (thinking=false&streaming=false when OFF), so they cannot overwrite a transient SSE body. The transient thinking query alone uses streaming=true. Newly durable visible rows on the thinking=false baseline tail get a one-shot thinking=true&streaming=false content read when ON, keyed by generation/row/revision, retaining the result only in the bounded in-memory thinking cache; never re-query the entire tail for this. Thus thinking ON does not reduce the text stream to the 4,999 UTF-16-unit first fragment or 1Hz query cadence. Test a transient text over 5,000 units while toggling ON/OFF and receiving late page/content queries. Test that the existing two 30,000 JSON-byte cuts plus bounded metadata fit the 64KiB admission budget; report an explicit limit error if that invariant is violated, never silently omit thinking. Running thinking exposes only its labelled partial first fragment; transient text retains the full bounded SSE preview, with no continuation/full-copy claim for either; durable rows enable revision-bound continuation. Late replies need the current preference epoch. On a preference toggle retain already-loaded body text as a labelled loaded portion, hide thinking immediately if OFF, invalidate content/page cursors and restart the current window/row from offset 0 under the new scope within budget. Never append across preference scopes; pick cache values by full query key rather than operation-only `projection()`. Do not mix alternate thinking subscriptions or restore hidden text from stale snapshots. Preserve OFF preference across Core reconnect and client restart.

Keep durable sync/cursor separated from transient mailbox. Same-domain/instance disconnect retains bounded last text marked reconnecting, not final. A new authoritative snapshot replaces transient state; instance/domain/generation changes clear matching transient/cursors/tombstones and revalidate reading positions. Display cache stale, reconnecting, disconnected, no data and query error distinctly; cached content never masquerades as current. Maintain existing outbox protocol: save versioned draft, persist original request ID/body and clear only matching draft in one transaction, then submit; timeout/disconnect/5xx reconciles receipts. Do not create a new request ID for unknown outcomes or retry an accepted side effect.

Enumerate every fixed state written by Rust in a shared tested presentation map: PENDING→queued, SENDING→sending, TRACKING→accepted/processing, ACCEPTED→accepted, COMPLETED→command completed, FAILED→failed; UNCERTAIN/UNKNOWN/RECEIPT_MISSING/VERIFY_ACCEPTED→unconfirmed/reconciling; UNSUPPORTED_RECEIPT→unrecognized receipt, no automatic replay. STOP_* states remain lifecycle-only, never message completion. UNSUPPORTED_VERSION and CONTRACT_INVALID→unconfirmed/may already be recorded, never known rejection. Correct deliver() to mark these post-2xx decode/validation failures UNCERTAIN so the existing pending reconciliation queries their original request_id; regression-test a successfully accepted POST whose response decode/validation fails. Only proven local pre-send validation/capability failures or proven non-2xx Core rejection codes can be labelled rejected (existing network/5xx ambiguity stays unconfirmed). Any unknown future state is labelled unrecognized with the code, never success or automatic retry; do not falsely assert rejection where no rejection evidence exists. A source/state inventory regression covers every Rust writer. Map actual outbox states/receipts to these labels; command completion is distinct from model/task completion. Retain failed/unknown request text, provide copy or restore-to-editor only on explicit action, and never overwrite a newer draft. The existing snapshot includes only the last 50 outbox entries and a 2048-character body prefix, so add a narrow read-only local outbox-detail IPC keyed by expected domain and existing request UUID, restricted to message commands and the existing 1 MiB command cap. Never parse a snapshot prefix as complete JSON or restore it as the complete draft. Provide bounded pending/failed-message listing so unresolved rows beyond the latest 50 remain reachable. Protect FAILED message bodies by changing the quota-eviction and 30-day-cleanup predicates to exclude rows whose query operation is messages. Existing failed rows become protected automatically; no new column, table, user_version change or schema migration. The explicit discard action removes exactly one current-domain terminal failed/confirmed-rejected message row after the user has recovered/copied its text and confirmed discard; it never deletes pending/uncertain/unresolved intent. Copy/restore alone does not delete the original. If protected content fills the existing quota, refuse a new enqueue without losing the editor text. Keep unresolved intent protected, and successful durable commands on existing resolved-retention policy. Local detail/recovery is not a new send or replay endpoint. Before restoring UNKNOWN/UNCERTAIN/RECEIPT_MISSING/VERIFY_ACCEPTED text, warn that it may already be recorded; show any loaded durable match via request_id and let the user explicitly choose restore/copy. A subsequent manual send is a new request and can duplicate an earlier side effect. Test quota and age cleanup with existing failed messages, bind/reverification transitions, concurrent enqueue and targeted discard.
