| C3 mode loss / Reset / Hard Reset | An unavoidable raw-stream limitation: unbracketed pasted bytes can look typed and may become commands/actions. | C4 IME | Committed bytes are typed text. Enter cannot submit. Native candidate anchoring, Ctrl+S/Ctrl+G during composition and composition during streaming paints need actual terminal evidence. |

Master must acknowledge the C2/C3 narrowing **before merge**, alongside the concrete terminal acceptance results; it is not approval to replace the terminal with a browser.

Input read before raw mode, paste mode and first paint are all ready is discarded with a visible count/notice and never dispatched, including on reinitialization. First ready paint and activation happen synchronously before accepting input. No startup type-ahead can authorize Resume/Submit.

### 2. Decoder and ordered event pipeline

Use a custom injected `Terminal` implementation, not pi-tui `ProcessTerminal`; no global modifier probe, native addon, kitty/modifyOtherKeys negotiation or terminal query replies. Codex independently confirmed the review's hazards in installed `dist/terminal.js`, `dist/stdin-buffer.js` and `dist/tui-alt-screen.js`. Keep a product test that refuses native addon loading.

One StringDecoder decodes bytes exactly once; never give raw Buffers to StdinBuffer. A bounded product framer owns paste start/end markers before key decoding; StdinBuffer, if used for ordinary keys, must never see a paste-start marker. On paste overflow, discard until the closing marker with a visible error; never switch the remaining body to key mode. Stray end markers outside paste are inserted as paste-origin data, not actions. Only flush a lone ESC timeout outside paste. UTF-8 errors, incomplete escape sequences and incomplete pastes preserve the canonical draft; incomplete paste text is not committed. Same-chunk suspicious-control quarantine is defence-in-depth only, with the split-marker residual retained as an expected-failure witness.

Translate into existing InputProtocol events and `app.event(value, localLease)`. Typed bursts split at UTF-8-safe boundaries of at most 64 KiB. A complete paste maps to begin/chunk/commit in one serialized event task, with no timer/network/disk wait interposed between chunks; this prevents human paste duration from consuming InputProtocol's five-second transaction deadline. The framer has a 4 MiB text cap; the serialized pending input queue has an 8 MiB cap and explicit overload recovery. Record current revision at task execution against the canonical editor, not a speculative second editor. Preserve selection/revision checks across asynchronous clipboard and confirmation operations. During a large-edit decision, only Apply/Cancel and safe inspection are dispatched; later captured input remains bounded and ordered, never silently discarded or executed as a decision. All refusal and pending state stays visible through repaint.

### 4. Shutdown and local lease ownership

Keep the existing Outbox algorithm and its before/after-fsync guards. Its current generation mechanism is already a revocable lease; rebind it to the local terminal session and rename comments/status text as needed. Do not redesign the dispatcher. No synchronous paint or await may occur from the final guard to fetch initiation; onChange schedules paint only. Revocation blocks new POST initiation but does not cancel a POST already started; shutdown retains its existing abort/reconciliation semantics. Existing matching durable receipts remain eligible for handoff.

At the **start** of shutdown: revoke input/send authority, synchronously remove input/resize listeners, restore saved raw mode, cursor, bracketed paste and alternate screen (best effort if output is already lost), and cancel renderer timers. Only then perform the bounded flush and stderr report. Keep persistent, idempotent signal/exception handlers installed until process exit so repeated signals cannot bypass restoration. Handle stdin/stdout error/end/close; EIO/EPIPE means terminal loss, stops further writes and closes the client. Recoverable input quarantine is distinct: reset incomplete input, revoke the lease, show the refusal and require an explicit local recovery action; no replay of ambiguous queued actions. Unsupported ordinary keys produce a notice, not whole-client teardown.

Choose no job-control suspension: raw Ctrl+Z shows a hint; SIGTSTP triggers graceful close. SIGSTOP/SIGKILL cannot be intercepted and may need shell `reset` and client reopen; SIGCONT after an external forced stop immediately closes conservatively instead of silently reauthorizing sends. Test child-node, tsx/npm parent and process-group signals separately, plus PTY hangup, repeated signals during slow flush and EPIPE. Keep Core independent. The writer's fsync/QoS algorithm remains unchanged.
