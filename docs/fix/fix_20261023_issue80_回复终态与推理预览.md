## 3. 回复与活动终态

对已有权威 assistant main.message、content 为数组的记录按下表投影：

| stopReason | outcome / incomplete | 无可显示内容时 | 模型活动 |
| --- | --- | --- | --- |
| stop | completed / false | 保持原省略 | succeeded |
| toolUse | continued / false | 正常 tool-only 保留活动，不造空消息或失败 | 模型调用 succeeded，工具保留自身状态 |
| length | truncated / true | 保留 text 为空的状态消息，不造正文/推理 | **truncated**，phase 明确为 `输出已截断` |
| error | failed / true | 保留状态消息 | 保留现有失败语义 |
| aborted | interrupted / true | 保留状态消息 | 保留现有取消/中断语义 |
| 缺失/未来值 | unknown / 兼容既有行为 | 保持既有规则，不猜成功 | 非已知 length 时保留旧 ModelCall 规则 |

length 截断适用于 MAIN、TASK、COMPACTION（含 settings 发起的 compaction）各类模型调用；live/recent 与历史重建统一使用 `输出已截断`，不改父 task/compaction 业务状态。实时结束前明确设置 phase，或最小扩展观察用途的 end helper；现有 end 无 error 时保留原 phase，不能只调用 end 就声称阶段文字已改。本地 ActivityStatus 增加 truncated，实时 transport 和历史 model 投影共同使用；公开 Activity.status 仍为开放字符串，在源 schema 描述中写明。已结束的截断调用不得继续活跃，也不能在 live→durable 替换后变成 succeeded。检查状态消费者的穷举/终态假设。length 的 ModelCall 仍为 RESPONSE_SAVED，响应字节、重放身份、工具执行次序、时间、重试和预算不变；不新增业务状态。

若传输失败且没有权威 assistant 消息，保留真实 ModelCall/活动故障，不伪造持久成功消息或将 transient 正文持久化。无 display_call_id 的旧消息沿用 event ID。redacted-only 的异常结果同样保留空状态行，正常 tool-only 不产生该行。

### 3.1 空失败来源与稳定展示身份（R1 B1/B2）

区分两种来源：(a) provider error/aborted 经最终尝试 diagnostic stream 返回，带新 call ID，可能含 partial；(b) 上游 Agent.handleRunFailure 因异常合成空 text，stopReason 取 Agent 自身 abort flag。下一调用 preview start 之前失败，旧日志可能继承上一 display_call_id。Core 停止先 abort modelLifetime，再由 host.close 调用 agent.abort，因此传输取消可能对应合成 error 消息。

异常空状态事件不得以相同 display_call_id 覆盖另一个既有持久 assistant 事件；改用自身 source event ID 并省略 call_id，原消息正文、outcome、顺序保持。自己调用的状态结果仍可替换自己的 transient preview。按持久日志顺序确定身份，同一 source event 重复处理幂等。通过一个共享展示身份 resolver 同时供 Timeline 和 ApplicationService 的 eventMessages/messageEvents 使用，包含 around-by-event 和 related 定位；解析元数据增量维护，不增加每次查询全历史扫描。先前 tool-only 事件即使无消息行，也保留其持久 call 关联，后来的无关失败不能因此误归属于它。此规则必须处理已有历史，不能只修新写入。

新写入在每个 assistant message_end 成功持久后清空 displayCallID；当前事件捕获的 ID 保持，toolResult 不消费新模型 call ID。覆盖下一 start 前的 call-limit/budget/prepareRequest 故障，以及上一回复后尚未新调用的故障。仅改展示元数据；messageIdentityHash 已剔除 display_call_id，不改 ModelCall 身份或上游 Agent。

空 error/aborted 先解析没有冲突的调用关联。若同 session 的关联 ModelCall 为 INTERRUPTED 且 failure_kind=CANCELLED，即使存储的合成 stopReason=error，也投影 interrupted、incomplete=true。其他情况保留 error→failed、aborted→interrupted。这里明确保留真实 Agent/provider abort 在没有可解析 call 时仍为 interrupted，不从错误文本或旧调用猜取消。无需新增持久字段、解析原始 error 字符串或改写响应。回退 event ID 的空 error 不借用上一调用的取消状态；非空 provider 响应仍按 stopReason 处理。

回归包括：可见 text+toolUse 后发生 pre-call 故障；历史 fixture 中两持久事件复用 display ID；两个 event 的 around 定位各自正确，原正文不丢、失败独立且 reopen ID 稳定；独立 Core 在调用中停止并 reopen，空状态与 interrupted 活动一致；缺失/跨 session/陈旧关联和无 call 的真实 aborted。若实测确认另外的 RECOVERY_BLOCKED 恢复策略问题，只记录给协调单独跟进，不在 #80 改 session recovery policy。

## 4. 短预览契约

公开 Message 与 SSE preview 都增加可选 `thinking_preview`，共享 schema 定义 `ThinkingPreview`：`{text: string, truncated: boolean}`。它是与 thinking 开关独立的展示元数据；缺失表示当前投影没有可显示推理。`thinking` 继续是显式展开的全文分片。短预览截断不能复用 Message.truncated（transient 保存上限）或 outcome=truncated（模型 length）。

VIEW-02 允许固定 20 字符前缀；当前 pi-ai ThinkingContent 无独立可复用 summary 字段，因此明确采用此选项，不寻找或生成摘要。共享纯函数只读取已有非 redacted thinking，按 content index 顺序，将非空可显示块以 `\n` 拼接；完整展开也遵循同一约定。不 trim、不做 Unicode normalization，不读签名、opaque/redacted 内容，不造摘要、不调用模型。使用 Node 22 的 Intl.Segmenter / grapheme 计数，返回前 **20 个 extended grapheme clusters**，不按 code unit/code point 截断。分隔符、空白同样按 grapheme 计数。仅确定后面还有可显示内容时加一个 `…`，不占 20 字符。完整恰好 20 个时不加。每次由当前快照重算，不拼接旧短预览或正文。

增加 **4 KiB JSON 编码后 text 预算**，包含可能的省略号，任何情况下不拆 grapheme。极端超长 grapheme 可使结果不足 20 个；若一个完整 grapheme 都放不下，返回 `{text:"", truncated:true}`，不伪造正文或省略号。此例外保住现有响应字节上限。取得有界前缀及是否仍有内容后即停止，不增加隐藏全文缓存或全历史扫描；源尾部因保存预算丢失时明确截断，不能声称推理完整。

固定一种来源方案：在 Previews.update 中，从当前 event.partial.content、保存裁切之前使用共享 helper 计算 thinking_preview，不再维护另一套逐块截断来源方案。检查所有带内容的更新及 redaction 转换，终态 done/error 快照也须撤销旧可见推理。对保存的 thinking 块按同一当前源复核/移除，避免显式展开泄露先可见后 redacted 的旧内容。只保存有界元数据，随原临时条目淘汰。正文耗尽共用保存预算不能抹掉当前源仍有的短推理前缀，也不能谎称短推理被截断。测试 end/delta 替换、排序、跨 delta emoji/组合字符；后续 delta 可以扩展最后一个 grapheme 并重算前缀。

分段输入限制为逻辑非空块换行连接后的前 4,097 个 UTF-16 单元；只收集此前缀，不 join/copy 隐藏全文。若源仍有后续内容，先丢弃窗口最后一个 segment，避免它是不完整 cluster；跨越该窗口的 cluster 本来也无法放入 4 KiB JSON-text 预算。遇到孤立 surrogate（含流中尚未配对的高 surrogate）在其前停止，不输出它或编码时凭空出现的 U+FFFD；有源内容被省略则标记 truncated，后续完整 delta 重算。fixture 选择稳定 Unicode 序列并记 Node/ICU 版本；运行时升级可使展示前缀变化，但不影响持久身份。保留 4 KiB 而非可选建议的 1 KiB，由既有按字节装页逻辑减少行数，并用 200 候选行验证页上限。

服务端仅当 truncated 且已有非空前缀时追加一个展示用 U+2026；原前缀自身末尾若就是 U+2026 不删改。GET/SSE 自带统一文本，客户端不要再加一次标记。原内容不保证终端安全；API README 要求客户端渲染前 escape/sanitize 控制符和 ANSI，具体实现交 #82。

redaction 移除已有 transient 行全部可见块时，仍推进 revision，保留稳定行但内容为空且无 thinking_preview；不因 redaction 单独创建新的正常空 preview 行。之前取得的内容游标必须返回 CURSOR_EXPIRED，而非 INVALID_FRAGMENT_OFFSET。ApplicationService 先对当前行元数据检查 cursor revision，再套用 offset，覆盖内容缩短、过期、最终化；新请求继续正常 offset 校验。

同一 helper/字段用于持久 timeline、around、content 分片和 transient。默认 GET 即使 streaming=false 也为活跃预览提供短预览元数据；完整 transient 正文仍由现有 streaming 控制。这样默认 GET/SSE 的短预览一致，而正文契约不变。过期预览不提供推理短预览；持久发布从权威响应重算并覆盖临时内容。

## 5. 展开、有界读取与身份

默认 thinking=false 不含 thinking，thinkingLength/thinkingOffset 的有效值为零，只有未读正文能产生内容 next_cursor。thinking_preview 不计入 length/offset，不推进游标，也不修改持久消息的权威 revision。即使推理很长，只有推理的持久消息默认仍为 next_cursor=null。

thinking=true 显式读取现有有界完整推理分片；流中还需 streaming=true。不新增 SSE 展开参数，SSE 始终只给短预览，完整流中推理通过显式 GET。保留每正文/推理分片最多 4,999 UTF-16 单元及 30,000 JSON 字节的裁切和 scalar-safe offset 语义、内部完整消息分片最多 64 KiB、timeline 1 MiB/200 行上限。新增最多 4 KiB 元数据后若需要，调整分片预算以保持完整序列化响应的 64 KiB 上限。展开分片须能无损拼回全文，不要求每片末尾为 grapheme 边界，但不能拆 surrogate；grapheme 保证专用于短预览。

保留 8 预览/128 块/32,768 保存单元、SSE 512 KiB 连接预算、transient 丢弃阈值和持久追赶。不新增自动补读循环、无界展开、永久摘要记录或保留策略。/cotvisible 与展开/收起 UI 属于 #82；#80 只验证服务端请求/响应契约。

游标继续绑定 message ID、内容 revision、实例及准确 thinking/streaming 开关。切换开关从首片重读，旧作用域游标拒绝。流中增长或最终持久化后旧内容游标失效，客户端按稳定 ID 重新请求。SSE preview.id 仍为 call ID，公开消息 ID 仍为 message:call_id，source_event_id 保留日志身份。preview→durable 不改变顺序，不合并不同 retry attempt，不把 preview_status=saved 当持久成功。

测试重复/乱序观察、先持久后看到预览或相反、8 条上限淘汰后的 expired/ revision 更新、过期后迟到持久结果和 reopen。重启丢弃临时预览；持久消息 ID、outcome、短预览可重建；内容/timeline cursor 不是永久书签。GET/SSE 展开不产生 Store 记录、模型调用、输入/上下文身份修改、viewed/presented/read 命令或传输重试。
