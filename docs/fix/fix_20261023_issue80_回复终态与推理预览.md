## 3. 回复与活动终态

对已有权威 assistant main.message、content 为数组的记录按下表投影：

| stopReason | outcome / incomplete | 无可显示内容时 | 模型活动 |
| --- | --- | --- | --- |
| stop | completed / false | 保持原省略 | succeeded |
| toolUse | continued / false | 正常 tool-only 保留活动，不造空消息或失败 | 模型调用 succeeded，工具保留自身状态 |
| length | truncated / true | 保留 text 为空的状态消息，不造正文/推理 | **truncated**，phase 明确为 `输出已截断` |
| error | failed / true | 保留状态消息 | 保留现有失败语义 |
| aborted | interrupted / true | 保留状态消息 | 保留现有取消/中断语义 |
| 缺失/未来值 | unknown / 兼容既有行为 | 保持既有规则，不猜成功 | 非已知 length 时保留旧 ModelCall 规则 |

本地 ActivityStatus 增加 truncated，实时 transport 和历史 model 投影共同使用；公开 Activity.status 仍为开放字符串，在源 schema 描述中写明。已结束的截断调用不得继续活跃，也不能在 live→durable 替换后变成 succeeded。检查状态消费者的穷举/终态假设。length 的 ModelCall 仍为 RESPONSE_SAVED，响应字节、重放身份、工具执行次序、时间、重试和预算不变；不新增业务状态。

若传输失败且没有权威 assistant 消息，保留真实 ModelCall/活动故障，不伪造持久成功消息或将 transient 正文持久化。无 display_call_id 的旧消息沿用 event ID。redacted-only 的异常结果同样保留空状态行，正常 tool-only 不产生该行。

## 4. 短预览契约

公开 Message 与 SSE preview 都增加可选 `thinking_preview`，共享 schema 定义 `ThinkingPreview`：`{text: string, truncated: boolean}`。它是与 thinking 开关独立的展示元数据；缺失表示当前投影没有可显示推理。`thinking` 继续是显式展开的全文分片。短预览截断不能复用 Message.truncated（transient 保存上限）或 outcome=truncated（模型 length）。

共享纯函数只读取已有非 redacted thinking，按 content index 顺序，将非空可显示块以 `\n` 拼接；完整展开也遵循同一约定。不 trim、不做 Unicode normalization，不读签名、opaque/redacted 内容，不造摘要、不调用模型。使用 Node 22 的 Intl.Segmenter / grapheme 计数，返回前 **20 个 extended grapheme clusters**，不按 code unit/code point 截断。分隔符、空白同样按 grapheme 计数。仅确定后面还有可显示内容时加一个 `…`，不占 20 字符。完整恰好 20 个时不加。每次由当前快照重算，不拼接旧短预览或正文。

增加 **4 KiB JSON 编码后 text 预算**，包含可能的省略号，任何情况下不拆 grapheme。极端超长 grapheme 可使结果不足 20 个；若一个完整 grapheme 都放不下，返回 `{text:"", truncated:true}`，不伪造正文或省略号。此例外保住现有响应字节上限。取得有界前缀及是否仍有内容后即停止，不增加隐藏全文缓存或全历史扫描；源尾部因保存预算丢失时明确截断，不能声称推理完整。

不能让预览仓库容量截断点的半个 surrogate/grapheme 外泄。短预览应在保存裁切前从当前合法可见源派生，或保存有界前缀元数据及推理自身的截断依据；状态随预览条目淘汰且总量有界。不得因为正文很长使全局 text+thinking 截断标志变真，就谎称一段短推理也被截断。测试 end/delta 替换、块排序、redaction 转换、跨 delta emoji/组合字符。流中前缀反映当前收到的内容，后续 delta 可以延伸最后一个 grapheme 并替换短预览。

同一 helper/字段用于持久 timeline、around、content 分片和 transient。默认 GET 即使 streaming=false 也为活跃预览提供短预览元数据；完整 transient 正文仍由现有 streaming 控制。这样默认 GET/SSE 的短预览一致，而正文契约不变。过期预览不提供推理短预览；持久发布从权威响应重算并覆盖临时内容。

## 5. 展开、有界读取与身份

默认 thinking=false 不含 thinking，thinkingLength/thinkingOffset 的有效值为零，只有未读正文能产生内容 next_cursor。thinking_preview 不计入 length/offset，不推进游标，也不修改持久消息的权威 revision。即使推理很长，只有推理的持久消息默认仍为 next_cursor=null。

thinking=true 显式读取现有有界完整推理分片；流中还需 streaming=true。不新增 SSE 展开参数，SSE 始终只给短预览，完整流中推理通过显式 GET。保留每正文/推理分片最多 4,999 UTF-16 单元及 30,000 JSON 字节的裁切和 scalar-safe offset 语义、内部完整消息分片最多 64 KiB、timeline 1 MiB/200 行上限。新增最多 4 KiB 元数据后若需要，调整分片预算以保持完整序列化响应的 64 KiB 上限。展开分片须能无损拼回全文，不要求每片末尾为 grapheme 边界，但不能拆 surrogate；grapheme 保证专用于短预览。

保留 8 预览/128 块/32,768 保存单元、SSE 512 KiB 连接预算、transient 丢弃阈值和持久追赶。不新增自动补读循环、无界展开、永久摘要记录或保留策略。/cotvisible 与展开/收起 UI 属于 #82；#80 只验证服务端请求/响应契约。

游标继续绑定 message ID、内容 revision、实例及准确 thinking/streaming 开关。切换开关从首片重读，旧作用域游标拒绝。流中增长或最终持久化后旧内容游标失效，客户端按稳定 ID 重新请求。SSE preview.id 仍为 call ID，公开消息 ID 仍为 message:call_id，source_event_id 保留日志身份。preview→durable 不改变顺序，不合并不同 retry attempt，不把 preview_status=saved 当持久成功。

测试重复/乱序观察、先持久后看到预览或相反、8 条上限淘汰后的 expired/ revision 更新、过期后迟到持久结果和 reopen。重启丢弃临时预览；持久消息 ID、outcome、短预览可重建；内容/timeline cursor 不是永久书签。GET/SSE 展开不产生 Store 记录、模型调用、输入/上下文身份修改、viewed/presented/read 命令或传输重试。
