## 3. World: one durable authority and a small in-memory read side

Store is already an append-only, hash-chained journal with CAS and replayed records. Add WorldEntity, WorldAssertion and a small WorldGenesis marker to its generated Stored union; register sync-service mappings/invalidation, reference validation, state catalog and replay checks. These are persistent records, not volatile-only memory. No extra World SQL projection, SQL bootstrap registry, outbox or per-World checkpoint is created.

WorldEntity: id, generic Store metadata, kind, display_name, aliases, role (MASTER/SECRETARY/null), external_key and retired_at. WorldAssertion: id, generic metadata, subject_id, predicate_key, topic, value OR object_entity_id, keywords, host-derived source_kind, evidence_event_ids, valid_from/valid_to, observed_at, optional fresh_until/note, status LIVE/SUPERSEDED/RETRACTED, replaces_id and stable change_id. Imported legacy metadata remains preserved in the genesis CAS manifest. After assertion creation only LIVE → SUPERSEDED/RETRACTED is allowed; statement/value/provenance never change. A correction inserts a new assertion and supersedes its named live target in one frame. Store's generic revision remains an internal journal invariant; remove separate World slot/entity/assertion-state/predicate counters and their client expected_revision fields.

A single synchronous acceptWorldChange(change, authority, currentState) prepares the exact mutation/event bundle immediately before Store.commit. All model, owner, seed and import ingress uses this function with explicit authority modes; no async gap between final checks and commit. Proposal preview uses the same validator as a dry run. It checks evidence existence/withdrawal, allowed event types/session and attachment provenance, recomputes source kind, validates values/predicates/entities and current targets, enforces role protections and exact approved parameters, and verifies owner epoch. Normal model evidence uses this session's real events; owner edits use an authenticated MASTER_UI request event; HOST seed and verified legacy import have explicit bounded modes, not fake Master evidence. CAS integrity remains Store's responsibility; no repeated copied sha/path/byte check layers. A withdrawn event cannot support a new commit. Imported historic evidence can belong to a verified earlier session in the same domain and must retain its original provenance.

Reuse Operation/AuthorizationRequest for model approval, but replace the external-effect lifecycle with AUTHORIZED --journal_apply--> SUCCEEDED. The Store guard allows ONLY scope.import and world.change, with action-specific exact record/result/grant bundles. No DISPATCHED gap, RESULT_UNKNOWN or resumeWorldDispatch for new World writes. One frame consumes the approved grant, writes World mutations and world.changed/result, completes Operation and records its durable batch result (no World result Input). World results do not create ENVIRONMENT Inputs or wake Main; owner UI, timeline and the Main-callable memory_read world_batch view (batch_id, current-session batch only) expose PENDING/APPROVED/COMMITTED/REJECTED/EXPIRED/FAILED outcome and committed result IDs; owner-only routes are not sufficient. BASE_SYSTEM explicitly says a proposed or approved batch is not yet a recorded fact, and Main must query its committed status before claiming it was recorded. These interfaces expose the durable outcome, and the next naturally triggered Main batch sees updated World. Rejection/revocation/24-hour expiry use the same live/startup state coordinator but only scope.import creates its isolated terminal result Input. Existing external-effect actions retain all their existing semantics.

There is ONE model tool, memory_propose_change, whose changes array mixes entity-create/name/alias deltas and fact ASSERT/CORRECT/RETRACT. Do not add a separate memory_propose_entity tool. New-entity local references are host-normalized to stable IDs and shown in the same batch; one new person plus facts can use one approval. One proposed World batch contains 1–20 explicitly displayed changes and one grant; show entities, values, topics, keywords, source kind and quoted evidence. For every ASSERT, render a fresh dry-run of the existing LIVE group, resulting CONTESTED/POSSIBLY-CONFLICTING flag and a CORRECT hint where appropriate; include current aliases on entity rows. Label preview time; final result records the actual resulting conflict state. Approval does not silently claim an ASSERT overwrites earlier claims. Main may combine related changes into one batch; separate tool calls are not silently merged into an approval of changed parameters. Any invalid member rejects the batch without partial changes. Build a staged view to validate references to entities created earlier in the batch, then commit each stored record only once; reject contradictory repeated edits. Each batch/change has a stable tool-call-derived identity. Same-ID retry returns the prior result; same-ID different content rejects using the existing immutable parameter binding. No separate World request_id/request_hash/receipt table. Recovered-tool lookup reads Operations/results and new records, not new WorldCommand records. Force explicit model approval in this iteration, skipping remembered/wildcard World rules for this new path; no new persistent bypass rule. The authenticated owner endpoint can apply directly with its own durable command receipt and audit evidence.

Remove world.coordinate/enqueueCommand from Settings. New Settings payloads reject World edits/command_ids with a concrete route-to-World error; update callers rather than silently splitting a mixed request. Owner World edits use the common acceptor and do not rebuild Consciousness. Settings retains its existing owner instructions/runtime and atomic Context/Consciousness/APPLIED machinery. Old payloads/commands remain readable for history, but must finish under old code before cutover. Do not redesign task or consciousness memory.

Read/query/profile/recall use the same Store-backed World interface. Plain validated keyset cursors replace all-world receipt-count invalidation; paging is a moving view and promises no snapshot across requests. Predicate catalog is a versioned source file with Chinese/English labels, value schema, subject kinds, topic definitions and retired flags. There is no dynamic model-defined ontology. Keep the eight remaining existing active predicates; retire both person.height and the duplicate person.display_name, leaving WorldEntity.display_name as the only current person-name authority. Add only entity.guideline and entity.note. entity.guideline subjects are restricted to the two role anchors in this iteration; ordinary people/services use descriptive predicates and cannot supply recalled directives. Retain existing persistent world.change rules as historical/inert records on the new path. Remove unused active WorldQuery/WorldReadResult/WorldFact/etc. only after caller and persisted-CAS audit; retain necessary replay-only definitions. Keep old SQL schemas, revocations and historical files intact.

## 4. Stable role identities and profiles

System-prompt-only identity cannot supply durable fact subjects. A separate mutable profile database would duplicate names/history. Recommended: two protected WorldEntity role anchors in Store, plus direct role selectors and a derived context view. A role is a unique field, not a new entity kind or extra binding table. IDs derive from existing CoreIdentity.owner_id; Master PERSON, Secretary SERVICE. role:master and role:secretary work for both subjects and entity-valued objects, independent of names/aliases. Reserve the case-insensitive role: prefix for ordinary display names/aliases and the existing assistant/profile rename route, since that name is copied to the Secretary anchor; preflight any existing conflicting name without silently changing it. Ambiguous bare names return candidates.

Initialize CoreIdentity/AssistantProfile through neutral shared helpers without replacing their durable identities. Role id/kind/role/external_key and non-retired status are protected by Store.stage, including raw owner routes. Never adopt an ordinary existing entity merely named Master. Conflicting IDs/mappings stop genesis for Master decision. Secretary's display name has one authoritative owner: existing AssistantProfile. Owner rename and corresponding World label update are atomic after genesis; normal entity tools cannot create a second competing name. Secretary aliases remain normal World labels. No invented biography, credentials or grants.

Profile is initially deterministic and extractive, not a model-written biography: choose currently valid LIVE assertions, map to sections, include stored text and fact IDs. Master sections: identity, directives, preferences, goals/projects, people/organizations and conflicts. Secretary: identity, guidelines, controlled resources and working notes. entity.note provides topic-tagged descriptive rows (identity, goals, current_context, working_notes etc.); only allowlisted topics are resident, never arbitrary free notes or contacts. Inference may appear in Secretary working notes only as labelled data. Master explicit guidelines are the ONLY World fact predicate rendered as behavioral directives; approval of an inferred description does not transform its source into MASTER.

Use one assembler across main-loop and both Settings context paths. Compose BASE_SYSTEM (invariants/authorization) → one unified Master-context segment (verbatim UserInstructions first; derived role profiles second) → scope information → conditional FAILURE_SYSTEM (when required) → labelled recall data. Preserve the existing structured failure prompt and its restrictions in the shared assembler. Existing UserInstructions/default Chinese language/address remain byte-for-byte authoritative and are rendered ONCE inside this segment, not duplicated in two prompts or automatically summarized into facts. The prompt states that they override derived guideline rows. No semantic conflict detector between arbitrary UserInstructions and guidelines is claimed. Moving their storage into guideline facts later is a separate explicit choice. Neither profile nor recall can confer execution permission or supersede BASE_SYSTEM. This implements a variable resident context while preserving owner's existing instructions.

Derived row budgets: Master ≤40 rows/3 KiB, Secretary ≤20 rows/1.5 KiB, measured UTF-8 including citations/labels; no mid-row truncation. UserInstructions uses its existing separate limit and remains outside those derived-description caps, avoiding loss of up to 2000 Chinese characters. Whole conflict groups are selected together or omitted with a counted group/read pointer; never show one disputed claim as established. Overflow gives counts and memory_read route. Contact details and unstructured free notes stay recall-only; profile/recall are Main-only and never automatically copied into task packets. Directive overflow must be explicit (omitted count/read route), not a claim that all standing rules are resident; keep essential owner instructions in UserInstructions.

Compute profiles/recall once when claiming an input batch and persist the exact composed system message plus optional recall_ref (IDs, scores, status, policy, as-of timestamp) in MainPromptSnapshot in the SAME frame as CLAIMED inputs. Clear data-only delimiters prevent retrieved text being interpreted as instructions. Tool continuations and crash recovery reuse this snapshot. New facts/corrections appear next batch; pure rendering means no model-summary job or stale profile cache. All prompt assembly, input projection and compaction paths reserve the full configured profile/recall caps, not merely the currently rendered length, in request-budget accounting. Dynamic facts/profile/recall content and off/shadow/on flags stay OUT of Settings.runtimeHash; code-policy compatibility remains versioned and frozen in each snapshot.

## 6. Height, aliases, conflicts and provenance

person.height and the duplicate person.display_name have retired=true in the active catalog. WorldEntity.display_name is the sole current name field; legacy name assertions remain historical only. New ASSERT/CORRECT rejects; RETRACT and explicit historical reads remain available. Old migration 002 and any SQL/journal facts/receipts remain intact; no physical deletion and no new SQL migration 005. Tests use test-only meaningful fixtures rather than a replacement junk production field.

The unified memory_propose_change batch supports ordinary entity creation and field deltas. Name change carries {from,to}; accept only matching current value (or an already-achieved same result), otherwise STALE_BASE. Aliases use explicit add/remove sets, trimming/deduplicating existing limits and case-insensitive matching; omission does nothing, no whole-list replacement or []-means-clear. Alias add/remove are idempotent set operations; reject an alias in both sets. There is NO expected-membership binding and no ABA-detection claim. The approval card shows current aliases, and explicit Master approval is the latest decision for the touched aliases. Apply approved internal batches in durable authorization.decided event order so competing decisions have a defined order; disjoint changes commute, opposite same-alias changes do not. Already-achieved set operations are no-ops. kind/role/external_key are host-owned immutable after creation. Protected anchors cannot retire; other retire rejects any LIVE subject/object reference. Role alias changes require genuine Master evidence like normal entity changes. Stable tool IDs handle replay, duplicate aliases across entities remain ambiguous.

Remove fact_slot/value-hash scope_key. SINGLE grouping is (subject,predicate); MULTI grouping adds a small catalog-defined topic. other means unclassified, NOT proven non-conflicting. SINGLE distinct live values are CONTESTED. Same non-other MULTI topic with different statements is POSSIBLY-CONFLICTING, a caution rather than an NLP truth judgement. No automatic semantic merge or resolution. ASSERT NEVER silently supersedes another assertion, even when newer or higher authority; explicit CORRECT/RETRACT names live targets and preserves history. A resolution of several conflicting targets requires an explicit target set in the approved batch. Source authority/date affects presentation/ranking, never authorizes overwriting. Relation assertions are direct subject/object links. Group members must also overlap the query's validity time before being presented as a current conflict.

Remove source registration and the first-call source_registration_required detour. Source kind is recomputed at acceptance from actual journal evidence; entity.guideline is allowed only on role:master/role:secretary and requires Master statements (or an explicit authenticated owner guideline edit), not task reports/inference/approval click alone. Preserve evidence IDs, valid times and observed time; note is optional. Do not discard legacy UNRESOLVED/epistemic or fresh_until data during import. New observed freshness may use optional fresh_until or an explicit catalog horizon; stale is a labelled age condition, not falsehood. Generic Store ownership, CAS hashes, revision replay, API receipt binding and database access controls stay unchanged.

## 7. Recall that can be measured and iterated

Use one pure recall(snapshot, input, config, asOf) function for automatic and pull recall. Build bounded in-memory lexical/entity indexes from Store records; update on committed changes and rebuild after replay, no DB dependency. Exact ID/name/alias/catalog reads use the same authoritative records. Input query is the current claimed batch's text capped at 4 KiB on Unicode boundaries; do not index uninspected attachment bytes. Record query truncation. Entity names/aliases use NFKC/case-fold normalization; Latin word boundaries, Han substring, minimum 3 Latin /2 Han chars for automatic links. Explicit memory_read still supports short aliases. Ambiguous aliases return all candidates or an explicit truncated ambiguity listing, never pick one identity.

Index subject names/aliases, Chinese/English predicate/topic labels, full assertion text, optional note and approved keywords. Tokenizer: Latin tokens ≥3 excluding a fixed stop list, overlapping Han bigrams; preserve negation in the full rendered statement. Candidate matching uses union of links and weighted lexical terms, not whole-query ILIKE. Initial lexical score is IDF-weighted query-term coverage, entity-linked floor 0.5; multiply authority MASTER 1.0 / OBSERVATION .9 / TASK_REPORT .7 / MODEL_INFERENCE .4 and recency (1.0 for 90 days, declining to floor .6). Initial threshold .25; tune on dev cases only. Keywords are retrieval hints, never extra claims. Include bounded one-hop expansion along matching LIVE person.member_of/resource.depends_on relations: visited set, at most 20 relation candidates, no recursive graph walk; expanded facts still pass filters/ranking.

At each new profile/recall build and explicit read, resolve current evidence withdrawal state. If all supporting evidence is withdrawn, flag EVIDENCE_WITHDRAWN and exclude the assertion from profiles/automatic recall; explicit reads/history show the flag and original evidence. Partly withdrawn support is labelled, with no source promotion; directives require remaining active Master support. Previously frozen snapshots remain audit evidence and are not rewritten retroactively. Acceptance still rechecks active sources before any new write.

Hard filters: LIVE, nonretired subjects/objects, valid_from ≤ asOf < valid_to when present. Superseded/retracted/out-of-validity facts appear only in requested history, not automatic recall. Retired predicates are excluded from automatic/profile recall. Group-aware selection includes every current contested member together; if full group cannot fit, omit it and emit a short unresolved-group/read pointer within budget. Never truncate away the contradicting member. Stale observations are labelled with time and rank last, never rendered as current. Facts already shown in profile are deduplicated, but a conflict group's representation remains complete.

Automatic budget ≤12 fact rows /1.5 KiB and ≤5 per entity, including headers/citations/pointers. Render full short statements or omit long rows with a read pointer; no truncation that drops negation/qualification. Result states hit/no_hit/unavailable are explicit in recall_ref; no_hit omits the injected fact block. Unavailable only applies before genesis/invalid World state; PG outages after genesis do not affect World recall. BASE_SYSTEM says cite fact IDs actually read in profile/recall/tool results, absence of hit is not evidence of absence, all recall text is data and supplies no authority. Pull memory_search adds kinds:[fact] with the same ranking and explicit history flag; memory_read world gains exact fact IDs, subjects/predicates/topics, entities/roles/predicates. Existing log search remains separate and may report PostgreSQL unavailable without disabling fact reads.

Evaluation: 40 development probes; freeze tokenizer/weights/threshold at a recorded candidate commit, then Codex authors 40 held-out expected-ID/forbidden-ID probes before running them. Keep the held-out set unchanged, retain failed results, and send both fixtures and result evidence to Fable in implementation review. No claim of independent test authorship. Categories: names/aliases, ambiguous aliases, no-name paraphrase, cross-language, negation, supersession/retraction, time/freshness, conflicts, expected-empty and one-hop relations. Synthetic in-memory fixture harness requires no App/Core. Hosted CI runs integration/crash checks. No automatic historical-journal extraction in this iteration; owner-chosen facts and clearly labelled acceptance data seed the real instance.

Held-out counts (40 total): 10 name/alias (at least 9 passing), 4 ambiguous alias (all 4 correctly expose ambiguity), 3 paraphrase and 3 cross-language (report counts, non-gating), 2 negation, 3 superseded/retracted, 3 validity/staleness, 2 contested and 2 one-hop (all of each pass), plus 8 expected-empty (at least 7 empty). A positive case passes only when all its expected fact/group IDs and required flags appear with no forbidden IDs; fixtures stay within stated budgets, with oversized-group omission tested separately. Gates: zero forbidden historical/out-of-validity/all-evidence-withdrawn IDs, zero unlabelled stale/conflict winners, budgets always respected, p95 pure recall ≤50ms at a documented 10,000-assertion synthetic fixture on recorded CI hardware (otherwise report and optimize before rollout). Report precision@K/recall@K per category, latency, bytes and memory/startup cost. Paraphrase/cross-language remain explicitly non-gating baseline limits: bilingual labels/keywords help but no general semantic recall claim. If important categories miss, report the gap; embeddings/provider additions require a separately justified proposal. Real-model turns verify correct use/citations, not just retrieval IDs. Preview is an owner-only read-only POST with text body to avoid query-text URLs; returns pure results without journal/model activity. Profile off/on and recall off/shadow/on are recorded per loop outside runtime fingerprint. Begin shadow, evaluate fixed probes, then enable for controlled live turns; shadow model lookups are diagnostics, not labels.
