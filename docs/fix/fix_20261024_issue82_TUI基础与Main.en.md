## 3. Deterministic input and command grammar

One declarative registry provides exact case-sensitive name, aliases, scopes, typed arguments, completion, help and handler. Global: `/M`, `/T`, `/help [command]`, `/send [literal text]`, `/quit`; Main: `/cotvisible [message_id] [on|off]` (`/cotv`), `/more <message_id>`, `/latest`, `/history [before|after]`; local-draft/outbox actions in both views: `/pasteblock <id> <expand|collapse|edit|remove|copy>`, `/outbox [request_id]`, `/retry <request_id>`, `/discard <request_id>` (only safely rejected/never-submitted records; unknown is refused). Actual command names may be refined without changing semantics, and must be documented before implementation review. Task `/cancel` and #83 `/attach`, `/paste`, `/open` are reserved with explicit NOT_IMPLEMENTED help/errors, never fake successes.

Only a whole submission starting with a typed slash outside pasted nodes and outside literal mode is parsed as a command. A paste is data and never invokes handlers. Slash-looking text inside a pasted block, /send remainder or model/tool output is never reparsed. Unknown slash input is an error and remains editable; no automatic message fallback. Token grammar for commands other than /send: ASCII whitespace separator, single/double quotes, backslash escaping quote/backslash; reject unmatched quotes, extra/missing/duplicate arguments, control characters, newline command chains and shell operators. No eval, subprocess shell, interpolation, pipes, command chaining or fuzzy routing. /send takes the remaining text literally (including semicolons, quotes, slashes and newlines), so these cannot become commands.

Main normal-text submit freezes and sends the current Main draft. Functional-view normal-text or literal-mode submit saves the local draft and explains /send; never routes to Main implicitly. `/send` from the command bar with no inline text submits exactly the current view's draft. With inline text it creates an explicit draft replacement candidate and shows its payload; it must not silently combine it with a hidden earlier draft. Use a second explicit submit to confirm replacement if a nonempty draft would be overwritten; cancel preserves that draft. In ordinary editor command mode, `/send <literal payload>` strips only the command prefix and submits that explicit payload plus explicitly attached IDs. Empty text with no attachments is rejected. Switching views, selection, expanding, pasting and completion never submit. Sending freezes a revision; typing during network I/O creates a subsequent revision and late responses cannot clear newer edits.

Aliases are fixed name-to-command mappings in local configuration, with no embedded arguments or script, no collisions and no broadened scope. Completion covers applicable commands, enums, visible stable message/paste/outbox IDs; cap 20 candidates with identity context. Short IDs must be unique before submission and are expanded/frozen visibly. There is no applicable file-path argument in C1; path completion joins the same registry in #83. Tab only edits or cycles candidates; even completion to /quit requires an explicit submit.

## 4. Durable state, frozen outbox and safe cleanup

New client state under a dedicated `tui-v1/` child of the selected Core data/profile directory, outside Core's Store structures. Validate directory ownership, no symlink traversal, mode 0700, files 0600. No token persisted into drafts/logs. One writable TUI per state root using an exclusive lock; stale/ambiguous lock fails visibly, never automatically steals another writer. Keep each domain separate: binding includes `data_domain_id`, API version and `mode`; store `instance_id` as connection generation, not replay authority. Reattach/revalidate on endpoint replacement, reconnect, before reconciliation and send. Foreign domain/API/mode data is quarantined/readable but cannot be sent or cleaned using the new endpoint; no implicit migration. Ordinary same-domain Core restart may change instance/token and is supported after reattach.

Use a small fs-backed atomic manifest plus immutable body/paste blobs, rather than modifying Core or adding a database server. Persist blobs (exclusive create, fsync) first; then persist a complete versioned manifest via temp file, fsync, atomic rename and directory fsync. A serialized writer commits draft references, outbox entry and removal of that exact draft revision together. Only durable manifest completion authorizes a POST. Write errors leave the old committed draft/outbox intact, show saving/error state, and disable send until resolved. Render current typing immediately but distinguish unsaved from saved; no claim that unflushed keystrokes survive abrupt power loss. Normal quit waits for pending durable saves. Corrupt/incomplete files are preserved and reported; no automatic reset. Startup validates schema/hash/size, references and ownership. Fault injection at each blob/manifest/rename/cleanup boundary must recover either the old or new committed state without losing the sole payload.

Freeze method, route, complete JSON body including request_id, exact text and ordered attachment_ids, serialized bytes/hash, binding and originating view/revision. Current HTTP body ceiling is **1,048,576 UTF-8 bytes for the whole JSON**, not just text. Validate schema/text limits and serialized bytes before accepting into outbox; preserve all original content on rejection. Empty/whitespace with no valid attachments refuses. Text-only is C1's product path; retain ordered attachment ID slots and input/withdrawal metadata for #83 without implementing image UI or silently dropping a future nonempty attachment list.

State model: saved draft → durable PREPARED → SENT/UNKNOWN → RECEIVED (with authoritative receipt) → minimal handed-off record. HTTP timeout/disconnect or crash never implies rejection. On restart/in-flight ambiguity first GET `/requests/{id}` on the original verified binding. Matching receipt confirms original acceptance regardless of later business state; durably save receipt/handoff before freeing payload. Genuine NOT_FOUND on that binding permits the same frozen request/ID retry; auth/network/version/domain errors do not. Never generate a new ID automatically. Deterministic pre-admission rejection retains original editable body; editing and explicitly resubmitting creates a new intent only after the old rejection is known. Conflict is a visible preserved error, not success. Retry scheduling is serialized with bounded backoff (1–30 seconds); one in-flight submission per entry, bounded concurrency 1. On startup unresolved entries reconcile automatically, but failed entries require explicit retry/edit.

Receipt acceptance is distinct from model/input/task outcome. A received request is labeled received, then render authoritative Input/message/session states (queued/running/completed/failed/unknown as applicable). Do not label a POST or animation as business completion. Receipt.state FAILED with acceptance ACCEPTED is still reliable receipt; keep minimum audit/status and Core history access while freeing duplicate text after durable handoff. Unknown handoff bodies stay reachable through paginated `/outbox`, not only the most recent 50 rows.

Cleanup can unlink only verified TUI-created blobs within the owned root, never source files. Preserve references across all drafts/outbox/domains. Idempotent acceptance cleanup occurs after the manifest records the validated receipt; crash after receipt but before unlink simply retries cleanup. Explicit discard of an unreferenced draft block can remove its own copy; unknown/in-flight outbox is not discardable. Other orphan/staging records default to **three calendar years from persisted created_at** in a recorded timezone (default Asia/Hong_Kong), Feb 29 anniversary clamped to Feb 28; do not implement 1095-day arithmetic. Active references and unknown handoffs override expiry. An interrupted blob creation has its own created_at envelope; missing/corrupt provenance is preserved for explicit inspection. No Core-history GC.

Capacity defaults: 256 MiB total managed staging including protected/orphan content, 1,000 outbox entries, 2 MiB manifest ceiling and 4 MiB per editable draft; settings validated with finite positive bounds. These allow substantial text-only work without unbounded staging. Reserve capacity for an atomic manifest replacement and handoff metadata; account physical old/new blobs and crash leftovers before admitting a new edit/paste/outbox. Never evict protected or unexpired orphan data to make room. Refuse the new operation, retain the last saved draft and display actionable quota usage. Removable read caches are separate, bounded to 8 MiB, and cannot hold the sole draft/outbox body. Quota and disk-full behavior are tested, including new typing/paste rejected without replacing prior saved content.

## 5. Paste structure and rendering safety

Ordered draft nodes preserve exactly the text received from the terminal (including tab and newline sequences); no hidden normalization before request freeze. Multiline paste collapses to a UI node such as `[pasted 20 lines]` with opaque UUID, byte length and line count. The label is not serialized into content and typing that label creates only ordinary text. Multiple pastes, text insertions, undo and block editing/removal preserve original ordering. Expanded block editing uses its actual text and creates a new durable revision; removal/copy must address the stable node ID. Copy is an explicit action using a fixed macOS executable with separate stdin/args if necessary, never shell interpolation; no automatic clipboard read or image clipboard support. If native copy alone suffices at G0, avoid an extra helper. Flatten nodes once into canonical payload text; don't reread a mutable external source during retry.

Separate stored/request text from safe display. Strip/neutralize C0/C1/ESC/CSI/OSC and bidirectional display controls from untrusted rendered strings, preserving ordinary newlines/tab layout through controlled rendering. Do not execute terminal links, title changes, clipboard sequences, color or cursor movement embedded in Core text/paste. Rendering sanitation must not mutate frozen message bodies or run command parsers. Test malicious escape fragments, emoji ZWJ, CJK and marker spoofing.

## 6. Sync, reading position and CoT

Implement a streaming UTF-8 SSE framer with split codepoints/lines, LF/CRLF, multiline data, comments, event/id fields and blank-event dispatch. Bound raw undecoded/frame input to 512 KiB; malformed/oversize frames cause reconnect and durable catchup, not cursor advancement or guessed skipping. Validate known DTO shapes and event identities. `change` is durable; `transient`/heartbeat never advances durable cursor. Disconnect/backpressure uses one reconnect loop with bounded exponential backoff and cancellation on quit.

Bootstrap/rebuild sequence: verify binding → GET sync/cursor C0 → fetch bounded Main snapshot and session → consume sync/changes from C0 (100 tx/page) → apply invalidations/refetch affected bounded window until caught up → commit coherent view state/watermark → open stream from committed cursor. Fetches are generation-tagged; stale responses after view/binding/instance changes are discarded. Changes that overlap the snapshot trigger authoritative refresh or stable revision-aware merge, never regress a newer snapshot. Transactions are applied as units; watermark is persisted only with corresponding snapshot state or durable invalidation/rebuild markers. In-memory or evicted windows always rebuild at cold start; persisted cursor alone never implies their state exists. RESYNC_REQUIRED discards only derived view caches and starts the C0 protocol, protecting drafts/outbox. If invalidation refresh fails, do not advance past an unrepresented state without a durable pending invalidation marker. Document and test the chosen marker/snapshot scheme.

SSE transient preview replaces by stable message_id/call_id; durable timeline rows supersede previews, preserving message/event identity and anchors. A missing/expired transient is not proof that no durable event exists: redacted empty stop/tool-only messages can intentionally be omitted. Show unavailable/expired preview truthfully, reconcile bounded timeline, and do not synthesize failures or alter Core recovery policy. Terminal outcomes, partial/truncated replies and empty failure placeholders follow #80's source identities; never attach an empty failed turn to the preceding answer.

Default timeline and content reads use thinking=false. Display the server's 20-grapheme thinking_preview safely; server already adds U+2026, including valid newline-plus-ellipsis endings, so never append a second ellipsis or recompute it by code units. `/cotvisible [message_id] [on|off]` affects the explicit/selected stable message and locally shows its target; no selection yields a clear error. On explicit expansion fetch thinking=true with streaming=true only for a current transient; at most 4 fragments or 128 KiB per action, with a visible “more” boundary. `/more <id>` continues a bounded batch and yields to input; collapse cancels pending loads and hides full thinking. Empty/redacted content remains empty. No background full-CoT prefetch or model parameter change.

Keep at most 200 timeline rows / 2 MiB visible body data and 8 MiB LRU fragment cache; budget by bytes as well as item count. Initial page 30, historical page 50, one content loader, no automatic unbounded page chain. Cache key includes binding, instance, message ID, revision, thinking/streaming options and fragment cursor. On CURSOR_EXPIRED or instance change discard instance-bound cursors, relocate by stable message_id/event_id via `/timeline/around`, and re-read a bounded prefix. Saved reading anchor = view + stable message/event ID + grapheme offset/row offset, never pagination cursor. Stream updates leave the reader anchored; show new-item count and `/latest` to explicitly follow the end. Resize recomputes cell positions from the same anchor. Missing anchor produces an explicit fallback notice, not a false restored-position claim.

Known #80 recovery limits remain separate: isolated graceful-stop reopen RECOVERY_BLOCKED is recorded evidence; length persisted before finish causing replay Agent.continue failure is source inference, unverified. #84 evaluates both. If either blocks #82's concrete mandatory gate, preserve failure and ask coordinator for a narrow scope decision; do not waive the gate or silently modify Core recovery policy.
