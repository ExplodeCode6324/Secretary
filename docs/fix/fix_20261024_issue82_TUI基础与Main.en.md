## 3. Deterministic input and command grammar

One declarative registry provides exact case-sensitive name, aliases, scopes, typed arguments, completion, help and handler. Global: `/M`, `/T`, `/help [command]`, `/send [literal text]`, `/quit`; Main: `/cotvisible [message_id] [on|off]` (`/cotv`), `/more <message_id>`, `/latest`, `/history [before|after]`, `/select <message_id>`, `/copy <message_id> [loaded]`; local-draft/outbox actions in both views: `/pasteblock <id> <expand|collapse|edit|remove|copy>`, `/outbox [request_id]`, `/retry <request_id>`, `/discard <request_id>` (only safely rejected/never-submitted records; unknown is refused). Actual command names may be refined without changing semantics, and must be documented before implementation review. Task `/cancel` and #83 `/attach`, `/paste`, `/open` are reserved with explicit NOT_IMPLEMENTED help/errors, never fake successes.

Only a whole submission starting with a typed slash outside pasted nodes and outside literal mode is parsed as a command. A paste is data and never invokes handlers. Slash-looking text inside a pasted block, /send remainder or model/tool output is never reparsed. Unknown slash input is an error and remains editable; no automatic message fallback. Exact `/send` prefix: match case-sensitive `/send` followed by end-of-input or one ASCII space; consume exactly that one separator, preserving all subsequent payload whitespace/newlines. `/sendx` is unknown, `/send\n...` is rejected as an invalid command prefix. `/cotvisible on|off` uses the selected message; an argument other than on/off must be an exact/uniquely resolved message ID, optionally followed by on/off. Token grammar for commands other than /send: ASCII whitespace separator, single/double quotes, backslash escaping quote/backslash; reject unmatched quotes, extra/missing/duplicate arguments, control characters, newline command chains and shell operators. No eval, subprocess shell, interpolation, pipes, command chaining or fuzzy routing. /send takes the remaining text literally (including semicolons, quotes, slashes and newlines), so these cannot become commands.

Main normal-text submit freezes and sends the current Main draft. Functional-view normal-text or literal-mode submit saves the local draft and explains /send; never routes to Main implicitly. `/send` from the command bar with no inline text submits exactly the current view's draft. In ordinary editor command mode, `/send <literal payload>` strips only the command prefix and submits that explicit payload plus explicitly attached IDs. Empty text with no attachments is rejected. Switching views, selection, expanding, pasting and completion never submit. Sending freezes a revision; typing during network I/O creates a subsequent revision and late responses cannot clear newer edits.

Aliases are fixed name-to-command mappings in local configuration, with no embedded arguments or script, no collisions and no broadened scope. Completion covers applicable commands, enums, visible stable message/paste/outbox IDs; cap 20 candidates with identity context. ## 4. Durable state, frozen outbox and safe cleanup

The helper alone holds the TUI lock and performs all blob/manifest/cleanup writes through a bounded request/ACK pipe; parent Node never writes state behind it. Before reporting READY or acquiring the lock, the helper installs SIGHUP/SIGINT/SIGTERM/SIGTSTP ignore handlers, so foreground terminal hangup/interrupt cannot kill the writer during the parent’s bounded flush. Its ordinary lifetime ends on stdin EOF or explicit close; SIGKILL still releases the kernel lock. Parent death closes stdin; helper finishes or fails the current atomic operation, exits and releases flock. Helper death means no further writes or POSTs until reopen/recovery; a competing TUI can only acquire after the old writer stops. Test concurrent launches, parent SIGKILL, helper kill, and restart. An existing lock filename/PID alone never blocks recovery. “Ambiguous” means unsafe filesystem/ownership or an unresponsive live lock holder; fail visibly without killing it. Use a small fs-backed atomic manifest plus immutable body/paste blobs, rather than modifying Core or adding a database server. Persist blobs (exclusive create, fsync) first; then persist a complete versioned manifest via temp file, fsync, atomic rename and directory fsync. A serialized helper commits draft references, outbox entry and removal of that exact draft revision together. Typed bodies live in blobs, not the 2 MiB metadata manifest. State model: saved draft → durable PREPARED (`attempted:false`) → durable ATTEMPTED/UNKNOWN (`attempted:true`, written and fsynced **before every POST**) → RECEIVED → minimal handed-off record. A PREPARED entry may be discarded only while attempted=false; the single dispatcher and state helper serialize discard against setting the attempt marker. Any still-UNKNOWN attempted entry, even after a genuine NOT_FOUND, cannot be casually discarded while an old request could still be in flight: reconcile/retry the original ID. Per-binding FIFO uses a durable monotonic enqueue sequence; the UNKNOWN/attempted head blocks later sends. A confirmed pre-admission rejection becomes NEEDS_EDIT and leaves the runnable queue while retaining its body, so later entries may proceed with an explicit visible notice. That confirmed pre-admission-rejected entry may be explicitly discarded; restore/edit becomes a new tail intent only on an explicit submit. Bound concurrency to one dispatcher for this selected binding. HTTP timeout/disconnect or crash never implies rejection. On restart/in-flight ambiguity first GET `/requests/{id}` on the original verified binding. GET returns a RequestStatus with nested `receipt`, `result`, `resources`, not a bare Receipt. Validate receipt.request_id and command === "messages". REQUEST_CONFLICT preserves the body and quarantines the entry; never clear it based on GET alone. Once an exact-byte POST returns the validated matching receipt, acceptance is confirmed regardless of later business state; durably save receipt/handoff before freeing payload. This replay is an idempotency check, after reconciliation, not a new intent or blind new-ID retry. Lost conflict-response + existing same-ID/different-body is a required negative test. Genuine NOT_FOUND on that binding permits the same frozen request/ID retry; auth/network/version/domain errors do not. Never generate a new ID automatically. Deterministic pre-admission rejection retains original editable body; editing and explicitly resubmitting creates a new intent only after the old rejection is known. Conflict is a visible preserved error, not success. Retry scheduling is serialized with bounded backoff (1–30 seconds); one in-flight submission per entry, bounded concurrency 1. On startup unresolved entries reconcile automatically, but failed entries require explicit retry/edit.

Idempotent acceptance cleanup occurs after the manifest records the validated receipt; crash after receipt but before unlink simply retries cleanup. Explicit discard of an unreferenced draft block can remove its own copy; unknown/in-flight outbox is not discardable. Active references and unknown handoffs override expiry. An interrupted blob creation has its own created_at envelope; missing/corrupt provenance is preserved for explicit inspection. After successful handoff, compact metadata goes to a paged receipt archive outside the active manifest; keep only a bounded recent index there. Minimal receipt records expire three calendar years after created_at only when cleanup is durably complete and no live reference requires them; a pending cleanup ticket is protected. Archive bytes remain in the 256 MiB budget, so capacity exhaustion still refuses admission, but completing 1,000 messages is not a permanent entry-count dead end. ## 5. Paste structure and rendering safety

Document one canonicalization before staging: terminal-delivered CRLF and lone CR become LF; tabs, other Unicode and all remaining received content retain exact order, with no trimming/tab expansion/path-space insertion. Display line counts and freeze the canonical LF form; the UI/help states this rule. Original clipboard bytes that Terminal itself filters cannot be recovered or claimed preserved. Multiline paste collapses to a UI node such as `[pasted 20 lines]` with opaque UUID, byte length and line count. The label is not serialized into content and typing that label creates only ordinary text. Multiple pastes, text insertions, undo and block editing/removal preserve original ordering. Expanded block editing uses its actual text and creates a new durable revision; removal/copy must address the stable node ID. The pinned explicit-copy policy in section 2 applies; native copy can remain a tested convenience, not a hidden fallback. Separate stored/request text from safe display. Strip/neutralize C0/C1/ESC/CSI/OSC and bidirectional display controls from untrusted rendered strings, preserving ordinary newlines/tab layout through controlled rendering. Do not execute terminal links, title changes, clipboard sequences, color or cursor movement embedded in Core text/paste.
