# 持续运行与无实例请求预算

2026-11-09，Master 授权敏捷实例持续启动，不设请求预算，仅敏捷变更时短暂停机。

检查发现实例处于 STOPPED；使用原数据域启动后恢复原会话。现用启动路径没有旧验收 launcher 的总模型请求/工具计数、限时台账或 EXHAUSTED 停机机制。单请求上下文容量、输出大小及单轮故障保护属于运行合同，本次不改变 Core 逻辑。

新增用户级 launchd 服务 com.secretary.agile：登录自启，KeepAlive 保持守护运行；守护串行每 30 秒检查同一 Core 与 PostgreSQL，在退出后调用现有启动路径恢复，无总调用额度、无截止时间。caffeinate -is 阻止空闲睡眠（-s 在交流供电下生效），不承诺关机、强制睡眠或未登录期间服务可用。

维护停机先写 .local/maintenance.json，再请求 Core 正常停止；守护看到标记即跳过。显式启动清除标记；自动启动后再次核对标记，避免与维护请求竞态而重新开机。数据库、Core、TUI 和配置全部使用原目录，不清库、不复制成新运行实例。凭据不写入 LaunchAgent。

验证范围：脚本/配置语法、现有类型和文档检查；同一实例维护停机跨越守护周期、恢复运行、数据域和历史连续性，以及守护自动恢复。验证结果保存在 .local/continuous-service-verification.json。不会为验证另建数据域或调用付费模型。

本变更只在 agile 分支；合入 main 仍需 Master 许可。

实施验证已通过：维护停机持续 35 秒，跨越一次守护周期仍保持停止；显式启动恢复。随后通过正常退出模拟服务消失，守护自动拉起原数据域，session 不变，原 6 条时间线记录全部存在，历史检索 ready。未执行 SIGKILL/断电测试，也未停掉数据库模拟故障。launchd 配置检查、脚本语法、TypeScript、669 份 Markdown 的链接与国际化检查均通过。
