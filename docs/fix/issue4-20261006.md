# Issue 4：失败记忆提取的显式单次恢复与结果对账

状态：按 Master 已批准的 Issue 4 范围实施，尚未验收。独立本地分支 `feature/issue4-explicit-memory-recovery`，继承完整已审查基线 `0092867b6e1b9d07e65090f0d3814d402ac75caf`。不得推送、合并、部署或关闭 Issue。

## 接口与状态契约

TUI/Web 共用 Host 的只读失败分组预检及显式恢复服务；主模型没有解除保护工具。预检区分 `BLOCKED`（证据不足或旧执行未知）、`READY`（可消费一次明确授权）、`RECONCILE`（已有完整响应，可确定性复用）、`SUCCEEDED`（已有提取成功）。展示结果不能隐式授权。

用户请求携带 request_id，精确绑定旧 attempt、session、服务端重建的来源身份/证据/边界、policy、实现版本、运行配置 hash 和预期工作记忆 revision。同 request_id 同 payload 返回持久结果，同 ID 改参拒绝。授权消费先落盘，再精确绑定 ModelCall，最后才能发送。使用来源锁、领取代次与 Store revision CAS 防双重拥有者和迟到提交。

旧 attempt 及原始日志不可变；恢复新增 parent_attempt/recovery_request 关联。先核查已提交回执、已保存完整响应与已成功分段，复用确定性解析、校验和提交。失败不等于未发送；超时、无终态 started、无法精确关联的 legacy、无法证明旧执行静止或隔离的情况保持 BLOCKED。重启只对账，不自动重发。一次授权至多一次新调用，再失败继续停发；不承诺网络 exactly-once，UI 明示可能重复计费边界。

恢复仅限所选失败来源分组，不能触发未授权段、重复 summary 模型调用或重复 World 提交。沿用来源身份、legacy alias、source_batch、事件 owner/时间/通知及事务校验；settings.retry、compact、新消息、重启不构成授权。确定性提交如果因其他来源或运行版本变化无法完成，应明确保留阻塞状态。
