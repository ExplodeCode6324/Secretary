# Issue #10 PR2b：聊天与导航

状态：PR #42 审查修订与本机验收完成，初版证据缺口已更正，当前结果见末节；三项 CI 以修订后的 PR 精确 head 为准。Master 已批准合并 PR #41 并继续下一阶段，基线为 main `aca83234f47259c31154d546918afc7462918040`，使用原 Core 工作区分支 `codex/issue10-native-chat`。本阶段仅关联 #10，不关闭 Issue，不删除旧入口。

## 范围与实现决定

- 保持简单原生文字、按钮与分区；字号和布局遵循总计划，后续再做美学设计。名称返回对话；任务、记忆、设备、产物及业务设置尚未实现的入口禁用并说明。连接配置与本地显示偏好可用。
- 聊天使用 Core timeline / around / message content 合同；历史分页、直接定位和长文本续读使用 opaque cursor，禁止自行计算 UTF-16 偏移。只缓存有限页面与正文；明确加载更多，不自动读完整历史。
- 输入为原生文本编辑器，Return 换行，Command-Return 发送，组合输入时不发送。草稿按目标 Identity 保存；先 outbox 事务落盘才清空输入，失败保留文字。回执显示受理、拒绝或未确认，不能把受理当成模型完成。
- 阅读位置按消息 ID 与局部位置保存；最新模式的后台刷新保持贴底；历史阅读、选中或展开时保留视口，回到最新由用户明确操作。偏好变更使旧请求失效并清除隐藏的思考/预览；预览以 call_id 对齐最终记录，不推进同步 cursor。
- swift-markdown 0.6.0 解析 GFM；原生呈现正文、列表、引用、代码与表格，代码/宽表局部横向滚动，可复制，不执行 HTML 或远端脚本。
- 关联旁栏只显示服务端明确关联，每类最多五项，不按正文猜测关联；后台刷新不构成 viewed。审批/决定保留跨页计数和未实现说明，实际处理留 PR2c。

## 无窗口恢复（Master 补充）

PR2a 的普通关窗重开已验证，但未覆盖异常保存状态。PR2b 增加常驻“打开主窗口”菜单和 Dock 点击 reopen 兜底；已有主窗口则激活，不创建重复连接模型。即使窗口视图尚未建立，恢复入口也必须存在，不能把恢复监听只挂在窗口内部。

测试分开记录：隔离恢复状态的冷启动回归；不忽略恢复状态的菜单恢复；Dock 恢复；恢复后唯一窗口及原有控件。保留首次失败，不删除系统保存状态，不修改系统权限，不将单纯 app.activate 当成创建窗口。

## 方案调整与暂不实施项

- 使用系统 Dock 点击 reopen 与 Window 菜单/⌘0，共用单一 SwiftUI Window；不增加自定义 Dock 菜单。前者已直接覆盖 Master 的恢复诉求，避免重复入口和第二套窗口状态。
- 关联仅开放 session/message。活动投影没有可直接作为 event locator 的来源 ID，不用 activity ID 冒充 event ID；后续明确合同后再增加活动来源导航。
- 历史分页替换有限页面，提供前后翻页和 ID 定位；不做无限累积列表。单条超过 256 KiB 按纯文本呈现，续读上限 4 MiB，超限说明而不继续占用无界内存。
- 审批、决定、任务/产物详情、记忆等日常管理仍按既定 PR2c 交付；旧入口不删除，Issue #10 保持开放。当前跨页只显示待处理计数和阶段说明，不能宣称已可处理。

## 验证中发现并保留的首次失败

- UI fixture 启动脚本最初误用数据目录变量，启动了默认演示目录中的 fixture Core。核对本次实例后仅停止该实例，保留现场，未向该实例输入测试消息。脚本改用正确的 `SECRETARY_DATA`，并在启动测试前断言 endpoint 必须位于独立临时目录；客户端 Debug 数据库隔离的初版声明有误，见末节更正。
- 路径文本框处于输入法编辑态时，AX 显示完整文字但绑定值尚未提交，附着得到 ENOENT。连接动作现在先提交当前编辑；退出也结束编辑。未放松 endpoint 权限/身份校验。
- 中文输入法会转换 XCUITest 的英文模拟按键；确定性合成文本改用粘贴，仍实际验证 Return 换行、重启恢复、⌘Return 发送。另对原生 NSTextView 的 marked text 测试禁止发送。
- macOS SwiftUI 文本使用 AX value，而非 label；发送后内容实际存在，测试改为断言 value。原有失败日志和 xcresult 留在本机忽略目录，未删除或改写。
