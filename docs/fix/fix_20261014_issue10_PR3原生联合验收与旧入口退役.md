## 3. PR2c 四条建议的处置

| 建议 | PR3 方案 | 验收 |
| --- | --- | --- |
| N1 下载超时 | 下载使用独立 URLSession，普通 JSON/SSE 配置保持各自用途。初始下载资源总时限 30 分钟、无数据等待 30 秒；参数集中并可在测试中缩短。保留认证、禁止重定向、取消和 1 GiB 上限。此为有界策略，不保证任意慢连接都能完成 | 本机受控限速下载持续超过原 60 秒仍成功；持续停顿、总时限到期、用户取消、切域/版本变化均停止且不能打开半文件。做一次接近 1 GiB 的隔离下载，记录时长、内存与临时磁盘占用；小文件/缩短时限测试不能冒充大文件通过 |
| N2 重复哈希 | 优先在缓存最终接纳边界保留一次完整内容校验，缓存命中校验保留。先核对所有 download 调用者及 mock 契约；只有单一校验责任明确、没有未校验打开路径时才去重，否则本 PR 保留重复校验并记录原因 | 错误 hash/长度/ETag、篡改缓存、链接替换、下载中断都不能成为可打开文件；记录新下载整文件读取次数，不为了性能降低完整性检查 |
| N3 并发提示 | 保持单下载，不增加队列。区分“已有下载进行中”和服务不可用，相关按钮/提示反映真实状态 | 第二次请求不覆盖首个进度/结果；完成、失败或取消后可重新下载 |
| N4 拒绝合同 | 在 API v1 手册说明命令 POST 受理前拒绝、持久受理后的失败回执，以及 GET 查询错误的区别。REQUEST_CONFLICT 表示本次参数未被接受，不能推导同 ID 从未存在。对照实际 admission 边界补 Core 与 Swift 合同测试；若边界不符则先修复并复核，不仅补注释 | 覆盖未受理的错误、已受理后领域失败、响应丢失后重查、同 ID 同参重投及改参冲突；已受理命令不得降为未受理或换 ID 重做，坏命令不阻塞独立后续命令 |

N1、N3、N4 纳入本轮实施；N2 按上述条件处理。所有下载实验均使用本机受控服务，不开放远程 Core，不开展 #13 网络接入。
