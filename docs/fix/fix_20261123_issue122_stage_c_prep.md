## 2. C06 · 普通维护之后如何使用纠正

绑定正常输入 A、更正 B、两者的已处理事件 ID 及更正后首个有资格的请求。用普通无关轮次推动正常 WORKING_MEMORY 提交，确认其覆盖 B。B 处理后起算真实十分钟，计划只发一次自然探针，须满足下文前提。记录修订、来源覆盖，分别识别仍作为当前结论的 A 和合法历史 A。到限细分 NOT_TRIGGERED、RUNNING_AT_CAP、FAILED_RETRY_PENDING、FAILED_TERMINAL。缺少合格维护边界时，维护的语义判决未决；后续用对 B 仍保留此前维护失败。

自然使用取首个合格探针实际发送的物理请求；分开记录重试和工具续轮。绑定序列化正文哈希、角色和调用，检查当前 Context、常驻画像、Consciousness、自动召回四个来源。检查 **B** 及其改写、助手或工具回声、仍有效的限制，另记 A 是否可见。B 已常驻时按正常使用判定。四源均证明 B 缺席时，要求找回原引用、同一调用链实际收到匹配的工具结果，且最终回答有据可依。存在不透明状态或抓取不全则 UNRESOLVED。单列“旧 A 仍常驻且 B 已冷”是否达到。健康的当前状态可以通过维护项，冷状态未达到时仍标未触发；需检索却无证据猜中计失败。常驻 B、不存在的事件、无关提及采用独立对照。合成的旧状态只用于验证判定程序，隐藏答案与 SUT 隔离。

维护样本按 journal 顺序选**首个**覆盖已处理 B 的普通维护提交，即使此时无关活动尚未结束。连续保留该提交后首个能看到它的 Main 快照作为生效见证，包括先出现的无关请求。使用项只冻结一个自然探针输入，第二个观测输入为零。固定无关前缀已处理且已有覆盖提交时，在十分钟上限前发一次；只取与该探针输入和 loop 绑定、冻结快照包含覆盖修订的首个 Main 物理发送。首发快照过旧或缺捕获则未决。重试和工具续轮属同一轨迹，可用于交付/读取/使用证据，不能替换首发的缺席判据。宿主被动轮询不占输入。到限任一前提不满足则不补发，使用标 NOT_TESTED，维护按实测判；前提满足却缺合格发送则使用 UNRESOLVED。维护和探针修订分别保留，旧 A 与冷 B 的组合按探针实际可见性判。离线实施只建设评分程序和独立答案对照，评分者不可见答案。后续获准评分时冻结 Opus 5.5 Extra 评分者身份和版本，再用其校准常驻 B 改写、仅回声有 B、确实冷 B、历史 A、仅保留未变限制等对照。改动的日期与未变限制分别判；校准判错则保留抓取并暂停语义评分。

## 3. C12b · 写入确认丢失后的原域重启

C12a 提供 checkpoint 恢复后的同操作对账与一次写入，缺少独立持久化的旧进程退出见证。只为隔离设施自有的 file.write 扩展故障路径。在实际副作用之前，持久化 run、lineage、数据域、执行、操作、资源和预期内容摘要，将接受的请求与独立预期绑定。仅路径相同不足以布置故障。写入并 fsync 后、结果持久化前，记录绑定同一操作的持久见证，只中断身份已确认的 benchmark worker。目标到期未出现，记录前提未达到。

先持久化旧身份的独立 OS STOPPED 见证，再启动新 worker。沿用 run、lineage、数据域身份与目录，核验不同进程身份的 RUNNING 见证。捕获核验前 RESULT_UNKNOWN、同 ID 的普通宿主 verify-write 回执、后续 APPLIED 历史，以及观察窗内后续所有写尝试。绑定实际内容摘要，跨两个进程生命周期独立计数物理写入，预期一次，显式标注宿主协助。证据中断则未决，证实第二次副作用则失败。fixture 应覆盖原域直接重启的正例，以及退出见证缺失或模糊、不同操作或数据域、checkpoint 恢复、仅有故障标记、相同字节重复写入、观察中断等反例。将来真实运行前冻结控制器阻塞/中止的时限、观察窗和停止条件。

顺序由 benchmark 自有 worker 保证。固定版 effects.ts 的 applyWrite 在调用写工具前执行 auth.dispatch，随后写入、fsync、读回目标、生成 CAS 证据，再同步调用 auth.finish。在 dispatch 拦截点先持久化操作绑定。冻结的合成请求明确指定自有文件名及字节，独立冻结预期次数和摘要。在 worker.ts 现有 finish 拦截点核对 DISPATCHED、真实结果、目标及 CAS 字节；在任何产品结果持久化前追加并同步实际写记录。命中唯一已布防操作时持久化并同步见证，在当前同步调用中终止此 worker，不调用原 finish 或返回产品路径。见证或终止失败时在拦截点阻塞，既不返回，也不向 applyWrite 抛出会被持久化成 UNKNOWN 的异常；有时限的控制器中止该自有 fixture，记录故障前提未达到。控制器独立观察 STOPPED，在重启前检查旧进程的持久操作历史。若旧进程已落盘同操作结果，则故障未命中，增加专门反例。跨两次进程寿命，以 benchmark 效果账本中每次完成并 fsync 的目标写分别计数，相同字节的重复写也逐次计。verify-write、仅 dispatch、UNKNOWN 错误、最后存在文件均不构成一次写证明。用派发前观测和独立完成记录覆盖全窗，有潜在效果的尝试未配对、观察缺口或存在未监测的写路径即未决。拒绝该隔离场景范围外的能力。
