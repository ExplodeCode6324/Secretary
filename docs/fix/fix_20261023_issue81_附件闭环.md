## 3. 具体公共契约

全部沿用本机 loopback、owner 认证和 data-domain 边界，前缀 `/api/v1`；不通过 shell 处理路径，不给 task-only 调用者新增受支持的 owner 凭据传递路径。

| 操作 | 方案 |
| --- | --- |
| POST `/attachments/import` | `{request_id,source_path,expected_sha256,expected_bytes,name}`。UUID；绝对路径≤4096字符、无NUL；小写64位hex；正十进制字节数字符串；展示名1–255字符、无分隔符/控制符。返回202既有 Receipt，资源 AttachmentImport。 |
| GET `/attachments/{id}` | attachment_id/import_request_id/name/media_type/bytes/sha256/width/height/created_at/availability；bytes为十进制字符串，尺寸整数。仅最小元数据，无路径/base64；未知404。 |
| GET `/attachments/{id}/content` | 先核验长度和SHA，再返回原始不可变字节；octet-stream、attachment filename*、Content-Length、强ETag、nosniff、no-store；不存在/损坏410 ATTACHMENT_UNAVAILABLE；首版无Range。 |
| 既有 GET `/requests/{id}` | 导入进度/结果；COMPLETED给稳定附件身份，FAILED给稳定错误码；QUEUED/RUNNING/UNKNOWN不允许删源。 |
| 既有 POST `/messages` | 保留必需text；允许空字符串搭配1–4个有序attachment_ids；数组可省略，禁止重复ID。正文及附件均空白/空时报错。正文在前，图片按数组顺序；不伪造正文。 |

导入ID与发送ID必须不同，使用既有全域冲突检查。同ID改任一字段（路径/名称/hash/长度/顺序）冲突。公共指纹保留完整body，所以省略字段与显式空数组重试仍可能冲突，客户端固定载荷；只有内部纯文本哈希将空附件归一为无附件。不同导入ID即使相同字节，也产生独立附件身份，可复用CAS。一个ready附件可以绑定多条独立消息，关系在各Input中，不维护“只属于一条消息”的可变指针。

202仅说明接收导入工作；只有对账到COMPLETED并取得ready附件元数据，客户端才可删除自己管理的源暂存。Core不删除源文件。此后重试/发送/历史/重启不依赖源路径。此前客户端保留快照；复制前崩溃且源变化或消失，可明确失败，但不能读取其他字节冒充原请求。

错误包含INVALID_REQUEST/REQUEST_CONFLICT、SOURCE_UNREADABLE/CHANGED、TYPE_UNSUPPORTED、INVALID_IMAGE、TOO_LARGE、CAPACITY_FULL、NOT_READY/UNAVAILABLE、MODEL_UNSUPPORTED（附件错误用ATTACHMENT_前缀），以及CAPACITY_BLOCKED。schema/auth/ID错误在准入前失败，异步导入失败持久记FAILED；消息失败不得留下Input/已接收回执。HTTP映射和可重试性文档化、测试化；不确定IO保留身份及UNKNOWN/PENDING，不宣称无影响。

## 4. 存储、校验、容量及崩溃边界

首批仅静态PNG/JPEG，以实际字节识别并完整解码，不信扩展名/MIME。增加固定版本sharp及lockfile，限制像素、完整解码检查截断/损坏、单帧，不改写输出。APNG须独立检查动画标识，不能仅解第一帧。GIF/WebP/AVIF/HEIC/SVG/PDF等明确拒绝。保留原始字节，不自动转换/缩放；实施验证sharp在两系统的实际行为。

提议默认：每文件5MiB，单边≤4096、总像素≤4,194,304；每消息最多4附件、原始字节合计≤10MiB；每Core域逻辑导入预留预算1GiB、10,000导入身份；单个有界导入worker。相同内容不同身份仍独立计费，物理CAS可去重。使用具名、启动时校验的配置并在能力元数据公布。这是导入限额，不承诺全部可导入图片都适合当前模型上下文。

路径读取使用fd/O_NOFOLLOW及适用的非阻塞打开，fstat确认普通文件后有界读取；拒绝目录、最终symlink、device/FIFO/socket、无权限/空文件/超限。路径父组件拒绝symlink，或明确固定规范化父路径；fd身份和预期hash/长度作为替换竞争的最终判断。比较读取前后fstat身份/长度/时间；观察到修改就拒绝。对即将复制的同一Buffer哈希。中文、空格、shell元字符均按字面处理。路径只留在私有命令数据，不进普通元数据/错误/日志正文。

新记录：AttachmentImport（不可变请求身份、预期digest/长度、预留字节、PENDING/READY/FAILED、预分配稳定附件ID、脱敏错误）；不可变Attachment（Store所属域/owner、导入ID、名、核验格式/尺寸、ObjectRef）。Input增加可选有序不可变附件快照和带版本完整内容digest；快照含ID、真实ref及元数据，由服务端解析，客户端不能提交CAS路径。源schema union、状态处理、Store重放/引用/身份约束、生成types完整同步，不改写旧记录。

1. 先验证schema/全域ID/容量，分配稳定ID，同帧提交Import PENDING预留+ApiCommand QUEUED。预留先于附件字节落盘，不能跨await持有同步withAdmission。
2. 专用worker读取/校验有界字节，或核验预期hash对应的已写CAS；受限完整解码后调用现有CAS/fsync。内存一份文件Buffer及有界decoder输出；不扫描整个CAS。
3. 同帧提交Attachment、Import READY、ApiCommand COMPLETED/result/resource IDs。这才是正式交接。CAS已落盘但同帧未提交的崩溃，从预留的预期CAS身份重新核验并完成；CAS不存在才重读匹配预期hash的源，否则失败。
4. 启动时在通用RUNNING→UNKNOWN前仅对附件走专用确定性reconcile，不改通用恢复策略。CAS完整性不明保留预留并报告unavailable/unknown，不虚报ready、不删可能有引用的对象。
5. 明确发生在任何CAS写入之前的校验失败，同帧FAILED并释放字节预留（身份保留且占数量）；CAS可能存在后失败仍保留预留，首版不自动回收。磁盘满/fsync/journal失败不得给成功回执。注明临时峰值开销与全Store磁盘容量不是同一配额。

重启从记录重建配额，包括pending；ready/unbound无过期删除。容量满拒绝新导入；下调限额低于已用量也只禁新预留。发送仍检查逐消息和模型预算。

消息准入先解析并验证全部ready附件/字节、模型能力、单次输入预算，然后通过既有admission同帧提交Input、input.accepted、内部receipt、ApiCommand。已接收消息重试应返回原回执，即使源已删/模型配置已变；不重新绑定。同ID并发不能产生重复导入或消息。

## 5. 身份、上下文、provider与恢复

无附件保持当前正文payload、`{text,producer}`哈希、v1 secretary_input和旧身份行为。有附件用版本化规范描述哈希正文payload digest及有序`{attachment_id,sha256,bytes,media_type}`；名/尺寸作为独立不可变快照。改变/重排/删图必变身份。Store禁止Input修订改变绑定/digest。v2标记检查session/input/timestamp、完整顺序、实际解码base64后的hash/MIME和描述，不能只比正文。无标记旧匹配只允许真正纯文本消息和Input。

inputMessage从已校验CAS构造Pi真实user数组：可选text+有序image/data base64/mimeType。通过既有putMessages、Context、checkpoint、model.context/model.request持久化真实多模态消息；首版接受内部不可变CAS中base64开销，不传播到公共列表。recordInputMessages、legacy context、input coverage、working-memory源身份、settings/history anchors的比较都纳入；不修改#80助手展示身份排除规则。

首版压缩保守策略：纯文本摘要/搜索证据不能让图片Input退出。投影/settings重建保留原图像消息；从文本historical anchors中排除图片Input，通过冻结source范围内的真实Input引用重建。新settings source明确绑定图片输入/refs，旧source缺字段不授予图像覆盖资格。不重复插入、不越过冻结边界复活、不信任伪造tag。working-memory可摘要但保留原图；放不下就capacity blocked。未来视觉摘要后的图像退场单独做。纯文本历史及timer/feedback规则保持。

发送准入和dispatch/replay前都检查model.input包含image且adapter是已支持两种之一。接收后部署变为不支持，保留Input并明确阻塞，不退化纯文本。测试自建image fixture，默认fixture不改。

预算保持纯文本原policy/估算；有图使用新版本保守策略：既有完整JSON UTF-8字节估算（含base64）加每图`8192 + width*height`，贯穿准入、prepareRequest、压缩规划、最终payload。不是provider精确计量，也不提前实施#71。额外限制消息/payload字节，继续执行input/output/context reserves；每个独立表示各算一次图像附加量，转换前后不能丢也不在同一次重复算。最终hook之后检查完整图像数量/顺序/MIME/hash和模型/output上限，任何替换/过滤都在HTTP前拒绝。大图可能导入成功但发送CAPACITY_BLOCKED，明确实际限制；若复核认为不适合，明确收紧范围/调整策略，不虚构provider能力。

用实际安装的Pi转换、roleModel/streamSimple连接本机mock provider，捕获两种adapter最终HTTP JSON并返回有效synthetic流。验证真实图像块、顺序、digest，而不是只截获自制StreamFn输入。不计划改上游submodule；若必要先拿证据交协调范围裁定。密钥只留既有closure，不进复核日志。

恢复覆盖导入、消息准入、checkpoint先于input事件修复、provider请求持久化前后。从固定CAS/绑定恢复，沿用model-call不确定性/重试策略，不宣称provider外部执行恰好一次。CAS缺失/损坏整体拒绝，不只发剩余文字。源删除后ready导入重试/读取/历史/replay继续工作。
