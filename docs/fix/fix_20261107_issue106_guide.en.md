## 3. Input, completion and submit contract

1. Enable guide only in ordinary Task root/detail input. Main typed `/guide` gets a deterministic wrong-scope error with the draft intact. Matter mode keeps all slash text literal: decision Shift+Enter answers its exact decision; authorization controls stay separate. Guide never bypasses them. Task ordinary text and fully pasted commands remain drafts. No new extra approval dialog.
2. Parse a manually typed leading slash, case-insensitive command name, one ASCII separating space, one exact Task name, one ASCII space, a strict permanent round `[1-9][0-9]*` within JS safe integer range, then exactly one syntax space. Preserve **every character after that final space**, including additional leading/trailing spaces, quotes, backslashes, dollar signs, tabs, multiple pasted blocks and line breaks. Only whitespace-empty validation uses trim. “Exact” starts at the expanded editor draft after existing input ingestion: `normalizePaste` already maps CRLF/lone CR to LF and removes terminal/control sequences except TAB/LF. A physical Tab key is completion/navigation, never literal TAB insertion; a TAB inside a paste block survives expansion. Guide does not alter this existing ingestion. The expanded draft is what gets hashed/frozen and must reach Core unchanged. Body is never subsequently parsed as another command, escaped, shell-expanded or normalized. Invalid Unicode that cannot be represented faithfully is rejected, never silently repaired.
3. The title token uses #105 NFC exact-title semantics; a bare token must contain no whitespace/quotes/backslashes; double-quoted names support only escaped quote and backslash. Guide interprets names as titles (`selector_kind=title`), not opportunistic UUID prefixes. Other locator commands keep their existing `auto` / `--id` behavior. No new guide `--id`, single quotes or shell grammar. Reject a newline immediately after the round (help: the body must begin after a space on that same line), smart quotes/full-width separators/full-width or leading-zero rounds with an actionable ASCII example; do not rewrite the body.
4. Add a narrow title-prefix parser shared as appropriate with the locator module; do not feed the whole multi-line guide through the whole-selector regex or split/join its tokens. Expand the DraftSnapshot exactly once and retain snapshot/provenance plus expanded immutable raw text. Only guide gains a multi-line body. No change to newline rules for navigation/cancel/follow.
5. Completion uses existing bounded suggestions (20), inserts correctly quoted titles, then suggests actual permanent rounds and current states. No inferred current/latest target. Stale results are discarded by editor, page, navigation and connection generations. Argument completion stops at the body boundary and never replaces a pasted block/body suffix. Existing `applyCompletion` rebuilds line 0 and can discard later lines: the guide branch must splice only the exact argument span and preserve every subsequent line/range/block; cover completion while a multiline suffix already exists. Tab/Enter accepts a candidate without sending. Shift+Enter follows the existing editor rule: incomplete command may accept a candidate, complete guide explicitly submits. Preserve #105's paced-input, arrows, undo and `start + oldLength` provenance fix; test actual EditorBridge paths, not only parser functions.
6. Debounce preview by header identity only, not body edits. A guidance-ineligible response may read `purpose=browse` to show the actual state and rejection reason, but can never enable submission. When a complete header resolves, show the exact title/round/state and “this execution only” in the existing input/status area; this is read-only and invalidates on header/connection changes; a body edit alone does not rerun lookup. On explicit submit, freeze the submitted draft synchronously, resolve that captured title+round using the existing guidance resolver, and never read a later editor value as its body/target. If no valid preview was displayed yet, the captured command itself still names the target; show the resolved target before POST without adding a second confirmation. Navigation during resolution does not retarget an explicitly submitted command; domain/client changes cancel pre-POST work and retain it for reconciliation.
7. Reject >16,384 UTF-8 bytes before POST and retain the draft; no split/truncation. When an authoritative currently cached execution list proves the 64-item / 65,536-total-byte limit would be exceeded, show the known-limit rejection. Final Core admission remains authoritative under concurrency. Do not require fetching all historical unrelated guidance on every keystroke. Resolve/query is read-only; invalid syntax/target/body produces zero business writes.
