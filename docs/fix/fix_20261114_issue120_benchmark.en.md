## 3. Owned domains, initialization and safe lifecycle

The benchmark deployment is a dedicated test facility, not one ever-growing shared data directory. Every independent `scenario × frozen configuration/code × repetition` receives a unique run UUID and fresh domain. A repeat never discovers/attaches to another run. Within-run restarts preserve accumulated state and original request identities; future simulated-date advances do not initialize again.

**Pre-write deployment guard:** every CLI subcommand resolves the actual checkout and benchmark root and refuses before creating even a lock/directory when the checkout is the protected agile path, a symlink alias/overlap, or contains persistent-deployment indicators (`data/core/journal.jsonl`, `.local/runtime.json`, `.local/maintenance.json`, or checkout-local launchd configuration referring to `com.secretary.agile`). The globally installed service alone is not grounds to reject main on the same Mac. Test exact path, alias, marker and nested-root refusal with stand-ins. `agents.md` must explicitly say the benchmark exception never applies inside the agile checkout even after main is synced there. Protected roots cannot be passed as config/output/PG paths either.

Use a private **stable execution slot per independent lineage**, `.local/benchmark/slots/<lineage-id>/active/`, for Core journal/CAS, Shared/task/Scope workspaces, runtime discovery, mutable caches and temporary files. Independent runs have distinct lineages/paths; each incarnation has its own run UUID, ownership nonce and directory identity. Evidence/checkpoints/registry and retired incarnations are outside the active slot. Runtime ports and API tokens are unique and loopback-only; use a socket/port reservation plus identity handshake, fail on collision, never attach to a service because a port responds.

Source inspection after R1 confirmed that even Shared/NONE `workspace_binding.root_path` is absolute (`scopes.ts:binding/rootFor`), immutable in Store, and write verification compares an operation's saved absolute resource. Therefore restoration uses a fresh physical directory at the **same canonical pathname for that lineage**, not arbitrary path relocation. Hold an exclusive lineage lock; stop and prove exit of all old processes; seal a full checkpoint; persist a slot-handoff intent; atomically move the old active directory to a private retained incarnation; promote a newly restored staging directory into the now-empty slot; verify its new inode/nonce and actual hashes before boot. No symlink alias or journal/CAS rewriting. A new PG cluster, API token and instance remain mandatory. Only one incarnation of a lineage may run; parallel branches at the same absolute path are refused. The registry binds run IDs to current/retired locations so cleaning an old run cannot delete its successor. Interrupted promotion is reconciled by persisted ownership identities, never by path existence alone. This is fresh owned storage at a reused logical path, not reopening the old data directory. Arbitrary-path portability is explicitly NOT_TESTED.

Use **a dedicated local PostgreSQL cluster for each run** (independent PGDATA, socket directory, port, database and role), initialized by the coordinator's known binaries. The Core gets only that run's non-superuser database credentials; the controller manages cluster lifecycle. Reject arbitrary existing DSNs/PGDATA. Verify PG system identifier, actual `data_directory`, database OID/name/owner and run marker against the controller registry before any reset/stop/restore. CI ordinary regression DSNs are not benchmark clusters. A deliberate query confirming connectivity is not sufficient ownership proof.

All controller-side `initdb/pg_ctl/pg_dump/pg_restore/psql` invocations also use resolved absolute binaries and a sanitized environment with explicit socket/host, port, database and user as applicable. Remove inherited `PG*`, select explicit private empty pgpass/service files where applicable, and never read user defaults. Secret-bearing flags are not logged. Pin PostgreSQL **major 18** for this first harness and use the same major across server/dump/restore; record exact patch/binary identity. CI installs PG18 server+client via Ubuntu PGDG packages and Homebrew `postgresql@18` on macOS, without starting global services; resolve installation paths and assert the major. Cache installation where safe; raise only affected job timeouts from 20 to 30 minutes if needed, report actual duration. Missing binaries/version mismatch fail the required job, not skip. Local inspection found PG 18.6, but CI installation has not been exercised.

Build child environments from a small allowlist, not `{...process.env}`. Explicitly resolve model roles, flags, output/context limits, Core DSN, token, discovery path and temp/cache locations. Do not read `.env.local`, production `SECRETARY_*`, PG service/password files, notification secrets, default discovery or inherited proxy/Node preload settings. An explicit benchmark config may reference an approved existing provider credential; the controller passes only necessary secrets through a private channel, with no key in argv/report. No key acquisition or implicit agile-key reuse is part of this plan; live runs require explicit credential selection before starting. Missing configuration is a refusal, not fallback. Do not repurpose shell `HOME`/`CODEX_HOME` variables.

Maintain an explicit reviewed inventory of effective `SECRETARY_*` settings, including dynamically constructed role/limit families. At run preflight compare source-discovered keys/families with that inventory and reject unclassified additions/unknown config keys. Record every effective non-secret value, deliberate unset/default and secret-presence reference, never secret values. Give worker, PG and controller explicit per-domain temporary paths; worker `TMPDIR` must isolate the Store journal lock. Use a dedicated benchmark worker calling product `App.open` and `serveCore`; describe evidence as product App/API through a benchmark entry, not a test of the production launcher. It must require sink injection before open and cannot fall back to `sendPush`.

An exclusive controller lock and durable state transitions (`CREATED`, `RUNNING`, `STOPPED`, `CHECKPOINTED`, `RESTORING`, `COMPLETE`/`FAILED`/`INCOMPLETE`, `EVIDENCE_SAVED`, `CLEANED`) prevent concurrent ownership. Persist creation intent before resources; record partial setup so interruption can be resumed or quarantined without guessing. Marker contains schema version, random ownership nonce, run/config identity and canonical paths; registry is outside agent access. PID alone is insufficient: record start identity, expected executable/arguments, process group and control-channel handshake. Unknown/reused PID means refusal, not kill.

Cleanup accepts a run ID, never a free-form path or DSN. Require trusted registry + matching private marker + expected owner/mode + canonical containment with path-component boundaries; reject symlinks/hardlink anomalies, roots/ancestors, production or unknown domains, foreign/shared DB, changed ownership, active/unidentifiable processes and missing evidence. Stop only owned Core/children and PG, wait for exit, retain raw evidence/first failures/checkpoints, then clean only that domain. If shutdown or evidence sealing fails, retain everything. Recheck identity immediately before mutation under lock, and revalidate directories when walking; test replacement races with barriers. No generic recursive delete of a supplied path, no `git clean`, no production-root delete probes.

## 4. Backup → restore → continue: first operational milestone

Before broader memory scenarios, prove a complete drill with benchmark-generated state. Normal Core APIs create a session, synthetic facts, a Shared task artifact, stable command/request records, controlled notifications and a due/pending action scenario. Fixtures may drive the protocol-only version; a separately labeled online continuity smoke follows. No real agile backup is launched.

1. Freeze source/dependencies/config/case hashes and fixture/sink settings. Confirm all targets are benchmark-owned before `App.open` can recover or a pump can run. Only Shared/NONE internal workspaces are used initially; external DIRECTORY Scope bindings and registered PROGRAMs are refused for this first checkpoint format. This explicit limitation avoids pretending directory renaming safely remaps immutable action parameters.
2. Verify an action reached the local counted sink; retain a durable sink ledger outside rollback scope. Use explicit barriers for a response-loss/unknown-outcome boundary, never timing-only sleeps. Record stable request/body/authorization identity. After interruption, reconcile existing records; never replay an unknown external effect merely to learn its result.
3. Stop old OS worker and verify exit; stop every action child. At this quiescent boundary copy authoritative Core/CAS/workspaces and take a logical PG dump plus cluster/config/version manifest. World authority remains journal/CAS; PG is the rebuildable search index, with legacy `wm` relevant only to import. Copy configuration references without stale API secrets/discovery/PID files; exclude `core-endpoint.json`, `core.log`, `push-secrets/`, `owner.lock` and other runtime locks from the bootable checkpoint. Preserve diagnostic source versions of excluded files only in controller evidence, inaccessible to workers. Hash every artifact; verify journal sequence, CAS closure, dump readability and complete relative file inventory. A listing-only `pg_restore --list` is necessary but not acceptance. For a fresh run, assert the normal product `worldStartupPreflight` selected `world.bootstrap_selected(fresh=true)` and FRESH genesis; do not create a fake legacy `wm` schema. For restore, preserve original World state. At capture catch up and freeze `mem.checkpoint`; verify its source/sequence/digest and row counts after actual import and show first indexing accepts the checkpoint without a rebuild. An intentional mismatched-index fixture must rebuild from journal and never serve stale rows; do not accept a hidden rebuild as proof the positive dump restored correctly.
4. Restore into a **new owned physical directory/cluster** registered with a new run incarnation, using the stable lineage slot handoff in §3. Validate source checkpoint completeness and exact frozen code/config/scenario/dependency fingerprints before boot; mismatch/corruption refuses. Recreate PG ownership with new local credentials (`--no-owner`/explicit owner, no restored global roles), then actually import the dump. Do not restore production connection settings, push secrets, endpoint/token or process locks. Preserve logical session/domain/request identity, canonical workspace path and prior state; change directory inode/nonce, PID/Core instance, API endpoint/token and cluster ownership. Record parent checkpoint, lineage and physical incarnation separately. The retired source is sealed and never booted at its relocated archive path.
5. Any product absolute path/process metadata is inspected before boot. Require every recorded operation process to be persistently STOPPED or independently proven dead under existing identity rules; otherwise refuse before `App.open` can signal any process. If a state cannot be safely restored under existing contracts, refuse with the exact unsupported binding; do not edit journal/CAS records to conceal a failed restore or silently treat it as fresh initialization. Verify a new continuation of the original Shared task reads/writes its restored workspace and reconciles the original write resource; a CAS artifact download alone is insufficient. Compare retired-directory hashes before/after and include a canary that must never be read/written. Assert all resolved workspace roots, cwd and effect targets remain under the current active slot.
6. Before recovery, install counted `pushDelivery`, restrict authorization to workspace writes and product-approved workspace reads, reject arbitrary shell/PROGRAM and unexpected targets, and use only the benchmark's PG/model routes. No inherited permissions, destinations or credential files. Retain scheduled state, but any resulting action must stay in the controlled domain/sink. Report a local test effect as local, never delivered to a real service.
7. Start a new OS worker PID, prove old PID dead/new instance present, query original request IDs and state, continue the same timeline, read restored artifact through the product, and check sink attempt/effect counts. Duplicate delivery attempts and duplicate committed effects are reported separately; no sink deduplication may hide a duplicate Core attempt. A known committed command is not executed twice; RESULT_UNKNOWN operations remain blocked until evidence-based reconciliation (not a claim about push retries).

Test a normal stop/checkpoint and a bounded crash/restart/unknown-effect case. Do not claim power-loss durability or arbitrary mid-write database backup support. Checkpoint branches preserve common-prefix identities but are not independent statistical repeats. New repeats have neither prior responses nor mutable cache state; checkpoints may contain the current lineage's authorized past only. Any later observation probe that changes memory must be declared by its case.

The unknown business-effect case uses the product's `file.write`/`verify-write` and stable API command reconciliation, with a fixture-only barrier at the chosen persistence boundary. It is not an exactly-once push-delivery claim. Current `Pushes.run()` requeues interrupted `SENDING` deliveries; this is a source-observed retry contract, not a newly discovered product defect. The successful checkpoint scenario finishes and persists acknowledged prior pushes before capture and creates a new due notification on continuation; assert each expected local effect and count every attempt. A checkpoint containing an ambiguous `SENDING` push is a refusal case for this no-duplicate-effects drill, retained for later disposition, never silently replayed or deduplicated into PASS. No production push repair is included.

## 6. Evidence and unified report format

A versioned JSON report is authoritative; render a human Markdown summary from it. Reuse it for both tracks. Required fields:

- identity: report schema, track, case ID/version, run/repeat/lineage/incarnation, issue, source SHA/tree, tracked diff and untracked relevant source hashes, submodule SHA, lockfile/build/dependency/runtime versions;
- frozen setup: input/adapter/config hashes; oracle hash private to controller, sanitized reference publicly; model role/provider/requested ID and observed revision if exposed (otherwise `UNAVAILABLE`), flags, seed, timezone and UTC wall timestamps;

A failed assertion remains FAIL even when later steps are INCOMPLETE; budget exhaustion/interruption/missing required evidence cannot become PASS;

A post-ack/pre-send crash leaves a send-intent with dispatch unconfirmed, not a falsely counted physical send. Persist actual transport entry/result separately, retaining uncertainty where no response survives. Aggregate prior attempts and elapsed budget when resuming. Redact tokens/DSNs/private content publicly; retain raw evidence at 0700/0600. Report generation failures must preserve source evidence. No overwrite of a first failure with a green rerun.
