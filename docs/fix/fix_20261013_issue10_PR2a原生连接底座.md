## 审计要求的三个决定

1. **SQLite 事务边界**：唯一编辑副本的草稿删除与完整 outbox 插入在同一 BEGIN IMMEDIATE 事务内；提交成功后才允许联网。请求回执与 outbox 状态单独提交，不以 HTTP 成功推进同步 cursor。每个同步事务的缓存更新、失效标记与 applied cursor 原子提交。刷新失败时保留旧 cursor 和失效状态。RESYNC 仅重建投影与水位，保留草稿、outbox、阅读锚点、通知展示证据。
2. **数据域与代次**：data_domain_id 来自 Core 的持久域标识，客户端不生成替代值。客户端每次附着/切换/恢复增加本地连接 generation，取消旧连接。每次 await 之后核对 generation；核对与 SQLite 写入之间不 await。owner/domain/session 为缓存作用域，outbox 记录原 session；旧 session 的未受理命令不自动重投。实例变化保留同域 durable cursor/outbox，重新加载实例分页。
3. **CI 门禁**：Linux Core 与 macOS 原生检查独立运行，汇总 job 保留 `verify` 名称，使用 always() 并要求两项都 success。macOS 失败或跳过时汇总失败，Linux 自身可能仍绿。开工实查 main 尚无 branch protection，因此这里保证工作流结论，不虚称 GitHub 已强制禁止绕过合并；本次不修改仓库保护设置。

## 实施中发现及调整理由

- Core 分配 client_id；客户端只先生成注册 request_id，不能将本地 UUID 当成已注册身份。集成测试暴露这一差异后，改为原注册请求对账并将回执、分配 ID 和 outbox 状态同事务保存。
- 并发读取从前置草案的四个收紧到两个，为同步暂存和变更页保留 32 MiB 原始响应预算。进程 RSS 包含解码对象与系统库，不冒充同一数字。
- 通知 API 从旧到新分页，必须逐页处理，不能只读首页。冷启动/离线响应先持久化，匹配域重新附着后再提交；SCHEDULED 与 PRESENTED 分开记录，崩溃窗口只抑制不确定重复，不承诺 exactly-once。
- A0 缓存/流式解析/reason 分页/32 KiB 内容页保持不变：r2 已逐项接受，无新反证，不在原生工程阶段再改领域代码。
- PR2a 只解码连接/回执/同步/通知所需 DTO，业务详情完整 DTO 随消费它的 PR2b/PR2c 添加；原始投影可缓存，但不能称业务页面已实现。阅读锚点预留保护表，产物缓存、Markdown 渲染和完整业务页面按原分期继续。
- Xcode 使用本机运行签名，构建日志明确 ad-hoc 下 hardened runtime 未启用；本阶段不宣称已具备分发签名、公证或沙盒隔离。
