## 独立复测与顺序

两案可单独复测，各自从干净的隔离 benchmark 数据域开始，各一次。建议 **C12b → C16**。上次 C16 运行到第 97 个工作负载请求时传输未决，排在后面的 C12b 零发送。C12b 上限 25 次，先独立封存 C12b 工作负载，再运行并封存 C16。至少一案具备评分资格才做共享校准，候选先评 C16，再评 C12b，跳过不合格候选。C12b 的恢复效果由机械证据裁定，评分器另评义务断言。已完整收包的语义校准失败即关闭候选评分；评分响应传输不完整即永久停发剩余请求。

现有 runner 把旧系列、顺序、批准摘要及账户例外写入 `stage-c-targeted-policy.ts`。评分准备在 `targeted-reader-workload.ts` 要求存在对应实体运行，现有导出器绑定上一补充包的四个位置。因此新方案须离线打通逐案终态、评分和追加发布，并验证同一批准下已经封存的首案在第二案中断后仍可导出。每案独立认领，同一 Go 账户、预算及停发规则覆盖两案和评分。

## R75 实现复核后的冻结条件

六份已校验的 Go 工作负载归档中，1,170 个完整响应从预留到结算的 P95 为 15.169 秒，P99 为 23.901 秒，最长为 46.709 秒。该请求用于上下文压缩，产品调用全程 47.683 秒。R71 的 96 个完整响应最长为 26.949 秒。第 97 个请求使用 main 模型执行压缩，传输中断；随后同会话被本地拒绝的是新的 MAIN 调用，两者的首次尝试分开保留。

据此，工作负载每次发送前保留 60 秒；每次额度读取前至少剩余 65 秒。元数据暂时不可用时按已批准的上限立即复查，每次最多 5 秒。C12b 的发送由测试程序串行化：任务回复已保存、正等待本次原生写入时，其他请求也须等待。冻结单须明确复查耗尽且模型零发送时，停发是否涵盖下一案。评分器沿用自己的来源及校准有效期。

实现复核还要求以真实 worker 和隔离的模拟 Go 账户检验两个案、恢复链以及单案封存后的导出。演练数据单列，公开实测表仍以新冻结批准后的真实回执为准。
