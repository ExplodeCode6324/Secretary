## 2. Source findings at the plan base

- `tui/remote.ts`: reads latest 50, catches up from a durable tail, retains an unbounded message Map and eagerly concatenates every body fragment. There is no older-history navigation. `confirmed`, notices and component caches must also be bounded; shrinking only the Map is insufficient.
- `tui/view.ts`: `follow: "none"` is already correct. The anchor sums trimmed rendered characters across headings/preview/body, so it is unsuitable when CoT or Markdown layout changes. All document lines are currently materialized.
- `tui/app.ts`: Main/Task editors and views are distinct; the first Main load goes to the end once. Arrow viewing and paste-to-editor handoff exist. Main boundaries currently do not fetch pages. Transient errors are appended to the whole Main document rather than attached to the relevant boundary.
- `tui/input.ts`: already disables Pi's default submission and captures expanded text before explicit Shift+Enter. However it passes expanded text to `parseInput`, losing the distinction between a typed leading slash and one originating inside a paste. CoT commands are absent. Default Pi markers are not Hermes summaries.
- `tui/state.ts` / `delivery.ts`: version-1 drafts contain an expanded raw string and generation; one pending immutable request contains raw/body/id, conservative UNKNOWN reconciliation and recovery. This preserves current plain text but not a resumable block structure. Reuse the request rules; extend snapshots, bindings and recovery together.
- `application-service.ts` / `timeline.ts`: timeline `before`/`after`, `timeline/around`, body fragments, `thinking`, `streaming`, revision and existing preview metadata exist. Body cursors encode UTF-16 text/thinking offsets and revision; public content reads expose only a cursor, not seek offsets. Timeline query limit is at most 200; byte limits can return fewer rows. Mode/instance/revision changes invalidate cursors. R2 uses existing cursor walks and removes the proposed offset projection; see §4.
- Pi's pinned Editor paste Map, segmentation and marker parser are private and hard-code `[paste #…]`. `setText` clears the Map; `submitValue` expands, trims and clears it before callback. Merely replacing strings in rendered lines breaks wrapping/cursor geometry. The adapter needs an explicit compatibility seam, not an untested cosmetic replacement.

## 3. Parameters and bounded historical reading

Register these starting parameters before implementation: **N=50 timeline items**, **B=50 items per request**, **H=200 resident timeline metadata items**, plus **4 MiB of resident UTF-8 body/CoT text**. Activity rows, including filtered non-tool activity, count toward N/B/H; bytes and Core page limits can shorten a page. Bodies and metadata evict independently: a row without its body has a local loading placeholder and stable ID, never an empty-body claim. Pin the visible body window and evict nonvisible bodies first. Assemble a settled message whole only if its combined text/thinking fits **1 MiB** and the shared 4 MiB budget. Beyond that threshold use at most **8 nearby Core fragments** in the windowed path described below. These thresholds control residency, not available content. Main submission retains the existing 1 MiB serialized wire cap; the history budget does not claim to bound intentionally growing user drafts, V8 overhead or the separate Core process.

Introduce a small Main history controller (new `tui/history.ts`, integrated through RemoteViews), with a bounded ordered window and before/after boundary locators. Use API order and stable IDs for deduplication, not insertion order or timestamps alone. Keep the reading window separate from the latest-arrival watermark. New arrivals invalidate a bounded tail view or unread indicator; they must not evict the visible anchor or fetch/store every unseen body. Traversal from old to new must cover intermediate pages rather than join two nonadjacent windows as though contiguous.

At top/bottom boundaries, read B in the requested direction. Coalesce a boundary read, ignore obsolete generations, and preserve the visible anchor until the replacement page is ready. Evict the furthest nonvisible items/fragments and matching components, render rows, references, notices and revision markers together. Retain only bounded boundary metadata and the active page anchor, not a growing list of every historical ID/cursor. Re-read discarded ranges through existing Core APIs; never write another log or delete Core history. Preserve already displayed content during errors; show an explicit gap/unavailable sentinel if the source is genuinely missing.

Body fragments are demand loaded for the viewport and a small adjacent window. Read/evict/re-read segments of an oversized message in both directions by walking the existing opaque cursor chain from its start or a bounded valid checkpoint, summing the returned text/thinking lengths. Discard traversed text outside the target window. Retain bounded Markdown continuation context or reconstruct it by a prefix walk; seeking without prefix context would not solve Markdown rendering anyway. Do not replace supported Markdown with plain text or truncate large messages to meet a cache budget. The feasibility gate must demonstrate fenced code, long paragraphs and nested/loose lists across windows; if the pinned renderer cannot support this safely, revise the plan before implementation proceeds beyond the gate.

Filtered-only pages: when a user moves through a boundary, scan at most four B pages or 200 raw rows per asynchronous batch until visible content or a genuine boundary appears. If more filtered rows remain, retain the advanced cursor and a visible continuation/loading sentinel and yield to the event loop; continue from that cursor on the same queued navigation or the next arrow operation. Never restart the same invisible page or silently label it the start/end. Keep input usable and bound concurrent page/body reads to two, with only one coalesced successor per direction. Count returned first-fragment text toward the byte budget immediately, not only assembled bodies.

Observe item/fragment counts, retained text bytes, component/render-cache counts and Node heapUsed/RSS at start, after >H traversal, after reverse traversal and after repeated cycles. Diagnostic counters are test-only, not persisted UI activity. Deterministic limits apply to retained content/structures; heap/RSS are corroborating observations rather than a promise that V8 returns pages immediately. Bounded in-flight reads and render windows must also be measured.

## 4. Anchor and recovery through existing reads

Anchor shape: `{item_id, region: body|thinking|header|activity, block_start_utf16, row_in_block, measured_width, instance_id, timeline_generation, revision}` plus a viewport placement hint. This is a source block plus its body position, not an absolute screen row. Use the pinned Pi-exported `Marked` (locked marked 18.0.11) to identify block `raw` spans; do not claim that Pi Markdown exports source maps. Render bounded blocks with Pi Markdown, retaining mapping from component rows to that source block. Preserve whole-document spacing and reference definitions; test headings, ordered and loose lists, quotes, fences, links/tables supported by the baseline, repeated identical text and incomplete streaming syntax. Do not add a new math/HTML/Mermaid support promise. In an oversized block, retain its source start, continuation context and window source range; a prefix walk reconstructs discarded context without retaining all earlier text.

Heading, summary and body have separate regions, so CoT insertion preserves the same body block and row exactly at unchanged width. Prepend, eviction/reload and Main/Task return restore the same logical anchor. Resize reflows within the same source block and clamps its row to the nearest existing row; this is block-relative restoration, not a false guarantee of exact source-character mapping through arbitrary Markdown transforms. Test that it never jumps to another message or the latest output. Without explicit-send follow active, passive output, including output arriving while already at the bottom, never invokes initial positioning again. Explicit POST follow takes precedence over anchor restoration; see the [native acceptance follow-up](fix_20261031_issue91_native_acceptance.en.md).

If a thinking anchor becomes hidden, retain that logical anchor while showing the message's collapsed summary; re-expansion restores its block/row unless the user deliberately navigated elsewhere. Revision is comparable only within the same `(instance_id, timeline generation)`: it is an in-process timeline counter, not a content hash. Determine shortening from newly read region content/length, not revision inequality; notify only if the actual anchor was removed. Across process/generation changes, discard version comparisons and revalidate against fresh content. Never present mixed-revision fragments as one body. Transient content missing after restart is explicitly unavailable; no durable CoT is fabricated.

Treat every cursor as scoped to `(Core instance, timeline generation, query mode, message revision where applicable)`. Mode switch/restart/explicit cursor rejection invalidates relevant tokens and increments a client request generation. Re-locate with **`timeline/around?message_id=…&limit=1&thinking=…&streaming=true`**, assert the target is actually returned, then use its fresh before/after cursors and page outward by B. `limit=50` can hit the byte ceiling before reaching the target and is not used for relocation. Preserve at most two nearest durable neighbours per side and available `source_event_id` as fallback locators. If the anchor is missing, try its source event and then these nearest surviving neighbours with explicit displacement/gap notice. If none survives, retain an unavailable sentinel and let the next deliberate navigation start a freshly queried recent window with a gap notice; do not silently jump to latest on a passive refresh. On instance/generation change rebuild order from current Core pages; old displayed rows remain only as a separately labelled temporary snapshot until replaced, never merged as a contiguous current window. Cross-domain history/drafts remain isolated.

Error actions: `CURSOR_EXPIRED` and `TIMELINE_RESET_REQUIRED` invalidate and relocate; `TIMELINE_ITEM_NOT_FOUND` invokes the bounded neighbour fallback; `INVALID_FRAGMENT_OFFSET` (not expected from normal opaque cursor use) revalidates from the start once, then reports a local protocol error; network/read errors preserve content and offer the next user retry. Settled items get at most one automatic relocation per failed operation. Only a successful page with no continuation establishes a history boundary.

Running previews are a separate path: `preview_status:"running"` changes revision on deltas and has an existing 32,768 UTF-16-unit cap. Read the affected item with `around(...limit=1)` on coalesced invalidation, not a 50-row expanded-history refresh. Build a coherent bounded snapshot from offset zero; any continuation read must still match the same generation/revision. Expiry during a running snapshot is normal supersession: discard incomplete new assembly, preserve the last coherent display, and re-read on the next coalesced invalidation, without a transient error or blocking retry loop; passive refresh does not start follow, while already active explicit-send follow is preserved. Display a continuation-in-progress indicator for a partially available preview. On settlement, use ordinary demand pagination to read the full durable body, preserving its logical anchor. Test a CJK streaming body and expanded reasoning exceeding one Core fragment, interrupted preview expiry, and preview-to-durable replacement.

**R1's content-offset API extension is removed.** Existing cursor walks reach every available position with constant retained prefix memory and also reconstruct Markdown context. No new fields/endpoints or generated contract changes are planned. If implementation measurements demonstrate an actual unmet requirement, record the reproducer and propose the smallest read-only change for renewed review; do not quietly add this API or weaken browsing/Markdown behavior.
