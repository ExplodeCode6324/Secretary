# Fix 计划与实施记录

本目录保存修复计划、Master 批准范围及后续实施记录。先制定计划，Master 确认后实施；状态更新附实际日期和证据。

Core 相关工作统一在 `secretary-core` 主工作目录进行，所有 fix 文档写入该目录的 `docs/fix/`。不另建独立工作区或专门的计划目录；需要区分工作时在同一仓库使用分支。

## 文件命名

- 有 Issue：`fix_YYYYMMDD_issueN_具体功能描述.md`。
- 无 Issue：`fix_YYYYMMDD_具体功能描述.md`。
- 日期是计划建立日期；同一 Issue 可以按范围拆成多份文档。
- 分支名放正文，不放文件名。改名时同步仓库内引用。

## 统一页首

```markdown
# Issue #N：具体功能描述

- 日期：YYYY-MM-DD
- 关联 Issue：[#N](https://github.com/ExplodeCode6324/Secretary/issues/N)
- 文档状态：待 Master 确认
```

无 Issue 时标题省略编号，关联字段填“未关联 Issue”。当前计划使用“待 Master 确认 / 已批准待实施 / 实施中 / 待验收 / 已完成”表达进度；历史文档统一标记“历史计划与实施记录”，原状态、批准内容和验收结论保留在正文。

## 新计划正文

1. **目标与基线**：需求、实际提交 SHA、前置 Issue、工作目录与分支、范围。
2. **现状与原因**：源码证据、问题路径与尚待验证的判断。
3. **方案与修改范围**：行为、不变量、涉及文件及合同变化。
4. **实施步骤**：基线冻结、修改顺序与交付物。
5. **验收标准**：场景、预期、命令与证据位置。
6. **风险与回退**：工作量、具体风险、回退方式。
7. **执行记录**：批准、修改、首次失败、验证与剩余工作。

历史记录保留原章节与内部引用，只统一文件名、页首和 Markdown 排版。代码块中的命令、原始证据和历史结论保持原义。
