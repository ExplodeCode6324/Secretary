### 3.1 Empty failure producers and stable display identity (R1 B1/B2)

Two sources must be distinguished in the analysis: (a) a provider error/aborted response returned through transport's final-attempt diagnostic stream, with a fresh call ID and possibly partial content; (b) upstream Agent.handleRunFailure, which synthesizes empty text after an exception and takes stopReason from the Agent abort flag. A failure before a new preview start can inherit the prior display_call_id in existing logs. Core shutdown aborts modelLifetime before host.close calls agent.abort, so a cancelled transport may be accompanied by a synthetic error message.

A status-only abnormal assistant event must never replace a different existing durable assistant event using the same display_call_id. Resolve it to its own source event ID and omit call_id; preserve the earlier row/body/outcome/order. A status-only result for its own call may replace that call's transient preview. Resolve identities deterministically in durable log order; repeated processing of the same source event is idempotent. Apply this rule through one shared display-identity resolver used by both Timeline and ApplicationService's eventMessages/messageEvents mappings, including around-by-event and related lookup. Keep resolution metadata incremental; do not introduce per-query whole-history scans. For earlier tool-only events, also reserve their durable call association, so a later unrelated failure is not falsely attributed to that saved call merely because its message row was omitted. Existing logs need this projection rule even after a forward fix.

For new writes, clear displayCallID after each successfully persisted assistant message_end. Keep the emitted event's captured ID intact; toolResult events do not consume a fresh model-call ID. Include failures before the next transport start (call limit/budget/prepareRequest) and failures after a reply but before another call. This is only display metadata; messageIdentityHash already removes display_call_id. Do not change ModelCall identity or upstream Agent implementation.

For an empty error/aborted event, first resolve the non-colliding call association. If that associated ModelCall belongs to the same session and is INTERRUPTED with failure_kind=CANCELLED, project outcome=interrupted and incomplete=true even when the stored synthetic stopReason is error. Otherwise preserve error→failed and aborted→interrupted. This deliberately retains a genuine Agent/provider abort as interrupted even without a resolvable call; it does not infer cancellation from error text or a stale prior call. No new persistence field, raw-error parsing or stored response rewrite is needed. A status-only error that fell back to its event ID cannot borrow the preceding call's cancellation state. Nonempty provider responses retain the ordinary stopReason mapping.

Regressions: visible text+toolUse then a pre-call failure; two durable events with a reused display ID in a historical fixture; both events resolve correctly through timeline/around?event_id, first body remains intact, second failure is separate, and IDs survive reopen. Also run isolated Core stop mid-call, retain its logs and reopen to verify the empty row agrees with interrupted activity. Include missing/cross-session/stale associations and genuine aborted-without-call fixtures. If that experiment confirms a separate RECOVERY_BLOCKED recovery-policy issue, record it for coordination as a separate follow-up; do not change session recovery policy in #80.

## 4. Short preview contract

Add an optional `thinking_preview` to public Message and SSE preview objects, backed by a shared schema definition `ThinkingPreview`: `{text: string, truncated: boolean}`. It is display-only and present independent of `thinking`; absence means no displayable reasoning is available in that projection. Keep `thinking` as the existing opt-in full-content fragment. Do not overload Message `truncated` (transient source retention) or Message `outcome: truncated` (model length stop) with short-preview truncation.

VIEW-02 permits a fixed 20-character prefix. Current pi-ai ThinkingContent has no separate reusable summary field, so this plan adopts that option explicitly rather than searching for or generating a summary. A shared pure helper consumes only existing non-redacted thinking strings in content-index order. Concatenate nonempty displayable blocks with `\n` (also use that exact convention for expanded thinking); no trimming, Unicode normalization, invented summary, signatures, opaque encrypted/redacted payload, or model call. Count extended grapheme clusters via Node 22 `Intl.Segmenter` with `granularity: "grapheme"`, not code units/code points. Separators and whitespace use the same grapheme segmentation. Return the first at most **20 graphemes**; append one `…` only when further displayable content is known to exist. The ellipsis does not count toward 20. A 20-grapheme complete source has no ellipsis. Recompute from current snapshot; never append a new preview to an old preview or to body text.

Keep a hard **4 KiB JSON-encoded text budget**, including a possible ellipsis, and never split a grapheme to meet it. Pathological giant graphemes may yield fewer than 20; when no whole grapheme fits, return `{text:"", truncated:true}` with no fabricated text/ellipsis. This explicit exception preserves the existing response bounds. Stop after determining the bounded prefix and whether more exists; do not introduce a full hidden-text cache or full-history scan. Any retained-tail loss must be represented as known truncation rather than claimed complete reasoning.

Choose one source strategy: compute thinking_preview in Previews.update from the current event.partial.content before retention clipping, using the shared helper; do not maintain a separate per-block truncation-provenance scheme. Inspect all content-bearing updates, including redaction transitions; terminal done/error snapshots must also revoke any stale visible thinking. Revalidate/remove retained thinking blocks against the same current source, so explicit expansion cannot leak an earlier visible block after redaction. Store only bounded preview metadata with the existing disposable entry. A long body consuming the shared retention budget must not erase a short-preview prefix available from the current source or falsely mark short thinking as truncated. End/delta replacement, block ordering and split emoji/combining sequences are explicit tests. A live prefix reflects current received content; later deltas may extend its last grapheme and replace the prefix.

Bound segmentation input to the first 4,097 UTF-16 units of the logical nonempty-block-joined thinking stream, collecting this prefix without joining/copying the entire hidden content. If more source exists, discard the final segment of that window before choosing the prefix: it might be an incomplete cluster, and a cluster crossing the window cannot fit the 4 KiB JSON-text budget. Stop before an unpaired surrogate (including a dangling high surrogate in a live delta); never emit it or U+FFFD invented by encoding. Mark omitted available source as truncated; a later complete delta recomputes the prefix. Keep fixtures on established Unicode sequences and record Node/ICU versions; display previews may change with Unicode runtime upgrades but do not affect durable identity. Retain 4 KiB rather than the optional 1 KiB suggestion; the existing byte-aware page packer may return fewer rows and will be tested with 200 candidate rows.

The server appends exactly one display U+2026 marker iff truncated and the retained prefix is nonempty; the original prefix can itself end with U+2026 and is not altered. This keeps GET and SSE self-contained; clients must not append a second marker. Raw content is not terminal-safe: document that clients must escape/sanitize control/ANSI sequences before terminal rendering; implementation belongs to #82.

When redaction removes all visible blocks from an already indexed transient row, still advance its revision and retain its stable row with empty content/no thinking_preview. Do not create a new empty normal preview row solely for redaction. A body cursor from before this replacement must return CURSOR_EXPIRED, not INVALID_FRAGMENT_OFFSET. ApplicationService must validate cursor revision against current row metadata before applying offsets, including for shrink/expiry/finalization; fresh valid requests retain their normal offset validation.

Apply the same helper/fields to durable timeline, timeline/around, content fragments and transient previews. Default GET includes this metadata for an active preview even with `streaming=false`; full transient body remains controlled by the existing streaming flag. This makes default GET and SSE short-preview semantics consistent without changing their existing body contract. Expired previews carry no reasoning preview. Durable publication recomputes from the authoritative response and wins over disposable source content.

## 5. Expansion, bounds and identity

Default `thinking=false` omits `thinking`, keeps effective thinkingLength/thinkingOffset zero and permits a content next_cursor only for unread body. `thinking_preview` does not contribute to lengths/offsets, revisions of authoritative stored messages, or cursor progress. A reasoning-only durable message has its short preview and `next_cursor:null` by default even if reasoning is very long.

Explicit `thinking=true` returns bounded existing full-thinking fragments; include `streaming=true` to read live content. No new SSE option: the stream remains short-preview only; full live reasoning uses explicit GET. Preserve the current at-most-4,999-unit / 30,000 JSON-byte per text/thinking fragment cuts and UTF-16 scalar offset semantics, at most 64 KiB internal message fragment, 1 MiB timeline page and 200-row limit. With up to 4 KiB extra metadata, adjust fragment budgets if required to retain the full serialized 64 KiB bound. Expanded fragments remain losslessly concatenable; they need not end at a grapheme boundary, but must retain surrogate safety. The short preview alone promises grapheme boundaries.

Maintain the existing eight previews / 128 blocks / 32,768 retained units, SSE 512 KiB connection budget, transient drop threshold and durable recovery. Do not add eager fetch loops, unbounded expansion, new permanent summary records or new retention policy. TUI expansion/collapse controls are #82 work; #80 verifies the server request/response contract only.

Cursors remain scoped to message ID, content revision, instance and the exact thinking/streaming flags. A flag switch starts a fresh first fragment; a cursor from the other flag scope is rejected. Growing or finalized live source invalidates an old body cursor; clients refetch the stable message ID. Preview `id` remains call ID; public row `id` remains `message:<call_id>`; durable source_event_id preserves the log identity. Do not change order on preview→durable replacement, merge different retry attempts, or promote preview_status=saved to authoritative success.

Test duplicate/reordered observations, durable-before/after-preview visibility, eight-entry eviction (expired metadata and revision advance), late durable arrival after expiry, and reopen. Restart loses transient entries; durable rows/outcomes/previews reconstruct with the same message IDs; body/timeline cursors are not permanent bookmarks. Read-only preview/expansion must create no Store records, model calls, input/context identity changes, viewed/presented/read commands, or transport retries.
