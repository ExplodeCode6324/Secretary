## 3. 时间线合同与身份

保留 `GET timeline`、`timeline/around`、`messages/{id}/content` 和 sync/changes 权威路径。消息增加向后兼容的可选字段（最终命名由合同测试固定）：`source_kind`（`master_input`、`assistant_response`、`task_feedback`、`notification`、`system_input`）、`source_event_id`、适用时的 `outcome`（`completed`、`continued`、`truncated`、`failed`、`interrupted`、`unknown`），以及下表中已有源记录提供的直接 ID。关联查询复用已有 `GET /api/v1/related`，不新增通用关联模型。只输出已有 Store 记录及其直接类型引用可证明的事实；不存在的关联留空。不暴露原始载荷、凭据、文件系统路径或整张来源图。持久化与模型/任务结局分开；未知值用中性标签降级，旧客户端可忽略新字段。

`timeline.ts` 保留来源事件/类型和已有结局/引用，`application-service.ts` 投影公开 DTO。助手 stopReason 穷尽映射为 stop→completed、toolUse→continued（步骤继续，不是最终答案）、length→truncated/incomplete、error→failed、aborted→interrupted、缺失/其他→unknown。截断/失败/中断的 incomplete 投影同步一致，不改业务状态机，每个值有合同用例；活动采用自己的状态；反馈/通知按真实字段取关联。不从文字、名称、时间或邻近位置推断。公开 ID 为 `message:<call_id>` 时仍保留真实 source_event_id，复用既有 event→message 的 around 定位。编辑权威手写源 `docs/api/v1/schema.json`（仅有需要才改 operations.json），运行 npm run api:generate 生成 Core api/contracts.ts 和 OpenAPI，再运行 desktop npm run contracts:generate 生成桌面 DTO/Rust 内嵌副本；说明性 API 文档单独更新，不手改生成合同；补对应 Core 投影/合同测试。

行身份包含 domain、instance、timeline generation、稳定行 ID；call_id 只关联预览/最终，不能用数组下标。保留服务端顺序/游标，瞬态追加行明确标识，持久记录到达后恢复服务端顺序。任何到达顺序均由 durable 覆盖 transient。有界 finalized 集合淘汰不能导致旧预览复活：只接纳当前有效 mailbox/window 的瞬态 ID，流/域/实例重置时清理；已淘汰且不确定的 ID 先权威核实，不能当新消息。

## 4. 渲染、长内容与安全

将 MarkdownIt 配置提取到生产模块，关闭 HTML，不执行 HTML/svg/iframe；远程图片显示替代文本，不嵌入资源。沿用 MarkdownIt 表格和 fenced code，保留代码空白、代码块内横向滚动。渲染缓存按 domain/instance/timeline generation、行 ID/revision、内容长度/版本和显示偏好设键并限额；不整体替换时间线 HTML。

链接只在用户主动激活后打开，显示目标并可复制地址。TypeScript 和窄范围原生 opener 都解析 URL，只允许绝对 http/https，拒绝 javascript/data/file/自定义 scheme、凭据、控制字符混淆及错误 URL。新增单一 bridge_open_url IPC：以已有 reqwest::Url/url parser 再校验，在 macOS cfg 下直接调用 Command::new("/usr/bin/open").arg(validated_url)，URL 上限 2048 字节，不经 shell、不允许任意可执行文件/参数，仅开放该自定义命令权限。链接用不导航控件，显示目标/复制动作；WebView 导航 guard 仅允许打包 app origin（开发时准确 Vite loopback origin），拒绝外部导航/新窗口。显示有界 ASCII/punycode host，主动检查可取完整目标。复制采用用户激活下 navigator.clipboard.writeText，先在真实 WKWebView app scheme 验证成功/失败；若不可用，预先限定的 fallback 为只写 bridge_copy_text IPC、2 MiB 上限，在 macOS cfg 以 UTF-8 stdin 传给 /usr/bin/pbcopy，明确设置 LANG 和 LC_ALL 为 en_US.UTF-8，仅开放自身自定义权限，不读剪贴板、不经 shell。测试中才使用 pbpaste 验证 CJK/ZWJ 往返，并覆盖无继承 locale 的 launchd 类环境，生产不读剪贴板。pbcopy 写完全部 stdin 并关闭后才等待，2s 超时清理并如实报错。open 仅将 IPC 等待限为 2s；冷启动浏览器仍在运行时报告“已请求/结果未确认”，异步回收完成，不杀掉可能成功的启动、不自动重试。不新增第三方 opener/clipboard 包、通用权限或 CSP 放宽；通过小型本地 Tauri plugin 的 on_navigation hook 为现有配置创建的窗口加 guard，不重建窗口；渲染/hover 不自动联网。

每次分片捕获 domain、instance、timeline generation、行 ID/revision、偏好 epoch 和请求序号；每行最多一笔在途，游标只接纳一次，校验身份/修订后恰好追加一次。导航重置、偏好变化、卸载后的迟到结果丢弃。CURSOR_EXPIRED 保留旧正文并标陈旧，丢弃旧游标、显式重载该修订，不能拼接不同修订。使用不透明服务端游标组装原始正文/思考，不在 JS 重算服务端偏移。服务端当前只保护代理对，不保证全部字素：Intl.Segmenter 保留跨片末尾字素，先拼接再分段，在后续内容/EOF 确认边界后提交；测试 ZWJ、组合音标、旗帜、非 BMP，不归一化、不丢失/重复 code unit。

默认展示有界预览、显式继续读取。拟定硬限额：每页请求 50 行（服务端最大 200 行/1 MiB）；驻留最多 3 页/150 行；原始正文及思考合计 8 MiB UTF-8，单条展开最多 2 MiB；渲染片段缓存 8 MiB；前台读取并发 2、思考刷新并发 1。接纳/拼接前检查字节。单行或活动选择将超限时保留现有内容、停止预取，显示手动继续/替换边界，不能静默截断或淘汰已选/聚焦内容。完整复制由用户主动触发，在 2 MiB 内读到 EOF 才报告完整；否则提供明确标注的“复制已加载部分”。卸载/切域停止请求并清理缓存。

## 5. 阅读窗口、选择和历史

优先采用有界分页窗口及稳定 keyed DOM，本 Issue 不引入可变行高虚拟列表。最多 150 个行壳、正文也受限；淘汰前固定可见锚点、焦点行、选择两端和已展开详情。固定项阻碍淘汰时停止后台加载并提供手动入口，不突破限额；页/高度/修订映射也不得无界增长。base timeline page version 改变时，将离开尾部的驻留页标陈旧；至少间隔 2 秒，仅对话窗口附着/可见时合并重查保存的页描述，不跟随每次 sync cursor 变化触发（最多 3 页、并发不超 2）；描述保留原始不透明 cursor/direction 或 around locator 和查询 flags。原 live 页离开尾部后按保留边界/around 描述刷新；按 ID/revision 对账并服从选择正文延迟规则。游标过期/generation 改变时按可见锚点重建、作废其他描述，不新增 interval-change API。原生/fixture 验证最新页以外的活动状态和预览→持久仍会更新、不移动阅读者。不得按轮询时间重建 body，也不重复写入未变的 innerHTML。

更新前捕获顶部可见行 ID/相对像素偏移和贴底状态，布局后恢复；补偿锚点上方尺寸、字体、分片增长。贴底沿用 24px 阈值，且须处于 live、没有文本选择/聚焦展开/显式历史窗口。向上滚动立即退出贴底。发送不再无条件 latest()，历史/选择保留，显示入队状态和“回到最新”。后台新消息只更新提示；明确点击回到最新才退出历史并跟随。后台刷新绝不改变关联选中范围。

较早/较新分页按稳定 ID 合并去重并保留顺序，淘汰远端页前恢复锚点。around 用 message_id 或 event_id（二选一）取得有界周边；对当前 message_id 接受活动行 ID 的行为加合同回归，否则明确回退最近消息。提供精确 ID 定位与“查找已加载内容”，标明驻留范围并跳转/高亮；当前没有全文 API，不声称全局搜索，不自动遍历历史、不建立第二搜索索引。不存在/过期/实例重启说明原因并提供重试/最新；timeline generation 变化后按保存的 ID 重建，不能复用旧游标。

持久化有界 anchor v2：domain/session、行种类/ID、像素偏移、live/history；兼容 v1 和旧数字锚点。草稿继续使用现有版本事务。思考偏好完全独立，按 §6 存 per-domain localStorage，不进入 Core settings；anchor v2 仍限 1024 字节，不包含思考值/查询偏好，迟到锚点写入不能恢复思考。锚点/偏好不包含正文。重启按 ID around 恢复并按当前字体/宽度限制偏移，记录消失时显式回退。切页保持编辑器/IME DOM；尽可能在隐藏/关闭时冲刷待保存锚点，常态有界防抖。

选择依赖稳定文本节点：被选中行的正文变化延后，最多合并保留最新有界修订至选择结束，不无限冻结无关权威状态。用户主动导航需要替换正文时，以该动作作为边界；展开动作和焦点保持原控件。原生测试断言选择文本及锚点偏移（几何未变时 ≤2 CSS px）；窗口改变时要求同 ID/上下文可访问，不要求不可能的绝对像素不变。

## 6. 思考、同步和发送

思考默认开启，正文默认折叠并可展开，折叠时仅显示摘要，关闭后立即从展示和内存思考缓存清除。持久基线 timeline 订阅保持 thinking=false；按需思考使用一次性 query，绝不写入持久投影缓存。开关不调用当前会重置 sync/cache 的 subscribe()；偏好 epoch 拒绝关闭前的在途结果。这是显示和数据最小化约定，不声称安全擦盘或能暴露 provider 隐藏推理。按域 localStorage key 持久化（复用主题/动效显示偏好机制），无保存偏好或读取失败时默认 ON，写入失败仍保持本次选择；与锚点完全独立，不需偏好表迁移。偏好只允许查看 Core 已公开、未遮蔽的思考内容，不扩大内部隐藏推理暴露范围。各查询采用下述 flags，并保持各自 cursor scope 一致；SSE 保持现有纯文本 mailbox。只刷新可见正在生成的消息 ID：messages/{id}/content?thinking=true&streaming=true，不带 cursor 取首片，不轮询整页 1 MiB。全局每秒最多一个请求、并发 1、每次最多接纳 64 KiB，多个可见生成行轮转，并受既定总预算限制；结束/隐藏/离线停止。ON/OFF 均以 SSE 作为瞬态行唯一正文来源，统一采用 Core 块间换行规则；逐行 query 只贡献思考，完全忽略其 text。ON 时 page/around/durable-content 使用 thinking=true&streaming=false，OFF 为 thinking=false&streaming=false；只有瞬态思考查询使用 streaming=true，不能让其他响应覆盖 SSE 正文。ON 时，thinking=false 基线尾页中新出现的可见持久行，按 generation/row/revision 单次读取 thinking=true&streaming=false content，结果只放有界内存思考缓存，不为此反复重查整页。这样思考 ON 不把主回复限制为首片 4,999 UTF-16 units 或 1Hz。测试 >5,000 units 瞬态正文、开关及迟到页/content 响应；验证两份 30,000 JSON-byte cut 加有界元数据小于 64KiB，违反时明确报限额错误，不静默遗漏思考。生成思考只展示有标记的首片，瞬态正文保留有界完整 SSE 预览；两者都不开放续读/完整复制声明；持久后才开放修订绑定续读。迟到响应须匹配偏好 epoch。偏好切换保留已加载正文并标局部内容，OFF 立即隐藏思考，作废内容/页游标并在新范围内从 offset 0 重载当前窗口/行，受限额约束，不能跨范围拼接；按完整 query key 选缓存，替换仅按 operation 的 projection() 选取；不混用不同思考订阅，不让旧快照恢复被关闭内容。关闭偏好跨 Core 重连和客户端重启保留。

持久 sync/cursor 与瞬态 mailbox 分离。同域同实例断线保留有界上次文本、标记重连，不称最终；新权威快照替换瞬态。域/实例/generation 改变清理对应预览、游标及 finalized 集合并重新核实阅读点。缓存陈旧、重连、断线、无数据、读取错误独立展示，缓存不能冒充实时。发送保留现有顺序：版本草稿→同事务持久化原 request ID/body 并清除匹配草稿→网络提交；超时/断线/5xx 查回执。未知结果不换 ID 重发，不重放已受理副作用。

建立所有 Rust 固定写入状态的测试映射：PENDING→已排队、SENDING→发送中、TRACKING→已受理/处理、ACCEPTED→已受理、COMPLETED→命令完成、FAILED→失败；UNCERTAIN/UNKNOWN/RECEIPT_MISSING/VERIFY_ACCEPTED→未确认/对账；UNSUPPORTED_RECEIPT→未识别回执且不自动重放；STOP_* 仅用于生命周期，不表示消息完成。UNSUPPORTED_VERSION 和 CONTRACT_INVALID→未确认/可能已记录，不归为已知拒绝；修正 deliver() 将这些可能发生在 2xx 后的解码/校验失败标 UNCERTAIN，以现有 pending 路径按原 request_id 对账，并测试已成功受理但响应解码/校验失败。只有已证实的本地发送前校验/capability 拒绝或非 2xx Core 拒绝才显示拒绝（已有 network/5xx 歧义仍未确认）；未知未来状态显示未识别及原码，不称成功或自动重试，也不凭空认定拒绝；源码状态清单回归覆盖所有 Rust 写入点。真实 outbox/回执按此映射；命令完成与模型/任务完成分开。失败/未知请求保留唯一文本，仅用户主动才复制或恢复到编辑器，不覆盖新草稿。当前快照只含最近 50 条及 2048 字符 body 前缀，因此增加窄范围只读本地 outbox-detail IPC，绑定 expected domain 和既有 request UUID，仅限消息命令并沿用 1 MiB 命令限额。不能将摘要前缀当完整 JSON 或完整草稿；提供有界待确认/失败消息列表，让最近 50 条以外的未解决项仍可访问。修改配额淘汰及 30 日清理谓词，排除 query operation 为 messages 的 FAILED 行，自动保护既有失败消息，不增加列/表、不修改 user_version、不做 schema 迁移。用户恢复/复制并确认丢弃后，精确删除当前域的一条终态失败/确认拒绝消息；不删除 pending/uncertain/未解决意图，复制/恢复本身不删原件。保护内容占满既有配额时拒绝新入队并保留编辑器文本。未解决意图继续保护，成功持久命令保留原清理策略；详情/恢复不产生新发送或重放接口。恢复 UNKNOWN/UNCERTAIN/RECEIPT_MISSING/VERIFY_ACCEPTED 前明确提醒可能已入记录，按 request_id 显示已加载持久匹配，让用户主动复制/恢复；之后手动发送是新 request，可能重复此前副作用。测试既有失败消息的配额/年龄清理、bind/重新核验转移、并发入队和精确丢弃。旧二进制仍可打开 schema v1，但执行旧清理策略，不声称 #62 二进制也有新保护。所有合并前 #63 执行（普通 Release 资源、人工/native/模型）均使用专用 #63 profile ID 和隔离 Core/DB/client 路径，绝不复用 #62/日常 profile；普通 Release 使用 app_data_dir 下按 profile 存储，连接前核实 ID/路径，不误用 native-test override 假设。普通 Release 合成资源 harness 与真实 profile 断开。仅在新增竞态测试证明缺陷时调整版本捕获/发送串行。原生 textarea，Cmd+Enter 发送、Enter 换行、候选确认不发送。PhaseUI 立即反馈但不代表业务成功。异步读写使用适用的域/实例或代次保护。
