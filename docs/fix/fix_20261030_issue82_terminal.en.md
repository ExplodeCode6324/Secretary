Add a minimal additive read-only list projection (schema source, generated DTO/OpenAPI and contract tests together): active executions with IDs and actual states; latest execution ID/state or null; pending request count. Add the fields to TaskSummary itself so #83 can extend them. No active execution means explicitly none, not RUNNING. Pending requests do not imply executing. - Pi Editor submission is exclusively application-owned: set `disableSubmit=true`; never use Editor.onSubmit for routing. Track bracketed-paste framing at the terminal adapter (including split frames and trailing input), delegate paste/newline/editing to Editor, and submit only outside paste with no autocomplete menu open. Snapshot `isShowingAutocomplete()` BEFORE handling Enter: an open menu consumes Enter for completion only, even if it closes while handling the key. Test both Enter and Tab completion, closed-menu next Enter, leading spaces, trailing spaces, no file suggestions, paste framing and failed-submit cursor/undo preservation.

## 3. Interaction contract

Full-screen body switches Main/Task; only bottom editor and optional short hint/error line persist. Each screen may have its own title. No permanent top bar, sidebar or responsive two-column mode. Small-window handling reserves a usable editor and tells the user if the terminal is too small; widening/heightening increases capacity only. Start Main at newest recent message. Main/Task round trips preserve stable message/task ID and text offset; duplicate navigation and root /back cause no reset, hint or history mutation. Do not auto-follow arrivals after initial positioning. Rendering updates must not overwrite editor content/cursor.

One command registry serves parsing, scope, completion and help. Names are case-insensitive; parameters retain original case/bytes. Only original character zero '/' starts parsing. Unknown slash commands and invalid arguments produce local errors and preserve input. Navigation commands accept no non-whitespace arguments (trailing spaces/tabs from completion are allowed), no extra lines, chaining or shell evaluation. Text after `/send` and `/rawmessage` is a literal payload, never recursively parsed. Define delimiter as the first one ASCII space separating command and payload; preserve everything after that delimiter, including additional spaces/newlines. Empty or whitespace-only payload is rejected without discarding input. `/send` with no payload cannot send an invisible saved draft: reject empty input in this text-only batch. `/rawmessage` is Main-only and affects this submission only.

Implemented commands: global /M, /T, /back, /help; Main-only /send and /rawmessage. Task /send or /rawmessage reports scope error with no POST. Ordinary Task submit keeps its text and does not route anywhere. `/T` appended to a draft is text; navigating requires replacing/clearing it to a standalone command, with no hidden command buffer or navigation shortcut. Two ordinary drafts only, no Task-ID drafts. Help truthfully lists later commands as unavailable; completion offers only implemented in-scope entries. There is no object-taking command in #82, so no fabricated object completion; future object candidates remain with their consumer batch. Completion must never submit.

Proposed keys: Enter submit (an open completion menu consumes it without submit), Shift+Enter/Ctrl+J newline where supported, application-owned backslash+Enter fallback, Tab completion, viewport PageUp/PageDown and wheel scrolling, Ctrl+C graceful client exit even with a selection. Keep Pi copy-on-select; it is separate from Ctrl+C. Disable AltScreen search and previous/next prompt-jump defaults in this batch; Home/End remain editor line-start/end, not viewport navigation. Do not call addToHistory. Verify actual parent-vs-editor key precedence in preflight. Record exact effective bindings after native preflight; do not add new navigation keys. Errors clear on the next ordinary edit or submitted command, before presenting any fresh error; async render ticks do not clear them. UI activity never creates a message or audit entry.

Main theme: model white; Master light blue with upper/lower separators; tool entries fixed light pink and separate lines; available thinking_preview light gray, no generated fallback. Reuse Core's bounded/redacted <=20-grapheme preview with its existing ellipsis, without truncating it again or deriving hidden reasoning. Single renderer for streaming and final/history content. Fixed Markdown sample covers paragraphs, headings, emphasis, lists, quotes, inline code and fenced code; separately document links/tables actually supported, make no math/Mermaid/HTML claim. Treat remote text/control sequences as untrusted display data; reuse safe component rendering and test escape/control sequences cannot operate the terminal or become input commands.

## 4. Core reads, synchronization and limited reading scope

Use `/core`, `/session`, `/timeline`, `/timeline/around`, `/messages/{id}/content`, `/tasks`, `/scopes`, `/sync/cursor`, `/sync/changes`, `/sync/stream`, `/requests/{id}` and POST `/messages` only as actually needed. Record exact consumed methods/routes against operations.json after implementation; list every remaining operation with a reason. Core private token remains local and never enters evidence.

Initial Main: latest 50 entries plus this run's arrivals, resident for the run, no eviction/cache limit/re-read engine in #82. Display a truthful recent-window boundary, not 'beginning of history'. #91 owns H, eviction/re-read and older-history paging. Stable ID and text-offset anchors on the loaded entries survive navigation, resize and reflow; ScrollView uses follow:none and the app reapplies anchors after heights change above them. Own sends also do not auto-scroll: the editor clears on local durable transfer, and a short local 'submitted; receiving status...' hint identifies progress while reading position stays unchanged. Initial loading/error and same-domain Core restart may resnapshot current recent data; retain already loaded records during reconnect so this run's reading position is not lost. Missing authoritative content is reported in place, not silently relocated.

Task reads 50 per API page, initially the existing oldest-first creation/first-sequence order; label it 'basic task list — creation order', not the final current-task aggregate. Register page traversal using viewport scroll reaching the displayed next/previous boundary; page changes retain stable ID where available, and explicit traversal may move to the requested page. No synthetic Scope count or full filtering/sorting. Fields called pending_request_count are labelled 'queued requests', distinct from #92 pending interactions. The test must traverse beyond first page if needed to reach running/waiting real tasks.

Use a single owned SSE connection with abort/generation tracking; consume cursor/changes and resnapshot on reset/expired cursor. Coalesce invalidations per query key; refresh only affected queries; do not treat stream events as authoritative finished messages. Prevent responses from a superseded connection/domain overwriting current state. Reconnect backs off and preserves drafts, anchors and visible content. instance_id change within the same data domain reacquires cursors; different data_domain_id/API/mode isolates pending submission and drafts rather than replaying/cleaning against another store. No automatic retry based on an auth error or network failure disguised as NOT_FOUND.

## 5. Minimal local draft and pending-submit protection

Resolve Core data via SECRETARY_DATA or .demo-data relative to launch cwd, as core-cli does; distinguish CORE_MODE_MISMATCH from absent Core. Use ~/Library/Application Support/Secretary/tui/v1/<data_domain_id>/<mode>/ (API version is v1), outside the Core data root, with restrictive permissions, a versioned atomic JSON snapshot for two expanded ordinary drafts and at most one unresolved Main submission; no generic queue/server/Core draft table. Domain/API/mode identity, created_at, request_id and exact serialized message are persisted with the pending record. Reject multiple writers with a small kernel flock holder, using the repository Python/flock pattern without importing JournalOwner or its journal/worker protocol. Parent pipe closure releases the helper; helper death stops writes and sends immediately. Verify exclusion and parent/helper termination. Do not unlink/recreate the locked inode or use stale-PID deletion. This is only a lock, not a persistence service. No importing old Tauri or withdrawn TUI state.

Debounced draft snapshot (proposed 300 ms) plus flush before navigation/submit/normal exit; temporary file + atomic replacement. Clearly document that abrupt process/power loss can lose edits since last saved snapshot; normal exit/reopen and send failures cannot lose drafts. No per-keystroke fsync. Submission and receipt transitions use a durable checkpoint (file sync, rename, directory sync as supported) before network send or deleting the sole text copy. Disk errors preserve memory/raw text, block network send if pending snapshot failed, show local error, and do not silently complete exit when save failed. Preserve recovery files on corrupt/version-mismatched data and fail closed instead of resetting them.

On submit: validate raw expanded payload, schema text maximum 1,048,576 and serialized JSON total <=1,048,576 UTF-8 bytes including envelope/escaping (`api-v1.ts:183`). Durably capture exact serialized body and request_id BEFORE POST; the normal draft may then clear for editing new text. One unresolved submit is distinct from the two ordinary drafts; double Enter cannot start another transaction. Status distinguishes pending/unconfirmed, durable Core acceptance and downstream business state. Receipt.acceptance=ACCEPTED confirms handoff even if receipt.state later becomes FAILED/UNKNOWN; do not report business success. Persist handoff before cleaning only that request's text copy; never overwrite a newer ordinary draft.

On timeout/disconnect/startup retain original body/ID, do not automatically replay. Display pending text and ID in a read-only local recovery item, explicitly labelled not part of authoritative Main history. If Main is empty on recovery, restore its original payload to the editor; if newer text exists, keep both separate. Explicit ordinary Main submit retries ONLY when its parsed payload exactly matches the pending payload and a visible hint says it will retry that request ID. Different text is preserved and locally blocked; it cannot implicitly send the old request. User may use existing text selection/copy to restore the displayed original; no new hidden command mode. Reverify same domain/API/mode, then POST the exact persisted serialized body/ID idempotently, rather than relying on CoreClient's lost HTTP status for an 'authoritative 404' gate. GET requests/{id} is read-only status reconciliation: a verified accepted receipt can settle handoff without replay; an error alone never authorizes deletion/new ID. Preserve exact-body transport for replay in a narrow CoreClient method if required, retaining loopback/auth validation. 409 REQUEST_CONFLICT fails closed: keep record, show actual conflict, never mint a replacement ID.

A definitive pre-acceptance validation rejection is separate from an accepted request whose business state failed. With no newer draft, restore rejected text for correction; with newer text, never overwrite/merge. Save rejected text to a uniquely named owned recoverable JSON file, display its path and copyable original in the local recovery item, then release the resolved pending slot only after that save succeeds. It remains protected while the recovery item is referenced, then follows the three-year orphan rule. Newer ordinary draft can subsequently send; recovery is not a third ordinary editable draft or generic queue. Corrected text is a fresh explicit request. A duplicate conflict is NOT a validation rejection and does not release the slot. Tests cover both rejection races and changed-draft retry refusal.

Clean only owned obsolete/handed-off copies, not Core history, user files or task directories. Other orphan/temporary records default to three calendar years from created_at; leap-day anniversary clamps to February 28 in a non-leap year; active drafts and unresolved requests are protected regardless of age. No new storage quota in #82: working state is structurally limited to two ordinary drafts and one unresolved submission; recovery/orphan records follow the stated retention policy. Do not claim total disk usage is bounded under three-year retention. Genuine disk errors preserve existing material and block unsafe transitions. Basic plain multiline paste still must preserve real text and not auto-submit; custom folded-block presentation is #91, images #94. No claim that unimplemented paste-block provenance has passed.
