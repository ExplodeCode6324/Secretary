## 3. Interaction contract

Full-screen body switches Main/Task; only bottom editor and optional short hint/error line persist. Each screen may have its own title. No permanent top bar, sidebar or responsive two-column mode. Small-window handling reserves a usable editor and tells the user if the terminal is too small; widening/heightening increases capacity only. Start Main at newest recent message. Main/Task round trips preserve stable message/task ID and text offset; duplicate navigation and root /back cause no reset, hint or history mutation. Do not auto-follow arrivals after initial positioning. Rendering updates must not overwrite editor content/cursor.

One command registry serves parsing, scope, completion and help. Names are case-insensitive; parameters retain original case/bytes. Only original character zero '/' starts parsing. Unknown slash commands and invalid arguments produce local errors and preserve input. Navigation commands accept no non-whitespace arguments (trailing spaces/tabs from completion are allowed), no extra lines, chaining or shell evaluation. Text after `/send` and `/rawmessage` is a literal payload, never recursively parsed. Define delimiter as the first one ASCII space separating command and payload; preserve everything after that delimiter, including additional spaces/newlines. Empty or whitespace-only payload is rejected without discarding input. `/send` with no payload cannot send an invisible saved draft: reject empty input in this text-only batch. `/rawmessage` is Main-only and affects this submission only.

Implemented commands: global /M, /T, /back, /help; Main-only /send and /rawmessage. Task /send or /rawmessage reports scope error with no POST. Ordinary Task submit keeps its text and does not route anywhere. `/T` appended to a draft is text; navigating requires replacing/clearing it to a standalone command, with no hidden command buffer or navigation shortcut. Two ordinary drafts only, no Task-ID drafts. Help truthfully lists later commands as unavailable; completion offers only implemented in-scope entries. There is no object-taking command in #82, so no fabricated object completion; future object candidates remain with their consumer batch. Completion must never submit.

Proposed keys: Enter submit (an open completion menu consumes it without submit), Shift+Enter/Ctrl+J newline where supported, application-owned backslash+Enter fallback, Tab completion, viewport PageUp/PageDown and wheel scrolling, Ctrl+C graceful client exit even with a selection. Keep Pi copy-on-select; it is separate from Ctrl+C. Disable AltScreen search and previous/next prompt-jump defaults in this batch; Home/End remain editor line-start/end, not viewport navigation. Do not call addToHistory. Verify actual parent-vs-editor key precedence in preflight. Record exact effective bindings after native preflight; do not add new navigation keys. Errors clear on the next ordinary edit or submitted command, before presenting any fresh error; async render ticks do not clear them. UI activity never creates a message or audit entry.

Main theme: model white; Master light blue with upper/lower separators; tool entries fixed light pink and separate lines; available thinking_preview light gray, no generated fallback. Reuse Core's bounded/redacted <=20-grapheme preview with its existing ellipsis, without truncating it again or deriving hidden reasoning. Single renderer for streaming and final/history content. Fixed Markdown sample covers paragraphs, headings, emphasis, lists, quotes, inline code and fenced code; separately document links/tables actually supported, make no math/Mermaid/HTML claim. Treat remote text/control sequences as untrusted display data; reuse safe component rendering and test escape/control sequences cannot operate the terminal or become input commands.

## 5. Minimal local draft and pending-submit protection

Before Core attach succeeds, keep the editor disabled with a clear attach/mode error; no text appears durably saved under an unknown domain. Resolve Core data via SECRETARY_DATA or .demo-data relative to launch cwd, as core-cli does; distinguish CORE_MODE_MISMATCH from absent Core. Use ~/Library/Application Support/Secretary/tui/v1/<data_domain_id>/<mode>/ (API version is v1), outside the Core data root, with restrictive permissions, a versioned atomic JSON snapshot for two expanded ordinary drafts and at most one unresolved Main submission; no generic queue/server/Core draft table. Domain/API/mode identity, created_at, request_id, originating Core instance_id, last-attempt instance_id/time, original raw editor input and exact serialized message are persisted with the pending record. Reject multiple writers with a small kernel flock holder, using the repository Python/flock pattern without importing JournalOwner or its journal/worker protocol. Parent pipe closure releases the helper; helper death stops writes and sends immediately. Verify exclusion and parent/helper termination. Do not unlink/recreate the locked inode or use stale-PID deletion. This is only a lock, not a persistence service. No importing old Tauri or withdrawn TUI state.

Debounced draft snapshot (proposed 300 ms) plus flush before navigation/submit/normal exit; temporary file + atomic replacement. Clearly document that abrupt process/power loss can lose edits since last saved snapshot; normal exit/reopen and send failures cannot lose drafts. No per-keystroke fsync. Submission and receipt transitions use a durable checkpoint (file sync, rename, directory sync as supported) before network send or deleting the sole text copy. Disk errors preserve memory/raw text, block network send if pending snapshot failed, show local error, and do not silently complete exit when save failed. Preserve recovery files on corrupt/version-mismatched data and fail closed instead of resetting them.

On submit: validate raw expanded payload, schema text maximum 1,048,576 and serialized JSON total <=1,048,576 UTF-8 bytes including envelope/escaping (`api-v1.ts:183`). Durably capture exact serialized body and request_id BEFORE POST; the normal draft may then clear for editing new text. One unresolved submit is distinct from the two ordinary drafts; double Enter cannot start another transaction. Status distinguishes pending/unconfirmed, durable Core acceptance and downstream business state. Receipt.acceptance=ACCEPTED confirms handoff even if receipt.state later becomes FAILED/UNKNOWN; do not report business success. Persist handoff before cleaning only that request's text copy; never overwrite a newer ordinary draft.

On timeout/disconnect/startup retain original body/ID AND original raw editor input (e.g. `/rawmessage /T`, not its `/T` payload). Automatically perform read-only GET requests/{id} on startup, reconnect and before a blocked send, after verifying domain/API/mode. Reconcile BEFORE restoring any editor copy. No automatic POST replay. Accepted receipt settles handoff. Proven non-delivery releases the slot through the shared rejection recovery path. Proof is a same-domain NOT_FOUND from a later Core instance than EVERY persisted attempt, with the previous connection aborted and no POST issued to the new instance; Core's single-owner Store and instance replacement eliminate the prior in-flight request. In the same instance, NOT_FOUND alone, elapsed time, a failed fetch or abort do NOT prove non-delivery: retain UNKNOWN and explain that acceptance is unresolved. A 15-second server requestTimeout plus an arbitrary margin is not a cancellation barrier (timeout checking/scheduling and already-received work matter). Do not force restart Core from TUI. Explicitly retrying the same immutable request remains available while unknown; if the user no longer wants it sent, do not replay and report that an already-in-flight request cannot safely be declared cancelled. A later same-domain Core restart or authoritative accepted/rejected outcome allows resolution. This conservative limit is explicit for Master; no unproved cancellation promise.

Only after reconciliation, if Main is empty and fate is unknown or proven not delivered, restore ORIGINAL RAW INPUT and persist an editor binding {request_id, raw_input, draft_generation}; otherwise keep newer text untouched and display recovery metadata. The recovery item is a truncated preview/ID/path in the allowed bottom hint area, never a message/history entry or new panel. Full content is available through restoration or the owned recovery file. When acceptance is discovered later, atomically settle pending state AND clear only the unmodified bound editor copy, then publish UI changes. Edited text loses the unmodified binding and is preserved; a known accepted record cannot leave its unmodified restored copy available as a fresh send after restart/crash. Receipt settlement and restored-copy disposition share the same state snapshot. A blocked Enter triggers reconciliation but never falls through to create a new request if the bound copy has just been accepted/cleared. Require a subsequent explicit submit for any remaining new draft.

Explicit ordinary Main submit retries only when the parsed payload matches the unresolved payload and the visible hint identifies the original request ID. Different text is preserved and blocked only while the fate is unresolved; it cannot implicitly send the old request. After proven non-delivery/definitive rejection, the raw input is editable/discardable normally; unchanged recovered text can reuse its old ID, edited text is a new intentional request. Revalidate same domain/API/mode for every send. Existing CoreClient.command() can replay the parsed persisted body: Core fingerprints canonical {owner,path,body}, so equivalent JSON serialization preserves identity and needs no special transport method. Never reconstruct the request from an edited draft. 409 REQUEST_CONFLICT fails closed, preserves evidence, never mints an ID or treats the request as never delivered. Authentication/5xx/transport failures stay unresolved and trigger reattach/status handling, not draft deletion.

Only a genuine response for this attempt with the exact codes INVALID_REQUEST (schema), INVALID_INPUT, INVALID_JSON or REQUEST_TOO_LARGE qualifies as definitive pre-acceptance rejection; exclude 401/403, 409, 503 CORE_STOPPING/BUSY, 500 and transport errors. Use the verified fixed API code mapping, or preserve status in a small typed API error if implementation needs disambiguation; no broad INVALID substring heuristic. A definitive pre-acceptance validation rejection is separate from an accepted request whose business state failed. With no newer draft, restore rejected text for correction; with newer text, never overwrite/merge. Save rejected text to a uniquely named owned recoverable JSON file, display its path and copyable original in the local recovery item, then release the resolved pending slot only after that save succeeds. It remains protected while the recovery item is referenced, then follows the three-year orphan rule. Newer ordinary draft can subsequently send; recovery is not a third ordinary editable draft or generic queue. Corrected text is a fresh explicit request. A duplicate conflict is NOT a validation rejection and does not release the slot. Tests cover both rejection races and changed-draft retry refusal.

Clean only owned obsolete/handed-off copies, not Core history, user files or task directories. Other orphan/temporary records default to three calendar years from created_at; leap-day anniversary clamps to February 28 in a non-leap year; active drafts and unresolved requests are protected regardless of age. No new storage quota in #82: working state is structurally limited to two ordinary drafts and one unresolved submission; recovery/orphan records follow the stated retention policy. Do not claim total disk usage is bounded under three-year retention. Genuine disk errors preserve existing material and block unsafe transitions. Basic plain multiline paste still must preserve real text and not auto-submit; custom folded-block presentation is #91, images #94. No claim that unimplemented paste-block provenance has passed.
