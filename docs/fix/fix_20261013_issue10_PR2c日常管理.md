## 可靠性和资源约束

- 所有写操作持久化原请求及参数后才能显示入队；HTTP 202/receipt 受理不能当业务完成。请求丢失、重启或超时用同一 ID 对账；版本冲突让用户处理，不静默覆盖或自动批准。
- 页面异步查询绑定 owner/domain/session、连接代次和查询代次，切页/切域/改筛选后迟到响应不可覆盖当前页。聚合失效不能被根 revision 相同抑制。
- 只缓存最近必要详情；投影/正文磁盘 256 MiB、产物 1 GiB，遵循总计划。不能淘汰草稿、未确认命令或已展示记录；磁盘不足保留编辑并明确失败。产物不整体读入 JSON 内存；分页内容继续沿用有界策略。
- 通知的 presented/read 继续遵守实际展示/明确阅读证据。新增跨页入口不等于通知已读，后台刷新不提交 viewed/read。
- 承诺/任务/World 的来源只能用公开 ID，缺失明确显示不可用，不猜 activity 与 event 映射。
