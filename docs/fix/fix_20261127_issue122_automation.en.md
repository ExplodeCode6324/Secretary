## Scope and baseline

Build in secretary-benchmark from merge 09f4795cd8b8bb1d1d453a7052b4a0c43efa6308 (tree identical to reviewed PR #2 at 46eb58f). Core owns this plan. Ship the example, supported CLI, pinned Secretary dependency, judge worker, scoring materials, replay tools and operator instructions in the benchmark repository. Keep the legacy commands and exports readable. The new tool-validation cohort has its own identity. R79 C12b has a complete witness. Master accepted the C16 shortfall for that batch only (2/3 adjudicable, first repeat unresolved, five untested assertions). Those results retain their original interpretation.

## Operator contract

After recursive checkout, install pinned dependencies and the documented Node 22.19+, Python 3, PostgreSQL 18 server tools and supported Hermes reader release. The README must give reproducible acquisition and version checks for the reader and any isolation backend. Provide a synthetic public example that runs without local source patches, private historical receipts or personalized Hermes profiles. Copy the example, supply workload and judge credential references through local protected settings, and choose an approved live profile. The proposed happy path is `npm run benchmark -- evaluate --config examples/secretary-smoke.json`. It prints a run ID, status, and the path to `.local/benchmark/<run-id>/reports/report.md` and its JSON companion. The example names the public suite/version, C04-nonexistent, repeat 1, target, workload and judge profiles, rubric and limits. Preflight validates all pins, capabilities, credentials, isolation, prices/limits and output ownership before external dispatch. Print a human-readable remedy on failure. Report a measured poor answer as a completed measurement; incomplete execution/grading or invalid configuration has a distinct nonzero exit status.

Use the existing npm command family for selecting scenarios via config, regrade, report, baseline import and owned archive/cleanup. A CLI help example for each uses the run ID, without internal slot or batch identifiers. A live invocation resolves its approved freeze and ceilings once, so ordinary operation has no manual checkpoint between phases. Model/provider and reasoning profiles vary by run. Freeze actual served identity when available; identity mismatches invalidate grading/comparability under a strict profile. A missing serving version stays explicit. Do not replace it with an alias.
