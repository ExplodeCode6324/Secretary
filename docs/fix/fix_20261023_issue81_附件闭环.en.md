## 3. Proposed public contract

All routes retain the existing authenticated loopback local-owner/data-domain boundary and `/api/v1` prefix. Source paths never go through a shell. Remote callers and task-only clients do not gain a new supported owner credential path.

| Operation | Contract |
| --- | --- |
| POST `/attachments/import` | JSON `{request_id, source_path, expected_sha256, expected_bytes, name}`. UUID request; absolute path (max 4096 characters, no NUL); lowercase 64-hex digest; positive decimal-string byte count; display-only basename (1–255 characters, no separators/control characters). Return existing 202 Receipt, resource ID `AttachmentImport`. |
| GET `/attachments/{id}` | Ready attachment's minimal metadata: attachment_id, import_request_id, name, media_type, decimal-string bytes, sha256, integer width/height, created_at, availability (`available` or `unavailable`). No path/base64. Unknown ID 404. |
| GET `/attachments/{id}/content` | Authenticated immutable original bytes, checked length/hash before headers. `application/octet-stream`, attachment filename*, Content-Length, strong digest ETag, `nosniff`, no-store; no path exposure or inline execution. Missing/corrupt content 410 `ATTACHMENT_UNAVAILABLE`. No range support in v1. |
| Existing GET `/requests/{id}` | Authoritative import progress/result and stable attachment ID after COMPLETED; FAILED supplies a stable code. QUEUED/RUNNING/UNKNOWN never authorizes source deletion. |
| Existing POST `/messages` | Preserve required `text`, allow `""` only with 1–4 valid ordered `attachment_ids`; optional list, empty list equivalent to no attachments for internal text hash only. Reject duplicate IDs. Nonempty text keeps current size rules; both blank text and no attachments fail. Text is emitted first if present, then images in declared order. |

Import request_id and message request_id MUST differ (same global request namespace). Changing any submitted field, including source_path/name/digest/length/order, with the same ID conflicts. Public fingerprint continues to use the original complete body, so omitted vs explicit empty lists can still conflict on public retries; clients freeze exact JSON semantics. Different import IDs for identical bytes create distinct attachment identities and may share CAS bytes. Reusing one ready attachment across different messages is allowed; bindings live on each Input, not a mutable single-message pointer.

A 202 receipt means accepted import work, not transferred content. The client may delete its owned source temporary file only after GET requests reports COMPLETED and returns the ready attachment identity/metadata. Source files are never deleted by Core. After this point source deletion/changes do not affect import retries, sending, history or restart. Before this point the client preserves its snapshot. A crash before a copy completes can return explicit source missing/changed failure, never silently read different bytes.

Proposed errors include INVALID_REQUEST/REQUEST_CONFLICT, ATTACHMENT_SOURCE_UNREADABLE, ATTACHMENT_SOURCE_CHANGED, ATTACHMENT_TYPE_UNSUPPORTED, ATTACHMENT_INVALID_IMAGE, ATTACHMENT_TOO_LARGE, ATTACHMENT_CAPACITY_FULL, ATTACHMENT_NOT_READY/UNAVAILABLE, ATTACHMENT_MODEL_UNSUPPORTED and CAPACITY_BLOCKED. Schema/auth/id-conflict errors occur before admission. Async validation failures become durable FAILED import receipts. Message admission failures produce no Input and no accepted message receipt. HTTP mapping and retryability are documented/tested; unknown IO outcomes preserve pending/unknown identity rather than promise no effect.

## 4. Storage, validation, capacity and crash ordering

First formats: static PNG and JPEG only, determined from bytes and fully decoded; filename/extension/client MIME is not authority. Add pinned `sharp` dependency and lockfile for validation, with `limitInputPixels`, fail-on-invalid/truncated decode, single-frame requirement and no output rewrite. Reject APNG, GIF/WebP/AVIF/HEIC, SVG, PDF and other formats explicitly in v1. Original accepted bytes remain immutable; no silent conversion/resize. Validate sharp's actual PNG/JPEG behavior in the implementation; animated PNG detection must not depend only on first-frame decoding.

Limits proposed for coordinator approval: 5 MiB per file, 4096 per side and 4,194,304 pixels, 4 attachments / 10 MiB original bytes per message; 1 GiB logical import reservation budget and 10,000 import identities per Core data domain. Same-content new identities are charged separately (conservative accounting; physical CAS can dedupe). One bounded import worker at a time. Limits are named validated Core configuration with these defaults and exposed in capability metadata. They are import ceilings, not a promise that every imported image fits the model context.

Filesystem read: open absolute source using descriptor APIs with O_NOFOLLOW and nonblocking where supported; fstat regular-file check before bounded reads; reject directories, final symlinks, device/FIFO/socket, unreadable/zero files and bytes beyond max. Reject symlink path components or resolve and freeze an explicitly documented canonical parent before open; descriptor identity and expected digest/length are final authority against replacement. Compare fstat identity/size/time before/after; reject a mutation observed during reading. Hash exactly the bounded buffer to be copied. This addresses Chinese/spaces/metacharacters literally, without invoking shell. Source path is private command data, omitted from ordinary metadata/errors/log text.

New records: `AttachmentImport` (immutable request identity, expected digest/length, reserved bytes, state PENDING/READY/FAILED, stable allocated attachment ID, sanitized failure code); immutable `Attachment` (owner/data-domain association through the Store, import request, name, verified format/dimensions, ObjectRef). New Input optional ordered immutable attachment snapshots contain IDs and verified immutable refs/metadata, plus versioned full-content digest. Server resolves refs; clients cannot submit CAS paths or forged metadata. Extend schema unions, record/state handling, Store replay identity/ref validation and generated internal types, without rewriting old records.

Crash-safe sequence:

1. Validate schema/global ID namespace and capacity, allocate stable IDs, then atomically journal `AttachmentImport(PENDING)` reservation + ApiCommand(QUEUED). Admission is synchronous; never hold `withAdmission` across await. This reserves quota before any attachment bytes are written.
2. The attachment-specific worker reads/validates bounded bytes (or verified previously written CAS with expected digest), fully decodes within pixel/memory limits, puts original bytes in existing CAS and fsyncs. At most one file-sized in-memory buffer plus bounded decoder output; no general object scan.
3. One journal frame commits immutable Attachment + Import READY + ApiCommand COMPLETED/result/resource IDs. Only this is successful content handoff. A crash after CAS write but before frame commit is recovered from the reserved expected CAS identity, validated again, using the same allocated ID. A crash before CAS exists can re-read only matching source bytes; mismatch fails.
4. Startup routes only attachment imports through this deterministic reconciler BEFORE the generic interrupted-command handling. No generic UNKNOWN replay policy change. If CAS integrity is uncertain, retain reservation and report unavailable/unknown; never claim READY or clean a potentially referenced CAS object.
5. A definite validation/source failure before any CAS write atomically records FAILED and releases its byte reservation (identity still retained/count-limited). Once CAS may exist, retain the reservation even on failure; v1 has no automatic reclamation. Disk full/fsync/journal failure must not produce a successful receipt. Quota and temporary peak overhead are documented separately from a whole-store disk quota.

READY and unbound content/reservations are retained on restart, no age expiry. Capacity checks include pending reservations; replay rebuilds accounting from durable records. Full capacity rejects new imports without deletion. Changes in configured quota below current usage block new reservations but preserve existing content. Per-message caps and model checks still apply after import.

Message admission resolves all ready attachments and verifies all bytes before any mutation, verifies model capability and standalone input budget, constructs ordered immutable Input binding, then atomically commits Input + input.accepted + internal receipt + ApiCommand through existing admission. Existing accepted message retries return original receipt even if source vanished or configured model changed; never rebind. Concurrent same-ID submissions cannot double-import or double-admit.

## 5. Identity, context, provider and recovery

For no attachments, keep exact current `{text,producer}` internal request digest, Input payload, v1 secretary_input tag and legacy message identity behavior. For attachments, a versioned canonical descriptor hashes text payload digest plus ordered `{attachment_id,sha256,bytes,media_type}`; immutable snapshots carry dimensions/name separately. Changing/reordering/removing an image changes content identity. Store revisions must forbid changing bindings or the content digest. v2 secretary_input authentication verifies session/input/timestamp, full ordered content, decoded image hashes/MIME and descriptor equality; never accept a matching text hash alone. Untagged legacy matching is limited to genuinely text-only messages/Inputs.

`inputMessage` constructs real Pi user content arrays (optional text plus ordered `{type:"image",data:<base64>,mimeType}`) from verified CAS. Persist full actual multimodal messages through existing `putMessages`, Context, checkpoints and model.context/model.request journal references; no source-path dependency. Keeping base64 in internal immutable message CAS is accepted v1 storage overhead, not public-list payload. Canonical content checks must cover `recordInputMessages`, context legacy migration, input projection coverage, working-memory source identity, settings/history anchors and hash comparisons. Do not change #80 assistant display identity exclusions.

Keep their exact multimodal user messages through projection and settings rebuild; exclude them from text-only historical anchors and restore from validated Input references within frozen source boundaries. Text-only historical coverage and timer/feedback origin rules remain unchanged.

If the deployment changes after acceptance, preserve the accepted input and block with an explicit reason, not text fallback. Fixture models used to test images opt in explicitly; do not mutate the default text-only fixture.

It is a deliberately restrictive guard, not provider-exact vision accounting or #71 implementation. Enforce raw message/payload byte limits as well as model input/output/context reserves. The image surcharge must be added once on each independently evaluated representation, not twice in one representation, and remain after adapter conversion. Final payload validation checks complete ordered image count/MIME/digests and model/output caps after hooks; if a hook drops/replaces an image, reject before HTTP. Never silently filter unsupported blocks. Large/compressed high-resolution images can import but fail send with CAPACITY_BLOCKED; document this practical limit. If review finds this estimate unsuitable, tighten supported dimensions or policy explicitly rather than invent provider capability.

Use the installed Pi conversion through actual `roleModel`/streamSimple and a loopback mock provider that captures final HTTP JSON for both adapters, with valid synthetic streamed responses. No upstream submodule edits are planned; only if an unavoidable defect is demonstrated return it for scope review. Credentials stay in existing closures, never review logs.

Recovery tests interrupt imports, message admission, checkpoint before input-event repair, and before/after provider-request persistence. Resume with frozen CAS/bindings, retain existing model-call uncertainty/retry policy, never promise exactly-once external provider execution. Missing/corrupt CAS blocks whole input; no text-only fallback. After source deletion, ready import/retry/content/history and replay must work.
