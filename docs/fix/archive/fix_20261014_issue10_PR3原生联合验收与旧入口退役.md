## 3. PR2c 四条建议的处置

| 建议 | PR3 方案 | 验收 |
| --- | --- | --- |
| N1 下载超时 | 下载使用独立 ephemeral URLSession；只设置 30 秒无数据等待，资源时限沿用系统默认，不继承普通请求的 60 秒覆盖，不新增产品总时限参数。普通 JSON/SSE 配置保持各自用途。保留认证、禁止重定向、取消和 1 GiB 上限；远程总时限策略留 #13 | 用可缩短的测试停顿阈值覆盖持续有数据与真正停顿，并核对实际下载 session 未继承 60 秒资源时限；不再把超过 60 秒的限速实验列为必需。用户取消、切域/版本变化、超长内容均停止且半文件不可打开。接近 1 GiB 的一次实测及内存/临时磁盘峰值归 PR3c，不阻塞退役 |
| N2 重复哈希 | 定案：新下载的完整 SHA-256 只留在 ArtifactCache 接纳边界；缓存命中仍校验。HTTPTransport 保留流式计数上限、HTTP 状态、Content-Length/ETag、最终 fstat 长度、文件类型/权限和取消检查，移除整文件哈希读取。CoreTransport.download 只产出待校验临时文件，不能直接供系统打开。缓存分块哈希期间及原子接纳前检查取消 | 错误 hash/长度/ETag、篡改缓存、链接替换、下载中断和校验中取消都不能成为可打开文件；包括不校验 hash 的 mock。新下载只做一遍整文件 hash，完成网络接收不等于“可打开” |
| N3 并发提示 | 保持单下载，不增加队列。区分“已有下载进行中”和服务不可用，相关按钮/提示反映真实状态 | 第二次请求不覆盖首个进度/结果；完成、失败或取消后可重新下载 |
| N4 拒绝合同 | 在 API v1 手册说明命令 POST 受理前拒绝、持久受理后的失败回执，以及 GET 查询错误的区别。REQUEST_CONFLICT 表示本次参数未被接受，不能推导同 ID 从未存在。对照实际 admission 边界补 Core 与 Swift 合同测试；若边界不符则先修复并复核，不仅补注释 | 覆盖未受理的错误、已受理后领域失败、响应丢失后重查、同 ID 同参重投及改参冲突；已受理命令不得降为未受理或换 ID 重做，坏命令不阻塞独立后续命令 |

N1–N4 纳入 PR3a。所有下载实验均使用本机受控服务，不开放远程 Core，不开展 #13 网络接入。N3 同时处理当前 ManagementModel.download 会先取消旧任务再新建任务的重复点击行为：下载中禁用重复提交，缓存层保留 busy 错误兜底；主动取消或域/版本失效仍能停止原任务，不新增下载队列。

### 超时语义与 N2 调用者核查

Apple 文档说明，[timeoutIntervalForRequest](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/timeoutintervalforrequest) 在收到新数据时重置；[timeoutIntervalForResource](https://developer.apple.com/documentation/foundation/urlsessionconfiguration/timeoutintervalforresource) 是整个资源的时限，默认 7 天。因此这里是“保留系统默认资源上限”，并非无限超时。缩短停顿阈值只能证明停顿行为，不能单独证明移除了 60 秒资源限制；这两点分别验证。

在计划基线对 `src/`、`test_case/` 的 Swift 文件搜索 `.download(`、`func download(`，并追踪 cache.fetch，结果如下（行号对应 `89710d2`）：

| 调用者/实现 | 调用路径与结论 |
| --- | --- |
| `Secretary/ArtifactViews.swift:35`、`ManagementModel.swift:497` | UI → model → engine.download；只有 engine 返回已接纳 URL 后设置可打开文件 |
| `SecretaryKit/ClientEngine.swift:358` | 唯一生产 cache.fetch 调用；返回前还检查连接代次 |
| `SecretaryKit/ArtifactCache.swift:54` | 唯一直接调用 transport.download 的位置；随后 validate 临时文件并原子移入正式缓存 |
| `SecretaryProbe/ManagementProbe.swift:263,268` | 两处探针均经 engine.download → cache.fetch，没有绕过缓存 |
| `SecretaryKitTests/ManagementTests.swift:154,159,162,168,178` | 五处直接调用 cache.fetch；BinaryTransport（:124）只写字节、不做 hash，已有损坏内容案例由缓存拒绝，去掉传输层 hash 不削弱该契约 |
| `SecretaryKit/Transport.swift:38,45,117,126` | 协议声明、默认 unavailable 实现、HTTP 实现，以及系统 session.download；未发现其他直接调用者 |

以上路径均在 `src/secretary_macos/` 下：SecretaryKit/SecretaryProbe 位于 `Packages/SecretaryKit/Sources/`，SecretaryKitTests 位于 `Packages/SecretaryKit/Tests/`。当前 Transport.swift 是先等待系统 download 完成，再以 64 KiB 分块读取临时文件计算 hash；审查报告“边下边算”的描述不准确，但两层重复整文件校验的结论成立。
