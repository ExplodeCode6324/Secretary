Scope: N1-N4 only. No legacy retirement, Issue closure, merge or deployment.

Changes:
- A separate ephemeral download session waits up to 30 seconds for new data;
  its resource timeout is the platform default, independent of JSON/SSE's 60 seconds.
  Real loopback tests separately inspect the actual session configuration and prove
  a transfer lasting longer than a shortened idle timeout succeeds while data arrives.
- Transport retains authenticated HTTP, redirect rejection, delegate byte limits,
  Content-Length/ETag, regular-file/fstat length, private permissions and cancellation.
  It moves the downloaded file instead of reading/hashing its content.
- Cache admission is the single whole-file SHA-256 pass (64 KiB chunks); cache hits
  still validate. Chunk and pre-admission cancellation checks reject cancelled work.
  Whole-file content reads in application code: new download 1 (previously 2), valid
  cache hit 1. This is a source/call-path audit, not a filesystem I/O trace. Foundation
  moveItem can copy across volumes; no claim of universally zero-copy filesystem I/O.
- UI and model both reject duplicate download submission without cancelling the first.
  Cache busy is a distinct error, tested independently of the UI. Cancel/complete/fail
  release the controls; late progress from an older download cannot affect a new one.
- API documentation and HTTP/Swift tests distinguish command pre-admission rejection,
  a conflicting intent sharing an admitted ID, accepted partial effects, queued UNKNOWN,
  lost-response reconciliation and exact-byte retries. Core domain behavior is unchanged.
