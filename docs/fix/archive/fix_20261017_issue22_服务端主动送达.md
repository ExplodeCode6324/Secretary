## 设计

- 新增 PushTarget 和 PushDispatch 权威记录，沿用 journal/CAS、revision、生成 schema/type。目标最多 20 个。每个启用周期记录 notification sequence 水位，新增/重新启用仅接收该水位之后的新通知；旧周期待发项取消，避免恢复启用后倾倒历史。
- PushTarget 保存类型 BARK/NTFY/MACOS_NOTIFICATION、名称、无凭据端点、enabled、启用水位和免打扰配置。配置使用 owner API 与 request_id 幂等受理；修改绑定 expected_revision。凭据独立保存在 data_root/push-secrets/<target UUID>.json（0600，目录 0700）或固定命名环境变量，API 不接受也不返回凭据。Bark key 和 ntfy topic/token 均放私密配置，不允许把 key 写入公共 URL 路径。端点为 HTTP(S) origin，拒绝 userinfo/query/fragment/path；允许自建服务，说明第三方正文中转与明文 HTTP 风险。
- PushDispatch 每个通知/启用周期/目标唯一，保存状态 PENDING/SENDING/DISPATCHED/FAILED/CANCELLED、attempts、next_attempt_at、dispatched_at 和固定错误码。只有提供方成功受理才记录 dispatched_at，绝不写 presented/read。
- 用 Store projectionFrames 增量扫描 Notification 创建记录并补建 dispatch，启动重建索引后扫描漏项；确定性 ID 防重。通知已提交、dispatch 尚未建立时 SIGKILL，重启仍补建。新启用目标以持久 sequence 排除历史通知。
- 推送 worker 独立于 Host drain，App.pump 启动、close 等待并取消网络请求；同一实例只允许一次 tick，按目标分批，每次最多一个请求。先持久化 SENDING 与 attempts，再 await 外部请求。重启对 SENDING 按至少一次语义重试；最大首次加三次重试，退避 30 秒、2 分钟、10 分钟。最终失败可查询。请求超时 10 秒，禁用重定向，响应正文不进入日志。失败记录固定错误码，不保留原始异常/URL/响应。
- 免打扰按目标配置 IANA 时区和 HH:mm 起止（支持跨午夜，不允许相等）；期间延后，结束后将待发通知合并为一次摘要。每目标滚动一分钟最多三次发送（失败也计入），发送前持久化计数，重启保留。限流积压在下个可用槽合并发送。摘要总正文最多约 200 个 Unicode 字符加“在客户端查看”；单条同样截断，禁止完整产物。
- 目标禁用/修改发生在请求中时，已经发出的外部请求无法撤回；完成回写必须读取最新 dispatch，避免覆盖取消状态。目标配置修改取消旧待发并开启新水位，语义在 API 文档明确。每轮发送捕获目标版本和配置。
- ntfy 使用 JSON publish，topic/token 私密读取；Bark 使用 JSON POST /push，device_key 私密读取；macOS 使用固定 osascript 程序、正文通过 argv 传入，避免插值执行，其他系统固定 UNSUPPORTED_PLATFORM。命令正常退出只算系统接口已受理。

## API 与合同

GET push-targets、push-targets/{id}、push-dispatches、push-dispatches/{id}；列表复用分页，dispatch 可按 target_id/state 查询。POST push-targets 创建，POST push-targets/{id} 更新，带 request_id/expected_revision，配置禁用也走更新。公开 DTO 显式投影，不含凭据、文件路径。同步资源加入 push-targets/push-dispatches。新公共 schema、生成 DTO、API 使用说明与领域文档同步更新；不增加模型工具，不改 MasterInteract 决策语义。

## R1 revisions (supersede conflicting design bullets above)

R1: CHANGES_REQUIRED. All B1-B4 and N1-N5 accepted.

- B1: Only creation, re-enable, kind or endpoint changes start a new generation. The cutoff is the target transaction sequence (store.sequence + 1); eligible notification firstSequence must be strictly greater. Name/DND/timezone edits preserve pending deliveries. Disable cancels PENDING only.
- B2: SENDING represents an irreversible request already started. Success always becomes DISPATCHED, even if disabled in flight. Failure for an obsolete generation becomes CANCELLED and is not retried. Never overwrite a newer configuration from an async callback.
- B3: Freeze batches of at most 100 dispatches before sending. Atomically save batch_id, attempts+1, SENDING, next_attempt_at and attempt_history ({id, at}, max four entries). Retry the same membership without adding new notifications. All members share one attempt_id, so rolling per-target rate counts deduplicate physical attempts across dispatches. Worker never increments target revision for rate accounting. Rebuild counters on restart. A fourth interrupted attempt becomes FAILED/INTERRUPTED; it may already have reached the provider. Success updates the whole batch in one transaction. Overflow batches use subsequent rate slots.
- B4: Secrets are written only by the local administrator: data_root/push-secrets/<target UUID>.json, or JSON in SECRETARY_PUSH_<UPPERCASE_UUID_WITH_UNDERSCORES>. Environment wins. NTFY accepts {topic, token?}; BARK accepts {device_key}. Read fresh for each request. Directory must be owned by the current uid, non-symlink, mode 0700; file must be regular, same owner, O_NOFOLLOW, mode 0600, at most 8 KiB. Missing, unsafe or malformed secrets produce only SECRET_UNAVAILABLE. Rotate files with an atomic rename of a 0600 temporary file; restart to change environment. Disable before changing secret destination to prevent sending queued content to a replacement destination. No secret write API.
- N1: Cover MasterInteract, Host notices and Scheduler notices. text/plain is truncated; JSON uses only its text string or a fixed new-notification message, never raw internal IDs/metadata.
- N2: Reuse ApplicationService.command, ApiCommand and withAdmission for configuration. Same request replay preserves cutoff/generation; mutation and admission share one transaction. GET stays read-only. Unknown secret fields are rejected by API schema.
- N3: Master explicitly deferred phone acceptance: complete Core and isolated validation first. Real phone delivery remains NOT_TESTED. PR uses Refs #22 and leaves the issue OPEN for Master.
- N4: App.settle waits only for the current runnable worker pass, not future backoff or DND windows. Targets run in parallel (max 20), with one request per target. HTTP responses bounded to 8 KiB; Bark checks code=200, ntfy checks a message acceptance response. No redirects.
- N5: Document root-origin-only endpoints (no reverse-proxy path prefix), third-party relay and plaintext HTTP implications. macOS uses fixed osascript plus argv, bounded timeout, fixed error codes.
