| 层级 | 当前行为 | 结论 |
| --- | --- | --- |
| `src/pi_secretary/src/model.ts` | 调用 `streamSimple`，指定 `transport: "sse"`、`reasoning: "low"` | 模型侧已有流式接入；是否提供可见思考内容仍取决于模型及供应商 |
| `src/pi_secretary/src/transport.ts` | `durableStream` 等待 `response.result()`，保存完整响应后才把流交给 Agent | 实时增量未到达界面；同时承担执行工具前保存响应的重要约束 |
| `src/pi_secretary/src/host.ts` | 主会话仅在 `message_end` 保存 `main.message` | 没有主会话增量展示通道 |
| `src/pi_secretary/src/backend.ts` | `conversation()` 只提取 `text`；`/api/state` 使用 Store sequence 判断变化 | 思考内容未投影到 UI；纯内存增量也无法触发当前状态刷新 |
| `src/pi_secretary/web/app.js` | 每 700ms 拉取状态；按消息 ID 判断是否重建正文 | 只展示完成消息；同一消息新增文字不会按当前签名更新 |
| `src/pi_secretary/src/tui.ts` | 展示序列化过滤 thinking 和签名字段 | TUI 也没有可见思考展示；本次小字体需求的实施范围为 WebUI，保留 TUI 兼容性 |

页面已有“思考中”状态指示，不等于显示模型返回的思考内容。当前缺少两项显示开关。

## 2. 拟定交互与范围

在 WebUI 增加“显示设置”：

- **流式输出**：建议默认开启。开启时正文与已启用的思考区逐段更新；关闭时当前响应完成后一次展示。
- **显示思考过程**：默认开启（Master 已确认）。独立于流式开关，开启时显示供应商实际返回的可见 thinking/reasoning 文本或摘要；不保证取得模型完整内部思考，不通过提示词强迫补写或从正文推测。
- 设置按浏览器保存，刷新后保留；即时作用于当前和后续消息展示，不修改全局模型推理强度，不触发现有“应用设置并重建上下文”流程。UI 明示这是显示偏好。
- 四种组合均支持：流式正文、流式正文及思考、完成后正文、完成后正文及思考。关闭思考立即隐藏已有思考区；重新开启恢复有记录的内容。
- 思考区放在对应 Secretary 消息正文之前，支持展开/收起；正文保留当前字号，思考正文采用 12px，复用 `--muted`、`--surface`、`--line` 等现有暗色变量。避免继承正文标题样式后出现字号反超。
- 开启思考而供应商未返回内容时，完成后显示简短的“本次未返回可显示的思考内容”；生成时区分“等待内容”与已收到内容。
- 本轮覆盖主会话面向 Master 的回复，包括一次输入中多个模型调用的回复；后台 Task Agent、记忆整理和设置重建的内部输出不混入聊天。TUI 不增加新展示功能。

## 3. 实现方案

### 3.1 实时预览与持久化约束

为 `durableStream` 增加可选、仅供展示的增量观察接口，主会话接入；不依赖被完整响应等待阻挡的 Agent 回调来实现实时显示。

由一个消费者读取供应商事件，复制事件到供 Agent 后续消费的兼容流，同时将 `text_delta`、`thinking_delta` 等可见文本事件发送给有界内存预览。不能让 UI 和 Agent 并发消费同一个队列，避免事件被分走。完整响应保存成功后才允许 Agent 获取可执行响应；持久化失败则终止，不执行工具。观察接口失败不得改变模型或工具执行结果。

预览携带 session、loop、call、内容块索引、序号及运行状态，支持多个文本/思考块和工具调用前后分段。仅投影允许展示的文本，不发送签名、加密推理载荷或原始工具参数。预览不作为上下文、授权或执行依据；不逐 token 写入 Store。

最终展示以持久化 `main.message` 为准，通过明确的调用到消息关联将临时条目替换为完成条目，避免重复。定义完成、失败、中止及保存失败清理路径；未完成文本标注“未完成”，不能伪装成成功答复。浏览器断线或关闭不取消任务，也不重新发起模型请求。后端重启后以持久化状态恢复，丢失的内存预览不冒充历史完成内容。

### 3.2 后端实时通道与恢复

增加经过现有 Bearer token、同源和 client 校验的 `/api/stream` SSE 接口。前端使用支持 Authorization header 的 `fetch` 读取 SSE，不把 token 放入 URL。

- 保留 `/api/state` 承载持久状态、任务及授权；流式展示采用独立序号，不依赖 Store sequence。
- 建连和重连先给当前预览快照，再发送后续更新；实现快照与订阅间无丢失衔接、序号去重和过期快照重置。
- 限制缓存、单消息预览大小及慢客户端积压，合并高频增量；超过上限明确标记预览截断，最终正文仍以持久结果为准。
- 断开时释放订阅；设置关闭流式输出时停止实时订阅，仍可通过状态接口在完成后获得消息。重新开启从当前快照接续。
- `conversation()` 增加可选的可见思考字段及内容块关联，保留旧正文结构的兼容性；只返回当前会话内容。思考关闭时接口不下发该字段，前端缓存随关闭清理；偏好变化使状态缓存失效，不能被 `unchanged` 短路。

### 3.3 WebUI 更新

修改 `web/index.html`、`web/app.js`、`web/style.css`，增加独立显示偏好和思考区。按消息 ID 与内容版本增量更新对应节点，避免每个 token 重建整条时间线。保持原有安全文本/Markdown 渲染，不把模型文本作为 HTML 执行。合并连续渲染，并且只有用户位于底部时才自动滚动，保护历史阅读、文本选择和思考区折叠状态。

预期涉及 `transport.ts`、`host.ts`、`backend.ts`、上述三个 Web 文件及对应测试；必要时新增局部预览状态模块。优先利用现有响应记录保存思考文本，不新增逐 token 数据契约，不修改 vendored Pi 源码。若实现发现必须调整持久化 schema 或全局设置语义，先补充计划交 Master 复核。
