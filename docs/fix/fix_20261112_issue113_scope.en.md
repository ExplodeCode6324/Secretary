## 2. Main can request Scope import

Add Main-only scope_import and read-only scope_query. First iteration supports creating a logical NONE scope or importing an existing DIRECTORY; it does not recursively discover files, create arbitrary host directories, alter an existing scope, or archive one. Owner APIs retain their existing edit/archive function.

Import parameters: name, description, kind, root_path, notes_path and default_write (DIRECTORY default ask), plus host-derived identity. Requests expire 24 hours after proposal; expiry never deletes history. Validate at admission and again at apply: absolute existing physical directory, no symlinks in ancestors, no Core-data overlap, no active/busy scope overlap, safe relative notes path, and same directory device/inode identity as shown for approval. A changed directory or conflict rejects the original request without effect; a changed proposal needs a new approval. Filesystem race limits of existing scope path enforcement must not be overstated; directory handles/stat checks should minimize TOCTOU and detect replacements before commit.

Every model-originated import creates a durable Operation/AuthorizationRequest with action scope.import and exact normalized parameters/hash. Force an individual approval: no builtin rule, remembered authorization or wildcard rule can bypass it; approval is only through the authenticated owner decision route, never a Main/Task tool. Require at least one source event from a current-loop, same-session, non-withdrawn Master statement with no attachments; verify the referenced statement and its classification using the shared provenance validator. Include those source Master events, operation ID, canonical root, write default and parameters in approval display. No scope is visible before approval. Generic feedback/timer/structured-failure loops must not autonomously open imports; preserve failure-action scope guards for all new mutations.

Use a deterministic scope ID bound to the operation and add an explicit AUTHORIZED --journal_apply--> SUCCEEDED edge. Store.stage guards this edge by an explicit internal-action allowlist (scope.import and world.change), with separate required mutation/event bundles for each; for scope.import it requires, in the SAME frame: the exact matching grant APPROVED -> CONSUMED, a revision-1 deterministic Scope with matching parameters, the successful Operation receipt/result event and a deterministic completion Input. Each record is mutated ONCE. No ordered duplicate mutations and no durable DISPATCHED gap; external-effect actions cannot use this edge. Perform final synchronous filesystem checks and commit without an intervening await. For a definite apply failure (root changed/conflict/expiry), atomically cancel the Operation with effect NOT_STARTED, revoke its still-approved grant (or expire it only when actually expired), and persist a reason/result Input; no Scope. Grant invalidation has HOST provenance. Owner rejection/revocation races serialize through revisions. A grant already consumed at successful commit cannot retroactively undo the Scope.

scope.import explicitly skips match() and rejects remember; also reject creation of any persistent rule for this action. Recovery before commit retains the original pending/approved request; after commit returns the original scope/result. Scope record provenance is recorded in audit events and operation linkage; no new WorkScope fields are required. Never fabricate a direct MASTER_UI creation. Parameter-conflicting replay fails.

Main completion uses existing Input producer ENVIRONMENT, stable ID/dedupe key scope-import-result:<operation_id>, payload with the exact terminal result and original source-event references, and HOST input.accepted audit. Success/failure completion is part of the apply frame. Owner rejection/revocation gets an idempotent reconciliation step: on every pump and at startup, a terminal import with no result Input creates exactly one; pending imports produce no repeat notices. No Task Feedback with invented task/execution IDs. This Input wakes Main for read/query/report only; it is NOT new Master authority and its isolated loop cannot import, mutate entities or propose tasks. Task delegation using the created Scope is available on the next explicit Master turn. Isolate the notice at its position in main-loop.ts batch boundary selection, preserving input order; never batch it with a new Master turn. BASE_SYSTEM explicitly says ENVIRONMENT import-result notices carry no Master authority. A HOST expiry/reconciliation step runs at startup and on every pump. For a scope.import whose expires_at has passed, atomically transition PENDING or still-unconsumed APPROVED grant to EXPIRED, cancel WAIT_AUTH or AUTHORIZED Operation with NOT_STARTED and a specific expiry reason, and write the deterministic terminal ENVIRONMENT Input in the same frame. A live rejected/revoked import gets its missing result Input on the next pump, not only after restart; recovery repairs a crash between owner decision and notice. Expired rows cannot remain invisible WAIT_AUTH work. Skip already-consumed/terminal imports and never generate a second notice. Owner decisions, expiry and apply are serialized by revisions and the synchronous final commit. Preserve an existing MASTER_UI approver in decided_by (or null when no approver); HOST invalidation is recorded in the audit event and UI reason, never falsely displayed as Master revocation. journal_apply rechecks owner_epoch and rejects STALE_OWNER. MasterAttention/TUI already supports Main-scoped approvals; verify the whole path.

Change structured failure-action tool gating from a mutation denylist to an explicit allowlist so newly added mutation tools are denied by default. Add analogous read/report-only allowlisting for import-result Inputs. scope_query stays small: paginated active scopes/exact ID plus this session's imports and their status, not filesystem discovery; it covers scopes beyond the prompt-list limit. Explain macOS symlinked /tmp and /var rejection and let the user supply a real path.
