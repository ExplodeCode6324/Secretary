## 操作者如何使用

递归检出仓库，安装锁定依赖、Node 22.19+、Python 3、PostgreSQL 18 服务端工具及支持的 Hermes 评分器版本。README 给出评分器和隔离环境的获取、版本检查方法。公共示例用可公开的合成材料，在干净检出上就能运行，无须改代码、读取历史私有回执或使用个人 Hermes 配置。从示例配置开始，用受保护的本地设置引用工作和评分凭据，选择已授权的真实模型配置。

拟议主命令为 `npm run benchmark -- evaluate --config examples/secretary-smoke.json`。示例给出公开测试包及版本、C04-nonexistent、一次重复、目标与两个模型配置、评分规则和上限。命令打印运行 ID、状态以及 `.local/benchmark/<run-id>/reports/report.md` 和对应 JSON 的位置。发送请求前核验版本、能力、凭据、隔离、价格、上限和输出目录归属。遇错提示操作者可执行的修复动作。被测系统答错时仍可完成测量；配置无效、运行或评分不完整使用可区分的非零退出码。

沿用同一 npm 入口提供按配置选案例、重评、重建报告、导入基线和归档清理。帮助中逐项给使用示例，面向操作者只暴露运行 ID。一次真实调用加载并验证本轮获准的冻结与上限，正常路径没有人工接力。工作模型、评分模型及推理档位在运行间可换；记录能核验的实际服务身份。严格配置遇身份不符拒绝评分或严格比较，无法识别的版本明确列缺口。

## 构件与数据流

| 构件 | 复用与开发位置 | 边界与持久产物 |
|---|---|---|
| 命令及配置 | 在 test_case/online/benchmark/cli.ts 旧指令专用解析前分派新命令，复用已有校验与设施归属保护。配置、案例包、目标协议、证据格式均带版本。 | 规范化清单绑定工具、SUT、适配器、测试包、案例、次数、种子、模式、工作及评分身份、prompt/rubric 摘要、资源、上限和可选参照。凭据只填引用。未知字段、未支持的组合在实发前报错。 |
| 场景驱动 | 复用 baseline-scenarios.ts、baseline-timeline.ts 和 stage-c 试验语义。只打包可共享输入，标识公开历史导入、在线闭环、受控预置。 | 宿主持有答案、盲包映射、未来事件与评分材料，按正常入口逐事件投喂。记录案例、重复号、顺序、前后观测点、来源与摘要。共用回复、实际效果和 Secretary 专用 World/检索观测分别记录。 |
| 被测系统与设施 | 封装 Secretary 正常入口、源码锁定、Domains、worker 和 PG 生命周期。复用真实请求准入、结算和试验逻辑；prepareTrial 只支持 fixture，executeTrial 会核验真实 lane。抽取实际共享部分，避免伪造历史批次参数。 | 版本化外部进程协议采用 JSON 消息，含能力声明、启动、投喂、观察、可选 reset/重启、导出和停止。请求有 ID、确认和终态。每个设施绑定运行与目标。轻量脚本目标用同一协议给出已知正反例；外部目标可独立安装其可执行文件。 |
| 编排与恢复 | 复用 campaign.ts 的预留、持有者锁和不可变尝试。准备、运行、封存轨迹、校准、评分、发布、收尾各阶段在运行锁内原子记账。 | 保留首失败、效果未决、调用与超时上限、用量、费用或未知敞口。中断后在安全时停止本次 worker/PG 并保留证据。答错正常计入结果；发送未决按同一 ID 对账。只有完整检查点且清单匹配方可状态续跑，否则记录不完整并按独立有界尝试处理。 |
| 独立评分器 | 仓库交付非交互 Hermes 评分进程入口和传输适配。复用 stage-c-visibility-rubric.ts 的构造与响应校验、盲包约定以及 grading-transaction.ts 的不可变回执；保留历史 targeted-reader CLI 及版本专用验证器。 | 固定 prompt 与 rubric 随库版本化，只渲染盲包，记录实际请求正文摘要。校准、正式各包均用新上下文，同一冻结 provider、模型及推理档位。校准阈值随协议（沿用 R79 时为 28/28）。保留原始首答、真实传输、模型、费用、核验后的引用。输出无效、校准过期、身份不符均不得采为成绩。目标与评分者分别持有凭据、存储和进程权限。 |
| 结果与重放 | 分开存储不可变原轨迹、分版评分和确定性报告。复用公共 report.ts、历史结果读取器及固定导出器。 | 可搬移的运行包包含原轨迹、准确案例和答案版本或经验证的离线副本、实际效果证据及摘要；私有部分由操作者保存。每次评分另有 ID，绑定运行及评分配置摘要；重评产生新成绩并记录分歧。报告显式选用评分 ID，呈现质量、分母、未评/不可观测/不支持、首失败、效果、tokens、费用、延迟。规范报告排除渲染时刻和宿主路径。 |

限制目标工具及文件权限。可用 shell 的同一用户进程仍能读到目录外文件，单靠环境变量和私有目录不足以隔离。对支持平台采用操作系统权限边界，或在只挂载当前输入、自身状态且仅能访问工作模型端点的受限 worker/容器运行目标。控制器、评分凭据、答案和未来事件都在边界外。CI 用合成探针验证真实拒读（含别名路径），并检查目标实际外发正文。公开报告只保留脱敏结果。清理前确认进程与设施归属；停止态设施按已有归档和逐项读回规则释放。

## 实施顺序与验收

1. 先实现配置、单命令、可搬移运行包和脚本对照。在 correctness CI 中先用模拟目标及评分端，再用隔离的、版本锁定的 Secretary 加脚本模型。覆盖正反例、能力缺口、校准失败、评分中断恢复、目标效果未决、重复调用、隔离探针、材料缺失或损坏及预算耗尽。核验基线导入摘要和不兼容标识。将导出包复制到独立目录，原路径不可读时验证重评零目标调用、报告重建零模型调用。四个历史规范产物使用已有私有归档重放流程及清理证据的完整摘要核验；公开 CI 使用公开输入。保留首失败。
2. 接入真实 Secretary 和独立 Hermes API 评分路线，仍走同一命令。付费前先用已安装的准确评分器版本和本地模拟传输穿过实际请求构造、解析和回执路径。清洁安装所需的非秘密依赖必须随库提供或有可重现获取说明。若需要私有 R79 临时脚本或人工生成、递交评分材料，即未达到验收。目标与裁判分别控制调用、费用及时限，核实版本及计费归属，禁用静默换路。
3. 真实操作者验收拟用 C04-nonexistent，固定公开时间线，原因是该短对照已有真实运行和评分先例。采用已核实的必测 DeepSeek Flash 工作路线和独立 Hermes/DeepSeek 评分器。实发前另行冻结并授权案例字节、调用、费用、重试、停止条件、模型、推理档位与报告预期，预算覆盖两次评分所需的校准和实发。未参与开发的操作者从干净检出只按 README 操作。保存命令、解析配置、退出码、结果位置、偏离之处，人工搬包/回填回执/拼报告次数为零，并确有一次真实语义评分。对同一封存包禁用目标进行一次获准的真实重评；再禁用两个端点，以原评分逐字节重建首份报告。独立列出程序正确性、实模覆盖、真人操作、产品使用门槛。工具验收批次独立记账。
4. 第三项使用同一协议。ProkBot 原生 Host 负责对话、调度与记录，可裁去无关外部 UI，保留原生记忆体系和必要执行器，以实测轨迹证明维护确已触发，记录实际 Host 版本与裁剪清单。普通 pi 固定原版执行器和压缩次数及硬 reset；原 Hermes 备选改为同一 pi 加载固定版本的 pi-hermes-memory，使用干净存储，禁止索引操作者会话，观察实际扩展读写。各自声明可观测能力。此次桌面核对使用上游 [ProkBot](https://github.com/aha-duoduoduo/ProkBot) 与 [pi-hermes-memory](https://github.com/chandra447/pi-hermes-memory) 的说明，钩子与退出语义在第三项原生试跑核实。外部可执行文件可独立交付。预先指定共同案例及适用性；既有基线无法证明身份与条件等价时，在同一窗口交错采集 Secretary 参照；保留分母、能力和解释限制。原生对照与后续可选的借鉴型变体各用独立批次。
5. benchmark 实施 PR 更新源码、使用说明及运行示例，执行 npm run verify 与准确提交的既有 CI。保留首失败和私有原证据，公开脱敏回执。以准确提交差异、测试、实测与操作者记录请同一 Claude 会话复核，再交 Master 终审。本轮仅拟定设计，实施由 Master 确认后开始。
