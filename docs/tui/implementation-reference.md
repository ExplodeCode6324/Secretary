## 2 界面结构与 Main 呈现

### C02 双入口与统一布局

- 一级入口只有 Main 与 Task，整屏切换。
- 每次启动默认进入 Main。已处于命令目标页面时重复 `/M` 或 `/T` 不产生额外动作、提示或聊天消息，不重置阅读位置。内部视图的 `/back` 返回逻辑上一级；已在 Main 或 Task 一级页面时 `/back` 不做任何操作，也不产生错误、提示或聊天消息。
- 本次启动内返回已访问页面时，恢复最近一次离开时的阅读位置。这里的“最新阅读位置”指最后停留的消息或对象及正文位置，不是自动滚到最新消息；重新启动 Main 的初始定位仍按 C04。
- 跨页常驻范围仅为底部输入区域，可包含本版允许的底部提示行；不新增跨页常驻顶部菜单、状态栏或侧栏。各页面自己的标题不受此限制。
- 宽终端、高终端只让同一布局显示更多内容，不触发新的双栏布局。
- Main 的活动和待处理区域固定在输入框上方。Task 不显示这一提示区域。
- 可选的底部命令或错误提示行可作为输入区域的组成部分，不据此增加新的一级入口或业务面板。
- 不建设独立产物详情页，也不建设额外的执行过程仪表盘。

### C03 消息类型 颜色与 Markdown

| 内容 | 已定呈现 |
| --- | --- |
| 模型普通正文 | 白色 |
| Master 发言 | 浅蓝色，并有专门的上下分割线 |
| 工具调用及工具详情 | 使用浅粉色或另一种固定、可区分的专用颜色；另起一行 |
| 推理正文及推理摘要 | 浅灰色，降低视觉存在感 |
| 产物条目 | 位于模型回复末尾，使用与普通正文不同的颜色 |

不同消息类型单独起行，不能把工具输出、推理和普通正文混接成同一行。长内容可以正常换行，不把“单独占一行”解释为强制截断到一行。

模型输出的 Markdown 应正确呈现层级与格式。验收使用固定样例检查段落、标题、强调、列表、引用、行内代码和代码块；表格、链接等支持范围在实施说明中列明。数学公式、Mermaid、HTML 和内嵌媒体不能凭“支持 Markdown”被自动宣称全部支持。

具体色值、终端配色序号、行间距和分割线字符由实施者在目标终端上选择并记录，不重新打开已经确定的颜色语义。Master 发言的颜色和分割线、工具的独立行、推理的弱化显示均为验收内容。

### C04 历史加载与阅读位置

1. 启动仅加载近期一定数量的 Main 消息；首次进入 Main 定位到最新消息。
2. 继续向上滚动时，再加载更早消息，不新增一套历史库。
3. 新消息到来不自动跟随跳转，不强行把正在阅读的内容滚到最新位置。
4. 历史读取失败，在对应加载位置报错；保留已经显示的历史和当前输入。
5. 切换 CoT 前后保持阅读位置。这里保留的是正在阅读的消息及其正文位置，不要求展开后维持同一个绝对行号。
6. 上限只限制客户端内存缓存，不限制可回看的历史总范围。本次启动以来的 Main 消息均可持续上滚查看；继续上滚可读取现有日志中仍可取得的更早消息。被缓存淘汰的消息需要时重新分页读取，不能把淘汰边界伪装成历史起点。
7. 全历史全文搜索不纳入本轮。

切页返回沿用最后阅读锚点，不因离开期间产生新消息而跳到底部；缓存淘汰不取消按既有日志补读并恢复位置的能力。本轮不额外要求跨启动持久保存滚动位置。

CoT 模式改变、正文版本变化或 Core 重启可能使旧分页游标失效。客户端应以稳定消息 ID 和正文锚点重新定位，取得适用于当前模式的新游标后继续读取；不能循环重试同一失效游标，也不能把失效误报成历史结束。当前 Main 已有按消息定位的 `/around` 能力，游标同时绑定查询模式及服务实例密钥。[S3]、[S31]

首次加载量、每次补读量、缓存容量及其计量单位是实施参数，必须给出并用于验收。内存缓存限制不产生删除权威日志、另建历史库或缩短可浏览范围的要求。

### C05 CoT 与普通日志分离

- `/cotvisible` 与别名 `/cotv` 切换全部消息的推理展开和收起。
- 命令只在 Main 调用；Task 中的 Agent 思维链继承同一显示状态。命令可调用范围与显示效果作用范围是两个不同概念。
- 已显示、后续到达、随后补读的历史消息使用同一规则。无需一次性读取所有历史 CoT。
- 默认显示已有摘要或前 20 个可显示字符；无内容不虚构，不额外调用模型生成摘要。
- 展开、收起不新增 log，不补写此前未持久化的推理内容。
- 本轮暂不建设非 CoT 的独立日志入口，`/show logs` 不注册为命令。此取舍不取消既有日志记录、Main 中已确定的工具消息或 Task 最近三轮 Agent 对话历史。
- CoT 显示偏好允许跨启动保存，属于可选、低优先级功能，不设为首版阻断项。

## 3 Task 与 Scope

### C06 Scope 总览与默认展开

Task 主界面展示当前 Scope 的数量、每个 Scope 下的当前任务数量及任务条目。任务按 Scope 分组，条目默认展开，显示 ID、实际状态、时间等必要信息，不先把任务全部藏进折叠组。

| 分组 | 展示要求 |
| --- | --- |
| 普通 Scope | Scope 名称、当前任务数量及默认展开的任务条目；有名称且 kind 为 NONE 的实体 Scope 仍是普通 Scope |
| Shared Scope | `scope_id: null` 的任务统一放在同一逻辑组，显示该组自己的当前任务数；各 Task 使用独立临时工作目录 |
| Archived Scope | 单独展示已归档 Scope 的数量，不展开其任务；归档 Scope 检索后置 |

批注中的 Scope1、Scope2、Shared Scope、Archived Scope 示例用于确定逻辑层次，不作为最终字符画或固定像素布局。

**排序已定：**有活跃 Task 的组在上方，以组内最新调起的活跃 Task 排序，最新在前；没有活跃 Task 的普通 Scope 按 Scope 创建时间倒序。每个组内的 Task 均按最近一次执行时间倒序。不能用 Scope 的最近修改时间代替创建时间，也不能用 Task 创建时间、无关更新或查看时间代替最近执行时间。排序覆盖完整可浏览集合，不能只排当前取回的一页。

有活跃 Task 的逻辑 Shared 按同一活跃排序依据参与；没有活跃 Task 时，Shared 没有实体 Scope 的创建时间，其稳定位置由实施说明登记，不为排序虚构一个实体 Scope。属于当前集合但尚无执行的 Task 不得因时间为空被丢弃。实际执行字段、空值和同值的稳定顺序作为实施参数登记；列表刷新按稳定对象 ID 保留阅读与选择目标，不把行号重排变成目标变更。

**计数已定：**页头 Scope 总数只统计有当前 Task 的普通 Scope，不计空 Scope、逻辑 Shared、仅有历史任务的 Scope 或独立展示的 Archived Scope。各组数量统计本组当前 Task，历史任务不计入；同一 Task 的多次 Execution 不能重复计数。Shared 不计入页头 Scope 总数，但其组内当前任务仍须正常显示和计数。通过 ID 临时定位历史任务，不增加当前 Scope 或组内当前 Task 的数量；本书不额外增加一个全局 Task 总数。

例如：普通 A 有两个当前 Task，普通 B 有一个尚未执行的有效定时 Task，另有空 Scope C、只有历史任务的 D，以及含三个当前 Task 的 Shared；页头 Scope 总数是 2，A/B/Shared 的组内当前任务数分别是 2/1/3。是否显示空 Scope 的零项本身不由“不计数”推导为强制隐藏；默认当前集合按 C07 判断。

Shared Scope 的共同点是视图分组，不是工作目录。允许在统一父目录下按 Task 分配各自子目录，具体命名作为实施配置记录；不同 Task 的实际工作目录必须不同。临时目录以 Task 为单位，本轮不要求每次 Execution 重新分配目录，也不更改既有继续任务、周期执行的目录复用规则。

完成时只交付明确登记的产物，不自动交付整个临时目录及其中间文件。Task 临时工作目录的清理后续添加，本轮不新增完成即删除或退出即删除的动作。文件交付与 `/open` 的衔接见 C11、第 7.2 节及 U06。

归档 Scope 的当前代码含义见第 7.1 节；新增任务联动归档仍属 U07 的后续取舍。界面隐藏不表示任务已停止或完成业务归档。Scope 创建时间的现有字段缺口见 B03、第 7.4 节。

**可选交互：**输入框第一行再按上键进入 Scope 选择或筛选，仍是候选，不升级为首版强制要求；若采用，登记焦点、返回和草稿保护规则，并保持任务条目默认展开。

### C07 计划状态与执行状态

1. 默认集合以真实的未终结执行、排队请求或触发、有效后续调度，以及应显示的待处理或异常为依据，覆盖当前任务和定时任务。已结束且没有这些后续工作的一次性 Task 归入历史，不能仅因 TaskPlan 仍为 ACTIVE 而永久留在默认列表和当前计数中。
2. 排队、等待前提、等待授权、等待回答、结果未知、取消处理中、初始化失败等状态均应如实显示，不能只保留“正常运行”的行。没有未终结执行、排队或待处理事项的暂停计划不默认展示、不计入当前集合；仍有实际执行、等待或异常待处理时照常展示。不能仅凭暂停计划残留的时间字段把它当作有效未来调度。
3. “当前活跃”表达实际执行活动；TaskPlan.ACTIVE 只说明计划有效，既不证明正在执行，也不能单独决定当前列表成员资格。列表所需投影必须区分运行、等待、后续调度与历史。
4. 任务计划状态、当轮执行状态、最新结果与失败事项的处置分别表达。某轮成功不等于整个计划关闭；本次失败已经处理也不改变历史 FAILED。
5. 同一 Task 同时最多有一个未终结执行。定时任务当前正在执行，只计为一个 Task，同时展示计划属性和当轮状态，不重复计数为两项任务。
6. 不从“同一 Task 不并发”推导出所有 Task 必须串行；不同 Scope 或不同 Task 的调度沿实际后端规则处理。
7. Shared 的逻辑分组不新增组级 DIRECTORY 占用锁；不同 Task 的独立目录不因被放进同一视图组而互相占用。已有执行容量约束及其他真实目录 Scope 的既有规则继续适用。

现有正常调度和继续任务路径已有同一 Task 忙碌校验；普通执行完成路径更新 Execution、结果和相关请求，不自动把 TaskPlan 关闭。因此，上述当前集合需要明确投影，不能靠前端把 ACTIVE 改个显示名称完成。[S6]、[S12]、[S13]

公共列表补齐执行状态、计划或调度属性、筛选和计数数据；不为使列表消失而新增自动关闭计划。被默认列表排除的未归档暂停计划仍可按 ID 定位，继续显示真实 PAUSED 状态，不伪装成已完成。首批真实 Task 条目就要区分实际执行状态，完整排序和聚合仍归原批次三。

### C08 查询定位 任务详情与 Agent 历史

- `/search_task <task_id>` 在 **Task 主界面** 调用，支持完整 ID 和唯一短 ID。
- 查询结果在 Task 中定位，不自动打开详情。
- 不唯一短 ID 或不存在 ID 必须报错，不猜测目标。ID 查询不扩展成关键词全文搜索。
- 任务详情使用 `/taskdetail <task_id>`，在 Task 中打开。
- 本轮 Task ID 查询排除归档 Scope 下的任务：完整 ID、唯一短 ID、补全候选和 `/taskdetail` 都遵守同一可浏览范围，不能绕过归档排除。普通已完成历史任务不因此被当成归档任务。
- 返回使用 `/back`，回到逻辑上一级入口；已在一级页面时无操作。详情沿用 Task 的普通输入，不建立按 Task ID 保存的独立草稿。
- Agent 类任务详情必须能显示该 Agent 的实际对话历史。
- 不额外建设执行过程仪表盘；这不取消已经确定的 Agent 对话历史要求。

任务条目至少能识别任务 ID、目标、真实状态和必要时间；详情至少说明目标、执行或等待状态、最新结果和可用操作。Agent 对话按 Execution 清楚分组，默认查看最新 Execution；本轮展示最近三次执行，不做轮次切换器，也不增加第四轮及更早轮次的独立历史区块或入口。每一轮内部的长对话仍支持分页阅读；范围按记录所属 Execution 判断，不因消息引用了更早内容就删改原文。

**本版呈现解释，供继续批注：**最近三次包含最新一次，总数最多三轮；在同一详情中按新到旧连续分组展示，默认定位最新一轮。不足三次时显示实际已有轮次。记录不可取得时说明实际情况，不补造内容。此解释落实“默认最新、展示最近三次、不做切换”，不另增加轮次选择界面。

未归档的历史任务若不属于默认可见集合，ID 查询仍须能定位命中对象；采用临时结果条目还是临时筛选可由实现说明具体化，查询结果不增加当前集合计数。归档对象不进入结果或详情；明确输入其完整 ID 时给出当前范围不支持或未命中的局部反馈，不改为查另一个对象。这个限制属于当前 TUI 范围，不删除 Core 中的任务、历史或既有查询能力。

## 4 Main 活动区域与定向输入

### C09 输入框上方的活动与待处理

- 活动提示和待处理事项位于 Main 输入框上方的简短区域，不使用右侧栏。
- 授权、决策必须进入该区域；失败任务存在时单列一行；UNKNOWN（结果未知）独立单列，不混入普通失败或授权事项。
- 同时支持多项，按发起时间从新到旧排列，最新发起项在上。
- 看过的事项颜色较深，未看过的较浅；查看过不等于批准、回答或处理完毕。该颜色是客户端显示状态，不为改颜色调用会改变 Execution 留存时钟的 `/executions/{id}/viewed`。[S3]、[S30]
- Task 页面不显示这块活动或待处理提示区。
- 对某次失败的重做成功完成后，退出对应原失败提示。仅接收重试请求、排队或正在执行不算完成；其他无关后续轮成功也不能冒充这次重做完成。
- 对失败行选择取消，表示**不再重试本次失败**。由 Main 完成这次失败事项的处置后，退出待处理；原 Execution 和历史结果继续为 FAILED。该动作不关闭 TaskPlan、不停止未来周期、不取消其他请求或执行。
- 处理失败时显示错误，并在对应任务上保留显式失败标记；瞬时错误消失不得抹掉未解决状态。重做再次失败时保留或更新标记，不显示为已经解决。
- 已回答或批准的事项，在对应回答或授权操作确认完成后立即移出待处理，不等待 Task 完成，也不等待授权从 APPROVED 进一步变成 CONSUMED。重新查询不能把已完成的同一批准再次放回待处理。[S3]、[S32]

**失败行的处理路径已定：**Master 从 Main 失败行明确提交重试或取消意图，TUI 将意图及准确 Task、失败 Execution/结果归属交给 Main session，由主会话依据真实状态执行。查看或进入失败行不自动提交；沿用 Enter 先进入、再明确提交的原则。Task 内既定的 `/cancel --request` 和 `/cancel --execution` 仍用于真正取消指定请求或执行，与失败事项的“不再重试”处置分开。

主会话实际操作后，Main 失败行及 Task 展示按 Core 真实结果同步更新；不能只凭模型说“已处理”、通用接收回执或对终态执行的空操作取消就移除。接收、重试运行中、处置完成和处置失败分别体现；返回时保留原 Main 草稿，不把原稿拼进业务请求。既有通知或查询可以复用，缺少处置关联时按 B10 补齐。

处置必须对应**这一失败**，且能在刷新、重连或重开 TUI 后读到完成结果；不能只在客户端内存隐藏行，也不能永久屏蔽整个 Task，使其后续新失败消失。保存真实失败处置的必要业务状态，不等于建设 UI 操作流水。具体记录、事件或投影方式由实施选择。

**UNKNOWN 的产品处置已定：**不建设 TUI 裁定入口，独立显示为需要排查修复的异常，并保留真实状态、可定位的 Task/Execution 及已有原因。不能自动当作普通失败重试、冒充成功/失败或仅在客户端隐藏。正常使用中出现该状态，应追查原因；不扩展日常人工裁定流程，也不删除已有后端状态和恢复机制。

显示条数、区域最大高度、溢出浏览方式、失败行的具体键位与请求文案作为实施参数登记；必须能到达全部待处理项，不能只显示前几项后丢掉其余项。主会话路由、失败处置含义、真实完成条件和 UNKNOWN 无裁定入口均已确定，见 U05。

### C10 键盘选择与事项输入

Main 的已定交互路径：

1. 在输入框编辑多行文本时，上键首先按正常编辑规则移向第一行。
2. 光标已在输入框第一行时，再按上键进入上方待处理事项选择。
3. 用上下键选择事项，Enter 只选中并进入处理，不直接批准或提交回答；进入后再进行明确的批准、拒绝或发送操作。
4. 需要文字输入时复用下方输入框，提交内容针对该事项。
5. 完成输入并提交后，回到原 Main 输入，恢复此前的 Main 草稿。

Task 的已定交互路径：使用 `/show <item_id>` 打开授权或问题；参数指整个待处理事项的 ID，绝非事项内部某个答案选项的 ID。进入后，普通输入提交给这个事项，不作为 Main 消息，也不作为任意 Agent 聊天。提交成功后返回 Task 界面中的 Scope 任务列表，并刷新实际状态。

未提交时优先使用 Esc 退出处理，恢复进入前的 Main 或 Task 输入；如果目标终端无法可靠使用 Esc，可采用经实际验证的其他组合快捷键，并在帮助和验收记录中写明。退出处理不等于退出 TUI，也不构成业务提交。

未提交的事项回答不要求在退出后保留：默认可丢弃；若现有输入组件无需新增存储或恢复逻辑便自然保留，可沿用并在实施记录中说明，不额外建设回答草稿库或跨启动恢复。该许可只针对明确退出或目标失效后的临时回答，不影响原 Main/Task 草稿恢复，也不允许在普通提交失败、仍停留处理状态时静默丢稿。

目标已处理、过期或其他原因失效时，显示实际错误并退出该处理状态：从 Main 进入则返回 Main、恢复原稿；从 Task 进入则返回 Task 列表并刷新。错误提示必须在返回后仍有可见的呈现机会，不能随视图销毁而完全不可见，也不得把回答改投其他目标。

| 当前输入状态 | 普通文字提交的目标 |
| --- | --- |
| Main 普通输入 | 主会话 |
| Task 普通浏览 | 保留草稿，不发送到 Main 或 Agent |
| 已进入某个待输入事项 | 该明确选中的授权或问题 |
| Main 失败行中明确提交重试/取消意图 | 主会话，附准确目标；与授权或问题的定向回答区分 |

定向输入是本轮对旧功能页路由的明确补充。实现不能继续用“Task 普通文本一律不得提交”拒绝针对事项的输入，也不能继续允许 Task 中的 `/send` 向 Main 发送。

输入区必须能辨认当前对象与输入用途。进入授权处理后，应能查看这次待批准操作的实际动作、对象/资源及有效授权详情，提交使用该显示对应的当前 revision/display_hash；不能只显示一条截断摘要就让 Master 盲批，也不能把任意自然语言当作合法授权值。已有详情和校验能力可以复用，不由此新增 remember/revoke 管理菜单。[S3]、[S5]、[S32]

**授权或问题处理期间，任意命令均不适用。** 该输入状态先于所有全局和页面命令解析：`/M`、`/T`、`/back`、`/help`、`/send`、`/rawmessage`、`/open`、`/cancel`、`/show` 等均不得导航、转投 Main、打开文件或执行其他业务。普通编辑、换行、选项选择、明确提交和 Esc 退出仍然有效。文本问题的 `/tmp/a` 或 `/T` 可以作为字面答案提交给当前问题，不作为命令；授权仍只接受明确且合法的批准/拒绝动作。退出处理后，普通页面的命令规则恢复。

## 5 产物与外部打开

### C11 结果末尾的产物条目

1. 复用现有结构化 Task 结果及产物登记能力。
2. 在模型回复末尾罗列产物，使用与普通回复文字不同的颜色。
3. 每项展示含路径的名称和所属 Execution；有多个产物时，模型对每项给出解释。
4. 实施前检查 Task 回传和 Main 查询结果是否包含这些字段。缺失时补传递或投影，不能让模型编造路径或所属执行。
5. Main 的产物条目即为首版入口，不建设独立产物详情页。

**本版对“完成后只给回产物”的文件交付解释：**向 Main 交付明确登记的产物，不自动交付整个 Task 临时目录、缓存或中间文件。任务状态、必要结果摘要、Task/Execution 归属和已确定的 Agent 对话历史继续保留。无文件产物的任务不因此被要求额外制造文件；本轮复用已有产物登记，不另造一份存储体系。

### open 的对象已经确定

- `/open` 主要以文件路径为目标。
- 打开的是**工作区当前文件**，不是该次交付时保存的旧快照。
- 产物 ID 作为可选目标；若实现，必须先解析为对应当前工作路径，不能悄悄打开快照内容。
- 支持中文和空格路径，不通过 shell 字符串求值解释文件名。
- 绝对路径按其本身定位；相对路径必须有可查的基准，不能随选中项或当前页悄悄改变。
- Shared 不是公共文件根目录。每项产物必须准确定位来源 Task/Execution 的当前文件；不同 Task 都产生 `report.txt` 时，Main 条目与 `/open` 目标仍须可区分。只给出相同相对文件名而没有明确来源基准，不算完成路径交付。

目标不存在时仅报错一次，不误报成功、不持续刷错。Master 已明确退出的是错误提示，TUI 保持运行。错误按一次性短暂提示呈现后消失，具体可读停留时间由实施记录；不能让它长期驻留，也不能以退出客户端代替提示清除。

当前产物内容接口读取的是登记快照。新版 `/open` 必须依本轮选择实现当前文件定位，不能仅因为旧内容接口方便就改变对象。[S9]

## 6 命令 输入与局部反馈

### C12 命令表

**命令名称不区分大小写。** 这项决定覆盖旧稿“大写导航、小写操作、大小写敏感”的规则。仅命令名和已登记的别名按该规则处理，路径、正文和对象标识的内容不得统一改成小写。

**状态优先：**下表只适用于普通浏览和输入状态。已进入授权或问题处理时，整张命令表停止适用，包括标为全局的命令；按 C10 处理当前事项，Esc 退出后再恢复命令解析。

| 命令 | 已确定的可调用范围 | 已确定行为 | 剩余说明 |
| --- | --- | --- | --- |
| `/M` | 导航入口 | 进入 Main；已在目标页面则无额外动作 | 返回恢复最近一次阅读位置，启动默认 Main |

| `/help` | 普通状态全局 | 查看可用命令及说明 | 帮助反映真实作用域和参数；事项处理中不适用 |
| `/cotvisible`、`/cotv` | 仅 Main | 全消息推理展开或收起 | Task 继承显示状态，不在 Task 调用 |
| `/open <path>` | 仅 Main | 打开工作区当前文件 | ID 为可选目标，精确语法实施前登记 |
| `/send [正文]` | 仅 Main 普通输入 | 显式发送 Main 载荷 | 授权或问题处理中不适用 |
| `/paste` | 仅 Main | 保留既定显式粘贴入口 | 需区分文字、文件引用和图片；不能以此代替图片直接粘贴验收 |
| `/rawmessage <正文>` | 仅 Main | 仅本次消息按字面正文提交 | 正式拼写已确认 |
| `/search_task <task_id>` | 仅 Task 主界面 | 完整或唯一短 ID 定位，不自动展开 | 不覆盖归档 Scope 下任务；未归档历史任务仍可查 |
| `/cancel --request <task_request_id>` | 仅 Task | 取消明确的任务请求 | 观察实际取消结果，不替代 Main 失败事项处置 |

| `/show <item_id>` | Task 中的用途已明确 | 打开整个事项，随后输入针对该事项 | ID 类型已确认；是否也允许从 Main 调用见 U01 |
| `/taskdetail <task_id>` | 仅 Task | 打开任务详情及 Agent 最近三轮历史 | 默认最新、不做轮次切换器；同样排除归档对象 |

`/rawmessage` 与 `/cancel` 是正式拼写；`/rowmessage`、`/cancle` 是已经纠正的笔误，不作为必须兼容的别名，也不继续列为待选拼写。首版不注册直接创建任务的命令或表单；任务发起由 Main 主会话承担。

本轮不注册非 CoT 日志入口、`/attach`、独立 `/retry`、Main `/cancel` 或 UNKNOWN 裁定命令。Main 失败行提交主会话的业务请求按 C09 处理，不改变上表中 Task `/cancel` 的作用域。图片直接粘贴按 C14 交付，真实终端受限时才进入替代方案确认。

原稿中“功能页通过 `/send` 向 Main 发消息”的条目在本版撤销。Task 错页调用 `/send` 应给出局部错误，不向 Main 发送。

### C13 草稿与命令识别

- Main 与 Task 的草稿独立，不因切页、补全或选中对象而自动提交。
- 本期不增加“保留非空草稿，同时进入临时命令模式”的功能。
- 在普通输入状态，只有输入首字符为 `/` 且满足整次提交的已登记语法，才作为命令处理；授权或问题处理状态先于该规则，完全不进入命令分派。
- 首字符按实际原始输入判断，不能先 trim 再识别。Pi Editor 默认提交会 trim 展开文本，应用适配时须保留原始开头和需要提交的真实内容，避免把带前导空格的正文误当命令。[S27]
- 普通正文之前已有文字，再在后面输入 `/T` 或其他命令样式，仍是正文。不要扫描最后一行、自动修剪前导正文或执行多条命令。
- 一次提交最多执行一条命令，不支持 shell 替换、管道和命令串联。
- 补全只编辑输入，不执行。
- `/rawmessage` 只对当前一次消息生效，下一次输入恢复正常解析。
- 定向输入前的 Main 草稿与事项回答内容分开保存，返回后恢复原稿。

因此，非空正文中直接追加 `/T` 不构成切页方式。本期验收不能为了方便擅自添加导航快捷键或双缓冲命令模式。**不做 Task 详情独立草稿，也不建设按 Task ID 保存或恢复的草稿表。** 只保留既定 Main/Task 两份普通草稿；详情沿用 Task 输入区，文字不直接发送给执行 Agent。事项临时回答依 C10 单独处理。

### C14 多行粘贴和附件

多行粘贴采用 Master 指定的 Hermes 风格交互：有独立粘贴文本缓冲区，在输入区显示类似下面的摘要：

```text
<pasted xx lines xxx...xxx.txt>
```

摘要绑定真实内容；文件名和行数是显示信息，不替代正文。多次粘贴与手写内容保持顺序；发送时提交真实全文，不只发送摘要或临时文件路径。粘贴块内部的 `/T`、`/send` 或代码不会自动执行。

Pi Editor 的大段粘贴缓冲和 `getExpandedText()` 可以复用，但其默认标记样式、内存 Map 与提交清空行为不自动满足本书的 Hermes 显示和失败保留要求。应用层须接管展开后的实际载荷及草稿生命周期，确保组件清空后仍可依 Core 接收结果完成交接或恢复；只保存含标记的 `getText()` 不能恢复原文。无需重写整个编辑器，也不能仅把依赖接上就宣称草稿恢复完成。[S27]

**图片附件要求直接粘贴。** 在目标 macOS 终端中，Master 使用实际可用的粘贴操作，将系统剪贴板中的真实图片加入 Main 当前草稿；与文字混合发送时，图像内容必须经过既有附件契约进入消息。仅粘入文件名、路径、占位文字或改用 `/attach`，均不能代替这一能力。普通文本里的路径仍不自动变成附件。

具体粘贴键位与本机剪贴板适配方式在实际终端验证并记录，不事先声称某个组合键一定可用，也不要求终端必须内嵌绘制图片。Pi 的原生剪贴板接口可读取图片，macOS 实现已处理 PNG/TIFF 并转换为 PNG；优先复用该能力，再接 Secretary 的附件导入与发送合同。图片按键绑定和 Core 导入不是剪贴板组件自动完成的行为。[S26]、[S29]`/paste` 可保留既有辅助用途，但图片不能只能通过输入命令导入。粘贴只加入草稿，不自动发送。

若真实目标终端及可用本机适配确实无法实现直接粘贴，实施时记录环境、已尝试方式及失败现象，向 Master 说明并询问替代方案。得到决定前不得自行以路径上传、`/attach` 或浏览器操作代替并宣称通过；其他已确定功能继续完成。这是发生实际能力阻塞后的分支，不是现在新增一项入口选择题。

图文或图片导入、提交失败时保留原有草稿和已导入附件，明确指出失败，不静默丢图后只发剩余文字；对尚未成功导入的剪贴板内容不能伪称已有附件副本。

### C15 错误和 UI 状态

普通错误按实际原因显示，下一次用户操作后清除，不长期驻留。历史加载错误首先在加载位置出现。UI 提示不写入 Main 历史，不产生新用户消息，也不建立滚动、展开、补全的持久交易流水。

Main 失败行中由 Master 明确提交的重试/取消意图属于真实业务输入，应经现有主会话链路正常接收和记录。选择失败行、局部提示、刷新和标记呈现仍只是 UI 状态；已完成的失败处置则是必要业务结果，需可重新查询。不能为刷新另造一条 Master 消息，也不能以“UI 不入历史”为由阻止主会话收到这次业务请求或保存真实处置结果。

可使用输入区内的固定底部提示行。错误出现和清除不能覆盖草稿，也不能被误当成模型回复。`/open` 的一次性错误提示消失时客户端继续运行；事项失效的错误随返回过程可见；失败任务的状态标记与瞬时错误提示分开，不能一起清掉。

“下一次操作”具体包括哪些按键，以及是操作开始还是完成时清除，属于实施时需要记录的小型交互细节；验收至少验证一次普通编辑或下一条合法命令后旧错误已消失。

### C16 业务输入与生命周期

真实发送、取消、授权和回答继续复用 Core 的接收与状态能力；不能把本地已发出显示成业务完成。断线或失败不静默丢稿；同一次业务提交因断线、超时而重发时，保持原请求身份以避免重复执行。Master 明确要求失败任务重做，则按第 7.3 节发起后续工作并关联原 Task/Execution，不能把新的重做意图当成旧请求重放而只取回旧结果。这些要求不延伸为每次客户端显示操作的审计。

Task `/cancel` 必须明确请求或执行对象；无参、双目标、无效 ID 不执行。取消一轮 Execution 不代表未来周期计划已经停止。Main 失败行的取消按 C09 处置这次失败，保留 FAILED，不复用对终态执行空操作的回执冒充完成。

允许采用 Ctrl+C 退出而不另做 `/quit`；批注将其作为可考虑方案，具体退出键在 macOS 输入预检时记录。无论使用哪个出口，都只退出 TUI，后台继续。

既定临时材料规则针对 TUI 草稿、粘贴正文、附件及未交接内容：已可靠交接的文本副本及时清理，其他临时或孤立记录默认三个日历年，活跃引用受保护。该期限不要求保留 UI 操作记录。旧 Tauri 未发送数据不迁移。

本书规定保留结果与交接行为，不指定新增 Core 草稿库、独立可靠发送服务、逐次按键同步落盘、通用 fsync 写入器或大规模压力工程；按既有组件和当前草稿状态实现满足要求的最小方案。不能以这些额外工程是“旧稿合同”为由扩展首批，也不能直接删除已确认的三年规则。

已明确退出或目标失效后的未提交事项回答，采用 C10 的专门取舍：无需为保留它新增存储或恢复逻辑，不因“未交接内容”这一统称而要求持久留存。原 Main/Task 草稿及仍在处理中的发送失败材料继续受各自规则保护。

Task 临时工作目录的清理是后续工作，不因上述材料规则自动套用同一删除时限，也不要求目录必须位于系统 `/tmp`。本轮不新增目录回收器、完成即删除、产物搬迁或旧目录迁移。后续加入清理时再处理产物保留与 `/open` 路径衔接；本轮不得先删掉仍需交付和打开的文件。

### 7.1 Scope 归档 当前代码已经实现的含义

**结论：归档已经实现，其作用是关闭该 Scope 的新工作入口并阻止未开始的执行，不是把所属 Task 一并终结。** 当前入口是 `POST /api/v1/scopes/{id}/archive`，使用 `request_id` 和 `expected_revision`；`Scopes.archive()` 将 Scope 从 ACTIVE 改为 ARCHIVED 并记录 `scope.archived`，不遍历修改任务或删除文件。[S3]、[S14]、[S15]

| 对象或动作 | 当前代码的实际行为 | 依据 |
| --- | --- | --- |
| 新建 Task、继续已有 Task | 归档后新请求被 `SCOPE_ARCHIVED` 拒绝；可靠接收过的旧请求重放返回原结果不算接受新工作 | `Scopes.active()`、任务提案与继续入口，[S12]、[S14] |
| 已开始执行 | 归档本身不发取消；既有执行可沿原工作目录继续收尾 | 分派检查只对 `!started_at` 的执行阻断，[S14] |
| 已开始且等待授权 | 仍可批准后完成；归档不自动使原授权失效 | 仓库现有直接测试断言，[S16] |
| 已开始且等待回答 | 回答恢复后可继续；这是回答入口与分派条件组合得出的行为 | 源码组合推断，非本轮实测，[S14]、[S19] |
| 尚未开始的排队或就绪执行 | 分派受阻，进入前提未满足状态，原因为 `SCOPE_ARCHIVED` | 分派路径及现有测试断言，[S13]、[S14]、[S16] |
| TaskPlan 与未来调度 | 不级联关闭 TaskPlan，不自动清空请求或周期发生队列；计划状态没有随归档改变 | 归档仅更新 Scope；触发器仍按计划处理，[S6]、[S14]、[S20] |
| 目录、任务、产物及历史 | Scope 归档不删除这些对象；Execution 的留存与退役是独立生命周期，Scope 归档不触发该流程 | 归档函数、目录保留测试及状态契约，[S14]、[S17]、[S20] |
| 按 task_id 查询 | 既有任务仍可通过公开查询读取；继续任务能力则明确不可用 | Task 查询及 continuation 状态，[S3]、[S12] |
| 恢复归档 Scope | 没有公开 restore/unarchive 操作；普通更新不接受 state，且已归档 Scope 拒绝保存修改 | 公共契约、操作表及 `Scopes.save()`，[S5]、[S14]、[S15] |

**定时任务的边界：**归档没有关闭已登记的定时计划。依当前 `tick()` 与分派逻辑推导，到期计划仍可能生成尚未开始的 Execution，再因 `SCOPE_ARCHIVED` 被阻断；已有未终结执行时，周期发生点还可能按 QUEUE 规则累积。因此，不能把“执行未开始”描述成“定时计划已取消、队列已清空”。这是源码组合推断，本轮没有运行“归档后多次定时触发”的实验。[S6]、[S14]

现有 `workspace.test.ts` 明确写有以下断言：一个执行到达 WAIT_AUTH，另一个因 Scope 忙而等待；归档 Scope 后批准前者，前者最终 SUCCEEDED，后者仍未开始且原因变为 SCOPE_ARCHIVED。该测试说明了原设计的分界，但本次仅阅读断言，没有重新执行测试。[S16]

当前列表 API 不会自动把归档 Scope 的任务全部隐藏。“Archived Scope 仅显示数量、暂不展开”，以及本轮已决定的 Task ID 查询与详情排除这些任务，均需在 TUI 的统一可浏览范围中落实；不能从后端可查询推导成 TUI 应展示。Scope 归档的后端语义不因该界面过滤而改变，新增任务联动归档仍属 U07 的后续产品取舍。[S3]

上述浏览排除不抹去已开始执行的活跃授权、问题或异常。Main 仍按 C09 展示需要处理的真实事项；针对已知事项、请求或执行 ID 的既定处理入口继续遵守各自作用域与实际状态校验，不因所属 Scope 归档而默认自动回答、批准或取消。此边界不增加归档任务浏览页，也不新增 Archived 行的运行数量指标。

### 7.2 逻辑 Shared 独立目录与产物交付

Shared Scope 只把无特定 Scope 的 Task 组织到同一视图组。当前无 Scope 的默认工作目录已经按 Task 分配，可作为复用依据；本轮无需为这组任务绑定一个公共 DIRECTORY 根目录。[S6]

此前核对到的是 DIRECTORY Scope 的占用与串行约束，不是已经证明存在某个竞态缺陷。最新方案通过各 Task 独立目录避免引入同目录写入和组级占用问题；不为逻辑 Shared 增加 `SCOPE_BUSY` 锁，也不改动其他真实目录 Scope 的既有规则。目录分开不等于操作系统级安全沙箱，本轮没有新增跨目录访问隔离工程。[S14]、[S17]

文件交付使用现有结构化结果和产物登记：只把明确登记的产物及必要结果信息回传 Main。中间文件、缓存和整个临时工作目录不自动列为产物；产物的当前路径应准确指回来源 Task/Execution。Agent 最近三轮对话、状态和错误原因仍按各自要求展示。[S7]、[S8]、[S9]

Task 临时工作目录清理后置。本轮保留当前文件供 `/open` 使用，不新增完成即删除或产物迁移流程。未来清理需要同时处理产物可用性和引用路径，但这不成为当前 TUI 交付的额外清理项目。逻辑 Shared 不因此新增归档管理功能，U07 的实体 Scope 归档含义不自动套用到这一视图分组。

### 7.3 主会话处理失败与 UNKNOWN 的现有边界

**Main 已具备处理基础，但没有 `task_control.retry` 动作。** 现有路径是 `task_query` 读取对象，使用 `task_propose` 的 `reuse_task_id`、`parent_execution_id` 发起同一 Task 的后续轮，或用 `task_control(cancel / cancel_request)` 取消明确执行/请求。重试是后续 Execution，不把原失败轮改回运行中；原有忙碌、计划和未确认操作等前提仍生效，通知 Main 不保证必然立即发起新执行。[S12]、[S22]

**失败行取消的产品含义已经确定，后端仍缺支持。** `cancel()` 对终态执行直接返回，Main 工具随后仍返回 `accepted: true`；这既不产生新的执行状态，也不记录“本次失败不再重试”。当前 `/attention` 只聚合授权和决策，没有现成失败处置状态，不能把该空操作当成已实现本轮要求。[S3]、[S19]、[S22]

B10 必须补充可由 Main 完成的失败事项处置，并将结果关联到准确的失败 Execution/结果。完成后原 FAILED 保留，待处理退出，重新查询和重开不复活；同一 Task 的新失败独立可见。具体采用现有业务记录、事件或最小新增投影由实施决定，不在本文虚构一个已经存在的 API；不因此增加计划关闭、未来周期取消或 UI 审计系统。

**状态刷新有现成基础。** 任务结果反馈本来就会进入 Main；Master 从失败行明确提出的重试/取消是追加的业务指令，不是首次把失败事实告知主会话。现有 `SyncService` 会对 TaskPlan、Execution、TaskResult 等变化发出任务/执行相关资源失效信息；TUI 可据此重查实际状态，并让 Main 提示与 Task 展示一致。失败待处理投影和处置完成关联仍需补齐，不能只刷新会话文字。[S13]、[S23]、[S24]

**UNKNOWN 不是只有 bug 才会产生的代码状态。** 当前 Execution/Operation 使用 `RESULT_UNKNOWN`，反馈类型使用 `UNKNOWN`；本书的 UNKNOWN 是界面上的结果未知类别。外部 shell 已启动但超时、被中断或无法确认退出结果，program 的结果校验无法确认等路径都可能进入该状态，含义是副作用尚未查明。现有 Main 也有阻止仅因 UNKNOWN 反馈自动派生替代任务的约束。[S21]、[S22]

本轮产品要求是把 UNKNOWN 作为异常排查处理，不提供 TUI 裁定入口，不纳入正常失败重试菜单。它既不能被静默隐藏，也不能被自动改成成功或失败；既有证据、状态及后端核验/恢复接口保留。对未知执行发取消也未必立即消除未知状态，不能把“不做裁定入口”解释成已获得自动处置结论。[S3]、[S19]

### 7.4 本轮评审核实的支持缺口

| 问题 | 核实事实与实施边界 |
| --- | --- |
| Scope 创建时间 | WorkScope 只有可变的 updated_at，没有独立 created_at；创建与修改均记录 scope.saved。B03 需要可信的创建时间投影，可从首次保存的业务记录/事件取得或补最小字段；不能按最新 updated_at 冒充创建时间。[S14]、[S20]、[S33] |
| 授权批准后的待处理 | attention 的集合包括 APPROVED，但批准操作已经完成。TUI 的“待 Master 处理”筛选要排除这些已批准项；不是等待后续操作消费授权，也不删除授权历史。[S3]、[S32] |
| 历史游标 | Main 时间线游标绑定 thinking/streaming，正文游标还绑定版本；服务实例随机密钥使重启前游标失效。B01 以稳定消息定位恢复，不要求修改 Core 为永久游标。[S3]、[S31] |
| 旧失败能否继续重做 | 默认退役阈值为 172800 秒，基于结束/最近活动时间并受等待、未知操作和反馈等条件影响；并非所有失败都必在结束 48 小时后退役。继续任务拒绝 RETIRED 的父 Execution，且还有必须为最新轮等前提。界面需要如实报告不能重做，不能承诺任意旧失败都能原地重试。[S6]、[S12]、[S30] |

**旧失败处理已经确定：**已 RETIRED 或不满足现有继续前提时，明确报告不能按原执行继续及实际原因，不假报重试已经启动。原失败提示仍可按 C09 由 Master 明确选择“不再重试本次失败”并完成处置后退出；不能因重试被拒绝而自动隐藏。若 Master 仍要重新执行，由 Master 经 Main 明确提出新的工作，再沿普通任务提案链路承接；不自动延长留存、不重新激活 RETIRED 执行、不偷偷新建 Task，也不把新工作冒充原 Execution 的恢复。历史 FAILED 始终保留。

失败提示应绑定具体失败及其后续处置；周期任务的无关后续成功不等于指定失败已重做成功。是否将同一 Task 的多次尚未处置失败合并呈现可以继续评估，但不能通过合并丢失真实目标或永远屏蔽新失败。

## 8 已确认裁定与实施参数

### U01 命令登记与图片入口 本轮收紧

**已定：**详情命令 `/taskdetail <task_id>`；`/show <item_id>` 指整个事项；正式拼写 `/rawmessage`、`/cancel`；首版不提供直接创建任务入口，由 Main 主会话发起任务。

**未纳入必做的候选：**是否另设直接继续任务的 TUI 入口、是否给 Main 额外提供 `/show`。Main 的既定键盘入口、失败行交主会话处理及 Task `/show` 可独立实施，不被这两个候选阻断。真实 Agent 最近三轮历史继续必做，不被“日志入口暂不做”撤销。

### U02 定向输入 已关闭

**已定：**Enter 先进入处理；未提交优先 Esc 退出，不适用时使用已验证并登记的组合键；目标失效报错并返回；Task 提交成功后回 Task 列表并刷新；原 Main/Task 草稿恢复，不把回答改投 Main。未提交事项回答退出后不要求保留；若保留需要额外存储或恢复逻辑就不做，既有组件自然保留可沿用并记录。

**本轮关闭：**授权或问题处理期间任意命令均不适用，包括全局导航、帮助和 `/send`、`/rawmessage`。问题允许字面斜杠答案，只交当前事项；授权只能接受合法的明确动作。退出后恢复普通命令规则。Esc 仅在事项流程确定，不据此增加普通 Task 非空草稿的全局导航快捷键。

### U03 历史缓存 已关闭

仅限制客户端内存缓存，不限制历史可浏览范围；淘汰内容可从现有日志重读。N、B、缓存上限 H 的数值和单位属于实施参数，记录后即可验收，不再保留总历史截断选项。

### U04 open 错误对象 已关闭

消失的是错误提示，TUI 保持运行。错误只报一次、短暂可见、不长期驻留；显示时长作为实施参数记录，不要求零帧消失，也不再询问是否退出整个客户端。

### U05 失败处置与旧失败重做边界 已关闭

**已定：**Master 从失败行提交意图给 Main session，由主会话执行并按真实结果刷新。对应重做成功后退出提示；处理失败报错并保留任务标记；已回答或批准事项操作完成即移除；UNKNOWN 独立展示、无裁定入口。

**本轮关闭：**取消表示不再重试本次失败，完成真实失败处置后退出待处理，历史 FAILED 保留；不关闭计划、不停止未来周期、不取消其他请求/执行。处置须绑定这次失败，重查或重开不复活，同一 Task 的新失败不被屏蔽。该语义不再待定，B10 的支持方式由实施决定。

**本轮关闭旧失败边界：**不能沿现有路径继续时明确报错并保留提示；Master 可选择结束这次失败提示。仍需重做由 Master 经 Main 明确提出新的工作，不自动创建或延长留存、不冒充原执行恢复。第 7.4 节和 AC21 记录具体行为；无须再次裁定此项。

### U06 逻辑 Shared 与独立目录 本轮替换并关闭

最新决定覆盖 v1.3 的同目录方案：Shared 是逻辑 Scope；各 Task 使用自己的临时工作目录；完成时交付登记产物；清理后续添加。Shared 共目录绑定、组内 DIRECTORY 锁及相应串行取舍已撤销，不再作为待选题。目录路径与展示映射按实施配置登记，不新增旧目录搬迁或跨目录安全沙箱。

### U07 Scope 归档 查询排除已定 后端语义沿用

当前已实现的含义已在第 7.1 节列明：标记 ARCHIVED、阻断新工作和未开始执行，保留已开始执行收尾、目录与历史；不级联终结 TaskPlan 或未来调度，也没有公开恢复入口。

**本轮查询范围已定：**Task ID 查询暂不覆盖归档 Scope 下的任务，详情入口及补全也不能旁路命中；未归档的已完成历史任务仍可查询。TUI 的归档数量展示和检索后置继续有效。

当前后端归档语义沿用。若以后要求“归档 Scope 时一并停止或归档所属任务”，再另行确定运行、等待、未来周期和队列的处理，不自动加入本轮 TUI 必做范围，也不把这一后续取舍当作本轮查询排除的阻断项。

### U08 Agent 最近三轮 已定

默认最新 Execution；本轮展示最近三次，不做轮次切换。C08 明确了本稿的具体呈现解释：三次包含最新，在同一详情连续分组展示、普通滚动阅读；不足三次则按实际数量。无需再裁定默认哪一轮或是否增加切换器。更早轮次与恢复已经不可取得的记录不自动纳入。

### U09 导航 排序计数 草稿与暂停计划 已关闭

**已定：**启动 Main；重复 `/M`、`/T` 无额外动作；返回恢复离开时阅读位置；Main/Task 一级页 `/back` 无操作，内部视图仍返回上一级。

**本轮已定：**有最新调起活跃 Task 的组在前；无活跃 Task 的普通 Scope 按创建时间倒序；组内 Task 按最近一次执行时间倒序。页头 Scope 总数不计空、Shared、历史，组内只计当前 Task，Shared 自己的当前 Task 正常展示。Task 详情不建设独立草稿，仅保留 Main/Task 两份普通草稿。

**实施登记即可，不需重开产品选择：**准确时间字段及标签、尚未执行 Task 的空值位置、同值稳定顺序、无活跃 Task 的逻辑 Shared 稳定位置，以及按对象 ID 保持重排后的阅读与选择。不能以这些参数尚未登记为由把排序、计数、根页返回或草稿粒度继续列为未定。

**本轮关闭：**没有未终结执行、排队或待处理事项的暂停计划不默认展示，也不计入当前数量；未归档者仍可按 ID 定位并查看真实暂停状态。存在实际执行或等待时不能一并隐藏。输入首行上键选择/筛选 Scope 仍是可选交互，不设首版阻断。

## 10 可直接执行的验收操作

### AC01 真实终端 启动 双入口与阅读位置恢复

- **前置：**目标 macOS 终端、连接可用 Core、输入框为空；有非空真实 Task 样例，至少能区分正在执行和等待中的任务。
- **操作：**启动后确认 Main；停在一条历史消息中段，提交 `/M` 和根页 `/back`；再 `/T`，核对真实 Task 的 ID、执行状态及所属分组，滚到一个可识别对象后重复 `/t` 和根页 `/back`；用 `/m` 返回核对 Main 位置，再 `/T` 核对 Task 位置。进入已实现的内部视图后执行 `/BACK`；有新消息时复用 AC08。命令均从空输入开始。
- **预期：**每次启动进入 Main；双入口整屏切换，命令不分大小写；重复导航与一级页 `/back` 均无额外动作、提示或消息，不重置阅读位置。内部视图 `/back` 返回上级，往返恢复最近阅读对象和位置。Task 展示真实执行状态，不能用计划 ACTIVE 冒充正在执行；底部输入可用，后台继续。
- **失败判据：**有效 `/T` 不切换、只有空路由或假数据、所有 Task 只显示 ACTIVE 却标成执行状态、根页返回跳页或报错、返回丢失可恢复锚点、切到浏览器、导航作为聊天发送、增加跨页常驻菜单或侧栏。
- **分段验收：**首批完成真实双入口、基本状态投影、重复导航与根页无操作；缺少必要执行状态时随首批补最小读取投影。内部详情返回随批次三验收，不提前要求完整计数和排序。

### AC02 窗口尺寸与页面容量

- **前置：**Main 有长消息，Task 有超过一屏的任务；记录初始行列尺寸。
- **操作：**分别加宽、加高、恢复窗口；在两个一级界面重复。
- **预期：**同一布局显示更多内容；输入框仍可见；中文和宽字符不把相邻内容覆盖；Main 的活动区域保持在输入框上方。
- **失败判据：**宽度触发新侧栏或列表详情双栏、内容与输入重叠、放大后丢失当前对象。

### AC03 消息类型 颜色与分割线

- **前置：**同一会话含 Master 发言、模型回复、工具调用、推理及摘要。
- **操作：**逐项观察默认显示，再展开推理。
- **预期：**普通模型正文白色；Master 浅蓝且有上下分割线；工具专用颜色并另起行；推理浅灰；不同类型有独立起行边界。
- **失败判据：**所有内容同色、工具与普通正文混行、Master 分割线缺失、长工具文本为占一行而被静默删掉。

### AC04 Markdown 呈现

- **前置：**准备第 9 节固定 Markdown 样例，并记录支持语法列表。
- **操作：**让同一内容以完整历史消息及流式回复两种形式出现；查看窄一些和宽一些的窗口。
- **预期：**段落、标题、强调、列表、引用与代码层级可辨；代码中的字符和缩进保留；已登记的表格、链接等语法也正确显示。流式中已经形成完整的 Markdown 块应正确呈现；尚未闭合的标记允许暂态，输出结束后与同内容的历史读取结果一致。
- **失败判据：**全部 Markdown 原样堆成普通文本、列表层级丢失、正文或代码内容被丢失或改写、流式结束后仍与完整历史渲染不一致。不以每个未完成 token 前缀都达到最终排版作为验收要求。

### AC05 CoT 全消息开关与跨视图继承

- **前置：**Main 有多条 CoT 消息和无 CoT 消息；另有带推理内容的 Agent 任务历史。
- **操作：**在 Main 执行 `/CoTvIsIbLe`，查看现有消息并继续上滚；接收新消息；进入 Agent 历史；回 Main 用 `/cotv` 收起。
- **预期：**所有消息按同一开关显示；新消息及补读消息一致；Task 中推理继承状态；无 CoT 消息不虚构内容；普通日志不被当作 CoT。
- **失败判据：**只展开选中一条、补读后恢复另一种模式、别名失效、为显示重新调用模型。

### AC06 CoT 阅读锚点 游标恢复与不补写日志

- **前置：**Main 已补读至少两页，记录当前消息 ID 及正文位置；样例含已持久 CoT、无 CoT，以及可用时的仅临时 CoT。选择安静会话，排除正常后台新消息影响。
- **操作：**展开、收起 CoT，每次切换后继续越过一次分页边界，再返回记录的正文位置；对照相应消息原记录。
- **预期：**仍可恢复同一消息及正文位置，后续分页使用当前读取条件。旧游标因 thinking 等读取范围变化而失效时，通过现有按 message_id 定位能力重新取得有效分页，不反复重用旧游标。无新增用户消息、重复消息或因显示操作补写的推理；临时内容已不可取得时如实说明。
- **失败判据：**切换后跳到最新、旧游标使后续历史永久不可读或循环报错、消息重复或遗漏、原先没有 CoT 的记录被显示操作补写或伪造。
- **边界：**本项验证既有分页与定位能力的正确使用，不要求临时游标跨读取条件永久有效，不新增历史库或游标持久化工程。

### AC07 近期启动 连续上滚与缓存淘汰后重读

- **前置：**历史超过首批 N、多个补读批次及缓存 H；记录 H 的数值、单位和缓存占用观察方式。
- **操作：**启动观察定位；持续上滚，读取内容总量超过 H，使较早加载的一部分被回收；再反向滚动，重新读取被淘汰的消息和一条长正文。
- **预期：**本次启动首次 Main 只读近期并定位最新，上滚再补读；缓存占用按登记上限受控，被回收消息仍能从既有日志重读；顺序和正文完整、无重复和缺口，阅读位置正确。本次启动以来消息和更早仍可取得的历史，不因缓存边界消失。切页返回恢复上次阅读锚点，不重新套用首次启动的最新定位。
- **失败判据：**H 被实现成最多可回看条数、只减少可见行却把全部历史常驻缓存、淘汰后无法重读、分页漏消息或长正文只显示首片、删除持久日志来满足缓存限制。

### AC08 新消息不自动跳转

- **前置：**Main 可持续产生新消息。
- **操作：**停在一条历史消息中间，接收新的回复；以 AC01 的空输入导航方式切到 Task，在 Main 又有新消息后返回；再手动到最新位置，继续接收另一条回复。
- **预期：**均不因新消息到来而强制改变阅读位置；切页返回仍是离开前的阅读锚点；输入框中的编辑不被打断。
- **失败判据：**自动滚到底部、阅读锚点换成新消息、正在编辑的内容被流式刷新覆盖。

### AC09 历史读取失败 游标失效与恢复

- **前置：**已有至少两页历史加载成功，记录正在阅读的消息 ID 和正文位置，输入框有草稿；使用安静样例。
- **操作：**先在上滚补读时制造一次可恢复读取失败，进行普通编辑后恢复读取。另验证一次旧游标失效：受控重启 Core，或等效返回一次游标过期结果，二选一即可；随后继续补读并核对原阅读位置。
- **预期：**普通错误在加载位置出现，下一操作后清除，已读历史和草稿仍在。旧游标失效不作为历史终点；客户端可通过现有按消息 ID 定位能力重取有效分页并恢复阅读，消息不重复、不遗漏，无需重开 TUI 或清空草稿。
- **失败判据：**整页清空、错误写入 Main 历史、持续重放失效游标、因过期永久停止补读、回到错误消息或强制最新、草稿丢失、另建历史库绕过恢复。
- **边界：**一次明确的过期恢复场景即可，不扩成多轮 Core 故障或性能测试矩阵；CoT 读取范围变化复用 AC06。

### AC10 Scope 分组 排序与计数

- **前置：**两个普通 Scope 的活跃 Task 先后调起；另有两个无活跃执行但仍含当前任务的普通 Scope，创建时间不同。再备空 Scope、仅历史任务的 Scope 和含当前任务的 Shared。组内含最近执行时间不同的 Task 及尚无 Execution 的 Task，数据超过一屏或一页。
- **操作：**进入 Task，核对页头及各组数量，滚动加载后续内容；在另一组调起活跃 Task，观察顺序。更新旧 Scope 的无关信息，并让较早创建的 Task 产生更新一轮执行；再定位一条未归档历史任务，核对当前计数没有随查询增加。
- **预期：**最新调起活跃 Task 的 Scope 优先；无活跃 Task 的普通 Scope 按真实创建时间倒序，不能用 updated_at 冒充。组内按最近一次执行时间倒序；无 Execution 的 Task 仍显示，按登记的稳定空值规则放置。页头只计符合当前集合的普通 Scope，不计空、Shared 或仅历史分组；此样例为四个。各组另列自己的当前 Task 数，Shared 的当前任务照常计入本组；不新增全局 Task 总数。分页前后去重、计数及排序口径一致。
- **失败判据：**任意更新冒充新调起或创建时间、按 Task 创建时间代替最近执行时间、因无 Execution 隐藏定时任务、只排当前页、把加载行数当总数、重复计 Task、把 Shared 本组数量写成零、历史查询抬高当前计数、重排改变操作目标。已结束且无待处理或未来调度的一次性任务不能仅因计划 ACTIVE 永久算作当前任务。
- **实施登记：**说明真实 Scope 创建信息的来源与必要投影、最近执行时间字段、空值和并列值的稳定次序，以及 Shared 无活跃任务时的位置；不为逻辑 Shared 伪造实体 Scope 创建时间。计数排除不等于另行决定空组必须隐藏。

### AC11 计划与各执行状态

- **前置：**包含正在执行、仅计划有效、定时未执行、排队、等待授权、等待回答、结果未知、取消中和初始化失败；另有纯暂停无其他工作的计划，以及暂停但仍有执行/待办的对照。
- **操作：**进入对应 Scope 查看状态与当前计数；对比两个暂停样例，按 ID 定位被默认排除的未归档暂停计划；推动一个任务状态变化后刷新。
- **预期：**应显示的等待和异常状态均存在；计划有效与当前执行状态分别表达；UNKNOWN 保持结果未知的真实状态并作为需排查的异常，不提供裁定入口、不自动重试；某轮成功不会被无条件写成整个计划关闭。纯暂停且无其他工作的计划不进默认列表或当前计数，按 ID 仍可定位为 PAUSED；暂停但仍有执行/等待者正常显示。
- **失败判据：**所有 ACTIVE 都标为正在执行、等待项消失、错误状态被过滤、UNKNOWN 被猜成成功或普通失败、增加未批准的裁定入口、状态更新对应到另一任务、默认展示纯暂停计划、把仍在执行/等待的暂停对象一起隐藏、把查询到的暂停计划伪装为已完成。

### AC12 Shared Scope 逻辑分组与归档计数

- **前置：**两个属于当前集合的无 Scope Task、一个未归档历史 Task，以及两个已归档实体 Scope。
- **操作：**进入 Task，查看 Shared、页头 Scope 总数与归档数量；定位未归档历史任务后再次核对计数。
- **预期：**当前无归属任务进入同一个逻辑 Shared，Shared 本组显示两个当前 Task；Shared 不计入页头普通 Scope 总数，但组及条目照常显示。Archived Scope 单列实际数量，不展开任务；历史查询不增加当前计数。
- **失败判据：**每任务一个 Shared 分组、因页头不计 Shared 就隐藏它或把本组数量改为零、归档任务正常展开、归档数错误、把临时历史查询结果算作当前任务。
- **边界：**独立工作目录与产物交付另见 AC33。本项不增加全局 Task 总数、Shared 实体 Scope 或归档管理动作，不修改现有 Scope 归档业务。

### AC13 同一 Task 不并发执行

- **前置：**真实 Core 中一个 Task 正在执行；准备该 Task 的下一次定时触发及一个继续请求。
- **操作：**在首轮未终结时触发后续工作，分别核对 Core 和 TUI。
- **预期：**同一 Task 不同时运行两轮；排队或忙碌拒绝与实际后端规则一致；界面只计一个 Task，计划属性与当轮状态同时可辨。
- **失败判据：**后台已运行两轮但 UI 隐藏一轮、同一 Task 在不同状态分组重复计为两项、误把不同 Task 全部串行当作本需求。

### AC14 历史 ID 查询只定位并排除归档

- **前置：**有完整 ID、唯一短 ID、不唯一短前缀及不存在 ID；另有已完成但 Scope 未归档的任务，以及 Scope 已归档的任务。
- **操作：**在 Task 主界面分别提交 `/search_task <实际ID或前缀>`；检查定位、错误和补全候选；用同一归档对象的完整 ID 核对 `/taskdetail` 不旁路打开。
- **预期：**可浏览范围内完整与唯一短 ID 定位正确条目，不自动进入详情；未归档的已完成历史任务可命中；归档任务不进入结果、补全或详情。范围内不唯一和不存在明确报错，查询不改变任务业务状态，也不因定位历史任务而增加当前计数。
- **失败判据：**搜索直接打开详情、猜测不唯一目标、把所有已完成任务都过滤掉、归档对象被另一入口展开、定位错误对象、错误长期驻留。
- **边界：**查询排除不删除后端数据、不改变归档行为；归档范围已定，不再依赖 U07 另作选择。

### AC15 taskdetail 与最近三轮真实 Agent 对话

- **前置：**同一 Agent Task 有四次可区分的真实 Execution，每轮含不同消息；另有不足三轮的 Agent Task 和一个普通程序任务。
- **操作：**在 Task 列表记录阅读对象后输入 `/taskdetail <完整task_id>`；观察初始位置，滚动阅读最新三轮及其中一轮长对话；核对没有第四旧轮次的独立历史区块；再查看不足三轮任务，最后 `/back` 返回核对列表位置。归档详情排除复用 AC14 同一对象。
- **预期：**默认定位最新 Execution；同详情分组展示最近三轮，三轮包含最新；轮次不足时按实际数量；每轮内部可以补读长历史，Task 和 Execution 归属清楚。没有轮次切换器，不以 Main 摘要替代真实 Agent 消息；返回恢复列表最近阅读位置，不因日志入口后置而取消 Agent 历史。
- **失败判据：**只有结果摘要、只展示最新一轮而缺少另外两轮、混入其他 Task 或把多轮标成同一轮、自动增加第四旧轮次的历史区块、每轮只留第一片、虚构缺失记录。三轮内消息原本引用更早内容不算越界。
- **实施依赖：**B02 读取接口；正式命令、默认轮次和三轮范围已经确定，不再依赖旧 U01/U08 选择题。此处用完整 ID，不新增详情命令必须接受短 ID 的要求。
- **草稿边界：**不建立按 Task ID 或详情页分别保存的草稿；不把详情草稿恢复列为验收要求。底部命令输入和既有 Main/Task 普通草稿规则继续适用，不因此增加向 Agent 直接聊天的入口。

### AC16 Main 活动区 先后顺序与已看颜色

- **前置：**输入为空；按先后发起多个授权和决策，另有确定失败与 UNKNOWN；更新一个旧事项但不重新发起它。
- **操作：**在 Main 查看区域，进入一项阅读但不提交，按已登记的 Esc 或替代键退出处理，再从空输入切到 Task；核对本次仅查看操作对应的接口调用。
- **预期：**区域在输入框上方，多项按发起时间新到旧；旧项更新不冒充新发起；失败单列，UNKNOWN 独立作为需排查异常，可定位对象且无裁定操作。已看较深、未看较浅；查看不等于处理。Task 没有该提示区域。已看变色不调用 Execution 的 viewed 接口，也不改变执行留存状态。
- **失败判据：**出现侧栏、只能显示一项、只排序当前页导致新项遗漏、查看就被标为已处理、借 viewed 接口实现已读颜色、UNKNOWN 混入普通失败或授权、出现裁定菜单、Task 常驻该区域。
- **边界：**接口核对只需证明查看没有触发错误业务动作，不建设 UI 阅读审计或新的已读持久化系统。

### AC17 上键编辑边界和事项选择

- **前置：**Main 输入框有两行未发送文字，上方有至少两个待处理事项。
- **操作：**从第二行按上键到第一行，再按上键；用上下键选择事项，按 Enter。
- **预期：**先正常编辑移动，再进入事项选择；焦点和目标可辨；Enter 只进入处理。进入前后授权或决策仍待处理，不批准、不回答、不移除，也不发送 Main 草稿。
- **失败判据：**第二行就丢失输入焦点、选择行刷新后操作错对象、Enter 直接提交批准或回答、原 Main 草稿被发送或丢弃。

### AC18 Main 定向回答 批准完成与原稿恢复

- **前置：**Main 有未发送草稿 A、文字决策 D 和待批准授权；任务收到回答或授权后仍需继续执行。准备能观测批准后为 APPROVED、尚未 CONSUMED 的授权样例。
- **操作：**通过上键、选择和 Enter 进入 D，输入不同文字 B，用记录的发送操作提交；再进入授权，核对完整的实际动作、对象/资源及当前显示，随后明确批准。在授权仍为 APPROVED 时观察待处理区，刷新一次后复核。
- **预期：**B 只提交给 D，批准只作用于当前显示对应的授权，参数绑定实际 revision/display_hash；回答操作完成、授权确认 APPROVED 后立即移出待处理区，不等 CONSUMED 或整个 Task 完成。即使底层待处理查询仍返回 APPROVED，界面刷新后也不重新显示为待批准。两次返回均恢复原稿 A，B 不成为新的 Main 消息。
- **失败判据：**B 发给 Main 或其他事项、A 被覆盖、未展示实际授权内容或把旧参数的拒绝误报为成功、请求刚发出就显示已处理、批准后仍等待消费或 Task 结束才移除、刷新使已批准项复活、返回后仍绑定旧事项。
- **边界：**不删除授权记录，不由本项增加记住授权、撤销等新入口；授权/问题处理期间的命令禁用另见 AC24。

### AC19 Task show 与普通 Task 输入区分

- **前置：**Task 中有待回答事项 D，D 显示多个答案选项，其中一个允许的字面答案为 `/M`；另准备普通 Task 草稿。
- **操作：**普通浏览时提交一段文本并确认仍为草稿；由验收者正常编辑清空，再输入 `/show <D整个事项的ID>`。核对整个事项后，输入字面答案 `/M`，用记录的发送操作提交。
- **预期：**前一段留为草稿，不创建任务；`/show` 打开整个 D，不替用户选择答案。在问题处理状态，`/M` 没有导航命令效果，字面内容只作为 D 的答案提交；成功后回 Task 的 Scope 列表并刷新，状态与 Core 一致，不跳 Main。
- **失败判据：**普通 Task 文本误发或自动建任务、把事项 ID 当选项 ID、问题处理仍执行导航命令、答复落错对象、定向输入被一律拒绝、成功后滞留处理页或列表未刷新。
- **边界：**命令在处理状态不适用，不等于禁止以斜杠开头的合法问题答案；授权仍只能采用合法的批准或拒绝动作。

### AC20 目标失效 报错并自动返回

- **前置：**分别从 Main 与 Task 打开有效事项；在另一个合法入口处理或使该事项失效；本客户端尚有未提交回答。
- **操作：**尝试提交，观察错误与返回；不再额外按返回键帮助界面退出。
- **预期：**明确反馈已处理或失效并自动返回。Main 恢复原输入草稿；Task 返回列表并刷新；不会重复改变业务状态、改投 Main 或假报批准成功。返回过程不能把错误吞掉。
- **失败判据：**必须再按键才能离开失效处理状态、错误不可见、回答误发 Main、过期参数被接受为成功、原草稿被覆盖。交由 Core 校验旧请求并正确显示拒绝，不算失败。
- **回答保留：**失效返回后未提交回答可以不保留，不能据此判失败，也无需新增回答存储或恢复逻辑；原 Main/Task 草稿仍必须保护，旧回答不得回填给另一个事项。用户主动未提交退出另见 AC34。

### AC21 失败行委托主会话 真实处置与状态刷新

- **前置：**Main 有原稿 A，Task 普通输入为空；准备可重试失败、已终结 FAILED 和处理失败样例，记录各失败所属 Task/Execution。
- **操作：**进入失败行但先不提交，确认无自动操作；明确交 Main 重试并观察后续轮。另对终态失败明确选择取消这一失败的重试，核对处置完成和历史状态。先确认 A 完整恢复，再人工清空 A，执行 `/T` 查看状态，从空输入 `/M` 返回。复用 AC30 的重开步骤核对已处置项，并验证同 Task 后来的另一项失败及一次实际处理失败。
- **预期：**准确目标与意图经 Main 处理，A 不误发，TUI 不再重复直调。重试产生关联原 Task/Execution 的后续工作，成功后退出原失败提示。终态失败的取消表示不再重试这一失败：真实确认处置后退出待处理，刷新、重连或重开均不复活；原 Execution 仍为 FAILED、历史可查，不关闭计划或取消其他工作。后来的另一项失败不被旧处置屏蔽。仅接收请求、重试尚未成功或处置尚未完成时不移除；处理失败保留任务标记。真正取消请求/执行另按 AC29 验证。
- **失败判据：**只凭 Main 口头答复或终态 cancel 的空操作回执退出、把 FAILED 改成 CANCELLED/SUCCEEDED、仅本地隐藏后重开复活、永久屏蔽整个 Task、重复发起重试、顺带停止未来计划、界面长期不刷新、失败标记随瞬时错误消失、把 UNKNOWN 纳入普通重试。
- **边界：**终态失败处置含义已经确定，不再保留该选择题；需有可重读且关联具体失败的真实处置结果，具体存储/投影由实施决定，不新增 UI 操作流水或直接 `/retry` 命令。
- **旧失败分支：**准备一个 RETIRED 或其他确实不能继续的旧失败，向 Main 提出重做。应明确反馈原执行不可继续及原因，保留原失败提示；再明确选择不再重试，完成处置后退出且历史仍为 FAILED。如需验证新工作，另由 Master 在 Main 明确提出，走普通提案链路并保留新旧身份。自动延长留存、自动创建新 Task、把拒绝假报为重试启动或偷偷删除旧 FAILED 均失败。

### AC28 macOS 中文输入 换行 补全与终端预检

- **前置：**实际目标终端和真实系统输入法；共用一份记录发送、换行、补全、滚动、Esc、图片粘贴和退出的键位表，不预设某组合键在所有终端都可用。

### AC30 退出 重开与后台持续运行

### AC32 图片直接粘贴与失败保留

- **前置：**真实目标 macOS 终端，系统剪贴板有合法图片，Main 有文字草稿；核对实际模型支持图片、既有 vision/budget 配置可用，样例符合当前导入契约的格式与数量限制。另备普通路径文本及导入/提交失败样例，记录实际粘贴动作。前提不满足先明确记录，不要求新增配置界面或模型能力。

### AC33 Shared 逻辑归组 独立目录与产物交付

- **前置：**准备两个未指定 Scope 的任务要求 A、B：各自在工作目录生成 `report.txt`，内容分别带 A、B 标记，仅把它登记为产物；另产生一个不交付的中间文件。
- **操作：**通过 Main 发起 A 并确认完成，再发起 B 并确认完成；记录两次实际工作目录，核对两个同名文件的内容。在 Task 检查逻辑分组；已退出默认集合的任务用 `/search_task <task_id>` 定位。检查 Main 的产物条目，再分别 `/open` 两个明确路径。
- **预期：**A、B 属于同一个逻辑 Shared 组，实际工作目录不同；相同相对文件名互不覆盖。Main 只列登记产物及必要结果信息，不自动交付中间文件或整个目录；两个 `/open` 分别打开正确 Task 的当前文件。完成后没有新增自动删除源文件的步骤。
- **失败判据：**因逻辑同组而把两个 Task 绑定同一实际目录、同名文件互相覆盖、只交付整个工作目录、中间文件被自动列为产物、当前路径落到错误 Task、完成即删导致无法打开、为了 Shared 分组新增统一 DIRECTORY 占用锁。
- **分段验收：**Task 批次验证真实发起、分组、独立目录与同名文件互不覆盖；产物批次验证回复条目、只交付登记产物及 `/open`。只完成前段不能勾选整项通过。
- **边界：**本项不验收未来目录清理、跨目录访问权限隔离或并发压力，不要求迁移旧目录；既有容量限制及同 Task 不并发约束继续适用。

### AC34 未提交时 Esc 退出处理

- **前置：**Main 有原稿 A 和一个有效待回答事项；另准备 Task 的空输入及一个有效事项；记录实际退出键，优先 Esc。
- **操作：**在 Main 通过选择进入事项，输入回答 B 但不提交，按 Esc；确认原稿 A 完整恢复后，由验收者主动清空这段测试草稿，再执行 `/T`。从 Task 的空输入执行 `/show <事项ID>`，输入未提交内容并按 Esc。若目标终端确实不能使用 Esc，按记录的替代组合键重复。
- **预期：**两次均退出事项处理，不产生批准或回答；Main 原稿 A 恢复，Task 回到进入前的浏览和普通输入；Core 中事项仍待处理。退出处理不会退出 TUI。
- **失败判据：**Esc 误发送、误批准、关闭客户端、覆盖原 Main/Task 草稿、没有可用退出方式、未记录就假定某组合键有效。
- **回答保留：**退出后 B 不保留不算失败，不为保留新增存储或恢复逻辑；既有输入组件无额外代价自然保留可以接受，但 B 不得覆盖 A 或复用给另一事项。原稿恢复、无业务提交及可退出均必须通过；不把 Esc 扩展成普通 Task 草稿的全局导航键。
- **命令边界：**授权/问题处理期间包括 `/back` 在内的所有命令均不适用；本项使用 Esc 或已验证的替代退出键。一级页 `/back` 的无操作规则见 AC01，不将它当作处理状态的退出方式。
