## 1 需求权威与实施边界

### C01 新需求书作为实施依据

1. 本临时参考中已确定的条款作为 TUI 重建的当前需求依据；标为待定的行为不得由实现者自行补成产品决定。后续实施 issue 经 Master 确认划分后以本书为基础全面重写，旧 issue 中相冲突的文字不再作为当前要求。
2. 本轮重写范围为 #82 及之后全部 TUI 需求 issue。2026-10-30 盘点对应 #82、#83、#84；#85 至 #90 均为 PR，保留其实施、撤回及回滚历史。#81 及此前后端能力作为已完成基线，新增支持缺口跟随需要它的功能批次补齐，不将已完成基线重新实施。第 11 节只提出批次及编号映射，确认前不修改 issue 标题、正文、依赖或评论。
3. 后端不支持时，明确选择补充后端或调整需求，不得通过把旧接口限制包装成产品决定来缩减已定行为。
4. 采用分批实施、分批验收，不要求一批接入所有后端 API。每批记录实际接入能力及尚未接入的接口，不以接口覆盖率强迫扩展菜单。
5. 当前建设最小可用前端。Memory、World、Settings、Scope 管理菜单是后续可选建设项，并非永久排除。
6. 本轮不建设直接创建任务的 TUI 命令或表单。任务主要由 Main session（主会话）根据 Master 的输入发起；Task 提供查看与已确定的处理操作，不另立一套建任务流程。

首版运行于真实 macOS 终端，复用独立 Core 及本机接口。浏览器界面不能代替终端交付。退出 TUI 只断开客户端，不停止 Core、不取消后台任务、不创建新的权威主会话。

### 主要术语

| 术语 | 含义 |
| --- | --- |
| Main | 唯一主会话的界面 |
| Task | 一项任务 |
| Scope | 任务所属工作范围，可关联工作目录 |
| Shared Scope | 无特定 Scope 任务的共同逻辑分组，各 Task 使用独立临时工作目录 |
| TaskPlan | 后端任务计划对象，计划有效不等于当前正在执行 |
| TaskRequest | 提交给调度器的任务请求 |
| Execution | 某项任务的一次执行轮次 |
| Agent 对话历史 | 某 Task 的执行 Agent 实际产生的消息记录，不等于 Main 的任务摘要 |
| CoT | 模型已经提供且允许显示的推理内容 |
| 定向输入 | 已选择某个授权或问题后，底部输入提交给该事项的状态 |
| log | 现有会话或执行日志，客户端显示操作不向其中追加记录 |

## 2 界面结构与 Main 呈现

### C02 双入口与统一布局

- 一级入口只有 Main 与 Task，整屏切换。
- 跨页常驻范围仅为底部输入区域，可包含本版允许的底部提示行；不新增跨页常驻顶部菜单、状态栏或侧栏。各页面自己的标题不受此限制。
- 宽终端、高终端只让同一布局显示更多内容，不触发新的双栏布局。
- Main 的活动和待处理区域固定在输入框上方。Task 不显示这一提示区域。
- 可选的底部命令或错误提示行可作为输入区域的组成部分，不据此增加新的一级入口或业务面板。
- 不建设独立产物详情页，也不建设额外的执行过程仪表盘。

### C03 消息类型 颜色与 Markdown

| 内容 | 已定呈现 |
| --- | --- |
| 模型普通正文 | 白色 |
| Master 发言 | 浅蓝色，并有专门的上下分割线 |
| 工具调用及工具详情 | 使用浅粉色或另一种固定、可区分的专用颜色；另起一行 |
| 推理正文及推理摘要 | 浅灰色，降低视觉存在感 |
| 产物条目 | 位于模型回复末尾，使用与普通正文不同的颜色 |

不同消息类型单独起行，不能把工具输出、推理和普通正文混接成同一行。长内容可以正常换行，不把“单独占一行”解释为强制截断到一行。

模型输出的 Markdown 应正确呈现层级与格式。验收使用固定样例检查段落、标题、强调、列表、引用、行内代码和代码块；表格、链接等支持范围在实施说明中列明。数学公式、Mermaid、HTML 和内嵌媒体不能凭“支持 Markdown”被自动宣称全部支持。

具体色值、终端配色序号、行间距和分割线字符由实施者在目标终端上选择并记录，不重新打开已经确定的颜色语义。Master 发言的颜色和分割线、工具的独立行、推理的弱化显示均为验收内容。

### C04 历史加载与阅读位置

1. 启动仅加载近期一定数量的 Main 消息；首次进入 Main 定位到最新消息。
2. 继续向上滚动时，再加载更早消息，不新增一套历史库。
3. 新消息到来不自动跟随跳转，不强行把正在阅读的内容滚到最新位置。
4. 历史读取失败，在对应加载位置报错；保留已经显示的历史和当前输入。
5. 切换 CoT 前后保持阅读位置。这里保留的是正在阅读的消息及其正文位置，不要求展开后维持同一个绝对行号。
6. 上限只限制客户端内存缓存，不限制可回看的历史总范围。本次启动以来的 Main 消息均可持续上滚查看；继续上滚可读取现有日志中仍可取得的更早消息。被缓存淘汰的消息需要时重新分页读取，不能把淘汰边界伪装成历史起点。
7. 全历史全文搜索不纳入本轮。

首次加载量、每次补读量、缓存容量及其计量单位是实施参数，必须给出并用于验收。内存缓存限制不产生删除权威日志、另建历史库或缩短可浏览范围的要求。

### C05 CoT 与普通日志分离

- `/cotvisible` 与别名 `/cotv` 切换全部消息的推理展开和收起。
- 命令只在 Main 调用；Task 中的 Agent 思维链继承同一显示状态。命令可调用范围与显示效果作用范围是两个不同概念。
- 已显示、后续到达、随后补读的历史消息使用同一规则。无需一次性读取所有历史 CoT。
- 默认显示已有摘要或前 20 个可显示字符；无内容不虚构，不额外调用模型生成摘要。
- 展开、收起不新增 log，不补写此前未持久化的推理内容。
- 非 CoT 的执行日志使用独立查看入口。`/show logs` 是批注中的示例，最终语法见 U01。
- CoT 显示偏好允许跨启动保存，属于可选、低优先级功能，不设为首版阻断项。

## 3 Task 与 Scope

### C06 Scope 总览与默认展开

Task 主界面展示当前 Scope 的数量、每个 Scope 下的任务数量及任务条目。任务按 Scope 分组，条目默认展开，显示 ID、实际状态、时间等必要信息，不先把任务全部藏进折叠组。

| 分组 | 展示要求 |
| --- | --- |
| 普通 Scope | Scope 名称、任务数量及默认展开的任务条目 |
| Shared Scope | 所有无特定 Scope 的任务统一放在同一逻辑组，组内各 Task 使用独立临时工作目录 |
| Archived Scope | 只展示已归档 Scope 的数量，不展开其任务；归档 Scope 检索后置 |

批注中的 Scope1、Scope2、Shared Scope、Archived Scope 示例用于确定上述逻辑层次，不作为最终字符画或固定像素布局。

Shared Scope 的共同点是视图分组，不是工作目录。允许在统一父目录下按 Task 分配各自子目录，具体命名作为实施配置记录；不同 Task 的实际工作目录必须不同。临时目录以 Task 为单位，本轮不要求每次 Execution 重新分配目录，也不更改既有继续任务、周期执行的目录复用规则。

完成时只交付明确登记的产物，不自动交付整个临时目录及其中间文件。Task 临时工作目录的清理后续添加，本轮不新增完成即删除或退出即删除的动作。文件交付与 `/open` 的衔接见 C11、第 7.2 节及 U06。

归档 Scope 的当前代码含义见第 7.1 节；是否增加任务联动归档仍留 U07。仅在界面隐藏任务，不能据此声称任务已停止或已完成业务归档。

Scope 数量和任务数量必须标明实际统计含义，不能用当前已加载页的行数冒充总数。是否计入空 Scope、Shared Scope 是否计入页头 Scope 总数、组内计数是否含历史任务，见 U09。

**可选交互：**批注提出，可以在输入框第一行再按上键进入 Scope 选择或筛选，再以上下键和 Enter 操作。本版保留这一候选，不将“可以考虑”升级为首版强制要求；若采用，需登记焦点、返回和草稿保护规则，并保持任务条目默认展开。

### C07 计划状态与执行状态

1. 默认可见任务包括当前执行中的任务、定时任务以及仍应展示的活跃计划。
2. 排队、等待前提、等待授权、等待回答、结果未知、取消处理中、初始化失败等状态均应如实显示，不能只保留“正常运行”的行。
3. “当前活跃”用于表达正在执行；计划 ACTIVE 只说明计划有效、应在相应 Task 视图展示，不能直接标成“正在执行”。
4. 任务计划状态、当轮执行状态和最新结果分别表达。某轮成功不等于整个计划关闭。
5. 同一 Task 同时最多有一个未终结执行。定时任务当前正在执行，只计为一个 Task，同时展示计划属性和当轮状态，不重复计数为两项任务。
6. 不从“同一 Task 不并发”推导出所有 Task 必须串行；不同 Scope 或不同 Task 的调度沿实际后端规则处理。
7. Shared 的逻辑分组不新增组级 DIRECTORY 占用锁；不同 Task 的独立目录不因被放进同一视图组而互相占用。已有执行容量约束、同一 Task 不并发以及其他真实目录 Scope 的既有规则继续适用。

现有正常调度和继续任务路径已有同一 Task 忙碌校验。周期触发可排队，继续请求可返回忙碌原因；这是复用依据，需要有针对性地验证，不等于本次已经通过运行验收。[S6]、[S12]

公共列表必须补齐新视图所需的执行状态、计划或调度属性、筛选和计数数据。前端不能从一个 ACTIVE 字段猜出全部含义。

### C08 查询定位 任务详情与 Agent 历史

- `/search_task <task_id>` 在 **Task 主界面** 调用，支持完整 ID 和唯一短 ID。
- 查询结果在 Task 中定位，不自动打开详情。
- 不唯一短 ID 或不存在 ID 必须报错，不猜测目标。ID 查询不扩展成关键词全文搜索。
- 任务详情使用 `/taskdetail <task_id>`，在 Task 中打开。
- 返回使用 `/back`，回到逻辑上一级入口。
- Agent 类任务详情必须能显示该 Agent 的实际对话历史。
- 不额外建设执行过程仪表盘；这不取消已经确定的 Agent 对话历史要求。

任务条目至少能识别任务 ID、目标、真实状态和必要时间；详情至少说明目标、执行或等待状态、最新结果和可用操作。Agent 对话按 Execution 清楚分组，默认查看最新 Execution；本轮展示最近三次执行，不做轮次切换器，也不增加第四轮及更早轮次的独立历史区块或入口。每一轮内部的长对话仍支持分页阅读；范围按记录所属 Execution 判断，不因消息引用了更早内容就删改原文。

**本版呈现解释，供继续批注：**最近三次包含最新一次，总数最多三轮；在同一详情中按新到旧连续分组展示，默认定位最新一轮。不足三次时显示实际已有轮次。记录不可取得时说明实际情况，不补造内容。此解释落实“默认最新、展示最近三次、不做切换”，不另增加轮次选择界面。

历史任务若不属于默认可见集合，ID 查询仍须能定位命中对象；采用临时结果条目还是临时筛选可由实现说明具体化。归档 Scope 下任务能否通过直接 task_id 查询，单独由 U07 决定。

## 4 Main 活动区域与定向输入

### C09 输入框上方的活动与待处理

- 活动提示和待处理事项位于 Main 输入框上方的简短区域，不使用右侧栏。
- 授权、决策必须进入该区域；失败任务存在时单列一行；UNKNOWN（结果未知）独立单列，不混入普通失败或授权事项。
- 同时支持多项，按发起时间从新到旧排列，最新发起项在上。
- 看过的事项颜色较深，未看过的较浅；查看过不等于已经批准、回答或处理完毕。
- Task 页面不显示这块活动或待处理提示区。
- 失败任务在重做成功完成后退出原失败提示；取消实际完成后也可退出。仅收到重做或取消请求回执、仍在排队或执行中，均不算完成。
- 处理失败时显示错误，并在对应任务上保留显式失败标记；瞬时错误提示消失，不得同时抹掉尚未解决的失败状态。重做再次失败时，保留或更新该任务的失败标记，不显示为已经解决。
- 已回答或批准的事项，在相应回答或授权操作确认完成后立即移出待处理区，不等待整个 Task 执行结束。

显示条数、区域最大高度、溢出时的浏览方式属于实施参数，但实现必须保留到达全部待处理项的方式，不能只显示前几项后丢掉其余项。失败重做的具体入口、Main 如何转入仅 Task 可用的取消操作，以及 UNKNOWN 的具体裁定入口仍见 U05；是否显示 UNKNOWN 和已处理事项的退出时机不再悬置。

### C10 键盘选择与事项输入

Main 的已定交互路径：

1. 在输入框编辑多行文本时，上键首先按正常编辑规则移向第一行。
2. 光标已在输入框第一行时，再按上键进入上方待处理事项选择。
3. 用上下键选择事项，Enter 只选中并进入处理，不直接批准或提交回答；进入后再进行明确的批准、拒绝或发送操作。
4. 需要文字输入时复用下方输入框，提交内容针对该事项。
5. 完成输入并提交后，回到原 Main 输入，恢复此前的 Main 草稿。

Task 的已定交互路径：使用 `/show <item_id>` 打开授权或问题；参数指整个待处理事项的 ID，绝非事项内部某个答案选项的 ID。进入后，普通输入提交给这个事项，不作为 Main 消息，也不作为任意 Agent 聊天。提交成功后返回 Task 界面中的 Scope 任务列表，并刷新实际状态。

未提交时优先使用 Esc 退出处理，恢复进入前的 Main 或 Task 输入；如果目标终端无法可靠使用 Esc，可采用经实际验证的其他组合快捷键，并在帮助和验收记录中写明。退出处理不等于退出 TUI，也不构成业务提交。

目标已处理、过期或其他原因失效时，显示实际错误并退出该处理状态：从 Main 进入则返回 Main、恢复原稿；从 Task 进入则返回 Task 列表并刷新。错误提示必须在返回后仍有可见的呈现机会，不能随视图销毁而完全不可见，也不得把回答改投其他目标。

| 当前输入状态 | 普通文字提交的目标 |
| --- | --- |
| Main 普通输入 | 主会话 |
| Task 普通浏览 | 保留草稿，不发送到 Main 或 Agent |
| 已进入某个待输入事项 | 该明确选中的授权或问题 |

定向输入是本轮对旧功能页路由的明确补充。实现不能继续用“Task 普通文本一律不得提交”拒绝针对事项的输入，也不能继续允许 Task 中的 `/send` 向 Main 发送。

输入区必须能辨认当前对象与输入用途。授权选择对应明确的批准或拒绝动作，不能把任意自然语言直接当作合法授权值。[S5] Esc 后未提交的事项回答是否继续保留、定向输入时其他 Main 命令是否可用，仍作为 U02 的剩余小项；Enter、退出键方向、失效返回和 Task 成功返回刷新已经确定。

## 5 产物与外部打开

### C11 结果末尾的产物条目

1. 复用现有结构化 Task 结果及产物登记能力。
2. 在模型回复末尾罗列产物，使用与普通回复文字不同的颜色。
3. 每项展示含路径的名称和所属 Execution；有多个产物时，模型对每项给出解释。
4. 实施前检查 Task 回传和 Main 查询结果是否包含这些字段。缺失时补传递或投影，不能让模型编造路径或所属执行。
5. Main 的产物条目即为首版入口，不建设独立产物详情页。

**本版对“完成后只给回产物”的文件交付解释：**向 Main 交付明确登记的产物，不自动交付整个 Task 临时目录、缓存或中间文件。任务状态、必要结果摘要、Task/Execution 归属和已确定的 Agent 对话历史继续保留。无文件产物的任务不因此被要求额外制造文件；本轮复用已有产物登记，不另造一份存储体系。

### open 的对象已经确定

- `/open` 主要以文件路径为目标。
- 打开的是**工作区当前文件**，不是该次交付时保存的旧快照。
- 产物 ID 作为可选目标；若实现，必须先解析为对应当前工作路径，不能悄悄打开快照内容。
- 支持中文和空格路径，不通过 shell 字符串求值解释文件名。
- 绝对路径按其本身定位；相对路径必须有可查的基准，不能随选中项或当前页悄悄改变。
- Shared 不是公共文件根目录。每项产物必须准确定位来源 Task/Execution 的当前文件；不同 Task 都产生 `report.txt` 时，Main 条目与 `/open` 目标仍须可区分。只给出相同相对文件名而没有明确来源基准，不算完成路径交付。

目标不存在时仅报错一次，不误报成功、不持续刷错。Master 已明确退出的是错误提示，TUI 保持运行。错误按一次性短暂提示呈现后消失，具体可读停留时间由实施记录；不能让它长期驻留，也不能以退出客户端代替提示清除。

当前产物内容接口读取的是登记快照。新版 `/open` 必须依本轮选择实现当前文件定位，不能仅因为旧内容接口方便就改变对象。[S9]

### C13 草稿与命令识别

- Main 与 Task 的草稿独立，不因切页、补全或选中对象而自动提交。
- 本期不增加“保留非空草稿，同时进入临时命令模式”的功能。
- 只有输入的首字符为 `/`，且满足整次提交的已登记语法时，才作为命令处理。
- 普通正文之前已有文字，再在后面输入 `/T` 或其他命令样式，仍是正文。不要扫描最后一行、自动修剪前导正文或执行多条命令。
- 一次提交最多执行一条命令，不支持 shell 替换、管道和命令串联。
- 补全只编辑输入，不执行。
- `/rawmessage` 只对当前一次消息生效，下一次输入恢复正常解析。
- 定向输入前的 Main 草稿与事项回答内容分开保存，返回后恢复原稿。

因此，非空正文中直接追加 `/T` 不构成切页方式。本期验收不能为了方便擅自添加导航快捷键或双缓冲命令模式。是否需要每个 Task 详情单独草稿，仍列为 U09 的粒度问题；Main/Task 独立草稿本身已经确定。

### C14 多行粘贴和附件

多行粘贴采用 Master 指定的 Hermes 风格交互：有独立粘贴文本缓冲区，在输入区显示类似下面的摘要：

```text
<pasted xx lines xxx...xxx.txt>
```

摘要绑定真实内容；文件名和行数是显示信息，不替代正文。多次粘贴与手写内容保持顺序；发送时提交真实全文，不只发送摘要或临时文件路径。粘贴块内部的 `/T`、`/send` 或代码不会自动执行。

图片等附件沿明确导入链路处理。普通文本里的路径不自动变成附件。图文或图片发送失败时保留材料，不静默丢附件后只发剩余文字。`/attach` 是否保留及其范围尚未出现在新命令表中，见 U01。

### C15 错误和 UI 状态

普通错误按实际原因显示，下一次用户操作后清除，不长期驻留。历史加载错误首先在加载位置出现。UI 提示不写入 Main 历史，不产生新用户消息，也不建立滚动、展开、补全的持久交易流水。

可使用输入区内的固定底部提示行。错误出现和清除不能覆盖草稿，也不能被误当成模型回复。`/open` 的一次性错误提示消失时客户端继续运行；事项失效的错误随返回过程可见；失败任务的状态标记与瞬时错误提示分开，不能一起清掉。

“下一次操作”具体包括哪些按键，以及是操作开始还是完成时清除，属于实施时需要记录的小型交互细节；验收至少验证一次普通编辑或下一条合法命令后旧错误已消失。

### C16 业务输入与生命周期

真实发送、取消、授权和回答继续复用 Core 的接收与状态能力；不能把本地已发出显示成业务完成。断线或失败不静默丢稿，重试保持已有请求身份。这个要求不延伸为每次客户端显示操作的审计。

取消必须明确请求或执行对象；无参、双目标、无效 ID 不执行。取消一轮 Execution 不代表未来周期计划已经停止。

允许采用 Ctrl+C 退出而不另做 `/quit`；批注将其作为可考虑方案，具体退出键在 macOS 输入预检时记录。无论使用哪个出口，都只退出 TUI，后台继续。

既定临时材料规则针对 TUI 草稿、粘贴正文、附件及未交接内容：已可靠交接的文本副本及时清理，其他临时或孤立记录默认三个日历年，活跃引用受保护。该期限不要求保留 UI 操作记录。旧 Tauri 未发送数据不迁移。

Task 临时工作目录的清理是后续工作，不因上述材料规则自动套用同一删除时限，也不要求目录必须位于系统 `/tmp`。本轮不新增目录回收器、完成即删除、产物搬迁或旧目录迁移。后续加入清理时再处理产物保留与 `/open` 路径衔接；本轮不得先删掉仍需交付和打开的文件。

### 7.1 Scope 归档 当前代码已经实现的含义

**结论：归档已经实现，其作用是关闭该 Scope 的新工作入口并阻止未开始的执行，不是把所属 Task 一并终结。** 当前入口是 `POST /api/v1/scopes/{id}/archive`，使用 `request_id` 和 `expected_revision`；`Scopes.archive()` 将 Scope 从 ACTIVE 改为 ARCHIVED 并记录 `scope.archived`，不遍历修改任务或删除文件。[S3]、[S14]、[S15]

| 对象或动作 | 当前代码的实际行为 | 依据 |
| --- | --- | --- |
| 新建 Task、继续已有 Task | 归档后新请求被 `SCOPE_ARCHIVED` 拒绝；可靠接收过的旧请求重放返回原结果不算接受新工作 | `Scopes.active()`、任务提案与继续入口，[S12]、[S14] |
| 已开始执行 | 归档本身不发取消；既有执行可沿原工作目录继续收尾 | 分派检查只对 `!started_at` 的执行阻断，[S14] |
| 已开始且等待授权 | 仍可批准后完成；归档不自动使原授权失效 | 仓库现有直接测试断言，[S16] |
| 已开始且等待回答 | 回答恢复后可继续；这是回答入口与分派条件组合得出的行为 | 源码组合推断，非本轮实测，[S14]、[S19] |
| 尚未开始的排队或就绪执行 | 分派受阻，进入前提未满足状态，原因为 `SCOPE_ARCHIVED` | 分派路径及现有测试断言，[S13]、[S14]、[S16] |
| TaskPlan 与未来调度 | 不级联关闭 TaskPlan，不自动清空请求或周期发生队列；计划状态没有随归档改变 | 归档仅更新 Scope；触发器仍按计划处理，[S6]、[S14]、[S20] |
| 目录、任务、产物及历史 | Scope 归档不删除这些对象；Execution 的留存与退役是独立生命周期，Scope 归档不触发该流程 | 归档函数、目录保留测试及状态契约，[S14]、[S17]、[S20] |
| 按 task_id 查询 | 既有任务仍可通过公开查询读取；继续任务能力则明确不可用 | Task 查询及 continuation 状态，[S3]、[S12] |
| 恢复归档 Scope | 没有公开 restore/unarchive 操作；普通更新不接受 state，且已归档 Scope 拒绝保存修改 | 公共契约、操作表及 `Scopes.save()`，[S5]、[S14]、[S15] |

**定时任务的边界：**归档没有关闭已登记的定时计划。依当前 `tick()` 与分派逻辑推导，到期计划仍可能生成尚未开始的 Execution，再因 `SCOPE_ARCHIVED` 被阻断；已有未终结执行时，周期发生点还可能按 QUEUE 规则累积。因此，不能把“执行未开始”描述成“定时计划已取消、队列已清空”。这是源码组合推断，本轮没有运行“归档后多次定时触发”的实验。[S6]、[S14]

现有 `workspace.test.ts` 明确写有以下断言：一个执行到达 WAIT_AUTH，另一个因 Scope 忙而等待；归档 Scope 后批准前者，前者最终 SUCCEEDED，后者仍未开始且原因变为 SCOPE_ARCHIVED。该测试说明了原设计的分界，但本次仅阅读断言，没有重新执行测试。[S16]

当前列表 API 不会自动把归档 Scope 的任务全部隐藏。“Archived Scope 仅显示数量、暂不展开”的规则需要在 TUI 视图中落实。是否让 TUI 的直接 task_id 查询继续命中这些任务，以及是否扩展为任务联动归档，仍留给 U07；不能从后端可查询直接推导成已经批准新的界面入口。[S3]

### 7.2 逻辑 Shared 独立目录与产物交付

Shared Scope 只把无特定 Scope 的 Task 组织到同一视图组。当前无 Scope 的默认工作目录已经按 Task 分配，可作为复用依据；本轮无需为这组任务绑定一个公共 DIRECTORY 根目录。[S6]

此前核对到的是 DIRECTORY Scope 的占用与串行约束，不是已经证明存在某个竞态缺陷。最新方案通过各 Task 独立目录避免引入同目录写入和组级占用问题；不为逻辑 Shared 增加 `SCOPE_BUSY` 锁，也不改动其他真实目录 Scope 的既有规则。目录分开不等于操作系统级安全沙箱，本轮没有新增跨目录访问隔离工程。[S14]、[S17]

文件交付使用现有结构化结果和产物登记：只把明确登记的产物及必要结果信息回传 Main。中间文件、缓存和整个临时工作目录不自动列为产物；产物的当前路径应准确指回来源 Task/Execution。Agent 最近三轮对话、状态和错误原因仍按各自要求展示。[S7]、[S8]、[S9]

Task 临时工作目录清理后置。本轮保留当前文件供 `/open` 使用，不新增完成即删除或产物迁移流程。未来清理需要同时处理产物可用性和引用路径，但这不成为当前 TUI 交付的额外清理项目。逻辑 Shared 不因此新增归档管理功能，U07 的实体 Scope 归档含义不自动套用到这一视图分组。

### U02 定向输入 主流程已定

**已定：**Enter 先进入处理；未提交优先 Esc 退出，不适用时使用已验证并登记的组合键；目标失效报错并返回；Task 提交成功后回 Task 列表并刷新；原 Main/Task 草稿恢复，不把回答改投 Main。

**剩余小项：**退出或失效返回后，尚未提交的事项回答是否保留；定向输入期间 `/send`、`/rawmessage` 等 Main 命令的适用性。原 Main 草稿的保护不是未决项。Esc 仅在本节事项处理流程确定，不据此增加普通 Task 非空草稿的全局导航快捷键。

### U03 历史缓存 已关闭

仅限制客户端内存缓存，不限制历史可浏览范围；淘汰内容可从现有日志重读。N、B、缓存上限 H 的数值和单位属于实施参数，记录后即可验收，不再保留总历史截断选项。

### U04 open 错误对象 已关闭

消失的是错误提示，TUI 保持运行。错误只报一次、短暂可见、不长期驻留；显示时长作为实施参数记录，不要求零帧消失，也不再询问是否退出整个客户端。

### U05 完成后退出与失败标记 已定 入口仍需补齐

**已定：**重做成功完成、取消完成后退出原失败提示；处理失败报错并在对应任务显式标记；已回答或批准的事项在相应操作完成后立即移除；UNKNOWN 独立单列。重做再次失败属于处理失败分支，不按“完成”清空其失败标记。

**剩余：**Main 的失败行怎样进入重做或 Task 取消，以及 UNKNOWN 的明确裁定入口。不能据此擅自增加 `/retry`、Main `/cancel` 或整个 TaskPlan 的聚合取消。“放弃后移除”本轮未获确认，不作为已定退场方式。

### U06 逻辑 Shared 与独立目录 本轮替换并关闭

最新决定覆盖 v1.3 的同目录方案：Shared 是逻辑 Scope；各 Task 使用自己的临时工作目录；完成时交付登记产物；清理后续添加。Shared 共目录绑定、组内 DIRECTORY 锁及相应串行取舍已撤销，不再作为待选题。目录路径与展示映射按实施配置登记，不新增旧目录搬迁或跨目录安全沙箱。

### U07 Scope 归档 已完成代码核对 等待产品取舍

当前已实现的含义已在第 7.1 节列明：标记 ARCHIVED、阻断新工作和未开始执行，保留已开始执行收尾、目录与历史；不级联终结 TaskPlan 或未来调度，也没有公开恢复入口。

本轮先交付这一事实说明。**尚未决定是否修改该业务语义**：若希望“归档 Scope 时一并停止或归档所属任务”，需要再确定运行、等待、未来周期和队列怎样处理，不默认成为这版新增必做项。TUI 的归档数量展示和检索后置保持已定；直接 task_id 查询是否覆盖归档 Scope 下的任务仍可在此批注。

### U08 Agent 最近三轮 已定

默认最新 Execution；本轮展示最近三次，不做轮次切换。C08 明确了本稿的具体呈现解释：三次包含最新，在同一详情连续分组展示、普通滚动阅读；不足三次则按实际数量。无需再裁定默认哪一轮或是否增加切换器。更早轮次与恢复已经不可取得的记录不自动纳入。

### U09 原有界面细节 继续保留

- Scope 和任务数量的口径，Shared Scope、空 Scope、暂停计划和历史任务的计入方式。
- Scope 与组内任务的排序、数据更新时是否保持当前选中对象；是否采用 C06 的可选键盘选择或筛选。
- 时间字段表示创建、最近活动还是下次触发；不同含义应有标签。
- `/M`、`/T` 重复调用及返回时恢复什么位置；根页 `/back` 的行为；重新启动进入 Main 还是恢复上次界面。
- Task 详情草稿是否细分到每个 Task；Main/Task 草稿独立已经确定。

这些细节可以成组一次确定，不需要重新讨论已定的两级入口、默认展开和状态显示原则。

## 10 可直接执行的验收操作

### AC01 真实终端 双入口与返回

- **前置：**目标 macOS 终端、连接可用 Core、输入框为空。
- **操作：**启动 TUI，依次提交 `/T`、`/m`、`/t`、`/M`；进入已实现的内部视图后执行 `/BACK`。
- **预期：**Main/Task 整屏切换；大小写不影响命令识别；有上级时返回上级；切换不新增 Main 消息、不停止后台任务；底部输入区域始终可用。
- **失败判据：**`/T` 无反应、切到浏览器页面、导航作为聊天发送、底部输入区域之外又增加跨页常驻菜单、状态栏或侧栏。
- **依赖：**根页 `/back` 和重复导航的恢复细节按 U09 登记；不影响基本双入口验收。

### AC02 窗口尺寸与页面容量

- **前置：**Main 有长消息，Task 有超过一屏的任务；记录初始行列尺寸。
- **操作：**分别加宽、加高、恢复窗口；在两个一级界面重复。
- **预期：**同一布局显示更多内容；输入框仍可见；中文和宽字符不把相邻内容覆盖；Main 的活动区域保持在输入框上方。
- **失败判据：**宽度触发新侧栏或列表详情双栏、内容与输入重叠、放大后丢失当前对象。

### AC03 消息类型 颜色与分割线

- **前置：**同一会话含 Master 发言、模型回复、工具调用、推理及摘要。
- **操作：**逐项观察默认显示，再展开推理。
- **预期：**普通模型正文白色；Master 浅蓝且有上下分割线；工具专用颜色并另起行；推理浅灰；不同类型有独立起行边界。
- **失败判据：**所有内容同色、工具与普通正文混行、Master 分割线缺失、长工具文本为占一行而被静默删掉。

### AC04 Markdown 呈现

- **前置：**准备第 9 节固定 Markdown 样例，并记录支持语法列表。
- **操作：**让同一内容以完整历史消息及流式回复两种形式出现；查看窄一些和宽一些的窗口。
- **预期：**段落、标题、强调、列表、引用与代码层级可辨；代码中的字符和缩进保留；已登记的表格、链接等语法也正确显示。流式中已经形成完整的 Markdown 块应正确呈现；尚未闭合的标记允许暂态，输出结束后与同内容的历史读取结果一致。
- **失败判据：**全部 Markdown 原样堆成普通文本、列表层级丢失、正文或代码内容被丢失或改写、流式结束后仍与完整历史渲染不一致。不以每个未完成 token 前缀都达到最终排版作为验收要求。

### AC05 CoT 全消息开关与跨视图继承

- **前置：**Main 有多条 CoT 消息和无 CoT 消息；另有带推理内容的 Agent 任务历史。
- **操作：**在 Main 执行 `/CoTvIsIbLe`，查看现有消息并继续上滚；接收新消息；进入 Agent 历史；回 Main 用 `/cotv` 收起。
- **预期：**所有消息按同一开关显示；新消息及补读消息一致；Task 中推理继承状态；无 CoT 消息不虚构内容；普通日志不被当作 CoT。
- **失败判据：**只展开选中一条、补读后恢复另一种模式、别名失效、为显示重新调用模型。

### AC06 CoT 阅读锚点与不补写日志

- **前置：**记录正在阅读的一条消息及正文位置；样例含已持久 CoT、无 CoT，以及可用时的仅临时 CoT。选择安静样例以排除正常后台新消息影响。
- **操作：**展开、收起，向前后翻阅；对照相应消息的原记录和内容。
- **预期：**仍停留在同一阅读对象和正文位置；没有新增用户消息、重复消息或因显示操作补写的推理记录。临时内容消失后如实显示不可取得。
- **失败判据：**跳到最新、消息重复、原先没有 CoT 的记录被显示操作补写或伪造。

### AC07 近期启动 连续上滚与缓存淘汰后重读

- **前置：**历史超过首批 N、多个补读批次及缓存 H；记录 H 的数值、单位和缓存占用观察方式。
- **操作：**启动观察定位；持续上滚，读取内容总量超过 H，使较早加载的一部分被回收；再反向滚动，重新读取被淘汰的消息和一条长正文。
- **预期：**启动只读近期并定位最新，上滚再补读；缓存占用按登记上限受控，被回收消息仍能从既有日志重读；顺序和正文完整、无重复和缺口，阅读位置正确。本次启动以来消息和更早仍可取得的历史，不因缓存边界消失。
- **失败判据：**H 被实现成最多可回看条数、只减少可见行却把全部历史常驻缓存、淘汰后无法重读、分页漏消息或长正文只显示首片、删除持久日志来满足缓存限制。

### AC08 新消息不自动跳转

- **前置：**Main 可持续产生新消息。
- **操作：**停在一条历史消息中间，接收新的回复；再手动到最新位置，继续接收另一条回复。
- **预期：**两次都不因新消息到来而强制改变阅读位置；输入框中的编辑不被打断。
- **失败判据：**自动滚到底部、阅读锚点换成新消息、正在编辑的内容被流式刷新覆盖。

### AC09 历史读取失败与恢复

- **前置：**已有一段历史加载成功，输入框有草稿。
- **操作：**在上滚补读时制造一次读取失败；随后进行一次普通编辑或下一条合法操作，再恢复读取。
- **预期：**错误在加载位置出现；已读历史和草稿仍在；下一操作后旧错误退出；恢复后从正确位置继续，不重复或漏消息。
- **失败判据：**整页清空、错误写入 Main 历史、持续重复报错、加载失败导致草稿丢失。

### AC10 Scope 分组 任务条目与计数

- **前置：**至少两个普通 Scope，组内任务数不同，数据超过屏幕或分页大小；记录 U09 选择的计数口径。
- **操作：**进入 Task，逐组滚动，加载后续任务。
- **预期：**有 Scope 数量和各组数量；任务条目默认展开，包含 ID、状态及登记的必要字段；分页前后计数保持对应完整集合的含义。
- **失败判据：**只列 Scope 不列任务、已加载行数冒充总数、分页后同一 Task 重复计数、数量与标签含义不符。

### AC11 计划与各执行状态

- **前置：**包含正在执行、仅计划有效、定时未执行、排队、等待授权、等待回答、结果未知、取消中和初始化失败的样例。
- **操作：**进入对应 Scope，查看状态；推动其中一个任务状态变化后刷新。
- **预期：**应显示的等待和异常状态均存在；计划有效与当前执行状态分别表达；UNKNOWN 保持结果未知的真实状态；某轮成功不会被无条件写成整个计划关闭。
- **失败判据：**所有 ACTIVE 都标为正在执行、等待项消失、错误状态被过滤、状态更新对应到另一任务。

### AC12 Shared Scope 与归档计数

- **前置：**两个无 Scope 任务和两个已归档 Scope。
- **操作：**进入 Task，查看各组与归档部分。
- **预期：**无 Scope 任务都进入同一个 Shared Scope；Archived Scope 显示实际归档数量，不展开其中任务；不生成每任务一个共享分组。
- **失败判据：**无归属任务散落多组、归档内容正常展开、归档数错误。
- **边界：**本项验证共同逻辑分组；各 Task 独立工作目录及产物交付另以 AC33 验证。后台是否新增级联归档仍由 U07 决定，本项不把逻辑 Shared 当成新增归档管理对象。

### AC13 同一 Task 不并发执行

- **前置：**真实 Core 中一个 Task 正在执行；准备该 Task 的下一次定时触发及一个继续请求。
- **操作：**在首轮未终结时触发后续工作，分别核对 Core 和 TUI。
- **预期：**同一 Task 不同时运行两轮；排队或忙碌拒绝与实际后端规则一致；界面只计一个 Task，计划属性与当轮状态同时可辨。
- **失败判据：**后台已运行两轮但 UI 隐藏一轮、同一 Task 在不同状态分组重复计为两项、误把不同 Task 全部串行当作本需求。

### AC14 历史 ID 查询只定位

- **前置：**有完整 ID、唯一短 ID、不唯一短前缀及不存在 ID 的样例。
- **操作：**在 Task 主界面分别提交 `/search_task <实际ID或前缀>`；定位成功后检查主体。
- **预期：**完整与唯一短 ID 定位正确任务条目，不自动进入详情；不唯一和不存在都明确报错；查询不改变任务业务状态。
- **失败判据：**搜索直接打开详情、猜测一个不唯一目标、定位错误对象、错误长期驻留。
- **依赖：**归档 Scope 中任务的查询范围按 U07 单独验证。

### AC15 taskdetail 与最近三轮真实 Agent 对话

- **前置：**同一 Agent Task 有四次可区分的真实 Execution，每轮含不同消息；另有不足三轮的 Agent Task 和一个普通程序任务。
- **操作：**在 Task 输入 `/taskdetail <完整task_id>`；观察初始位置，滚动阅读最新三轮及其中一轮的长对话；核对没有第四旧轮次的独立历史区块；再查看不足三轮的任务，最后 `/back` 返回。
- **预期：**默认定位最新 Execution；同详情分组展示最近三轮，三轮包含最新；轮次不足时按实际数量；每轮内部可以补读长历史，Task 和 Execution 归属清楚。没有轮次切换器，不以 Main 摘要替代真实 Agent 消息。
- **失败判据：**只有结果摘要、只展示最新一轮而缺少另外两轮、混入其他 Task 或把多轮标成同一轮、自动增加第四旧轮次的历史区块、每轮只留第一片、虚构缺失记录。三轮内消息原本引用更早内容不算越界。
- **实施依赖：**B02 读取接口；正式命令、默认轮次和三轮范围已经确定，不再依赖旧 U01/U08 选择题。此处用完整 ID，不新增详情命令必须接受短 ID 的要求。

### AC16 Main 活动区 先后顺序与已看颜色

- **前置：**按先后顺序创建多个授权和决策，另有确定失败与 UNKNOWN；更新一个旧事项但不重新发起它。
- **操作：**在 Main 查看区域，阅读一项但不提交；然后切到 Task。
- **预期：**区域在输入框上方，多项按发起时间新到旧；旧项更新不冒充新发起；失败单列，UNKNOWN 另行独立列示；已看较深、未看较浅；Task 没有该提示区域。
- **失败判据：**出现在侧栏、只能显示一项、只排序当前页导致新项遗漏、查看就被标为已处理、UNKNOWN 被混入普通失败或授权、Task 常驻这块区域。

### AC17 上键编辑边界和事项选择

- **前置：**Main 输入框有两行未发送文字，上方有至少两个待处理事项。
- **操作：**从第二行按上键到第一行，再按上键；用上下键选择事项，按 Enter。
- **预期：**先正常编辑移动，再进入事项选择；焦点和目标可辨；Enter 只进入处理。进入前后授权或决策仍待处理，不批准、不回答、不移除，也不发送 Main 草稿。
- **失败判据：**第二行就丢失输入焦点、选择行刷新后操作错对象、Enter 直接提交批准或回答、原 Main 草稿被发送或丢弃。

### AC18 Main 定向回答与原稿恢复

- **前置：**Main 有未发送草稿 A，存在文字决策 D 和一个待批准授权；任务在收到回答或授权后仍需继续执行。
- **操作：**通过上键、选择和 Enter 进入 D，输入不同文字 B，用记录的发送操作提交；随后对授权重复进入处理，再进行明确批准操作。
- **预期：**B 只提交给 D；授权也仅作用于明确对象。各自操作确认完成后，事项立即移出待处理区，无需等整个 Task 完成；回 Main 恢复草稿 A。B 不成为新的 Master 主会话消息。
- **失败判据：**B 发给 Main 或其他事项、A 被覆盖、仅发出请求就显示已处理、操作完成后仍挂待处理直到 Task 结束、返回后仍绑定旧事项。

### AC19 Task show 与普通 Task 输入区分

- **前置：**Task 中有待回答事项 D，D 包含多个答案选项；另准备普通 Task 草稿。
- **操作：**普通浏览时提交一段文本并确认它仍为草稿；由验收者正常编辑清空这段测试草稿，再输入 `/show <D整个事项的ID>` 进入定向输入，提交 D 允许的有效答案，内容与前一段测试草稿不同。
- **预期：**前一段留为草稿，不被创建成新任务；`/show` 打开整个 D，不自动替用户选一个答案；后一段只发给 D。提交成功后返回 Task 的 Scope 任务列表并刷新，状态与 Core 最新查询一致。
- **失败判据：**普通 Task 文本误发或被自动建任务、把事项 ID 当作答案选项、定向输入被一律拒绝、答复落错对象、成功后仍滞留处理页或列表未刷新。

### AC20 目标失效 报错并自动返回

- **前置：**分别从 Main 与 Task 打开有效事项；在另一个合法入口处理或使该事项失效；本客户端尚有未提交回答。
- **操作：**尝试提交，观察错误与返回；不再额外按返回键帮助界面退出。
- **预期：**明确反馈已处理或失效并自动返回。Main 恢复原输入草稿；Task 返回列表并刷新；不会重复改变业务状态、改投 Main 或假报批准成功。返回过程不能把错误吞掉。
- **失败判据：**必须再按键才能离开失效处理状态、错误不可见、回答误发 Main、过期参数被接受为成功、原草稿被覆盖。交由 Core 校验旧请求并正确显示拒绝，不算失败。
- **局部待定：**失效后事项回答草稿是否继续保留见 U02；返回、提示和原稿保护已可确定验收。用户主动未提交退出另见 AC34。

### AC21 失败行的处理与退出

- **前置：**Main 有可分别验证重做、取消和处理失败的任务；明确处理对应哪个 TaskRequest 或 Execution，并登记 U05 的实际入口。
- **操作：**先发起重做，观察尚未完成及完成后两阶段；再发起取消，区分接收回执与实际取消完成；最后制造一次重做或取消失败，待瞬时错误清除后继续查看对应任务。
- **预期：**重做尚未完成时提示仍在，重做成功完成后退出原失败提示；取消实际完成后退出。处理失败会报错，且错误提示消失后对应任务仍有明确失败标记、仍可找到。已回答或批准事项的移除按 AC18，不能与重做执行完成混为一谈。
- **失败判据：**请求刚发出就移除、取消尚未完成就显示解决、失败标记跟随瞬时错误一起消失、假造 `/retry` 或 Main `/cancel` 入口、把未批准的“放弃”当作已定移除动作。
- **局部待定：**U05 只剩处理入口和具体对象需登记；退出条件、失败标记及 UNKNOWN 单列均已确定。

### AC22 产物末尾列表与当前文件

- **前置：**两个 Task 的不同工作目录各有同名、内容不同的登记产物，路径含中文或空格；其中一份在交付后被修改，与交付快照不同。
- **操作：**Main 接收任务结果，检查回复末尾的产物条目；分别 `/open` 两个当前路径，核对内容和来源。
- **预期：**有路径名称、所属执行、逐项解释及专用颜色；两个同名产物可区分，外部程序打开各自当前内容；修改过的文件不是旧快照。不新增产物详情页。
- **失败判据：**只有一句摘要、路径靠猜、把 Shared 当公共根目录而打开错误 Task 的同名文件、归属错误、打开旧快照、参数因空格断裂。
- **可选分支：**若实现 ID 入口，用 ID 再打开一次，仍应定位当前文件；未实现 ID 不阻断路径入口。

### AC23 open 不存在路径

- **前置：**Main 有一个已不存在的产物路径。
- **操作：**执行 `/open <不存在路径>`，观察一次可见反馈及其清除，再执行 `/help` 或其他合法命令。
- **预期：**仅报错一次，提示按登记方式消失；TUI 和 Core 继续运行，后续命令正常，不新增业务日志。
- **失败判据：**假成功、反复刷错、错误长期驻留、提示一出现便退出整个客户端、打开其他文件或旧快照。
- **实施参数：**记录短暂提示的可读停留方式，不要求零帧消失；U04 的退出对象已经确定。

### AC24 命令大小写和作用域

- **前置：**Main、Task 均可进入，输入框为空。
- **操作：**用不同大小写调用 `/M`、`/T`、`/help` 和 Task 中的 `/taskdetail <完整ID>`；在 Task 调用带有效参数的 `/send`、`/open` 及 `/cotvisible`；在 Main 调用带有效目标的 `/search_task`、`/taskdetail` 和 `/cancel`。
- **预期：**名称大小写不影响已允许命令；错页调用给局部错误，不执行业务、不改为普通消息；帮助反映正式拼写、真实范围和参数，不提供直接创建任务的首版入口。由 Main 实际发起任务的正向路径见 AC33。
- **失败判据：**沿旧大小写规则拒绝、Task `/send` 仍发 Main、错页调用被偷偷代办、帮助与真实范围不符、把笔误拼写列为必备规范命令。

### AC25 首字符规则与一次性纯文本

- **前置：**Main 普通输入状态，不在定向输入。
- **操作：**分别提交首字符是 `/` 的合法命令、正文中含 `/T`、前面有普通文字或空格再含 `/T` 的内容；再执行 `/rawmessage /T` 发送字面 `/T`，随后提交正常导航命令。
- **预期：**只有符合首字符及整次命令语法的输入执行；正文不被扫描；纯文本那一条作为内容发送，下一条恢复命令解析。
- **失败判据：**正文中命令被执行、先去掉正文再导航、纯文本模式永久残留、同次输入串联执行多条命令。

### AC26 独立草稿与非空输入限制

- **前置：**Main 输入为空；已确定可用的退出操作和草稿恢复能力。
- **操作：**进入 Task 写草稿 T，退出并重开 TUI；在 Main 核对没有把 T 放进 Main，发送一条 Main 消息使输入恢复为空，再用 `/T` 返回；在 T 后追加 `/M`，再用约定的发送操作提交。
- **预期：**Task 草稿 T 仍属于 Task；Main 消息与 T 不混合；提交包含 `/M` 的非空正文后仍留在 Task，内容保留为 Task 草稿，不产生 Main 消息。Main 原稿的保留由 AC18 的定向输入往返同时验证。
- **失败判据：**两个一级界面共用一份草稿、重新启动后误自动发送、追加命令被执行、为通过测试擅自加入临时命令模式。
- **依赖：**本例按重开进入 Main 描述。若 U09 选择恢复上次 Task 界面，须先登记可执行的跨页验收入口，再调整此步骤；本例不据此强制重启落点或新增快捷键。

### AC27 多段粘贴的真实内容

- **前置：**准备多段含中文、换行、代码和 `/T` 的文本，记录完整原文。
- **操作：**先手写一句，粘贴第一段，再手写一句、粘贴第二段，提交消息。
- **预期：**每段以 `<pasted xx lines xxx...xxx.txt>` 风格显示并有独立缓冲；实际提交内容与原文、手写文字顺序一致；不执行粘贴内命令。
- **失败判据：**模型只收到占位符或路径、内容丢失或乱序、行数与实际片段不符、粘贴触发自动发送。

### AC28 macOS 中文输入 换行与补全

- **前置：**目标终端和真实系统输入法；记录发送、换行、补全键。
- **操作：**先输入中文并确认候选，输入标点和宽字符，换行，继续编辑；验证完成后明确发送或主动清空这段输入。从空输入开始，再补全一个当前界面可用的命令及对象 ID，随后明确提交。
- **预期：**候选确认不发送；换行与发送可区分；字符及光标位置正确；补全只修改输入，不立即执行。
- **失败判据：**候选确认发送、字符错位或丢字、补全就发出业务动作、只用合成输入冒充系统输入法验收。

### AC29 显式取消目标与真实反馈

- **前置：**真实 Task 中分别有可取消请求和执行，另有定时计划；记录全部稳定 ID。
- **操作：**测试无参、双目标、无效 ID，再分别执行 `/cancel --request <实际请求ID>` 与 `/cancel --execution <实际执行ID>`；查看 Core 状态及未来计划。
- **预期：**错误参数不执行；正确命令作用于指定对象；本地发出、Core 接收与最终状态不混淆；取消一次执行不误称未来计划已停止。
- **失败判据：**用当前选中行猜目标、刷新后取消另一个对象、接收回执被显示成最终取消、错误停止其他计划。
- **边界：**正式拼写与目标语义均已确定；本项不新增整个 TaskPlan 的聚合取消。

### AC30 退出 重开与后台持续运行

- **前置：**有一个后台任务正在执行；TUI 有草稿。
- **操作：**使用记录的退出键关闭 TUI，核对 Core 继续；重新打开，读取状态和草稿；再进行一次可控断线与重连。
- **预期：**后台任务继续；仍是同一权威主会话；未发送草稿不误发；重连后状态与 Core 一致，消息不重复。
- **失败判据：**退出同时停止 Core、任务无故取消、重开产生第二主会话、重连重复发送、草稿被清理。

### AC31 UI 操作不进入会话历史

- **前置：**安静的 Main，记录当前权威消息边界；不要同时产生无关业务消息。
- **操作：**切页、帮助、补全、滚动、制造一个参数错误、清除错误、改变 CoT 显示。
- **预期：**这些操作只改变客户端呈现，没有新增 Master 消息、工具执行结果或专用 UI 操作流水。
- **失败判据：**命令反馈成为 Main 对话、每次滚动或展开增加持久业务事件、操作调用模型猜测路由。

### AC32 图片导入与失败保留

- **前置：**真实 macOS 图片剪贴板、一个含空格的合法图片路径、一个失败样例；使用支持图片的已登记模型输入路径。
- **操作：**在 Main 通过已实现的显式入口加入图片，与文字混合发送；再模拟导入或提交失败。
- **预期：**实际图像内容经附件契约进入消息；文字与图片对应正确；失败保留草稿和附件，不静默丢图后发送剩余文字；普通文本路径不自动上传。
- **失败判据：**只发送本地路径、图片未进入实际消息、失败后材料消失、因命令作用域错误在 Task 偷发 Main。
- **依赖：**路径加入入口和 `/attach` 是否纳入由 U01 明确；已确认的 `/paste` 作用域是 Main。

### AC33 Shared 逻辑归组 独立目录与产物交付

- **前置：**准备两个未指定 Scope 的任务要求 A、B：各自在工作目录生成 `report.txt`，内容分别带 A、B 标记，仅把它登记为产物；另产生一个不交付的中间文件。
- **操作：**通过 Main 发起 A 并确认完成，再发起 B 并确认完成；记录两次实际工作目录，核对两个同名文件的内容。在 Task 检查逻辑分组；已退出默认集合的任务用 `/search_task <task_id>` 定位。检查 Main 的产物条目，再分别 `/open` 两个明确路径。
- **预期：**A、B 属于同一个逻辑 Shared 组，实际工作目录不同；相同相对文件名互不覆盖。Main 只列登记产物及必要结果信息，不自动交付中间文件或整个目录；两个 `/open` 分别打开正确 Task 的当前文件。完成后没有新增自动删除源文件的步骤。
- **失败判据：**因逻辑同组而把两个 Task 绑定同一实际目录、同名文件互相覆盖、只交付整个工作目录、中间文件被自动列为产物、当前路径落到错误 Task、完成即删导致无法打开、为了 Shared 分组新增统一 DIRECTORY 占用锁。
- **分段验收：**Task 批次验证真实发起、分组、独立目录与同名文件互不覆盖；产物批次验证回复条目、只交付登记产物及 `/open`。只完成前段不能勾选整项通过。
- **边界：**本项不验收未来目录清理、跨目录访问权限隔离或并发压力，不要求迁移旧目录；既有容量限制及同 Task 不并发约束继续适用。

### AC34 未提交时 Esc 退出处理

- **前置：**Main 有原稿 A 和一个有效待回答事项；另准备 Task 的空输入及一个有效事项；记录实际退出键，优先 Esc。
- **操作：**在 Main 通过选择进入事项，输入回答 B 但不提交，按 Esc；确认原稿 A 完整恢复后，由验收者主动清空这段测试草稿，再执行 `/T`。从 Task 的空输入执行 `/show <事项ID>`，输入未提交内容并按 Esc。若目标终端确实不能使用 Esc，按记录的替代组合键重复。
- **预期：**两次均退出事项处理，不产生批准或回答；Main 原稿 A 恢复，Task 回到进入前的浏览和普通输入；Core 中事项仍待处理。退出处理不会退出 TUI。
- **失败判据：**Esc 误发送、误批准、关闭客户端、覆盖原 Main/Task 草稿、没有可用退出方式、未记录就假定某组合键有效。
- **局部待定：**回答 B 退出后是否继续保留由 U02 确定；本项已可验证退出、无业务提交及原稿恢复。此处不把 Esc 扩展成普通 Task 草稿的全局导航键。

### 11.2 依赖和每批完成条件

建议先完成批次一；二和三可以部分并行开发，但三的最终验收须等待二的 Main CoT 开关可用，才能验证 Task 继承。批次四依赖一、三，批次五依赖三、四。批次六依赖二、三及已有附件/产物合同，不必等待批次五的未定交互；#84 在六个功能批次均达到各自完成条件后收尾。领取与并行安排以最终确认的依赖为准。

每批均需演示真实 Core 用户路径，记录实际命令、前置数据、操作和结果；fixture 只能证明样式，不能替代真实对象路由、目录和产物。首批验收必须使用非空 Task 样例验证 `/M`、`/T` 整屏切换，不能只证明空态可显示。

跨批的 AC 必须标明已验收子步骤和未执行部分。例如批次二只通过 Main CoT，不能把包含 Task 继承的 AC05 全项勾选；批次三只通过独立目录，不能把含 `/open` 的 AC33 全项勾选。AC01 的内部返回、AC02 的活动区域、AC03 的推理呈现分别随三、四、二补齐，首批不能提前认领。

每批新增命令均须当批验证 AC24 中对应的大小写、参数保真和作用域分支；新增 UI 操作同样验证 AC31 对应的不入历史分支。全部功能批次完成时汇总完整证据，不能等到 #84 才首次检查后续命令的错页调用。未实现命令在帮助中明确状态，不能无声无效，也不能交给模型猜测执行。

每条 issue 的正文固定包含：用户结果、界面与命令、数据来源和必要后端增补、范围边界、开工前待定项、操作验收、完成证据及 API 使用情况。实现使用和未使用的 API 都更新 `api-coverage.md`，未使用不自动产生补菜单要求。代码合入与产品验收分别记录，不能用测试数量替代真实终端可用性。
