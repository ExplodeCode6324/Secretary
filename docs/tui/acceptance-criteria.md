# TUI 组合验收分项标准

本页将 [v1.7 固定来源](https://github.com/ExplodeCode6324/Secretary/blob/ed16e804d28c0b0048e37035349f1ff3f7982f38/docs/tui/implementation-reference.md) 的第 9–10 节完整吸收为正式验收标准，保留 AC01–AC34、前置、操作、预期、失败判据及边界。AC08、AC21、AC28、AC32 按六批最终交付裁定补充或替换。编号用于追溯，不表示全部通过。

当前运行行为见 [运行说明](run-and-test.md)，组合执行顺序见 [验收操作](acceptance.md)，来源与吸收范围见 [交叉表](source-map.md)，实际结果见 [#84 账本](../fix/evidence/issue84-combined/acceptance.md)。每项按子步骤登记证据类别；一条 API 路径不能把整个 AC 改为 PASS。Master 早先总体反馈继续保留，缺单项记录不推翻该反馈。

## 9 验收准备与记录方式

### 9.1 目标环境和参数

记录被测提交、精确 pi-tui 版本、Node 版本、macOS 版本、实际终端及其版本、字体、初始行列尺寸及至少一个更大尺寸。记录最小支持尺寸和窗口过小时的提示方式，这些实施参数不改变统一布局。先记录实际可用的发送、换行、退出、Esc、滚动、补全和图片粘贴键，检查作用域及相互冲突；输入法候选确认不能触发发送。

文本和代码复制列入目标终端可用性预检，优先验证组件或终端现成选择/复制能力。Pi AltScreen 已有选择与复制支持，但真实终端的剪贴板兼容性仍需验证；存在缺口时记录影响，不自动新增 `/copy`、新选区系统或修改已定键位。（历史来源 S28 见原 v1.7 文档）

记录首次历史条数 N、每次补读量 B、内存缓存上限 H 及其单位、活动区最大高度和溢出操作。H 只限制驻留历史缓存；数值不是本稿臆定的性能目标。还需记录一次性错误提示的可读停留方式，以及事项处理采用 Esc 还是经验证的替代组合键。

图片直接粘贴需要在真实系统剪贴板和目标终端中验证，记录图片来源、实际粘贴动作和本机适配方式。若能力确实受阻，记录已尝试方式并在实施过程中向 Master 询问替代；没有决定前按“未执行／能力受阻”保留，不拿路径上传或浏览器演示替代通过。

### 9.2 一组可重复使用的样例

| 样例 | 需要的内容 |
| --- | --- |
| Main 消息 | Master 发言、普通回复、工具调用、带 CoT 与无 CoT 消息；跨多个补读批次，数据量超过登记的内存缓存 H |
| Markdown | 固定段落、标题、粗斜体、列表、引用、行内代码、代码块；补上实现登记的其他语法 |
| 普通 Scope | 两个先后调起活跃任务的 Scope；两个无活跃任务但创建先后明确的 Scope，并更新较老者制造反例；组内有创建较早但最近执行更晚的 Task；另有尚未执行的定时 Task、空组和仅历史组 |
| Task 状态 | 正在执行、计划有效但未执行、定时、等待授权/回答、取消中、初始化失败；另有纯暂停且无其他工作的计划及暂停后仍有执行/等待的对照；UNKNOWN 只作异常样例 |
| Shared 与归档 | 两个由 Main 发起的无 Scope Task，实际目录不同；各自产生同名但内容不同的登记产物及不登记的中间文件；另有两个已归档实体 Scope |
| 历史查询 | 完整 ID、唯一短 ID、至少两个共用短前缀的任务、不存在 ID；一项已完成但 Scope 未归档的任务，以及一项 Scope 已归档的任务 |
| Agent 历史 | 一个 Agent Task 至少有四次可区分的真实 Execution；另有不足三轮的任务；各轮消息带不同标记 |
| 待处理 | 先后发起的授权与决策，已看/未看各一项，批准后仍为 APPROVED 的样例；可重做成功及失败、可处置后保留 FAILED 的样例，后续同 Task 新失败和 UNKNOWN；至少一个多选项决策及一个可输入字面路径的文本问题 |
| 产物 | 至少两个文件，其中一个在交付后被修改；另有一个已删除路径；包含中文和空格路径 |
| 粘贴 | 多段中文与代码，内容包含 `/T`，混合手写内容；另有系统剪贴板中的真实图片及普通图片路径文本，用于区分直接图片粘贴与普通文字 |

显示样例可用 fixture（固定测试样例）；计数、对象路由、并发约束和产物路径需要对照真实 Core 数据。输入法、实体按键和外部程序打开必须在真实目标终端操作。Agent 历史至少使用一次真实执行所留下的消息，不用 Main 摘要伪装。

### 9.3 结果标记

每项记录前置数据、实际操作、观察结果与证据位置，使用“通过、失败、未执行”；实际能力阻塞应另外说明原因。已经确认的行为不能继续标为待需求确定。实施参数先登记，新增需求或真实受阻后的替代方案单独提出，不能静默替换当前范围。

业务字段核对可以读取现有记录；不为验收建立新的 UI 审计系统。各分支实际状态以组合账本为准，本页不预填通过或未执行。

## 10 可直接执行的验收操作

### AC01 真实终端 启动 双入口与阅读位置恢复

- **前置：**目标 macOS 终端、连接可用 Core、输入框为空；有非空真实 Task 样例，至少能区分正在执行和等待中的任务。
- **操作：**启动后确认 Main；停在一条历史消息中段，提交 `/M` 和根页 `/back`；再 `/T`，核对真实 Task 的 ID、执行状态及所属分组，滚到一个可识别对象后重复 `/t` 和根页 `/back`；用 `/m` 返回核对 Main 位置，再 `/T` 核对 Task 位置。进入已实现的内部视图后执行 `/BACK`；有新消息时复用 AC08。命令均从空输入开始。
- **预期：**每次启动进入 Main；双入口整屏切换，命令不分大小写；重复导航与一级页 `/back` 均无额外动作、提示或消息，不重置阅读位置。内部视图 `/back` 返回上级，往返恢复最近阅读对象和位置。Task 展示真实执行状态，不能用计划 ACTIVE 冒充正在执行；底部输入可用，后台继续。
- **失败判据：**有效 `/T` 不切换、只有空路由或假数据、所有 Task 只显示 ACTIVE 却标成执行状态、根页返回跳页或报错、返回丢失可恢复锚点、切到浏览器、导航作为聊天发送、增加跨页常驻菜单或侧栏。
- **分段验收：**首批完成真实双入口、基本状态投影、重复导航与根页无操作；缺少必要执行状态时随首批补最小读取投影。内部详情返回随批次三验收，不提前要求完整计数和排序。

### AC02 窗口尺寸与页面容量

- **前置：**Main 有长消息，Task 有超过一屏的任务；记录初始行列尺寸。
- **操作：**分别加宽、加高、恢复窗口；在两个一级界面重复。
- **预期：**同一布局显示更多内容；输入框仍可见；中文和宽字符不把相邻内容覆盖；Main 的活动区域保持在输入框上方。
- **失败判据：**宽度触发新侧栏或列表详情双栏、内容与输入重叠、放大后丢失当前对象。

### AC03 消息类型 颜色与分割线

- **前置：**同一会话含 Master 发言、模型回复、工具调用、推理及摘要。
- **操作：**逐项观察默认显示，再展开推理。
- **预期：**普通模型正文白色；Master 浅蓝且有上下分割线；工具专用颜色并另起行；推理浅灰；不同类型有独立起行边界。
- **失败判据：**所有内容同色、工具与普通正文混行、Master 分割线缺失、长工具文本为占一行而被静默删掉。

### AC04 Markdown 呈现

- **前置：**准备上文第 9 节固定 Markdown 样例，并记录支持语法列表。
- **操作：**让同一内容以完整历史消息及流式回复两种形式出现；查看窄一些和宽一些的窗口。
- **预期：**段落、标题、强调、列表、引用与代码层级可辨；代码中的字符和缩进保留；已登记的表格、链接等语法也正确显示。流式中已经形成完整的 Markdown 块应正确呈现；尚未闭合的标记允许暂态，输出结束后与同内容的历史读取结果一致。
- **失败判据：**全部 Markdown 原样堆成普通文本、列表层级丢失、正文或代码内容被丢失或改写、流式结束后仍与完整历史渲染不一致。不以每个未完成 token 前缀都达到最终排版作为验收要求。

### AC05 CoT 全消息开关与跨视图继承

- **前置：**Main 有多条 CoT 消息和无 CoT 消息；另有带推理内容的 Agent 任务历史。
- **操作：**在 Main 执行 `/CoTvIsIbLe`，查看现有消息并继续上滚；接收新消息；进入 Agent 历史；回 Main 用 `/cotv` 收起。
- **预期：**所有消息按同一开关显示；新消息及补读消息一致；Task 中推理继承状态；无 CoT 消息不虚构内容；普通日志不被当作 CoT。
- **失败判据：**只展开选中一条、补读后恢复另一种模式、别名失效、为显示重新调用模型。

### AC06 CoT 阅读锚点 游标恢复与不补写日志

- **前置：**Main 已补读至少两页，记录当前消息 ID 及正文位置；样例含已持久 CoT、无 CoT，以及可用时的仅临时 CoT。选择安静会话，排除正常后台新消息影响。
- **操作：**展开、收起 CoT，每次切换后继续越过一次分页边界，再返回记录的正文位置；对照相应消息原记录。
- **预期：**仍可恢复同一消息及正文位置，后续分页使用当前读取条件。旧游标因 thinking 等读取范围变化而失效时，通过现有按 message_id 定位能力重新取得有效分页，不反复重用旧游标。无新增用户消息、重复消息或因显示操作补写的推理；临时内容已不可取得时如实说明。
- **失败判据：**切换后跳到最新、旧游标使后续历史永久不可读或循环报错、消息重复或遗漏、原先没有 CoT 的记录被显示操作补写或伪造。
- **边界：**本项验证既有分页与定位能力的正确使用，不要求临时游标跨读取条件永久有效，不新增历史库或游标持久化工程。

### AC07 近期启动 连续上滚与缓存淘汰后重读

- **前置：**历史超过首批 N、多个补读批次及缓存 H；记录 H 的数值、单位和缓存占用观察方式。
- **操作：**启动观察定位；持续上滚，读取内容总量超过 H，使较早加载的一部分被回收；再反向滚动，重新读取被淘汰的消息和一条长正文。
- **预期：**本次启动首次 Main 只读近期并定位最新，上滚再补读；缓存占用按登记上限受控，被回收消息仍能从既有日志重读；顺序和正文完整、无重复和缺口，阅读位置正确。本次启动以来消息和更早仍可取得的历史，不因缓存边界消失。切页返回恢复上次阅读锚点，不重新套用首次启动的最新定位。
- **失败判据：**H 被实现成最多可回看条数、只减少可见行却把全部历史常驻缓存、淘汰后无法重读、分页漏消息或长正文只显示首片、删除持久日志来满足缓存限制。

### AC08 显式跟随与被动消息保持阅读位置

- **前置：**Main 可持续产生新消息，含一条可在回复前主动上滚的输入。
- **操作：**明确发送并观察跟随；同 request ID 的明确重试也应启动跟随。随后上滚阅读历史，接收回复；从空输入切 Task，再返回 Main；手动回到最新后继续接收被动消息。另在已开启跟随时调整窗口、切 CoT 和重连。
- **预期：**显式发送启动跟随；主动阅读、事项选择、鼠标选择和切 Task 停止。返回 Main、手动到底和被动到达不重新启动。resize、CoT 和重连保留原跟随状态，输入被明确拒绝时停止。编辑内容与可恢复锚点不丢失。
- **失败判据：**未发送却被新消息拖到底；主动上滚后仍跟随；仅返回 Main 就重启跟随；跟随中切 CoT 无故停止；回复刷新覆盖草稿。
- **来源：**[#91 后续裁定](../fix/evidence/issue91-main-history/acceptance.md)取代 v1.7 AC08 的绝对不跟随表述。

### AC09 历史读取失败 游标失效与恢复

- **前置：**已有至少两页历史加载成功，记录正在阅读的消息 ID 和正文位置，输入框有草稿；使用安静样例。
- **操作：**先在上滚补读时制造一次可恢复读取失败，进行普通编辑后恢复读取。另验证一次旧游标失效：受控重启 Core，或等效返回一次游标过期结果，二选一即可；随后继续补读并核对原阅读位置。
- **预期：**普通错误在加载位置出现，下一操作后清除，已读历史和草稿仍在。旧游标失效不作为历史终点；客户端可通过现有按消息 ID 定位能力重取有效分页并恢复阅读，消息不重复、不遗漏，无需重开 TUI 或清空草稿。
- **失败判据：**整页清空、错误写入 Main 历史、持续重放失效游标、因过期永久停止补读、回到错误消息或强制最新、草稿丢失、另建历史库绕过恢复。
- **边界：**一次明确的过期恢复场景即可，不扩成多轮 Core 故障或性能测试矩阵；CoT 读取范围变化复用 AC06。

### AC10 Scope 分组 排序与计数

- **前置：**两个普通 Scope 的活跃 Task 先后调起；另有两个无活跃执行但仍含当前任务的普通 Scope，创建时间不同。再备空 Scope、仅历史任务的 Scope 和含当前任务的 Shared。组内含最近执行时间不同的 Task 及尚无 Execution 的 Task，数据超过一屏或一页。
- **操作：**进入 Task，核对页头及各组数量，滚动加载后续内容；在另一组调起活跃 Task，观察顺序。更新旧 Scope 的无关信息，并让较早创建的 Task 产生更新一轮执行；再定位一条未归档历史任务，核对当前计数没有随查询增加。
- **预期：**最新调起活跃 Task 的 Scope 优先；无活跃 Task 的普通 Scope 按真实创建时间倒序，不能用 updated_at 冒充。组内按最近一次执行时间倒序；无 Execution 的 Task 仍显示，按登记的稳定空值规则放置。页头只计符合当前集合的普通 Scope，不计空、Shared 或仅历史分组；此样例为四个。各组另列自己的当前 Task 数，Shared 的当前任务照常计入本组；不新增全局 Task 总数。分页前后去重、计数及排序口径一致。
- **失败判据：**任意更新冒充新调起或创建时间、按 Task 创建时间代替最近执行时间、因无 Execution 隐藏定时任务、只排当前页、把加载行数当总数、重复计 Task、把 Shared 本组数量写成零、历史查询抬高当前计数、重排改变操作目标。已结束且无待处理或未来调度的一次性任务不能仅因计划 ACTIVE 永久算作当前任务。
- **实施登记：**说明真实 Scope 创建信息的来源与必要投影、最近执行时间字段、空值和并列值的稳定次序，以及 Shared 无活跃任务时的位置；不为逻辑 Shared 伪造实体 Scope 创建时间。计数排除不等于另行决定空组必须隐藏。

### AC11 计划与各执行状态

- **前置：**包含正在执行、仅计划有效、定时未执行、排队、等待授权、等待回答、结果未知、取消中和初始化失败；另有纯暂停无其他工作的计划，以及暂停但仍有执行/待办的对照。
- **操作：**进入对应 Scope 查看状态与当前计数；对比两个暂停样例，按 ID 定位被默认排除的未归档暂停计划；推动一个任务状态变化后刷新。
- **预期：**应显示的等待和异常状态均存在；计划有效与当前执行状态分别表达；UNKNOWN 保持结果未知的真实状态并作为需排查的异常，不提供裁定入口、不自动重试；某轮成功不会被无条件写成整个计划关闭。纯暂停且无其他工作的计划不进默认列表或当前计数，按 ID 仍可定位为 PAUSED；暂停但仍有执行/等待者正常显示。
- **失败判据：**所有 ACTIVE 都标为正在执行、等待项消失、错误状态被过滤、UNKNOWN 被猜成成功或普通失败、增加未批准的裁定入口、状态更新对应到另一任务、默认展示纯暂停计划、把仍在执行/等待的暂停对象一起隐藏、把查询到的暂停计划伪装为已完成。

### AC12 Shared Scope 逻辑分组与归档计数

- **前置：**两个属于当前集合的无 Scope Task、一个未归档历史 Task，以及两个已归档实体 Scope。
- **操作：**进入 Task，查看 Shared、页头 Scope 总数与归档数量；定位未归档历史任务后再次核对计数。
- **预期：**当前无归属任务进入同一个逻辑 Shared，Shared 本组显示两个当前 Task；Shared 不计入页头普通 Scope 总数，但组及条目照常显示。Archived Scope 单列实际数量，不展开任务；历史查询不增加当前计数。
- **失败判据：**每任务一个 Shared 分组、因页头不计 Shared 就隐藏它或把本组数量改为零、归档任务正常展开、归档数错误、把临时历史查询结果算作当前任务。
- **边界：**独立工作目录与产物交付另见 AC33。本项不增加全局 Task 总数、Shared 实体 Scope 或归档管理动作，不修改现有 Scope 归档业务。

### AC13 同一 Task 不并发执行

- **前置：**真实 Core 中一个 Task 正在执行；准备该 Task 的下一次定时触发及一个继续请求。
- **操作：**在首轮未终结时触发后续工作，分别核对 Core 和 TUI。
- **预期：**同一 Task 不同时运行两轮；排队或忙碌拒绝与实际后端规则一致；界面只计一个 Task，计划属性与当轮状态同时可辨。
- **失败判据：**后台已运行两轮但 UI 隐藏一轮、同一 Task 在不同状态分组重复计为两项、误把不同 Task 全部串行当作本需求。

### AC14 历史 ID 查询只定位并排除归档

- **前置：**有完整 ID、唯一短 ID、不唯一短前缀及不存在 ID；另有已完成但 Scope 未归档的任务，以及 Scope 已归档的任务。
- **操作：**在 Task 主界面分别提交 `/search_task <实际ID或前缀>`；检查定位、错误和补全候选；用同一归档对象的完整 ID 核对 `/taskdetail` 不旁路打开。
- **预期：**可浏览范围内完整与唯一短 ID 定位正确条目，不自动进入详情；未归档的已完成历史任务可命中；归档任务不进入结果、补全或详情。范围内不唯一和不存在明确报错，查询不改变任务业务状态，也不因定位历史任务而增加当前计数。
- **失败判据：**搜索直接打开详情、猜测不唯一目标、把所有已完成任务都过滤掉、归档对象被另一入口展开、定位错误对象、错误长期驻留。
- **边界：**查询排除不删除后端数据、不改变归档行为；归档范围已定，不再依赖 U07 另作选择。

### AC15 taskdetail 与最近三轮真实 Agent 对话

- **前置：**同一 Agent Task 有四次可区分的真实 Execution，每轮含不同消息；另有不足三轮的 Agent Task 和一个普通程序任务。
- **操作：**在 Task 列表记录阅读对象后输入 `/taskdetail <完整task_id>`；观察初始位置，滚动阅读最新三轮及其中一轮长对话；核对没有第四旧轮次的独立历史区块；再查看不足三轮任务，最后 `/back` 返回核对列表位置。归档详情排除复用 AC14 同一对象。
- **预期：**默认定位最新 Execution；同详情分组展示最近三轮，三轮包含最新；轮次不足时按实际数量；每轮内部可以补读长历史，Task 和 Execution 归属清楚。没有轮次切换器，不以 Main 摘要替代真实 Agent 消息；返回恢复列表最近阅读位置，不因日志入口后置而取消 Agent 历史。
- **失败判据：**只有结果摘要、只展示最新一轮而缺少另外两轮、混入其他 Task 或把多轮标成同一轮、自动增加第四旧轮次的历史区块、每轮只留第一片、虚构缺失记录。三轮内消息原本引用更早内容不算越界。
- **实施依赖：**B02 读取接口；正式命令、默认轮次和三轮范围已经确定，不再依赖旧 U01/U08 选择题。此处用完整 ID，不新增详情命令必须接受短 ID 的要求。
- **草稿边界：**不建立按 Task ID 或详情页分别保存的草稿；不把详情草稿恢复列为验收要求。底部命令输入和既有 Main/Task 普通草稿规则继续适用，不因此增加向 Agent 直接聊天的入口。

### AC16 Main 活动区 先后顺序与已看颜色

- **前置：**输入为空；按先后发起多个授权和决策，另有确定失败与 UNKNOWN；更新一个旧事项但不重新发起它。
- **操作：**在 Main 查看区域，进入一项阅读但不提交，按已登记的 Esc 或替代键退出处理，再从空输入切到 Task；核对本次仅查看操作对应的接口调用。
- **预期：**区域在输入框上方，多项按发起时间新到旧；旧项更新不冒充新发起；失败单列，UNKNOWN 独立作为需排查异常，可定位对象且无裁定操作。已看较深、未看较浅；查看不等于处理。Task 没有该提示区域。已看变色不调用 Execution 的 viewed 接口，也不改变执行留存状态。
- **失败判据：**出现侧栏、只能显示一项、只排序当前页导致新项遗漏、查看就被标为已处理、借 viewed 接口实现已读颜色、UNKNOWN 混入普通失败或授权、出现裁定菜单、Task 常驻该区域。
- **边界：**接口核对只需证明查看没有触发错误业务动作，不建设 UI 阅读审计或新的已读持久化系统。

### AC17 上键编辑边界和事项选择

- **前置：**Main 输入框有两行未发送文字，上方有至少两个待处理事项。
- **操作：**从第二行按上键到第一行，再按上键；用上下键选择事项，按 Enter。
- **预期：**先正常编辑移动，再进入事项选择；焦点和目标可辨；Enter 只进入处理。进入前后授权或决策仍待处理，不批准、不回答、不移除，也不发送 Main 草稿。
- **失败判据：**第二行就丢失输入焦点、选择行刷新后操作错对象、Enter 直接提交批准或回答、原 Main 草稿被发送或丢弃。

### AC18 Main 定向回答 批准完成与原稿恢复

- **前置：**Main 有未发送草稿 A、文字决策 D 和待批准授权；任务收到回答或授权后仍需继续执行。准备能观测批准后为 APPROVED、尚未 CONSUMED 的授权样例。
- **操作：**通过上键、选择和 Enter 进入 D，输入不同文字 B，用记录的发送操作提交；再进入授权，核对完整的实际动作、对象/资源及当前显示，随后明确批准。在授权仍为 APPROVED 时观察待处理区，刷新一次后复核。
- **预期：**B 只提交给 D，批准只作用于当前显示对应的授权，参数绑定实际 revision/display_hash；回答操作完成、授权确认 APPROVED 后立即移出待处理区，不等 CONSUMED 或整个 Task 完成。即使底层待处理查询仍返回 APPROVED，界面刷新后也不重新显示为待批准。两次返回均恢复原稿 A，B 不成为新的 Main 消息。
- **失败判据：**B 发给 Main 或其他事项、A 被覆盖、未展示实际授权内容或把旧参数的拒绝误报为成功、请求刚发出就显示已处理、批准后仍等待消费或 Task 结束才移除、刷新使已批准项复活、返回后仍绑定旧事项。
- **边界：**不删除授权记录，不由本项增加记住授权、撤销等新入口；授权/问题处理期间的命令禁用另见 AC24。

### AC19 Task show 与普通 Task 输入区分

- **前置：**Task 中有待回答事项 D，D 显示多个答案选项，其中一个允许的字面答案为 `/M`；另准备普通 Task 草稿。
- **操作：**普通浏览时提交一段文本并确认仍为草稿；由验收者正常编辑清空，再输入 `/show <D整个事项的ID>`。核对整个事项后，输入字面答案 `/M`，用记录的发送操作提交。
- **预期：**前一段留为草稿，不创建任务；`/show` 打开整个 D，不替用户选择答案。在问题处理状态，`/M` 没有导航命令效果，字面内容只作为 D 的答案提交；成功后回 Task 的 Scope 列表并刷新，状态与 Core 一致，不跳 Main。
- **失败判据：**普通 Task 文本误发或自动建任务、把事项 ID 当选项 ID、问题处理仍执行导航命令、答复落错对象、定向输入被一律拒绝、成功后滞留处理页或列表未刷新。
- **边界：**命令在处理状态不适用，不等于禁止以斜杠开头的合法问题答案；授权仍只能采用合法的批准或拒绝动作。

### AC20 目标失效 报错并自动返回

- **前置：**分别从 Main 与 Task 打开有效事项；在另一个合法入口处理或使该事项失效；本客户端尚有未提交回答。
- **操作：**尝试提交，观察错误与返回；不再额外按返回键帮助界面退出。
- **预期：**明确反馈已处理或失效并自动返回。Main 恢复原输入草稿；Task 返回列表并刷新；不会重复改变业务状态、改投 Main 或假报批准成功。返回过程不能把错误吞掉。
- **失败判据：**必须再按键才能离开失效处理状态、错误不可见、回答误发 Main、过期参数被接受为成功、原草稿被覆盖。交由 Core 校验旧请求并正确显示拒绝，不算失败。
- **回答保留：**失效返回后未提交回答可以不保留，不能据此判失败，也无需新增回答存储或恢复逻辑；原 Main/Task 草稿仍必须保护，旧回答不得回填给另一个事项。用户主动未提交退出另见 AC34。

### AC21 失败行委托主会话 真实处置与状态刷新

当前操作以 [#93 正式说明](run-and-test.md)为准：中立详情中 Tab 选择重做或移除提醒，Shift+Enter 提交结构化 Main 意图。旧执行不可重做必须明确拒绝；INIT_FAILED 无重做；UNKNOWN 只读。以下“取消这一失败的重试”指移除该失败提醒，不是 `/cancel` 或关闭计划。

- **前置：**Main 有原稿 A，Task 普通输入为空；准备可重试失败、已终结 FAILED 和处理失败样例，记录各失败所属 Task/Execution。
- **操作：**进入失败行但先不提交，确认无自动操作；明确交 Main 重试并观察后续轮。另对终态失败明确选择取消这一失败的重试，核对处置完成和历史状态。先确认 A 完整恢复，再人工清空 A，执行 `/T` 查看状态，从空输入 `/M` 返回。复用 AC30 的重开步骤核对已处置项，并验证同 Task 后来的另一项失败及一次实际处理失败。
- **预期：**准确目标与意图经 Main 处理，A 不误发，TUI 不再重复直调。重试产生关联原 Task/Execution 的后续工作，成功后退出原失败提示。终态失败的取消表示不再重试这一失败：真实确认处置后退出待处理，刷新、重连或重开均不复活；原 Execution 仍为 FAILED、历史可查，不关闭计划或取消其他工作。后来的另一项失败不被旧处置屏蔽。仅接收请求、重试尚未成功或处置尚未完成时不移除；处理失败保留任务标记。真正取消请求/执行另按 AC29 验证。
- **失败判据：**只凭 Main 口头答复或终态 cancel 的空操作回执退出、把 FAILED 改成 CANCELLED/SUCCEEDED、仅本地隐藏后重开复活、永久屏蔽整个 Task、重复发起重试、顺带停止未来计划、界面长期不刷新、失败标记随瞬时错误消失、把 UNKNOWN 纳入普通重试。
- **边界：**终态失败处置含义已经确定，不再保留该选择题；需有可重读且关联具体失败的真实处置结果，具体存储/投影由实施决定，不新增 UI 操作流水或直接 `/retry` 命令。
- **旧失败分支：**准备一个 RETIRED 或其他确实不能继续的旧失败，向 Main 提出重做。应明确反馈原执行不可继续及原因，保留原失败提示；再明确选择不再重试，完成处置后退出且历史仍为 FAILED。如需验证新工作，另由 Master 在 Main 明确提出，走普通提案链路并保留新旧身份。自动延长留存、自动创建新 Task、把拒绝假报为重试启动或偷偷删除旧 FAILED 均失败。

### AC22 产物末尾列表与当前文件

- **前置：**两个 Task 的不同工作目录各有同名、内容不同的登记产物，路径含中文或空格；其中一份在交付后被修改，与交付快照不同。
- **操作：**Main 接收任务结果，检查回复末尾的产物条目；分别 `/open` 两个当前路径，核对内容和来源。
- **预期：**有路径名称、所属执行、逐项解释及专用颜色；两个同名产物可区分，外部程序打开各自当前内容；修改过的文件不是旧快照。不新增产物详情页。
- **失败判据：**只有一句摘要、路径靠猜、把 Shared 当公共根目录而打开错误 Task 的同名文件、归属错误、打开旧快照、参数因空格断裂。
- **可选分支：**若实现 ID 入口，用 ID 再打开一次，仍应定位当前文件；未实现 ID 不阻断路径入口。

### AC23 open 不存在路径

- **前置：**Main 有一个已不存在的产物路径。
- **操作：**执行 `/open <不存在路径>`，观察一次可见反馈及其清除，再执行 `/help` 或其他合法命令。
- **预期：**仅报错一次，提示按登记方式消失；TUI 和 Core 继续运行，后续命令正常，不新增业务日志。
- **失败判据：**假成功、反复刷错、错误长期驻留、提示一出现便退出整个客户端、打开其他文件或旧快照。
- **实施参数：**记录短暂提示的可读停留方式，不要求零帧消失；U04 的退出对象已经确定。

### AC24 命令大小写 作用域与处理状态禁用

- **前置：**Main、Task 均可进入，普通输入为空；另备一个独立授权处理样例，问题处理的字面命令样式答案复用 AC19。
- **操作：**用不同大小写调用 `/M`、`/T`、`/help` 和 Task 的 `/taskdetail <完整ID>`；在 Task 调用带有效参数的 `/send`、`/open`、`/cotvisible`，在 Main 调用 `/search_task`、`/taskdetail`、`/cancel`。进入授权处理后尝试导航、帮助及 `/send` 或 `/rawmessage`，再用 Esc 退出，核对普通页面命令恢复适用。
- **预期：**普通页面命令不分大小写，参数保真；错页调用局部报错，不执行业务或变成聊天。授权/问题处理期间所有命令均不适用，包括全局导航、帮助和发送命令；不切页、不向 Main 发出消息、不代替批准，退出仍用已登记按键。合法问题正文只提交给当前事项，见 AC19。帮助不提供直接建任务、非 CoT 日志、`/attach` 或 UNKNOWN 裁定入口。
- **失败判据：**大小写改变允许范围、Task `/send` 发 Main、处理模式被命令绕过、任意文字被当作批准、用 `/rawmessage` 绕过事项绑定、错页调用被代办、帮助与真实范围不符。
- **边界：**处理状态禁用不撤销普通 Main 的 `/send`、`/rawmessage`，也不扩大 Main `/cancel` 范围；各功能批次验证其实际交付的命令分支。

### AC25 首字符规则与一次性纯文本

- **前置：**Main 普通输入状态，不在定向输入。
- **操作：**分别提交首字符是 `/` 的合法命令、正文中含 `/T`、前面有普通文字或空格再含 `/T` 的内容；再执行 `/rawmessage /T` 发送字面 `/T`，随后提交正常导航命令。
- **预期：**只有符合首字符及整次命令语法的输入执行；正文不被扫描；纯文本那一条作为内容发送，下一条恢复命令解析。
- **失败判据：**正文中命令被执行、先去掉正文再导航、纯文本模式永久残留、同次输入串联执行多条命令。

### AC26 独立草稿与非空输入限制

- **前置：**Main 输入为空；已确定可用的退出操作和草稿恢复能力。
- **操作：**进入 Task 写草稿 T，退出并重开 TUI；在 Main 核对没有把 T 放进 Main，发送一条 Main 消息使输入恢复为空，再用 `/T` 返回；在 T 后追加 `/M`，再用约定的发送操作提交。
- **预期：**Task 草稿 T 仍属于 Task；Main 消息与 T 不混合；提交包含 `/M` 的非空正文后仍留在 Task，内容保留为 Task 草稿，不产生 Main 消息。Main 原稿的保留由 AC18 的定向输入往返同时验证。
- **失败判据：**两个一级界面共用一份草稿、重新启动后误自动发送、追加命令被执行、为通过测试擅自加入临时命令模式。
- **边界：**重开进入 Main 已确定，不能再恢复上次 Task 界面；普通 Main/Task 草稿保留与允许放弃的未提交事项回答是两类内容。
- **详情边界：**Task 普通草稿仍按本项保留；不建立按 Task ID 或详情页分别保存和恢复的草稿，不能以“详情草稿不做”为由删除 Main/Task 普通草稿。

### AC27 多段粘贴的真实内容

- **前置：**准备多段含中文、换行、代码和 `/T` 的文本，记录完整原文。
- **操作：**先手写一句，粘贴第一段，再手写一句、粘贴第二段，提交消息。
- **预期：**每段以 `<pasted xx lines xxx...xxx.txt>` 风格显示并有独立缓冲；实际提交内容与原文、手写文字顺序一致；不执行粘贴内命令。
- **失败判据：**模型只收到占位符或路径、内容丢失或乱序、行数与实际片段不符、粘贴触发自动发送。

### AC28 macOS 中文输入 换行 补全与终端预检

当前已交付鼠标松开复制显示内容及软换行，纳入本项实际终端核对；早期“能力不可用时记录”的说明不撤销已交付范围。Enter 换行、Shift+Enter 发送；Ctrl+C 在非空可编辑输入清空，Ctrl+- 撤销，空输入或无可编辑回答框时退出。

- **前置：**实际目标终端和真实系统输入法；共用一份记录发送、换行、补全、滚动、Esc、图片粘贴和退出的键位表，不预设某组合键在所有终端都可用。
- **操作：**输入中文并确认候选、标点和宽字符，换行继续编辑；明确发送或主动清空后，从空输入补全一个当前页面可用的命令及对象 ID，再明确提交。
- **预期：**候选确认不发送；换行与发送可区分；字符、光标位置正确；补全只改输入不执行。实际键位不与已确定的事项退出、图片导入和客户端退出行为冲突。
- **失败判据：**候选确认或补全即发送、字符错位或丢失、无法区分换行与发送、仅用合成输入冒充系统输入法验收。
- **复制预检：**尝试目标终端或现有组件提供的文本选择/复制，核对回复和代码文字是否完整。若不可用，记录环境与缺口；不因此自动新增 `/copy`、自建选区系统或更换框架，也不把未批准的复制功能扩成首版交付条件。

### AC29 显式取消目标与真实反馈

- **前置：**真实 Task 中分别有可取消请求和执行，另有定时计划；记录全部稳定 ID。
- **操作：**测试无参、双目标、无效 ID，再分别执行 `/cancel --request <实际请求ID>` 与 `/cancel --execution <实际执行ID>`；查看 Core 状态及未来计划。
- **预期：**错误参数不执行；正确命令作用于指定对象；本地发出、Core 接收与最终状态不混淆；取消一次执行不误称未来计划已停止。
- **失败判据：**用当前选中行猜目标、刷新后取消另一个对象、接收回执被显示成最终取消、错误停止其他计划。
- **边界：**正式拼写与目标语义均已确定；本项不新增整个 TaskPlan 的聚合取消。
- **终态边界：**本项以确实可取消的请求/执行验证真实取消。对已 FAILED 的失败事项“不再重试并退出待处理、保留 FAILED”的处置路径见 AC21；不得把普通 cancel 的空操作回执当作该处置已完成，也不由本项新增计划关闭。

### AC30 退出 重开与后台持续运行

- **前置：**有一个后台任务正在执行；TUI 有普通 Main/Task 草稿，最后停留在 Task。
- **操作：**使用记录的退出键关闭 TUI，核对 Core 继续；重新打开，读取状态和草稿；再进行一次可控断线与重连。
- **预期：**后台任务继续；重新启动默认 Main，仍是同一权威主会话；普通 Main/Task 草稿各归其位且不误发；重连后状态与 Core 一致，消息不重复。批次五交付后，AC21 复用本项确认已处置失败不再回到待处理，历史 FAILED 仍可查。
- **失败判据：**退出同时停止 Core、任务无故取消、重开仍在 Task 或产生第二主会话、重连重复发送、普通草稿被清理。已明确退出的未提交事项回答未保留，不按本项判失败。

### AC31 UI 操作不进入会话历史

- **前置：**安静的 Main，记录当前权威消息边界；不要同时产生无关业务消息。
- **操作：**切页、帮助、补全、滚动、制造一个参数错误、清除错误、改变 CoT 显示。
- **预期：**这些操作只改变客户端呈现，没有新增 Master 消息、工具执行结果或专用 UI 操作流水。
- **失败判据：**命令反馈成为 Main 对话、每次滚动或展开增加持久业务事件、操作调用模型猜测路由。
- **业务边界：**AC21 中 Master 明确提交给 Main 的重试/取消意图及完成的失败处置是业务输入和结果，允许并需要按现有链路记录或查询；本项不禁止这些业务状态。选择失败行、提示和状态刷新仍不新增合成 Master 消息或 UI 操作流水。

### AC32 图片直接粘贴与失败保留

当前 macOS 操作：Ctrl+V 导入剪贴板实际像素，Cmd+V 为普通文本粘贴。等待 READY 后才明确发送。API 导入图片的成功不能替代此原生路径。

- **前置：**真实目标 macOS 终端，系统剪贴板有合法图片，Main 有文字草稿；核对实际模型支持图片、既有 vision/budget 配置可用，样例符合当前导入契约的格式与数量限制。另备普通路径文本及导入/提交失败样例，记录实际粘贴动作。前提不满足先明确记录，不要求新增配置界面或模型能力。
- **操作：**直接执行已验证的粘贴操作，将剪贴板图片加入草稿，不先输入导入命令；核对附件导入成功后明确发送图文消息。供既有导入链路读取的临时材料在导入完成前保持可读。再核对普通路径文本仍为文字，分别验证导入失败和已导入后提交失败。
- **预期：**粘贴只加附件、不自动发送；真实图像经既有契约进入实际消息，文字与图片对应正确。失败保留原有文字和已导入附件，明确说明未成功导入的图片，不丢图后只发文字；Task 不因此偷发 Main。
- **失败判据：**只有路径/文件名/占位文字、尚未导入完成就宣称附件可用或删除源材料、图片未进入消息、失败后已有材料消失、以浏览器或 `/attach` 替代直接粘贴、粘贴即发送。
- **真实能力阻塞：**实际终端及可用本机适配仍无法支持时，记录环境与尝试证据，在实施中询问 Master 替代。确认前记为未执行／能力受阻，不自行改路径上传并通过；其他已定功能继续。只核对既有模型、预算与导入前提，不增加新格式转换、预算管理或模型选择功能。

### AC33 Shared 逻辑归组 独立目录与产物交付

- **前置：**准备两个未指定 Scope 的任务要求 A、B：各自在工作目录生成 `report.txt`，内容分别带 A、B 标记，仅把它登记为产物；另产生一个不交付的中间文件。
- **操作：**通过 Main 发起 A 并确认完成，再发起 B 并确认完成；记录两次实际工作目录，核对两个同名文件的内容。在 Task 检查逻辑分组；已退出默认集合的任务用 `/search_task <task_id>` 定位。检查 Main 的产物条目，再分别 `/open` 两个明确路径。
- **预期：**A、B 属于同一个逻辑 Shared 组，实际工作目录不同；相同相对文件名互不覆盖。Main 只列登记产物及必要结果信息，不自动交付中间文件或整个目录；两个 `/open` 分别打开正确 Task 的当前文件。完成后没有新增自动删除源文件的步骤。
- **失败判据：**因逻辑同组而把两个 Task 绑定同一实际目录、同名文件互相覆盖、只交付整个工作目录、中间文件被自动列为产物、当前路径落到错误 Task、完成即删导致无法打开、为了 Shared 分组新增统一 DIRECTORY 占用锁。
- **分段验收：**Task 批次验证真实发起、分组、独立目录与同名文件互不覆盖；产物批次验证回复条目、只交付登记产物及 `/open`。只完成前段不能勾选整项通过。
- **边界：**本项不验收未来目录清理、跨目录访问权限隔离或并发压力，不要求迁移旧目录；既有容量限制及同 Task 不并发约束继续适用。

### AC34 未提交时 Esc 退出处理

- **前置：**Main 有原稿 A 和一个有效待回答事项；另准备 Task 的空输入及一个有效事项；记录实际退出键，优先 Esc。
- **操作：**在 Main 通过选择进入事项，输入回答 B 但不提交，按 Esc；确认原稿 A 完整恢复后，由验收者主动清空这段测试草稿，再执行 `/T`。从 Task 的空输入执行 `/show <事项ID>`，输入未提交内容并按 Esc。若目标终端确实不能使用 Esc，按记录的替代组合键重复。
- **预期：**两次均退出事项处理，不产生批准或回答；Main 原稿 A 恢复，Task 回到进入前的浏览和普通输入；Core 中事项仍待处理。退出处理不会退出 TUI。
- **失败判据：**Esc 误发送、误批准、关闭客户端、覆盖原 Main/Task 草稿、没有可用退出方式、未记录就假定某组合键有效。
- **回答保留：**退出后 B 不保留不算失败，不为保留新增存储或恢复逻辑；既有输入组件无额外代价自然保留可以接受，但 B 不得覆盖 A 或复用给另一事项。原稿恢复、无业务提交及可退出均必须通过；不把 Esc 扩展成普通 Task 草稿的全局导航键。
- **命令边界：**授权/问题处理期间包括 `/back` 在内的所有命令均不适用；本项使用 Esc 或已验证的替代退出键。一级页 `/back` 的无操作规则见 AC01，不将它当作处理状态的退出方式。
