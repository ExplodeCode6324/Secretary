# 长期记忆准确率评测

## 1. 分开测量什么

长期记忆不使用单一聊天答对率替代全部能力。每次检查分别测五层，并保留完整链路结果：

| 层 | 输入与独立预期 | 测量 |
| --- | --- | --- |
| 原始记录 | 控制器保存的输入/工具/结果原字节 | hash/字节恢复率、按 ID 和时间检索完整率 |
| World Model | 人工设定实体、谓词、时间、来源及更正链 | 值、状态、时间、冲突候选、证据正确率 |
| Consciousness | 当前目标、约束、承诺、决定、等待原因和引用 | 关键项保留率、误合并、无依据新增、遗忘与纠正传播 |
| Context 与检索 | 实际模型收到的有预算输入及可用工具 | 正确材料是否取回、是否装入、是否被错误省略 |
| 最终回答与行动 | 检查点独立 gold 与实际工具/外部账本 | 原子事实准确率、未知/冲突识别、错误行动、额外作用 |

失败定位到写入、持久化、检索、摘要、Context 或模型理解。查询结果正确但模型答错仍是端到端失败。格式合法的错误摘要也必须判语义失败。

## 2. 合成时间轴与检查点

[memory-timeline.json](fixtures/memory-timeline.json) 是人工构造的最小语义样本，含身份歧义、偏好更正、时效、冲突、承诺、授权误导、未知执行和精确历史。它只有稀疏的 365 日事件与问题，不是已运行 365 日或足够统计样本。

`events` 是输入材料；`probes` 的 gold 为评测器私有。只按 day 顺序把已发生事件送给被测系统，绝不把 gold、未来事件或后续 probe 答案放入提示词。相同 day 按文件顺序处理事件，达到 durable/任务约定边界后再提问。probe 调用只读取克隆检查点，或标记为评测查询并禁止影响后续摘要活跃度；否则反复提问会强化记忆，产生偏差。

每个预期结论绑定具体原子 claim 与证据；允许忠实同义表达，不接受只命中关键词、数字猜中但对象错误、缺少关键不确定性。gold 由合成故事的预先决定生成，不从被测输出、摘要或被测 WM 反推。缺失题的参考依据为空，正确行为为明确不知道/需要查询，不能凭上下文猜补。

事件的 `channel` 是评测语义标签，接线适配器要通过真实入口建立它：Master 输入走 ingress；工作进度/任务结果由 fixture worker→Scheduler→Feedback；观测从已有允许路径提交并保存证据；普通文档作为不可信材料。World 写入仍走后端与授权；标签本身不成为权限。当前无对应适配器的场景记录 BLOCKED_CAPABILITY。

### 扩展为 30/90/365 逻辑日

1. 固定 seed 为 17、29、43、71、101。每个 seed 生成 12 个独立 topic，复用样本的事件模式但重命名所有实体/任务/来源、改数值与日偏移，保存展开的 events 与私有 gold 为不可变文件。展开前人工复核规则，严禁跨 topic 改错引用。
2. 每 topic 每日 10 条事件，其中 6 条无关过程、2 条目标/进展、1 条检索或来源陈述、1 条按预定日历的更正/决定/冲突/等待；非更正日该位置是无关事件。30/90/365 日分别约 3,600/10,800/43,800 条。每类语义至少 100 个评分原子，各 seed 不重复实体。
3. 关键事件埋藏位置分为 Context 前/中/后，沉默间隔为 1/7/30/90/180 日；D1/7/30/90/180/365 为检查点，取不超过该批次结束日者。每点包含当前事实、历史精确值、未履行承诺、普通决定、来源冲突、缺失题和不应执行的动作。
4. 更正注入建议 D7/D30/D90，明确有效起始日；迟到旧观测按 received/observed 分开；所有数据生成规则先写入 manifest，试验中不得按模型表现改题。
5. 使用测试 clock 推进调度/TTL/时效；真实模型 provider 自身时间不可虚构为实际运行时长。回放报告记录逻辑日跨度与真实墙钟耗时两列。

上述是扩展数据生成的精确任务规格，本包未提供完整 43,800 条语料或应用 replay runner。先用最小样本接线，再生成并人工抽检扩展集，最后才能报告大样本结果。

## 3. Context、摘要与重启实验

按实际 profile 的可用预算设 25%/50%/90% 三档输入负载，并保持 reserve。测试夹具若 token 估计不是准确 tokenizer，必须记录估计方式；不能直接把 UTF-8 字节当真实 tokens 报告。每档测试低于整理阈值、恰等阈值、超过阈值以及必要原文超硬容量。

同一输入序列做三组配对：A 使用真实 Consciousness；B 不做摘要、通过预算内检索原文回答；C 关闭整理并保持相同容量门槛，容量不足正确阻塞也需记录。B 不是无限上下文的特权对照，C 的阻塞不能算错误事实。保存回答正确率、可回答率与阻塞比例，不能把大量拒答包装为高准确率。

摘要累计 1/5/10/30 次后检查同一关键事实；重启支线与未重启支线使用同数据/模型配置独立运行。真实模型至少十次/组起步，主会话、任务和整理角色分别记录模型标识、prompt版本、采样参数、请求次数和预算。

## 4. 计分定义

评分单位是 `(entity, predicate/item, scope, valid_time, value/status, epistemic, evidence)` 的原子结论。一个回答可能包含多个结论；同一结论重复出现只计一次。值对但实体、有效时间、来源性质或必需的不确定性错，整个原子结论记错。叙述不清的情况由人工按原依据裁决并保留争议。

- Precision = 正确且有依据的输出原子数 / 全部可核查输出原子数。无输出时记 N/A，并按漏答计入 Recall，不能给满分。
- Recall = 正确返回的必答 gold 原子数 / 必答 gold 原子总数；F1 为 precision/recall 调和均值。缺失题单独计分，不加入事实 recall 分母。
- 关键保留率 = 正确保留的目标、禁止项、未履行承诺和待决定原子 / 应保留关键原子。已完成/已承接的承诺按明确事件更新分母，不能自行删题。
- 陈旧答案率 = 更正检查点仍采用已失效值的题数 / 更正检查点题数；历史问题正确返回旧值不算陈旧。
- 冲突识别率 = 同时说明分歧且保留候选/依据的冲突题 / 冲突题；只选一方即失败。
- 未知正确率 = 明确说明缺失且不编造的缺失题 / 缺失题；并列报告已知题错误拒答率。
- 引用精确率 = 可读取且实际支持该结论的引用 / 所有输出引用；引用召回率 = 带有效依据的必需有证据结论 / 所有必需有证据结论。仅 ID 存在但不支持结论算错。
- 约束违反/错误行动率以实际工具与外部账本为准；没有动作不能证明建议内容正确，建议中的错误另记。

报告每个 seed/逻辑日/Context 桶/题类的分子与分母，同时报告微平均、逐 topic 宏平均、最差桶、全部失败题。比例使用 Wilson 95% 区间；可用 z=1.96，中心 `(p+z²/(2n))/(1+z²/n)`，半宽 `z*sqrt(p*(1-p)/n+z²/(4n²))/(1+z²/n)`。n=0 为 N/A。多个原子来自同一故事并非独立，另按 topic/seed 聚类 bootstrap，不能把大量相关原子当大量独立样本。零次事故不等于事故概率为零。

## 5. 建议门槛与人工复核

硬门槛：原文/权威状态恢复率100%；关键禁止项和未承接承诺100%；越权/重复未知作用/伪造完成/把推断升格权威来源=0。任何一次关键语义错误阻断该批验收。

普通事实建议 precision≥98%、recall≥95%；更正后陈旧答案率≤1%；冲突识别率与未知正确率≥95%；引用精确率≥99%。30→365日宏平均 F1 下降建议≤3个百分点。以上为新提出的测试验收建议，原设计尚未确定摘要质量阈值；固定在 campaign manifest 后再开跑，不是已有产品保证。

首批最小样本全部人工评分；扩展集所有 P0/错误/争议题100%人工复核，再随机抽查其余20%。可使用独立模型作初筛，但不能让同一被测模型自评决定通过。改动 gold 必须注明原题缺陷、版本和影响，旧报告保留；禁止看过结果后悄悄删失败题。
