# 完整用户旅程与组合故障

由 [catalog.json](../catalog.json) 生成；修改唯一来源后运行 `python3 test/scripts/build.py`。

通用隔离设施、竞态排序和判定规则见 [执行协议](../PROTOCOL.md)。每个子情况独立执行和记录。evidence_level 是目标证据类型，不代表已经取得；真实模型场景中的确定性持久化子项可先以 OFFLINE_RUNTIME 单独报告。

## E2E-001 合成任务拒绝再新任务批准

P0 · 目标证据 `LIVE_MODEL` · `NOT_RUN`

依据：BrainStorm 2.1, 2.2, 2.3, 2.4, 2.5, 3.1, 3.2, 3.3, 3.4, 3.5, 4, 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 5.7, 5.8；语义约束 J06, J12, J13, J11。

规范：[BrainStorm_Baseline_v3.md](../../../BrainStorm_Baseline_v3.md)、[SCENARIOS.md](../../demo_design/SCENARIOS.md)、[PERSISTENCE.md](../../demo_design/PERSISTENCE.md)、[REVIEW.md](../../../../test_case/reports/implementation/REVIEW.md)。

前置：任务仅将合成数组求和输出到result文件，独立验证器预期0/31/3。

步骤：

1. 委派第一任务并拒绝。
2. 新任务等待批准时插入询问。
3. 批准。
4. 独立读取产物并核验。
5. 处理反馈。

预期与禁止结果：

- 拒绝无作用。
- 插入输入不丢。
- 第二任务只做约定范围。
- 结果/限制/证据准确。
- 主会话无直接执行。

证据：两task全链ID；产物独立测试；模型原文。
