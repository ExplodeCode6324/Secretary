## 后续记忆回归框架

#21/#28 的联合验收将扩展真实模型记忆场景：多轮形成事实、后续更正、上下文退出、整理和重启、长期未完成事项，以及从原始日志检索证据。

每个场景保存原始证据和预期状态，运行正常记忆链路，记录首次回答、检索结果、派生记忆及模型配置。失败时，可将正确原始证据直接放入同一模型 context 再测，以区分来源缺失、检索遗漏、记忆生成/退出和阅读推理问题。模型或记忆结构升级时，比较直接读取旧记忆与从原始记录重建后的结果。

当前已有真实整理与跨进程连续性场景；框架扩展随相关功能交付。离线测试验证状态与协议，真实模型测试记录语义质量及样本差异。

## 验证证据与运行边界

报告分别标明文档/源码检查、离线协议测试、实际 PostgreSQL、真实模型、PTY/虚拟终端、物理终端及 Master 人工验收。源码审阅、模拟模型或 SIGKILL 恢复不能分别替代运行证据、真实模型质量或断电持久性验证。逐项记录通过、失败、未测和环境阻断，不用一项通过代表整组。

故障回归同时检查持久状态、请求身份和实际副作用次数；响应丢失后按原请求对账，未知外部效果不能靠重做来验证。记录源码提交、配置、首次失败及后续修正，公开报告脱敏，原始材料留在受控目录。状态守卫、提交边界和现有测试入口以[系统不变量](../docs/invariants.md)为索引。

敏捷体验阶段只使用 Master 指定的唯一实例及固定数据域，全部运行数据保留；本目录保留的历史在线脚本可能新建数据域、数据库或清理测试资源，不得直接用于该实例。普通离线/CI 测试的临时 fixture 不构成敏捷部署方式，也不得连接敏捷数据库；需要故障注入或破坏性验证时先向 Master 说明并取得安排。

不得将 `SECRETARY_TEST_DATABASE_URL` 指向敏捷集群，也不得对它执行 `test:db:clean -- --apply`。模型自评不证明任务完成；竞态顺序用显式屏障控制，不靠 sleep；多条件守卫逐一破坏单个条件验证；报告列出用例总数与各状态计数，不只给通过率。
