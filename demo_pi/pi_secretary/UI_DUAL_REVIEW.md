# TUI / WebUI 双开复核

## Master 的入口

启动器位于仓库的 `demo_pi` 目录。

1. 先用 `/quit` 退出仍在运行的旧版独立 TUI，释放旧进程的数据锁。本次没有自动关闭 Master 的进程或操作现有授权。
2. 双击 `启动Secretary_Pi.command` 打开新版 TUI。
3. 双击 `启动Secretary_Web.command` 打开 WebUI；也可在新版 TUI 输入 `/web`。
4. 两者连接同一个后台、同一个 Session、同一数据目录 `.demo-data/interactive-live`，继续使用已有角色模型配置。已有历史会自动显示。

`/quit` / Ctrl+C 只关闭新版终端客户端；关闭网页也不停止任务。需要停止后台或更新后台代码时，运行 `停止Secretary后台.command`，再重新启动界面。后台启动时确定模型、数据库和数据目录配置；后开的界面直接连接已有后台。

不要同时启动旧的 `src/tui.ts` 独立宿主和新后台；数据锁会阻止第二个宿主写入。正常入口现已改为 `client-tui.ts`。

## 两个界面的内容

- TUI 用 256 色 SGR，解决只输出真彩色代码时的终端兼容问题。启动器明确启用色彩；Master 米色、Secretary 浅蓝、系统灰青、授权浅黄。输入/模型文本里的控制序列仍会被清理。
- 网页为深色会话工作区：左侧任务导航，中间连续会话和输入框，右侧按需展开决定/授权面板。颜色与 TUI 对齐，不用大面积卡片堆叠。
- Context 使用量在两个界面显示；来源是当前快照估算，并非供应商实测 token。
- 网页支持发送消息、查看任务及详情、普通工作决定、批准/拒绝/撤销、程序/记忆/操作查询。输入框也接受 TUI 的 `/` 命令，结果在详情窗口显示。
- 网页授权附带界面上那一版本的 revision 和 display_hash；若另一个界面已经处理，旧按钮请求会被拒绝。聊天文本不会成为授权。

## 同步与本地服务

单独后台持有 Store 锁、运行主会话和 Scheduler；TUI/WebUI 都只是客户端，不能各自启动第二轮模型。两端按照持久日志读取消息，网页约 700ms、TUI 约 350ms 刷新。网页消息重试沿用同一个 request ID。双端提交的不同消息都会保留；不保证两条同时到达的消息合并为同一轮调用。

服务只绑定 `127.0.0.1` 的自动分配端口，要求随机本地令牌并检查 Host/Origin。入口文件 `ui-endpoint.json` 权限 0600，API keys 不发送给浏览器。启动器使用 URL fragment 将本地界面令牌交给浏览器，页面立即清除 fragment，令牌只保存在该标签会话的 sessionStorage。

后台日志为数据目录中的 `ui-backend.log`。首次创建后台后，关闭全部界面仍会继续执行任务；使用专用停止入口结束后台。

## 本轮实际验证

- 实际浏览器截图检查了空会话、米色/浅蓝消息、任务列表、Context 和浅黄色授权面板。
- 实际网页发送消息，实际 TUI 客户端收到；TUI 发回消息，网页显示。
- TUI 创建测试程序授权，网页看到同一请求；网页拒绝后，TUI 待授权数归零，任务保存拒绝结果。
- 两个独立 TUI 进程同时启动同一空数据目录，只产生一个后台；双方看到彼此输入，关闭两个客户端后后台仍保留同一个 Session。
- HTTP 集成测试覆盖同键重投、陈旧授权、未带令牌和跨 Origin 请求拒绝。
- 实际 PTY 检查四类 256 色序列及 `SECRETARY_COLOR=256` 对继承 `NO_COLOR` 的显式覆盖。
- 类型检查、格式检查以及本次完整离线套件 46 项通过；1 项 PostgreSQL 测试因未配置数据库跳过。本轮没有重新调用在线模型。

**视觉证据边界：** 本轮查看了网页实际截图，并核对 Master 提供的全灰终端截图；工具仍不能访问 macOS Terminal 的原生窗口。因此没有把 PTY 颜色代码检查再次描述成“已看过 Master 的 Terminal 渲染”。新版采用兼容的索引颜色和启动器显式色彩配置，原生 Terminal 的最终观感请在上述启动器中验收。
