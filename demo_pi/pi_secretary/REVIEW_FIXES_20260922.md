## 已实现并通过对应复现的修复

| Review | 修改及验证边界 |
|---|---|
| F01 | 主会话在任何逐消息事件之前，保存含整个已领取输入批次的 Pi Context 与 Session 指针。SIGKILL 后第二条输入仍进入恢复后的模型调用。 |
| F02 | Store 在追加日志之前验证整个事务的快照、对象引用、事件和回执；验证后整体安装内存投影。额外验证多记录事务失败时日志和内存均不改变。孤立对象允许残留，不被当作已提交事务。 |
| F03 | 校验后的绝对路径直接传入 Pi read；拒绝 `@` 等别名；验证工作目录和祖先，避免替换根目录为符号链接。兼容 macOS 系统临时目录的规范路径。并发恶意替换的 OS 级竞态隔离不在此修复证明范围。 |
| F04 | 写操作与授权显示绑定目标内容 SHA-256 或 ABSENT；实际写入前再比对，旧批准不能覆盖并发修改。旧的无资源版本操作保守拒绝。 |
| F05 | World 提案中的证据内容必须匹配引用日志事件的 payload；不能拼接真实 Master 事件 ID 与另造内容。来源归属检查仍保留。 |
| F07 | 拒绝外帧未知字段、非规范 Base64、事件序号跳跃和重复事件/回执；重放与新写入共用事务预验证。 |
| F08 | 文件写入的最终边界重新检查任务前提；授权 dispatch 检查 owner epoch 和 attempt。重启时未分派操作的 owner 接管有独立持久事件，不在 dispatch 中静默接受旧 owner。 |
| F10 | 恢复时为持久化 OPEN 决定补建缺失反馈；按 decision ID 去重，关闭崩溃交接空档。 |
| F11 | 使用 Pi 原生 finishTurn 回调，根据 Scheduler 的持久状态结束本轮；read 后 write 等待授权的混合批次不会多调用一次模型。 |
| F12 | 工具去重键增加持久 transcript 中的 assistant 消息位置、工具名、参数摘要；恢复按各次 assistant 响应匹配回执，后续响应复用 provider tool ID 不再吞掉新意图。 |
| F15 | 整理成功后重新估算现有历史和待处理输入；仅容量足够时解除 CAPACITY_BLOCKED，不制造新 Input。 |
| F17 | 后续提案继承父任务原始材料、原始 Context 与结果详情引用。接受延迟后续时就固定父执行的保留关系，触发时移交给新执行，完成时释放；新任务仍有独立 workspace。 |
| F20 | MasterInteract 先保存 QUEUED；TUI 实际展示后才保存 SENT 与展示回执。重启可继续展示待发送项。回执表示本地展示，不表示 Master 已阅读；显示后、回执前崩溃可能再次展示。 |
| F22 | PostgreSQL 迁移逐步记录版本，串行化迁移；第 1 步已存在也继续补装第 2 步，兼容先前完整安装但没有第 2 步标记的库。 |
| F23 | 数据库连接、事务冲突、资源及服务故障类 SQLSTATE 不再写成永久业务拒绝；事务回滚，保留原 change ID 重试路径。实际 PG 注入 40P01 验证。 |
| F24 | 登记程序在独立进程组中运行，取消后 200ms 仍未退出则升级终止本任务进程组；有实际忽略 SIGTERM 的程序测试。无法确认的效果仍为 UNKNOWN。 |
